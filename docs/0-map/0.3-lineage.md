## 已废弃项目

这一节回答：哪些东西不该再用，官方让你换成什么？

| 名称 | 状态 | 官方替代品 | 来源 |
|---|---|---|---|
| Isaac Gym（预览版） | 官网标注为已弃用的遗留软件：仍可下载使用，但不再提供支持 | Isaac Lab | [^gym-page] |
| IsaacGymEnvs | GitHub 仓库已归档（只读） | Isaac Lab（官方提供迁移指南） | [^ige-repo] [^mig-ige] |
| OmniIsaacGymEnvs | README 声明 4.0.0 为最后一个版本，后续并入 Isaac Lab；仓库已归档 | Isaac Lab | [^oige-readme] [^mig-oige] |
| Orbit | 原仓库 `NVIDIA-Omniverse/orbit` 现在重定向到 `isaac-sim/IsaacLab`；Isaac Lab 1.0 在 Orbit 基础上发布 | Isaac Lab | [^lab-v1] [^mig-orbit] |

Isaac Lab 官方生态页对此有统一说法：Isaac Lab 取代了 IsaacGymEnvs、OmniIsaacGymEnvs 和 Orbit，这些旧框架均已弃用[^lab-eco]。

为什么这些旧名字至今还常被搜到？因为 Isaac Gym 时代留下了大量有影响的研究成果：同一生态页列举了基于 Isaac Gym 的足式运动、灵巧手操作、工业装配等工作[^lab-eco]，它们的开源代码大多仍停留在 Isaac Gym 或 IsaacGymEnvs 上。读这类论文代码时，把它当作思路参考，不要期待在主线环境里直接运行。

## 三次关键改名

这一节回答：同一个东西为什么有好几个名字，它们在代码里长什么样？

**第一次：Orbit → Isaac Lab 1.0（2024-06）。** 扩展 `omni.isaac.orbit`、`omni.isaac.orbit_tasks`、`omni.isaac.orbit_assets` 改名为 `omni.isaac.lab`、`omni.isaac.lab_tasks`、`omni.isaac.lab_assets`，脚本 `orbit.sh` 改为 `isaaclab.sh`[^mig-orbit-v1]。

**第二次：Isaac Lab 1.x → 2.0（2025-01），与 Isaac Sim 4.5 同步。** 两边一起改：

- Isaac Sim 的扩展前缀由 `omni.isaac.*` 改为 `isaacsim.*`，不少扩展同时被拆分，例如 `omni.isaac.core.world` 变为 `isaacsim.core.api.world`，`omni.isaac.kit.SimulationApp` 变为 `isaacsim.SimulationApp`[^lab-v2][^rename]。
- Isaac Lab 的扩展由 `omni.isaac.lab*` 改为 `isaaclab*`；原 `isaaclab_tasks` 下的适配层（wrapper）拆成独立的 `isaaclab_rl`，并新增 `isaaclab_mimic`[^lab-v2]。
- Isaac Lab 2.0 不再兼容旧版 Isaac Sim[^lab-v2]。

与 [0.2 的版本说明](0.2-layers.md)一致：5.x 中 `omni.isaac.*` 旧名仍以弃用扩展的形式保留，导入会打印弃用警告，官方计划在 6.0 移除[^sim-rn51]。

**第三次：仓库与文档地址。** 代码仓库从 `NVIDIA-Omniverse/orbit` 迁到 `isaac-sim/IsaacLab`（旧地址自动重定向），文档从 `isaac-orbit.github.io` 迁到 `isaac-sim.github.io/IsaacLab`[^lab-releases][^lab-v1]。IsaacGymEnvs 与 OmniIsaacGymEnvs 也从 `NVIDIA-Omniverse` 组织迁到了 `isaac-sim` 组织（推断：依据 GitHub API 对旧路径返回 Moved Permanently）。

## 看 import 判年代

这一节回答：拿到一段旧代码，怎么快速判断它能不能直接用？

"状态"一列针对 Isaac Sim 5.1.0 + Isaac Lab 2.3.2。

| import 语句 | 年代 | 在主线上的状态 | 换算后的写法 |
|---|---|---|---|
| `from isaacgym import gymapi` | Isaac Gym（2021–2022） | 不可用：独立产品，不随 Isaac Sim 分发 | 改用 Isaac Lab 重写任务 |
| `from omni.isaac.gym.vec_env import VecEnvBase` | OmniIsaacGymEnvs（2022–2024） | 不可用：5.1 的扩展目录中没有 `omni.isaac.gym`[^ext-check] | `isaaclab.envs.DirectRLEnv` |
| `from omni.isaac.orbit.envs import RLTaskEnv` | Orbit（2023–2024） | 不可用：扩展已改名[^mig-orbit] | `from isaaclab.envs import ManagerBasedRLEnv` |
| `from omni.isaac.lab.envs import ManagerBasedRLEnv` | Isaac Lab 1.x（2024） | 不可用：2.0 起改名[^lab-v2] | `from isaaclab.envs import ManagerBasedRLEnv` |
| `from omni.isaac.kit import SimulationApp` | Isaac Sim 4.2 及更早 | pip 安装下作为脚本首行会报 `ModuleNotFoundError: No module named 'omni'`；先 `import isaacsim` 之后才能导入（弃用）。二进制安装未实测[^kit-test] | `from isaacsim import SimulationApp` |
| `from omni.isaac.core import World` | Isaac Sim 4.2 及更早 | 弃用可用：在 `SimulationApp` 启动之后可以导入，打印弃用警告（校验方在 5.1.0 上实测）[^ext-check] | `from isaacsim.core.api import World` |
| `from isaacsim.core.api import World` | Isaac Sim 4.5 起 | 可用 | — |
| `from isaaclab.envs import ManagerBasedRLEnv` | Isaac Lab 2.0 起 | 可用 | — |

一个简单的判断法：看到 `isaacgym` 或 `omni.isaac.gym`，说明是 Isaac Gym 或 OmniIsaacGymEnvs 时代的代码，只能参考思路；看到 `omni.isaac.orbit` 或 `omni.isaac.lab`，按改名表替换包名，一般还能用；看到 `omni.isaac.core` 这类 Isaac Sim 旧名，暂时能跑，但应当迁移。改旧脚本时，第一处要改的通常就是开头的 `from omni.isaac.kit import SimulationApp`：在 pip 安装的主线环境里，它会在第一行就失败[^kit-test]。完整的新旧名对照见 [3.11 Isaac Sim 的 Python API 地图](../3-isaacsim/3.11-api-map.md)。

## 除了 import，还能看什么

这一节回答：资料里没有代码时，怎么判断它的年代？

很多教程和论坛帖子只有安装步骤或命令行，没有 import。这时可以看下面几类线索：

- **启动脚本名**：出现 `orbit.sh`，说明是 Orbit 时代；Isaac Lab 1.0 起改为 `isaaclab.sh`[^mig-orbit-v1]。
- **文档地址**：链接指向 `isaac-orbit.github.io` 的是 Orbit 文档；Isaac Lab 的文档在 `isaac-sim.github.io/IsaacLab`，而且按版本分路径（如 `/v2.3.2/`），先确认链接里的版本号[^lab-v1]。
- **Python 版本**：要求 Python 3.10 的对应 Isaac Sim 4.x；要求 3.11 的对应 Isaac Sim 5.x[^lab-install]。
- **环境名**：虚拟环境叫 `isaaclab` 的多半是 1.x 时代，2.0 起默认名改为 `env_isaaclab`[^lab-v2]。
- **下载方式**：要求从 NVIDIA 官网下载 "Isaac Gym Preview 4" 压缩包的，是 Isaac Gym / IsaacGymEnvs 时代[^ige-repo]。

判断出年代后，再回到上面的速查表：同一时代的 import 通常可以批量替换，跨过 Isaac Gym 这条线的则需要重写。

## 常见误解

:::{admonition} 误解一：Isaac Gym 是 Isaac Sim 的旧版本
:class: warning

不是。Isaac Gym 是独立发布的预览版 GPU 物理仿真工具，直接构建在 PhysX 上，从来不是 Isaac Sim 的一个版本。NVIDIA 后来把它的能力整合进了 Isaac Sim，任务库 IsaacGymEnvs 则由 Isaac Lab 取代[^lab-eco]。
:::

:::{admonition} 误解二：Orbit 是另一个框架
:class: warning

Orbit 就是 Isaac Lab 的前身。Isaac Lab 1.0 在 Orbit 基础上发布，仓库沿用同一个，版本号从 Orbit 的 0.3.1 接续到 1.0.0[^lab-v1][^lab-releases]。Orbit 时代的代码替换包名后，大部分概念仍然适用。
:::

:::{admonition} 误解三：OmniIsaacGymEnvs 还在维护
:class: warning

没有。它的 README 声明 4.0.0（2024-05-31）为最后一个版本，后续并入 Isaac Lab，仓库也已归档[^oige-readme][^oige-rn]。Isaac Lab 1.0 的 Direct 工作流就来自 OmniIsaacGymEnvs[^lab-v1]。
:::

:::{admonition} 误解四：`omni.isaac.*` 在 5.x 上已经不能用
:class: warning

还能用，只是会打印弃用警告；官方计划在 6.0 移除[^sim-rn51]。前提是 Kit 已经启动，或者已经 `import isaacsim`；pip 安装下直接把 `omni.isaac.kit` 写在脚本第一行会报错[^kit-test]。但 Orbit 与 Isaac Lab 1.x 的 `omni.isaac.orbit`、`omni.isaac.lab` 属于另一回事：它们是 Isaac Lab 自己的旧包名，在 2.x 中已经不存在。
:::

## 版本说明

- 本页的"状态"一列针对 Isaac Sim 5.1.0 + Isaac Lab 2.3.2。在 Isaac Sim 4.x 上，`omni.isaac.*` 是正式名称，不是弃用名。
- **Isaac Lab 3.0.0-EA**：3.0 又有一轮大改，包括四元数顺序、`.data.*` 返回类型、训练脚本入口等，这些不属于改名，见 [8.1 3.0 改了什么、为什么改](../8-frontier/8.1-what-changed.md)。
- **Isaac Sim 6.x**：官方计划移除 `omni.isaac.*` 弃用扩展[^sim-rn51]。本站尚未在 6.x 上实测，暂不下结论。

3.0 的差异以 [8.6 版本追踪](../8-frontier/8.6-version-tracking.md) 为准，本页最后核对的版本见该页核对状态表。
