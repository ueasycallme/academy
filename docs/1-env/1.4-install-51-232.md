# 安装 Isaac Sim 5.1 + Isaac Lab 2.3.2（pip 方式）

:::{admonition} 学习目标
:class: lead-goals

读完本页你能：

- 在干净的 Ubuntu 22.04 / 24.04 上装好本站主线组合
- 说出每一步在做什么、为什么这样做
- 用验证脚本和一次最小训练确认环境可用
- 识别最常见的五种安装问题
:::

:::{admonition} 前置知识
:class: lead-prereq

- [1.1 版本兼容矩阵](1.1-compat-matrix.md)、[1.3 硬件要求与显存预算](1.3-hardware.md)
:::

:::{admonition} Isaac Sim 5.1.0 已不再获官方支持
:class: warning

Isaac Sim 5.1.0 的官方文档每页顶部标注 "Unsupported release: Isaac Sim 5.1.0 is no longer supported."[^env01-unsupported] 本站仍以 Isaac Sim 5.1.0 + Isaac Lab 2.3.2 为主线，理由是 Isaac Lab 2.3.x 最高只支持 Isaac Sim 5.1[^env01-readme]，而 Isaac Lab 3.0 仍为 Early Access，GA 目标为 2026 年 10 月底[^env01-lab30]。3.0 GA 后本站将切换主线，进展见 [8.6 3.0 版本追踪](../8-frontier/8.6-version-tracking.md)。
:::

本页与 Isaac Lab v2.3.2 官方安装页的 pip 路线一致[^lab-pip]：先用 pip 装 Isaac Sim，再从源码装 Isaac Lab。每一步加了一句"为什么"。二进制包和容器的装法见 [1.6 容器化环境](1.6-container.md) 与 [1.7 二进制安装 vs pip 安装 vs 容器](1.7-install-methods.md)。

## 前置检查

这一节回答：开始之前要确认什么？

```bash
nvidia-smi          # 驱动版本：推荐 ≥ 580.65.06
ldd --version       # GLIBC：pip 安装要求 ≥ 2.35
df -h ~             # 磁盘：见下文实测占用
```

- **驱动**：Isaac Lab 2.3.2 推荐 Linux 驱动 580.65.06 或更新[^lab-idx]。不够就先升级，见 [1.3](1.3-hardware.md)。
- **GLIBC**：pip 安装的 Isaac Sim 要求 GLIBC 2.35 以上；Ubuntu 22.04 满足，Ubuntu 20.04 默认的 2.31 不满足，只能改用二进制安装[^lab-pip][^sim-pip]。
- **Python**：Isaac Sim 5.x 要求 Python 3.11，必须精确到小版本[^lab-venv]。Ubuntu 22.04 自带的是 3.10，24.04 自带的是 3.12[^ubuntu-py]，都不对；下一步会单独建一个 3.11 环境，不需要改系统 Python。
- **磁盘**：本站在干净环境中实测：装完后虚拟环境约 19 GB，Isaac Lab 仓库约 190 MB，Kit 的着色器等缓存写在环境内的 `isaacsim/kit/cache/`（约 350 MB，已计入虚拟环境），下载缓存写在 `~/.cache/ov`；安装过程中 pip 缓存另占约 11 GB（下载量），用 uv 时 uv 缓存约 2.4 GB（校验方实测）。建议预留 30 GB 以上。装完后可以用 `pip cache info` 查看、`pip cache purge` 清空 pip 缓存[^pip-cache]；uv 对应 `uv cache dir` 与 `uv cache clean`[^uv-cache]。清空后重装需要重新下载。

## 第一步：建独立的 Python 环境

这一节回答：为什么不直接用系统 Python？

官方强烈建议为 Isaac Lab 单独建环境：避免与系统 Python 和其他项目冲突，升级别的项目时不会把 Isaac Sim 弄坏，也方便复现[^lab-venv]。环境的 Python 版本必须与 Isaac Sim 一致，5.x 就是 3.11[^lab-venv]。

::::{tab-set}

:::{tab-item} conda

```bash
conda create -n env_isaaclab python=3.11
conda activate env_isaaclab
```
:::

:::{tab-item} uv

```bash
uv venv --python 3.11 --seed env_isaaclab
source env_isaaclab/bin/activate
```
:::

:::{tab-item} venv

```bash
python3.11 -m venv env_isaaclab
source env_isaaclab/bin/activate
```
:::

::::

三种方式怎么选：

- **系统里没有 Python 3.11**（Ubuntu 22.04 / 24.04 默认都没有）：用 conda 或 uv。两者都会自行下载 3.11，不影响系统 Python。uv 的写法取自 Isaac Lab 官方安装页，`--seed` 会一并装上 pip，Isaac Lab 的安装脚本需要它[^lab-venv]。
- **系统里已经有 `python3.11`**（`python3.11 --version` 能输出版本）：直接用 venv 即可。

然后升级 pip，Isaac Sim 的 pip 安装页要求在安装前先做这一步[^sim-pip]：

```bash
pip install --upgrade pip
```


## 第二步：用 pip 装 Isaac Sim

这一节回答：这一条 pip 命令装了什么？

```bash
pip install "isaacsim[all,extscache]==5.1.0" --extra-index-url https://pypi.nvidia.com
```

- `--extra-index-url https://pypi.nvidia.com`：Isaac Sim 的各个子包托管在 NVIDIA 自己的包索引上[^sim-pip]。
- `[all]`：安装全部主要的 Python 子包，如 `isaacsim-robot`、`isaacsim-sensor`、`isaacsim-ros2` 等[^sim-pip]。
- `[extscache]`：把 Isaac Sim 依赖的 Omniverse 扩展预先装进来（`isaacsim-extscache-kit`、`-kit-sdk`、`-physics`）[^sim-pip]。不装的话，首次启动时要从扩展注册中心下载。

装完后，Isaac Sim 位于环境的 `site-packages/isaacsim/` 下（本站实测）。

接着装与 Isaac Lab 2.3.2 配套的 PyTorch。x86_64 的 Linux 与 Windows 用 2.7.0 + CUDA 12.8[^lab-pip]：

```bash
pip install -U torch==2.7.0 torchvision==0.22.0 --index-url https://download.pytorch.org/whl/cu128
```

为什么要单独装：Isaac Lab 的安装脚本会检查 torch 是否正好是 `2.7.0+cu128`，不是就卸掉重装[^lab-sh]；提前装好可以省一次下载。

## 第三步：第一次启动与 EULA

这一节回答：第一次运行为什么会停住？

第一次导入 `isaacsim` 时，会在终端里询问是否接受 NVIDIA Omniverse 许可协议（EULA），输入 `Yes` 才会继续；接受后不再询问[^sim-pip]。

在脚本、容器或 CI 里没有人能回答这个提示时，可以用环境变量提前接受[^sim-pip]：

```bash
export OMNI_KIT_ACCEPT_EULA=YES
```

设置它表示你同意该许可协议的条款，请先阅读协议再设置。

验证 Isaac Sim 本身（会打开 GUI 窗口）：

```bash
isaacsim
```

首次运行需要拉取和编译扩展、着色器，官方说明可能超过 10 分钟[^lab-verify-sim]。之后使用缓存，启动会快很多。

## 第四步：从源码装 Isaac Lab

这一节回答：`isaaclab.sh --install` 做了哪些事？

```bash
git clone https://github.com/isaac-sim/IsaacLab.git
cd IsaacLab
git checkout v2.3.2
sudo apt install cmake build-essential
pip install "setuptools<82"                         # 见下文"先单独装 flatdict"
pip install --no-build-isolation flatdict==4.0.1
./isaaclab.sh --install        # 或 ./isaaclab.sh -i rsl_rl，只装一个 RL 库
```

- `git checkout v2.3.2`：官方文档默认跟随主分支；切到 tag 才能保证与本站主线一致。
- `cmake build-essential`：robomimic 编译需要，这两个包只在 Linux 上用得到[^lab-build]。
- `./isaaclab.sh --install` 依次做了四件事[^lab-sh]：
    1. 确认系统装有 cmake；
    2. 确认 torch 为 `2.7.0+cu128`（aarch64 为 `2.9.0+cu130`），否则重装；
    3. 把 `source/` 下每个包（`isaaclab`、`isaaclab_tasks`、`isaaclab_rl`、`isaaclab_mimic` 等）用 `pip install --editable` 装进当前环境；
    4. 按参数安装 RL 库：默认 `all`，可选 `rl_games`、`rsl_rl`、`sb3`、`skrl`、`robomimic`、`none`[^lab-build]。
- 脚本用哪个 Python：优先当前激活的 conda 环境，其次当前的 venv，都没有才用 Isaac Sim 自带的 Python[^lab-sh]。所以**一定要先激活第一步建的环境**。用 uv 建的环境（`pyvenv.cfg` 里含 `uv` 字样），脚本会改用 `uv pip install` 安装[^lab-sh-uv]，此时 `uv` 命令要在 PATH 中。
- **先单独装 flatdict**：Isaac Lab 2.3.2 固定依赖 `flatdict==4.0.1`[^lab-setup]，它只有源码包，安装时要现场构建[^flatdict]；pip 构建时会拉取最新的 setuptools，而 setuptools 82.0.0 起移除了 `pkg_resources`，构建因此失败[^setuptools82]。失败时其他包照常装上，只有 `isaaclab` 本身缺失，很容易漏看[^lab-5388]。先装旧版 setuptools、再关闭构建隔离装好 flatdict，`isaaclab.sh` 就不必再构建它。本站在 pip 与 uv 两种新环境中都复现了这个问题，上面两行命令在两种环境里都有效（本站实测，2026-09-30）。缓存里已有 flatdict wheel 的机器不会出错，但多这两步也没有坏处。报错详情见 {ref}`1.9 安装排障手册 <flatdict-pkg-resources>`。

**editable 安装的含义**：pip 不复制代码，只在环境里记下"`isaaclab` 在 `IsaacLab/source/isaaclab` 这个目录"。好处是改源码立即生效；坏处是**仓库目录不能再移动**。本站校验环境就遇到过：仓库移动之后，`import isaaclab` 报 `No module named 'isaaclab'`；如果当前目录下恰好有名为 `isaaclab` 的文件夹，则会得到一个空的命名空间包，同样不可用[^env]。

## 第五步：验证

这一节回答：怎么确认装好了？

先跑官方的空场景脚本[^lab-verify]：

```bash
python scripts/tutorials/00_sim/create_empty.py --headless
```

它会创建一个空场景并一直步进，终端里出现 `[INFO]: Setup complete...` 之后没有报错，就说明 Isaac Sim 与 Isaac Lab 已连通。这个脚本不会自己结束，按 `Ctrl+C` 退出；如果在后台用 `timeout` 跑，要用 `timeout -s KILL`，因为 Kit 不响应普通的 SIGTERM（本站实测）。

再跑本站的验证脚本，它逐项检查 Python、Isaac Sim、PyTorch、Isaac Lab，最后 headless 启动一次仿真[^ex]：

```bash
python examples/isaaclab-2.3/1.4-install/verify_install.py
```

预期最后一行是 `SUMMARY: 8/8 passed`。如果 `isaaclab` 的导入路径失效（见下文坑三），脚本会在启动 Kit 之前打印 `[FAIL] isaaclab import path` 与汇总行并退出，不会抛出一长串报错。

最后跑一次最小训练，确认 RL 链路通了：

```bash
python scripts/reinforcement_learning/rsl_rl/train.py --task Isaac-Cartpole-v0 --headless --max_iterations 100
```

本站在干净环境中实测（RTX 5070，2026-09-30）：100 次迭代共约 24 秒（含启动），日志最后一轮显示 `Learning iteration 99/100`、`Mean episode length: 300.00`，输出保存在 `logs/rsl_rl/cartpole/<时间戳>/`。

安装各步的实测耗时。全新下载约 11 GB，耗时主要取决于网速：本站在没有 pip 缓存时总计约 1 小时，缓存里已有大部分包时约 15 分钟。

| 步骤 | 有 pip 缓存 | 无 pip 缓存 |
|---|---|---|
| 建环境 + 升级 pip | 5 秒 | 6 秒 |
| 安装 Isaac Sim（`isaacsim[all,extscache]`） | 约 7 分钟 | 约 29 分钟 |
| 安装 PyTorch | 约 30 秒 | 约 6 分钟 |
| 克隆 Isaac Lab | 约 30 秒 | 约 1.5 分钟 |
| 预装 flatdict（两行命令） | — | 3 秒 |
| `./isaaclab.sh --install` | 约 5 分钟 | 约 18 分钟（含 rl_games 等 git 依赖） |
| 验证脚本 | 5 秒 | 6 秒 |
| Cartpole 训练 100 次迭代 | 约 24 秒 | 约 22 秒 |

*表：本站实测安装耗时（RTX 5070，2026-09-30）。"有 pip 缓存"为实现方在本机 pip 缓存已有大部分包时的运行（当时尚无预装 flatdict 一步，缓存中已有构建好的 flatdict）；"无 pip 缓存"为校验方在全新 pip 缓存下的复现，下载速度约 0.3–2 MB/s，Isaac Sim 一步为中断后重跑的耗时。两次运行都不能确认是真正的冷启动：本机有其他 Isaac Sim 运行留下的 `~/.cache/ov`；校验方复现时，Kit 的下载缓存写到了新指定的 `XDG_CACHE_HOME`，着色器缓存写在环境内的 `isaacsim/kit/cache/`（校验方实测）。所以表中 5–6 秒的验证与首次启动不代表全新机器，全新机器的首次启动以官方说明为准，可能超过 10 分钟[^lab-verify-sim]。*

## 环境变量与路径速查

这一节回答：装好之后，东西都在哪里？

| 项目 | 位置 | 来源 |
|---|---|---|
| Isaac Sim 安装位置（pip） | `<环境>/lib/python3.11/site-packages/isaacsim/` | 本站实测 |
| Kit 着色器等缓存（pip 安装） | `<环境>/lib/python3.11/site-packages/isaacsim/kit/cache/` | 本站实测 |
| Kit 下载缓存 | `$XDG_CACHE_HOME/ov/`（默认 `~/.cache/ov/`） | 本站实测 |
| Isaac Sim（Kit）日志 | pip 安装：`<环境>/lib/python3.11/site-packages/isaacsim/kit/logs/Kit/Isaac-Sim/5.1/`；二进制安装：`~/.nvidia-omniverse/logs/Kit/Isaac-Sim/` | pip 安装为本站实测（启动时终端会打印 `Logging to file:` 与具体路径）；二进制安装见 [^faq] |
| Isaac Lab 运行日志 | `/tmp/isaaclab/logs/` | 本站实测（启动时终端会打印具体文件名） |
| 训练输出（checkpoint、TensorBoard） | `IsaacLab/logs/rsl_rl/<实验名>/<时间戳>/` | 本站实测 |
| 自动接受 EULA | `OMNI_KIT_ACCEPT_EULA=YES` | [^sim-pip] |

*表 1：主要路径。二进制安装时还会用到 `ISAACSIM_PATH` 等变量，那是 [1.7](1.7-install-methods.md) 的内容，pip 方式不需要。*

## 常见坑

:::{admonition} 坑一：shell 里的 PYTHONPATH 把 ROS 2 的包混了进来
:class: warning

装过 ROS 2 的机器，`~/.bashrc` 往往 source 了 `/opt/ros/humble/setup.bash`，它会设置 `PYTHONPATH`。这些路径里的 Python 包会被 Isaac Lab 的环境看到，可能导致版本冲突或导入错误。本站在校验环境中遇到过[^env]。解决：在运行 Isaac Lab 的终端里 `unset PYTHONPATH`，或者用 `env -u PYTHONPATH python ...` 启动。
:::

:::{admonition} 坑二：脚本卡在 EULA 提示
:class: warning

在后台、容器或 CI 中第一次运行时，没有人回答 EULA 提示，看起来就像卡死了。设置 `OMNI_KIT_ACCEPT_EULA=YES` 即可[^sim-pip]。
:::

:::{admonition} 坑三：移动了 Isaac Lab 仓库后，import isaaclab 什么都没有
:class: warning

editable 安装记录的是绝对路径，仓库一旦移动，环境里的路径就失效了[^env]。解决：在新位置重新运行 `./isaaclab.sh --install`。
:::

:::{admonition} 坑四：驱动过旧
:class: warning

驱动低于推荐版本时，可能启动失败、黑屏或崩溃。先对照 [1.1](1.1-compat-matrix.md) 升级到推荐版本；新显卡或遇到驱动问题时，官方建议从 Unix Driver Archive 装最新的生产分支驱动[^lab-idx]。
:::

:::{admonition} 坑五：第一次启动很慢，被误判为卡死
:class: warning

首次运行要拉取扩展、编译着色器，官方说明可能超过 10 分钟[^lab-verify-sim]。只要终端还在输出日志、CPU 还在忙，就耐心等。本站实测的首次耗时见上文。
:::

:::{admonition} 坑六：Python 版本不是 3.11
:class: warning

Isaac Sim 5.1 的 pip 包精确要求 Python 3.11，用 3.10 或 3.12 时 pip 找不到匹配的包[^pypi]。建环境时明确写 `python=3.11`。
:::

:::{admonition} 坑七：自己写的 standalone 脚本退出时卡住不动
:class: warning

如果脚本自己创建了 `SimulationContext`，结束时直接调用 `simulation_app.close()`，进程可能一直不退出，CPU 占满（本站写验证脚本时遇到过）。解决：在 `close()` 之前先调用 `sim.clear_all_callbacks()` 和 `sim.clear_instance()` 释放仿真上下文。Isaac Lab 的环境类在 `close()` 中也是这样做的[^env-close]。用 `gym.make` 创建的环境，调用 `env.close()` 即可。
:::
