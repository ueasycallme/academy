# 安装 Isaac Sim 6.2 + Isaac Lab 3.0

:::{admonition} 学习目标
:class: lead-goals

读完本页你能：

- 在已装好 5.1 + 2.3.2 的机器上，再装一套 3.0，两套互不干扰
- 在三条安装路线中选一条：uv 自动、自管环境 + pip、不装 Isaac Sim 的最小安装
- 用 Cartpole 分别验证 Newton 与 PhysX 两个物理后端
- 避开 EULA、`uv sync`、nightly warp 等几个本站实测踩到的坑
:::

:::{admonition} 前置知识
:class: lead-prereq

- [1.2 版本选择决策树](1.2-version-decision.md)（两套并存）
- [1.4 安装 Isaac Sim 5.1 + Isaac Lab 2.3.2](1.4-install-51-232.md)
:::

:::{admonition} 基于 v3.0.0 正式版
:class: note

本页按 Isaac Lab v3.0.0 正式版（2026-10-19 发布，要求 Isaac Sim 6.2）写成，本站于 2026-10-23 在本机实测。本站此前按 v3.0.0-EA + Isaac Sim 6.1 写过一版，正式版里仍然成立的结论保留，变了的地方写明"EA 时如何"。最新状态见 [8.6 版本追踪](../8-frontier/8.6-version-tracking.md)。
:::

3.0 的安装方式与 2.3 不同：官方推荐用 `uv` 在仓库里自动建环境；默认安装的是 Newton 后端，不装 Isaac Sim，Isaac Sim 只是一个可选的 extra[^idx-paths]。本页实测了三条路线：

| 路线 | 做法 | 装不装 Isaac Sim | 本站环境大小 |
|---|---|---|---|
| A：uv 自动（官方推荐） | 仓库根目录 `uv sync` / `uv run` | 可选，`--extra isaacsim` | 8.1 GB → 25 GB |
| B：自管环境 + pip | 自建 venv，`uv pip install isaacsim…`，再 `isaaclab.sh -i` | 装 | 26 GB |
| C：最小安装（Kit-less） | 自建 venv，`isaaclab.sh -i 'newton,rl[rsl-rl]'` | 不装 | 7.8 GB |

*表 1：三条路线。环境大小用 `du` 分别统计；本机上 uv 装进各环境的文件与缓存是硬链接，几个环境共享文件，实际占用见"缓存与目录"一节。*

二进制安装、容器与从源码构建 Isaac Sim，本页不做，见官方安装页[^idx-paths]。

## 前置检查

这一节回答：开始之前要确认什么？

```bash
nvidia-smi       # 驱动：Isaac Lab 要求 Linux ≥ 580.65.06
ldd --version    # GLIBC：Isaac Sim 的 pip 包要求 ≥ 2.35
uv --version     # 路线 A 必需；B、C 也用它建环境
```

- **驱动**：有两个数字，别混在一起。Isaac Lab 3.0 安装页的要求是 Linux 580.65.06 或更新，因为默认环境装的是 CUDA 13.0 版 PyTorch[^idx-req]。Isaac Sim 6.2 的系统要求页列出的测试驱动是 Linux 595.58.03[^sim-req]，这是 NVIDIA 测过的版本，不是下限。本机驱动 580.178.04，满足前者，低于后者。本站在路线 A、B 上各启动了一次 Kit，日志里没有驱动相关的警告或错误。
- **系统**：Ubuntu 22.04 及以上、Python 3.12[^idx-req]。Isaac Sim 6.2 的系统要求页提示，Ubuntu 22.04 的支持已弃用，将来的版本会移除[^sim-req]。本机为 Ubuntu 22.04、GLIBC 2.35。Isaac Sim 5.1 及更早版本不受 3.0 支持[^idx-req]。
- **Python 3.12**：不需要装进系统。`uv` 会自动下载一个独立的 3.12 解释器，本机装的是 3.12.14，放在 `~/.local/share/uv/python/`。
- **硬件**：只装 Newton 时，内存与显存视任务而定；装 Isaac Sim 时，官方建议至少 32 GB 内存、16 GB 显存[^idx-req]。本机 62 GB 内存、32 GB 显存，峰值见表 3。
- **与 5.1 并存**：3.0 的环境和仓库都另放一处，不碰 2.3.2 的检出和 `env_isaaclab`（[1.2 两套并存](1.2-version-decision.md#两套并存)）。官方文档的克隆命令如下：

```bash
git clone https://github.com/isaac-sim/IsaacLab.git --branch v3.0.0 IsaacLab-3.0
cd IsaacLab-3.0
```

本站另有一份 2.3.2 的检出，所以用 `git worktree add ../IsaacLab-3.0-GA v3.0.0` 从同一个仓库再检出一份 v3.0.0，效果相同。

## 路线 A：uv 自动安装

这一节回答：官方推荐的方式是怎样的？

在仓库根目录直接用 `uv`，不需要自己建环境、也不需要激活[^idx-uv]。先装核心依赖（含 Newton，不含 Isaac Sim）：

```bash
uv sync                     # 第一次：建 .venv 并按 uv.lock 安装
uv run isaaclab train --rl_library rsl_rl --task Isaac-Cartpole-Direct physics=newton_mjwarp
```

需要 Isaac Sim 时加上 extra：

```bash
uv sync --extra isaacsim    # 再装 isaacsim[all,extscache]==6.2.0.0
OMNI_KIT_ACCEPT_EULA=YES uv run --extra isaacsim isaaclab train \
    --rl_library rsl_rl --task Isaac-Cartpole-Direct physics=isaacsim_physx
```

- **产物**：环境在仓库内的 `.venv/`，依赖版本由仓库自带的 `uv.lock` 锁定；extras 定义在根目录 `pyproject.toml`，其中 `isaacsim` extra 就是 `isaacsim[all,extscache]==6.2.0.0`[^pyproject]。训练输出写在仓库内的 `logs/rsl_rl/<实验名>/<时间戳>/`。
- **extras**：EA 的 extras 正式版都保留了，另外新增 `dev`、`skrl-jax`、`torchrl`[^pyproject]。`--extra ovphysx` 只装 OV PhysX 运行时，不装 Isaac Sim，可以在不启动 Kit 的进程里跑 PhysX（[8.8](../8-frontier/8.8-kitless.md)）。`--extra all` 不含 Isaac Sim[^idx-uv]。
- **命令**：3.0 统一用 `isaaclab train / play / zero_agent / random_agent / benchmark`，任务名去掉了 `-v0` 后缀，物理后端用 `physics=` 选择[^quickstart]（[8.1](../8-frontier/8.1-what-changed.md)）。
- **`isaaclab.sh` 还在**，但启动时提示已弃用，3.1 会移除[^lab-sh]。
- **实测耗时**：`uv sync` 用时 60 s，装 207 个包，`.venv` 8.1 GB；`uv sync --extra isaacsim` 再装 85 个包，`.venv` 到 25 GB。这两个数字都是在 uv 缓存里已有这些包时测的，第一次在新机器上装要加上下载时间（EA 时本站从零下载，两步共约 21 分钟）。

## 路线 B：自管环境 + pip

这一节回答：想像 1.4 那样自己管环境，怎么装？

```bash
uv venv --python 3.12 --seed env_isaaclab30_pip
source env_isaaclab30_pip/bin/activate
uv pip install --upgrade pip
uv pip install "isaacsim[all,extscache]==6.2.0.0" --extra-index-url https://pypi.nvidia.com \
    --index-strategy unsafe-best-match --prerelease=allow
uv pip install -U torch==2.11.0 torchvision==0.26.0 --index-url https://download.pytorch.org/whl/cu130
cd IsaacLab-3.0 && ./isaaclab.sh -i
```

命令取自正式版安装页"Python environment with Isaac Sim"一节[^idx-pyenv][^docs-ext]。那一节在 `isaaclab.sh -i` 之前还有 `sudo apt install cmake build-essential`，本机已有 cmake，本站跳过了这一步；安装脚本本身也只在找不到 `cmake` 时才会调用 `sudo apt-get`[^install-apt]。与 1.4 逐步对照：

| 步骤 | 2.3.2（1.4） | 3.0 |
|---|---|---|
| Python | 3.11 | 3.12 |
| Isaac Sim | `isaacsim[all,extscache]==5.1.0` | `isaacsim[all,extscache]==6.2.0.0`，uv 需加 `--index-strategy unsafe-best-match --prerelease=allow` |
| PyTorch | 2.7.0 cu128 | 2.11.0 cu130（EA 时为 cu128） |
| Isaac Lab | `./isaaclab.sh --install`，需先预装 flatdict | `./isaaclab.sh -i`，可带选择器；不带值时装核心包、`mimic`、`teleop` 和默认的 Newton、RL、可视化依赖[^idx-legacy] |

*表 2：两版 pip 路线对照。3.0 的 Isaac Lab 包本身不再依赖 Isaac Sim：Isaac Sim 只是 `isaacsim` 这个 extra[^pyproject]。*

本站实测：环境 26 GB。各步都在 uv 缓存已有这些包时完成，`isaaclab.sh -i` 一步用时 35 s，前面几步各几秒，不代表第一次下载的耗时。

## 路线 C：不装 Isaac Sim 的最小安装

这一节回答：只想用 Newton 后端，最少要装什么？

```bash
uv venv --python 3.12 --seed env_isaaclab30_kitless
source env_isaaclab30_kitless/bin/activate
uv pip install --upgrade pip
cd IsaacLab-3.0 && ./isaaclab.sh -i 'newton,rl[rsl-rl]'
isaaclab train --rl_library rsl_rl --task Isaac-Cartpole-Direct physics=newton_mjwarp
```

官方把这种安装称为 Kit-less：Python 3.12 环境，不装 Isaac Sim[^idx-legacy]。正式版里 Newton 已经是基础安装的一部分，`newton` 这个选择器什么也不做，安装时会打印 "Newton (engine + viewer) is part of the base install; nothing to install."，写不写都一样。本站实测用时 43 s（包都在 uv 缓存中），环境 7.8 GB，其中没有 `isaacsim`。它能跑 Newton 后端的训练，但不能用 `physics=isaacsim_physx`，也不能开 Kit 的图形界面；`physics=physx` 在这种环境里走 OV PhysX，要先装 `ov[ovphysx]`（[8.8](../8-frontier/8.8-kitless.md)）。

正式版还有一条路：把 `isaaclab` 当作依赖，从包索引装发布的 wheel，官方注明 wheel 只在大版本时发布[^idx-wheel]。PyPI 上 `isaaclab` 3.0.0 的 wheel 已于 2026-10-19 上传[^pypi]（EA 时没有）。本站没有走这条路，不在本页实测范围内。

## 验证

这一节回答：怎么确认装好了？

先用本站脚本检查版本和导入路径。它只做导入，不启动仿真[^ex]：

```bash
uv run python verify_install_30.py --require-isaacsim     # 路线 A
python verify_install_30.py                               # 路线 B、C（先激活环境）
```

路线 A 和 B 都是 `SUMMARY: 10/10 passed`。路线 C 是 9/9，没装 Isaac Sim 那一项记为跳过。脚本还检查 PyTorch 是不是 CUDA 13 的构建：环境里是 cu128 的 torch（比如漏了路线 B 的第三步，或者拿 EA 的环境来跑），那一项会失败。

再跑官方的 Cartpole 训练。本站按默认设置跑：4096 个环境、150 次迭代、不指定可视化器（默认就是不开）：

| 路线 | 后端 | 墙钟 | 其中训练 | 按进程显存峰值 | 主机 RSS 峰值 |
|---|---|---|---|---|---|
| A | Newton（第一次，空的 Warp 内核缓存） | 60 s | 28.5 s | 756 MiB | 2.9 GB |
| A | Newton（再次） | 22 s | 12.5 s | 756 MiB | 2.5 GB |
| A | PhysX（经 Isaac Sim 6.2，该环境第一次启动 Kit） | 26 s | 16.6 s | 3286 MiB | 4.8 GB |
| B | PhysX（经 Isaac Sim 6.2） | 29 s | 16.5 s | 3286 MiB | 4.9 GB |
| C | Newton（Warp 内核缓存已有） | 22 s | 11.1 s | 756 MiB | 2.4 GB |

*表 3：Cartpole（`Isaac-Cartpole-Direct`）实测，RTX 5090 32 GB，2026-10-23，测量期间 GPU 上没有其他进程。最后一轮 Newton 的 Mean reward 都是 4.94、Mean episode length 300（满长度），PhysX 为 4.88、297.3。两个后端都学会了，数值略有差别。*

Newton 第一次的墙钟比再次多约 38 秒，是 Warp 在编译内核：第一次运行时把 `WARP_CACHE_PATH` 指向一个空目录，跑完后里面生成了 30 MB 的内核，第二次用同一个目录就快了。正常情况下，内核缓存在 `~/.cache/warp/<warp 版本>/`。

**两套环境互不污染**：分别看三个 3.0 环境和 5.1 环境的 `sys.prefix` 与包版本。5.1 环境仍是 Python 3.11、isaacsim 5.1.0.0、torch 2.7.0+cu128；3.0 环境是 Python 3.12、isaacsim 6.2.0.0（路线 C 没有）、torch 2.11.0+cu130、warp-lang 1.17.0、newton 1.6.1、rsl-rl-lib 5.5.1。所有 3.0 环境里的 `isaaclab` 都指向同一份 v3.0.0 检出的 `source/`，因为是 editable 安装。

## 缓存与目录

这一节回答：3.0 把东西放在哪里，会不会和 5.1 混在一起？

| 项目 | 位置 | 与 5.1 共用吗 |
|---|---|---|
| uv 下载缓存 | `~/.cache/uv`（`uv cache dir`） | 共用，5.1 用 uv 装时也在这里 |
| uv 管理的 Python | `~/.local/share/uv/python/` | 各版本分开 |
| Warp 内核缓存 | `~/.cache/warp/<版本>/` | 根目录共用；5.1 环境里 Kit 用自带的 omni.warp.core 1.8.2（子目录 `1.8.2`），3.0 正式版用 1.17.0，各自一个子目录 |
| Newton 缓存 | `~/.cache/newton/`（394 MB） | 5.1 不用 |
| 远程资产的本地副本 | 系统临时目录下的 `https/<主机名>/…`，本机为 `/tmp/https/…/Assets/Isaac/6.2/` | 不共用；路径带版本号 |
| Kit 缓存 | 环境内 `isaacsim/kit/cache/`；`~/.cache/ov` 在 6.2 运行前后没有变化 | 实测不共用 |

*表 4：3.0 / 6.2 的缓存位置，本站实测。资产副本的位置由 `isaaclab/utils/assets.py` 决定：远程 URL 按"协议/主机/路径"映射到 `tempfile.gettempdir()` 之下[^assets]，所以 `/tmp` 被清空后会重新下载。本站只跑了不渲染的训练，Kit 着色器缓存很小，开图形界面后的增长没有测。*

**磁盘**：三个环境用 `du` 单独统计，分别是 25、26、7.8 GB；放在一起统计、硬链接只算一次，合计 31 GB。原因是 uv 从缓存把包链接进环境，而不是复制：本机同一个 torch 库文件的硬链接数为 5，缓存和几个环境共用一份。这次装三条路线时，用到的包 uv 缓存里都已经有了，分区的已用空间装前装后都是 113 GB。uv 文档写的 Linux 默认值是 clone（写时复制）[^uv-link]，本机的 ext4 不支持写时复制，实际得到的是硬链接（推断，依据是实测的链接数）。硬链接只能在同一个分区内建立：EA 时本站在另一个分区上另建过一个环境，uv 提示 `Failed to hardlink … falling back to full copy`，环境成了完整复制。所以只执行 `uv cache clean` 释放不了已装环境占用的空间，要连环境一起删掉。

## 常见坑

:::{admonition} 坑一：装了 Isaac Sim 之后，Newton 训练也要先接受 EULA
:class: warning

装了 `isaacsim` 之后，即使只跑 `physics=newton_mjwarp`，甚至只是 `isaaclab train --rl_library rsl_rl --help`，一启动也会询问是否接受 NVIDIA Omniverse EULA。在非交互的终端里，它会直接报 `EULA not accepted` 退出。路线 C 没装 Isaac Sim，同样的命令就不询问。两者对照是本站实测，EA 与正式版相同。解决：确认接受 EULA 后，设 `OMNI_KIT_ACCEPT_EULA=YES`[^idx-eula]。
:::

:::{admonition} 坑二：裸 `uv sync` 会删掉 Isaac Sim
:class: warning

`uv sync` 默认做精确同步：环境里多出来、但这次没有请求的包会被删掉；`uv run` 默认只补缺，不删包[^uv-sync]。EA 时本站在装了 `isaacsim` extra 的环境里执行 `uv sync --dry-run`，结果是 `Would uninstall 86 packages`，也就是整个 Isaac Sim。所以装了 extra 之后，每次同步都要带上它（`uv sync --extra isaacsim`），或者改用 `uv run --extra isaacsim …`。
:::

:::{admonition} 坑三：路线 B 只装到 Isaac Sim 就停，环境里是 nightly 的 warp
:class: warning

官方命令给 `uv pip install isaacsim…` 加了 `--prerelease=allow`。本站在正式版上实测，这一步装进了 `warp-lang==1.20.0.dev20261023`（nightly），以及 PyPI 上的普通 `torch==2.11.0`（EA 时是 1.19 的 nightly）。要等后面两步（PyTorch cu130、`isaaclab.sh -i`）跑完，才换成 `torch 2.11.0+cu130` 和 `warp-lang 1.17.0`。中途失败或漏跑后两步，环境里就是这些未锁定的版本。验证脚本会打印 warp 的版本，并检查 torch 是不是 CUDA 13 的构建，可以用它检查。
:::

:::{admonition} 坑四：第一次训练"卡住"半分多钟
:class: warning

Newton 后端第一次运行时，在 `[2/3] Creating environment` 之后会停一阵，没有任何输出，这是 Warp 在编译内核（见上文对照）。本站正式版、RTX 5090 上多出约 40 秒，EA、RTX 5070 上约一分钟。第二次起，同样的训练只要约 20 秒。不要因为一时没有输出就中断它。
:::

:::{admonition} 坑五：在 5.1 的环境里跑 3.0
:class: warning

5.1 的环境是 Python 3.11，3.0 要求 `>=3.12,<3.13`[^pyproject]，在 3.11 的环境里装不上。最常见的情况是忘了切换环境：同一个终端里先 `source` 了 5.1 的环境，再进 3.0 仓库，用的就是 3.11。路线 A 用 `uv run` 不需要激活环境，可以避开这个问题；B、C 先跑一遍验证脚本，看第一行的 Python 版本和环境路径。
:::

:::{admonition} 坑六：`uv sync` 等锁 5 分钟后失败
:class: warning

本站第一次执行 `uv sync --extra isaacsim` 时，等了 300 秒后以返回码 2 退出，报 `Timeout (300s) when waiting for lock on … is another uv process running?`。uv 用文件锁保护缓存里的包，锁文件是 `isaacsim-extscache-kit` 6.2.0.0 的；本站等锁的那 5 分钟里，本站同时在另一个环境里装同一个 `isaacsim[all,extscache]==6.2.0.0`，推断是它占着锁。等它结束后重跑，一次成功。遇到这条报错，先看看 `ps` 里有没有别的 `uv` 在装包；实在要并行，可以用 `UV_CACHE_DIR` 给其中一个指定独立的缓存目录，代价是不再共用硬链接。
:::

## 版本说明
