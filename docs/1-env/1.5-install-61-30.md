# 安装 Isaac Sim 6.1 + Isaac Lab 3.0-EA

:::{admonition} 学习目标
:class: lead-goals

读完本页你能：

- 在已装好 5.1 + 2.3.2 的机器上，再装一套 3.0 EA，两套互不干扰
- 在三条安装路线中选一条：uv 自动、自管环境 + pip、不装 Isaac Sim 的最小安装
- 用 Cartpole 分别验证 Newton 与 PhysX 两个物理后端
- 避开 EULA、`uv sync`、nightly warp 等几个本站实测踩到的坑
:::

:::{admonition} 前置知识
:class: lead-prereq

- [1.2 版本选择决策树](1.2-version-decision.md)（两套并存）
- [1.4 安装 Isaac Sim 5.1 + Isaac Lab 2.3.2](1.4-install-51-232.md)
:::

:::{admonition} 基于 3.0 EA
:class: warning

本页按 Isaac Lab v3.0.0-EA（2026-09-16）写成，本站于 2026-10-09 在本机实测。EA 不是正式版，GA 之后命令与依赖都可能变化，本页届时需要重验；最新状态见 [8.6 版本追踪](../8-frontier/8.6-version-tracking.md)。
:::

3.0 的安装方式与 2.3 不同：官方推荐用 `uv` 在仓库里自动建环境，Isaac Sim 变成一个可选的 extra，不装它也能用 Newton 后端训练[^idx-paths]。本页实测了三条路线：

| 路线 | 做法 | 装不装 Isaac Sim | 本站环境大小 |
|---|---|---|---|
| A：uv 自动（官方推荐） | 仓库根目录 `uv sync` / `uv run` | 可选，`--extra isaacsim` | 10 GB → 29 GB |
| B：自管环境 + pip | 自建 venv，`uv pip install isaacsim…`，再 `isaaclab.sh -i` | 装 | 31 GB |
| C：最小安装（Kit-less） | 自建 venv，`isaaclab.sh -i 'newton,rl[rsl-rl]'` | 不装 | 9.6 GB |

*表 1：三条路线。环境大小用 `du` 分别统计；本机上 uv 装进各环境的文件与缓存是硬链接，几个环境共享文件，实际占用见"缓存与目录"一节。*

二进制安装与容器本页不做，见官方安装页[^idx-paths]。

## 前置检查

这一节回答：开始之前要确认什么？

```bash
nvidia-smi       # 驱动：推荐 ≥ 580.95.05
ldd --version    # GLIBC：pip 包要求 ≥ 2.35
uv --version     # 路线 A 必需；B、C 也用它建环境
```

- **驱动与系统**：EA 要求 Ubuntu 22.04 及以上、Python 3.12，推荐驱动 580.95.05 或更新；Isaac Sim 5.1 及更早版本不受支持[^idx-req]。本机为 Ubuntu 22.04、驱动 580.178.04、GLIBC 2.35。
- **Python 3.12**：不需要装进系统。`uv` 会自动下载一个独立的 3.12 解释器，本机装的是 3.12.14，放在 `~/.local/share/uv/python/`。
- **硬件**：官方建议 32 GB 内存、16 GB 显存[^idx-req]，本机只有 16 GB 内存、12 GB 显存。下文的 Cartpole 在本机都能跑，峰值见表 3，但更大的任务本站还没有测过。
- **与 5.1 并存**：3.0 的环境和仓库都另放一处，不碰 2.3.2 的检出和 `env_isaaclab`（[1.2 两套并存](1.2-version-decision.md#两套并存)）。本站把仓库放在 `~/wuql_ws/isaac_sim/IsaacLab-3.0`，检出 tag `v3.0.0-EA`：

```bash
git clone https://github.com/isaac-sim/IsaacLab.git --branch v3.0.0-EA IsaacLab-3.0
cd IsaacLab-3.0
```

## 路线 A：uv 自动安装

这一节回答：官方推荐的方式是怎样的？

在仓库根目录直接用 `uv`，不需要自己建环境、也不需要激活[^idx-uv]。先装核心依赖（含 Newton、rsl_rl，不含 Isaac Sim）：

```bash
uv sync                     # 第一次：建 .venv 并按 uv.lock 安装
uv run isaaclab train --rl_library rsl_rl --task Isaac-Cartpole-Direct physics=newton_mjwarp
```

需要 Isaac Sim 时加上 extra：

```bash
uv sync --extra isaacsim    # 再装 isaacsim[all,extscache]==6.1.0.0
OMNI_KIT_ACCEPT_EULA=YES uv run --extra isaacsim isaaclab train \
    --rl_library rsl_rl --task Isaac-Cartpole-Direct physics=isaacsim_physx
```

- **产物**：环境在仓库内的 `.venv/`，依赖版本由仓库自带的 `uv.lock` 锁定；Python 依赖与 extras 定义在根目录 `pyproject.toml`，其中 `isaacsim` extra 就是 `isaacsim[all,extscache]==6.1.0.0`[^pyproject]。训练输出写在仓库内的 `logs/rsl_rl/<实验名>/<时间戳>/`。
- **命令**：3.0 统一用 `isaaclab train / play / zero_agent / random_agent / benchmark`，任务名去掉了 `-v0` 后缀，物理后端用 `physics=` 选择[^quickstart]（[8.1](../8-frontier/8.1-what-changed.md)）。
- **`isaaclab.sh` 还在**，但启动时提示已弃用，3.1 会移除[^lab-sh]。
- **实测耗时**：`uv sync` 用时 8 分 14 秒，装 192 个包，`.venv` 10 GB；`uv sync --extra isaacsim` 用时 12 分 44 秒，再装 86 个包，`.venv` 到 29 GB。两步的耗时主要是下载。

## 路线 B：自管环境 + pip

这一节回答：想像 1.4 那样自己管环境，怎么装？

```bash
uv venv --python 3.12 --seed env_isaaclab30_pip
source env_isaaclab30_pip/bin/activate
uv pip install --upgrade pip
uv pip install "isaacsim[all,extscache]==6.1.0.0" --extra-index-url https://pypi.nvidia.com \
    --index-strategy unsafe-best-match --prerelease=allow
uv pip install -U torch==2.11.0 torchvision==0.26.0 --index-url https://download.pytorch.org/whl/cu128
cd IsaacLab-3.0 && ./isaaclab.sh -i
```

命令取自 EA 文档[^docs-ext]。与 1.4 逐步对照：

| 步骤 | 2.3.2（1.4） | 3.0 EA |
|---|---|---|
| Python | 3.11 | 3.12 |
| Isaac Sim | `isaacsim[all,extscache]==5.1.0` | `isaacsim[all,extscache]==6.1.0.0`，uv 需加 `--index-strategy unsafe-best-match --prerelease=allow` |
| PyTorch | 2.7.0 cu128 | 2.11.0 cu128 |
| Isaac Lab | `./isaaclab.sh --install`，需先预装 flatdict | `./isaaclab.sh -i`，可带选择器；不带值时装核心包和默认的 Newton、RL、可视化依赖[^idx-legacy] |

*表 2：两版 pip 路线对照。3.0 的 Isaac Lab 包本身不再依赖 Isaac Sim：Isaac Sim 只是 `isaacsim` 这个 extra[^pyproject]。*

本站实测：三步分别用时 4 分 28 秒、8 分 41 秒、2 分 29 秒，共 15 分 38 秒，环境 31 GB。

## 路线 C：不装 Isaac Sim 的最小安装

这一节回答：只想用 Newton 后端，最少要装什么？

```bash
uv venv --python 3.12 --seed env_isaaclab30_kitless
source env_isaaclab30_kitless/bin/activate
uv pip install --upgrade pip
cd IsaacLab-3.0 && ./isaaclab.sh -i 'newton,rl[rsl-rl]'
isaaclab train --rl_library rsl_rl --task Isaac-Cartpole-Direct physics=newton_mjwarp
```

官方把这种安装称为 Kit-less：Python 3.12 环境，不装 Isaac Sim[^idx-legacy]。本站实测用时 1 分 25 秒（大部分包已在 uv 缓存中），环境 9.6 GB，其中没有 `isaacsim`。它能跑 Newton 后端的训练，但不能用 `physics=isaacsim_physx`，也不能开 Kit 的图形界面；可以做与不能做的事见 [8.1 Kit-less](../8-frontier/8.1-what-changed.md#kit-less)。

EA 文档还写了"作为依赖安装 `isaaclab` 包"一条路，并注明 wheel 只在大版本时发布[^idx-wheel]。2026-10-09 查 PyPI，`isaaclab` 的最新版本仍是 2.3.2.post1[^pypi]，3.0 EA 还没有 wheel，所以这条路本站没有做。

## 验证

这一节回答：怎么确认装好了？

先用本站脚本检查版本和导入路径。它只做导入，不启动仿真[^ex]：

```bash
uv run python verify_install_30.py --require-isaacsim     # 路线 A
python verify_install_30.py                               # 路线 B、C（先激活环境）
```

路线 A 和 B 都是 `SUMMARY: 10/10 passed`。路线 C 是 9/9，没装 Isaac Sim 那一项记为跳过。拿 5.1 的环境去跑这个脚本，Python、torch、isaacsim 版本几项都会失败，这也是检查有没有用错环境的办法。

再跑官方的 Cartpole 训练。本站按默认设置跑：4096 个环境、150 次迭代、不开可视化：

| 路线 | 后端 | 墙钟 | 其中训练 | 按进程显存峰值 | 主机 RSS 峰值 |
|---|---|---|---|---|---|
| A | Newton（第一次） | 76 s | 14.8 s | 360 MiB | 2.9 GB |
| A | Newton（再次） | 19–23 s | 11–13 s | 360 MiB | 2.7 GB |
| A | PhysX（经 Isaac Sim 6.1，第一次） | 37 s | 17.0 s | 2876 MiB | 5.0 GB |
| B | PhysX（经 Isaac Sim 6.1） | 34 s | 16.3 s | 2876 MiB | 4.9 GB |
| C | Newton | 26 s | 11.6 s | 360 MiB | 2.7 GB |

*表 3：Cartpole（`Isaac-Cartpole-Direct`）实测，RTX 5070 12 GB，2026-10-09。各次最后一轮的 Mean reward 都是 4.93–4.94，Mean episode length 都是 300（满长度），两个后端的训练结果一致。*

Newton 第一次多花的约 55 秒，是 Warp 在编译内核。对照实验：把 `WARP_CACHE_PATH` 指向一个空目录再跑，墙钟又回到 76.8 s，空目录里生成了 34 MB 的内核；正常情况下，内核缓存在 `~/.cache/warp/<warp 版本>/`。

**两套环境互不污染**：分别看三个 3.0 环境和 5.1 环境的 `sys.prefix` 与包版本。5.1 环境仍是 Python 3.11、isaacsim 5.1.0.0、torch 2.7.0；3.0 环境是 Python 3.12、isaacsim 6.1.0.0（路线 C 没有）、torch 2.11.0。所有 3.0 环境里的 `isaaclab` 都指向同一个 `IsaacLab-3.0/source/`，因为是 editable 安装。

## 缓存与目录

这一节回答：3.0 把东西放在哪里，会不会和 5.1 混在一起？

| 项目 | 位置 | 与 5.1 共用吗 |
|---|---|---|
| uv 下载缓存 | `~/.cache/uv`（`uv cache dir`） | 共用，5.1 用 uv 装时也在这里 |
| uv 管理的 Python | `~/.local/share/uv/python/` | 各版本分开 |
| Warp 内核缓存 | `~/.cache/warp/<版本>/` | 根目录共用；5.1 环境用 1.17.0，3.0 用 1.16.0，各自一个子目录 |
| Newton 缓存 | `~/.cache/newton/`（394 MB） | 5.1 不用 |
| 远程资产的本地副本 | 系统临时目录下的 `https/<主机名>/…`，本机为 `/tmp/https/…/Assets/Isaac/6.1/` | 不共用；路径带 6.1 |
| Kit 缓存 | 环境内 `isaacsim/kit/cache/`；`~/.cache/ov` 在 6.1 运行前后没有变化 | 实测不共用 |

*表 4：3.0 / 6.1 的缓存位置，本站实测。资产副本的位置由 `isaaclab/utils/assets.py` 决定：远程 URL 按"协议/主机/路径"映射到 `tempfile.gettempdir()` 之下[^assets]，所以 `/tmp` 被清空后会重新下载。本站只跑了不渲染的训练，Kit 着色器缓存很小，开图形界面后的增长没有测。*

**磁盘**：三个环境用 `du` 单独统计，分别是 29、31、9.6 GB；连同 uv 缓存放在一起统计、硬链接只算一次，合计 45 GB。原因是 uv 从缓存把包链接进环境，而不是复制：本机同一个 torch 库文件的硬链接数为 4，缓存和三个环境共用一份。uv 文档写的 Linux 默认值是 clone（写时复制）[^uv-link]，本机的 ext4 不支持写时复制，实际得到的是硬链接（推断，依据是实测的链接数）。硬链接只能在同一个分区内建立：校验方把环境建在另一个分区（`/tmp`）上复现时，uv 提示 `Failed to hardlink … falling back to full copy`，环境成了完整复制。所以上面 45 GB 的合计只在 uv 缓存与各环境同在一个分区时成立，跨分区时每个环境都要单独占满空间。由此可知，**只执行 `uv cache clean` 释放不了已装环境占用的空间**，要连环境一起删掉。本站装三条路线前后，uv 缓存从 4.2 GB 增长到 44 GB。

## 常见坑

:::{admonition} 坑一：装了 Isaac Sim 之后，Newton 训练也要先接受 EULA
:class: warning

路线 A 加了 `isaacsim` extra 之后，即使只跑 `physics=newton_mjwarp`，`isaaclab train` 一启动也会询问是否接受 NVIDIA Omniverse EULA。在非交互的终端里，它会直接报 `EULA not accepted` 退出。路线 C 没装 Isaac Sim，同样的命令就不询问。两者对照是本站实测。解决：确认接受 EULA 后，设 `OMNI_KIT_ACCEPT_EULA=YES`[^idx-eula]。
:::

:::{admonition} 坑二：裸 `uv sync` 会删掉 Isaac Sim
:class: warning

`uv sync` 默认做精确同步：环境里多出来、但这次没有请求的包会被删掉；`uv run` 默认只补缺，不删包[^uv-sync]。本站在装了 `isaacsim` extra 的环境里执行 `uv sync --dry-run`，结果是 `Would uninstall 86 packages`，也就是整个 Isaac Sim。所以装了 extra 之后，每次同步都要带上它（`uv sync --extra isaacsim`），或者改用 `uv run --extra isaacsim …`。
:::

:::{admonition} 坑三：路线 B 只装到 Isaac Sim 就停，环境里是 nightly 的 warp
:class: warning

EA 文档给 `uv pip install isaacsim…` 加了 `--prerelease=allow`。本站实测，这一步装进了 `warp-lang==1.19.0.dev20261008`（nightly），以及 PyPI 上的普通 `torch==2.11.0`。要等后面两步（PyTorch cu128、`isaaclab.sh -i`）跑完，才换成 `torch 2.11.0+cu128` 和 `warp-lang 1.16.0`。中途失败或漏跑后两步，环境里就是这些未锁定的版本。验证脚本会打印 warp 的版本，可以用它检查。
:::

:::{admonition} 坑四：第一次训练"卡住"一分钟
:class: warning

Newton 后端第一次运行时，在 `[2/3] Creating environment` 之后会停约一分钟，没有任何输出，这是 Warp 在编译内核（见上文对照）。第二次起，同样的训练只要约 20 秒。不要因为一时没有输出就中断它。
:::

:::{admonition} 坑五：在 5.1 的环境里跑 3.0
:class: warning

5.1 的环境是 Python 3.11，3.0 要求 `>=3.12,<3.13`[^pyproject]，在 3.11 的环境里装不上。最常见的情况是忘了切换环境：同一个终端里先 `source` 了 5.1 的环境，再进 3.0 仓库，用的就是 3.11。路线 A 用 `uv run` 不需要激活环境，可以避开这个问题；B、C 先跑一遍验证脚本，看第一行的 Python 版本和环境路径。
:::
