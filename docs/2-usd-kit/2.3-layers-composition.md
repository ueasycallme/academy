## 为什么需要合成

这一节回答：一个文件写完不就行了，为什么要多层？

[2.1](2.1-why-usd.md) 说过，USD 能在不改原文件的前提下覆盖其中的值（非破坏性编辑）。这是靠合成（composition）做到的：一个 Stage 由多个 Layer 叠出来，每个 Layer 只写自己负责的那部分意见（opinion），USD 按规则把它们合成一个结果[^comp]。由此带来三件事：

- **改参数不改原文件**：在更强的一层里写新值，原资产保持不动；
- **多人协作**：几何、材质、物理各写一层，互不覆盖；
- **一份资产多处复用**：场景里引用它，而不是复制它；改了资产，所有场景都跟着变。

## 五种合成弧

这一节回答：Layer 之间有哪几种"接法"？

| 合成弧 | 做什么 | 典型用途 | Galbot 厂商 USD 里的例子 |
|---|---|---|---|
| Sublayer | 把整个 Layer 叠到另一个 Layer 之下 | 按部门分层：几何、物理各一层 | `payloads/base.usda` 以 sublayer 叠入 `robot.usda`；`Physics/physx.usda` 叠入 `physics.usda` |
| Reference | 把另一个文件（的某个 Prim）挂到这里 | 场景里放一台机器人 | 根文件的 `/galbot_one_golf` 引用 `payloads/base.usda` |
| Payload | 和 Reference 一样，但可以不加载 | 大的、可选的部分，按需加载 | 每个变体选项都通过 payload 带进一份文件 |
| Variant（VariantSet） | 一组可切换的选项，每次只启用一个 | 同一资产的几种配置 | Physics（none / physics / physx）、Sensor、Robot、ROS 四个变体集 |
| Inherits / Specializes | 从一个"类" Prim 继承意见 | 让一批 Prim 共享可统一修改的默认值 | 本资产没有用到 |

*表 1：五种合成弧[^comp]。最后一行的两种用得较少，本页不展开。*

根文件 `galbot_one_golf.usda` 的核心只有十几行（节选）：

```usda
def Xform "galbot_one_golf" (
    prepend references = @./payloads/base.usda@
    variants = { string Physics = "physx"  string Sensor = "none" ... }
)
{
    variantSet "Physics" = {
        "none"    ( prepend payload = @./payloads/Physics/none.usda@ ) { }
        "physx"   ( prepend payload = @./payloads/Physics/physx.usda@ ) { }
        ...
```

Sublayer 写在 Layer 的头部元数据里，`payloads/base.usda` 开头（节选）：

```usda
#usda 1.0
(
    subLayers = [
        @./robot.usda@
    ]
)
```

## 强度顺序

这一节回答：同一个属性在几处都有值，谁赢？

USD 按 **LIVRPS** 的顺序判定强弱：Local（本地）> Inherits > Variant > Reference > Payload > Specializes[^livrps]。较新的 OpenUSD 文档把它写作 LIVERPS，在 Variant 与 Reference 之间多了一类较新的合成弧，本页的示例不涉及它。同一个 Layer stack 里，sublayer 列表中越靠前的越强[^layerstack]。

`livrps_demo.py` 在内存里建一个 `/Robot`，让 `mass` 在六处都有值，再依次删掉最强的那个：

```bash
python examples/isaaclab-2.3/2.3-layers-composition/livrps_demo.py
```

```text
合成结果：mass = 1.0（L 本地）
删掉本地值 → mass = 2.0（I 继承）
删掉 /_class 上的值 → mass = 3.0（V 变体）
删掉变体里的值 → mass = 4.0（R 引用）
删掉引用 → mass = 5.0（P 载荷）
删掉载荷 → mass = 6.0（S 特化）
```

*本站实测，usd-core。顺序与 OpenUSD 文档一致。*

记住一条就够用：**直接写在这一层的值最强，引用进来的值较弱**。这正是"不改原文件也能覆盖"的原理。

## Galbot 资产是怎么组织的

这一节回答：一个真实的机器人资产，各层分别放什么？

```bash
python examples/isaaclab-2.3/2.3-layers-composition/inspect_galbot_layers.py <描述仓库>/usd/galbot_one_golf.usda
```

```text
默认 Prim 上的合成弧（由强到弱）：
  Root         → galbot_one_golf.usda
  Variant      → galbot_one_golf.usda
  Payload      → payloads/Physics/physx.usda
  （Sensor、Robot、ROS 三个变体集同样各带一个 payload）
  Reference    → payloads/base.usda
载荷：
  全部加载（默认）：Prim 1517 个，刚体 78，关节 77，用到的 Layer 13 个
  不加载载荷（LoadNone）：Prim 7 个，刚体 0，关节 0，用到的 Layer 8 个
在 Session Layer 里把变体 Physics 切到 none：
  Prim 1440 个，刚体 0，关节 0，用到的 Layer 12 个
```

*本站实测（commit 2d496b0）。*

厂商的组织方式是：

- 根文件只放"选择"：引用基础资产，用四个变体集决定物理、传感器、机器人接口、ROS 各加载哪一份；
- 每个变体选项都通过 **payload** 带进来，不需要的部分可以不加载；
- 物理（`Physics/physx.usda`）单独成层，以 sublayer 叠在通用物理层 `physics.usda` 之上。所以同一套几何可以配不同的物理设置，切到 `none` 时，刚体与关节都消失，只剩可视部分。

这样组织的好处是一份资产服务多种用途（推断，依据是变体集的命名与内容）：做渲染演示时不加载物理，接 ROS 2 时打开 ROS 变体，而文件只有一套。

## Isaac Lab 加载资产时发生了什么

这一节回答：`UsdFileCfg(usd_path=...)` 在合成上做了什么？

1. 在 `{ENV_REGEX_NS}/Robot` 处建一个 Prim，**以 Reference 的方式**挂上 USD 文件[^lab-ref]；
2. 若配置了 `variants`，设置变体选择[^lab-spawn]；
3. 把 `rigid_props`、`articulation_props` 等写到这个 Prim 及其子 Prim 上[^lab-spawn]。这些值写在场景的 Layer 里，相对被引用的资产是 Local 意见，所以更强，覆盖资产里的值，资产文件本身不变。

两个后果：

- 资产里被做成**实例（instance）**的部分，在场景里不能逐个修改。[6.1.4](../6-galbot/1-asset/6.1.4-collision-mass-inertia.md) 实测：碰撞体在实例里，spawn 时的 `collision_props` 写不进去，只留下一条 WARNING。
- 多个环境由一台机器人克隆而来，克隆的是这份引用加上覆盖意见（[3.7](../3-isaacsim/3.7-cloner.md)、[4.5](../4-isaaclab/4.5-interactive-scene.md)）。

## Session Layer 与运行时的修改

这一节回答：仿真时用代码改了属性，改在哪一层？

用 Python 改属性，写进的是 Stage 当前的 **EditTarget**，默认是根 Layer[^edittarget]。Stage 还有一个 **Session Layer**：它比根 Layer 更强，不随 Stage 保存，只在 Stage 存在期间有效[^session]。临时的试验性修改写在这里最安全。`inspect_galbot_layers.py` 就是这样切换变体的：切换后根 Layer 里的选择仍是 `physx`，Session Layer 里是 `none`，清空 Session Layer 就恢复原状。

另外，GPU 物理仿真时，刚体的位姿、速度等状态不写回 USD 属性（[4.4](../4-isaaclab/4.4-simulation-context.md) 的 Fabric 一节）。所以运行中读 USD 属性看不到最新状态，保存 Stage 也不会把仿真结果存进去。

## 常见坑

:::{admonition} 坑一：改了被引用的文件，场景没变
:class: warning

只要还有打开的 Stage 持有某个 Layer，USD 再打开同一个文件时就会复用它，不重读磁盘。`layer_cache_demo.py` 实测：被引用的文件在磁盘上把 `mass` 从 1.0 改成 9.0，第一个 Stage 还开着时重新打开仍读到 1.0；对该 Layer 调用 `Sdf.Layer.Find(路径).Reload()` 后才是 9.0；所有 Stage 都关掉后再打开，则读到新值。Isaac Sim 运行期间当前 Stage 一直开着，推断同样会读到旧值（未在 Kit 中实测），所以改了资产文件后，重开进程最省事。
:::

:::{admonition} 坑二：载荷没有加载
:class: warning

用 `Usd.Stage.LoadNone` 打开，或在 GUI 里没有加载 payload 时，Galbot 资产只剩 7 个 Prim，刚体与关节都是 0（上文实测）。看到"资产是空的"，先确认 payload 是否已加载。
:::

:::{admonition} 坑三：变体选项名写错，不报错
:class: warning

把 Galbot 的 `Physics` 变体设为 `PhysX`（正确的是小写 `physx`），设置照样成功，结果是刚体数为 0（本站实测）。Isaac Lab 的 `select_usd_variants` 只在变体**集**不存在时给出警告，选项名不存在时照样写入[^lab-variants]。官方 Galbot One Charlie 的配置写的是 `PhysX`，那是另一份资产；照抄到 One Golf 上，物理就没了。设置后要读回刚体数核对。
:::
