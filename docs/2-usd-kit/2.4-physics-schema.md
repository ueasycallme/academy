## Schema 是什么

这一节回答：一个普通的 Xform 怎么就变成了"刚体"？

[**Schema**](../0-map/0.8-glossary.md#term-schema) 规定一类 Prim 应该有哪些属性、这些属性是什么意思[^glossary]。它有两种：

- **IsA Schema**（类型 Schema）：决定 Prim **是什么**，写在 Prim 的类型上[^glossary]。例如 `PhysicsRevoluteJoint` 表示这个 Prim 就是一个转动关节。
- **API Schema**：给已有的 Prim **追加一组能力**，不改变它的类型[^glossary]。"应用"（apply）一个 API，就是把它的名字记进 Prim 的 `apiSchemas` 元数据，此后这个 Prim 就拥有该 API 定义的属性。有些 API 可以带实例名多次应用，例如 `PhysicsDriveAPI:angular` 中的 `angular`[^glossary]。

物理大多走第二种。Galbot 的底盘 `base_link` 本身只是一个 `Xform`，物理层给它贴上三个 API 后，它就成了带质量的刚体，也是整台机器人的 Articulation 根：

```{code-block} usda
:lineno-start: 41
    over "base_link" (
        prepend apiSchemas = ["PhysicsRigidBodyAPI", "PhysicsMassAPI", "PhysicsArticulationRootAPI"]
    )
    {
        point3f physics:centerOfMass = (0.034222193, 0.0040757894, 0.07670002)
        float3 physics:diagonalInertia = (0.12010815, 0.09486162, 0.13627191)
        float physics:mass = 24.506
        quatf physics:principalAxes = (0.078462735, 0.9270959, 0.3247462, 0.16993134)
```

*Galbot `usd/payloads/Physics/physics.usda` L41–L48[^galbot-physics]。用的是 `over`，几何本体在另一个文件里，这里只追加物理（见 [2.2](2.2-usd-concepts.md)）。*

## UsdPhysics 与 PhysxSchema

这一节回答：为什么同一个 Prim 上既有 `Physics…API`，又有 `Physx…API`？

- **UsdPhysics** 是 OpenUSD 自带的通用物理 Schema，定义刚体、质量、碰撞、关节、驱动、Articulation、物理场景与物理材质[^usd-physics]。它不绑定某个物理引擎。
- **PhysxSchema** 是 NVIDIA 为 PhysX 提供的扩展，各个 API 的说明都是"PhysX … extended parameters"，即在通用 Schema 之上补充 PhysX 特有的参数，例如求解器迭代次数、关节最大速度[^physx-schema]。

Galbot 把两者放在两个文件里：`physics.usda` 只写 UsdPhysics，`physx.usda` 叠加 PhysxSchema（见 [2.1](2.1-why-usd.md) 图 1）。例如 `base_link` 在后者中多了 `PhysxArticulationAPI`，设置 `enabledSelfCollisions = 0` 与 `solverVelocityIterationCount = 1`[^galbot-physx]。

## 对照表：物理概念到 Schema

这一节回答：机器人 USD 里的物理，分别靠哪个 Schema 描述？

| 物理概念 | Schema | 关键属性 | Galbot 中的实例（本站实测数量） |
|---|---|---|---|
| 刚体 | `PhysicsRigidBodyAPI` | `physics:rigidBodyEnabled`、`physics:kinematicEnabled`、速度 | 每个连杆，如 `left_arm_link1`（78 个） |
| 质量与惯量 | `PhysicsMassAPI` | `physics:mass`、`physics:centerOfMass`、`physics:diagonalInertia`、`physics:principalAxes` | 同上，`left_arm_link1` 质量 1.6（78 个） |
| 碰撞体 | `PhysicsCollisionAPI` | `physics:collisionEnabled` | 连杆下 `collisions/` 中的网格与球体（184 个，含 40 个球体） |
| 网格碰撞近似 | `PhysicsMeshCollisionAPI` | `physics:approximation`：`convexHull`、`convexDecomposition`、`boundingCube` 等 | 144 个网格碰撞体，全部为 `convexHull` |
| 关节 | `PhysicsRevoluteJoint`；另有 `PhysicsPrismaticJoint`、`PhysicsFixedJoint`、`PhysicsSphericalJoint` 等 IsA 类型 | `physics:body0/1`、`physics:localPos0/1`、`physics:localRot0/1`、`physics:axis`、`physics:lower/upperLimit`（转动关节为度） | `joints/left_arm_joint1` 等；Galbot 只有转动关节（77 个） |
| 关节驱动 | `PhysicsDriveAPI:<实例名>` | `stiffness`、`damping`、`maxForce`、`targetPosition`、`type` | 手臂、腿、头、夹爪主关节与 4 个轮子（27 个） |
| Articulation 根 | `PhysicsArticulationRootAPI` | 无属性，标记"从这里往下按 Articulation 求解" | `base_link`（1 个） |
| 物理场景 | `PhysicsScene`（IsA） | `physics:gravityDirection`、`physics:gravityMagnitude` | 无：资产里通常不带，由使用方创建 |
| 物理材质 | `PhysicsMaterialAPI`（贴在 Material 上） | `physics:staticFriction`、`physics:dynamicFriction`、`physics:restitution` | 夹爪指尖材质，摩擦 1.5，经 `material:binding:physics` 绑定[^galbot-mat] |

*表 1：物理概念与 Schema 的对应。Galbot 列的路径省略了前缀 `/galbot_one_golf/`。Schema 与属性的定义见 UsdPhysics 文档[^usd-physics]；数量由本页示例脚本统计。未带驱动的 50 个关节里，40 个是全向轮上的被动滚子，10 个是跟随夹爪主关节运动的 mimic 关节（`PhysxMimicJointAPI`）。*

驱动的含义可以用 UsdPhysics 给出的公式理解：驱动力 = stiffness ×（目标位置 − 当前位置）+ damping ×（目标速度 − 当前速度），并受 `maxForce` 限制[^usd-physics]。这就是 PD 控制，Isaac Lab 里执行器（actuator）的参数最终也写到这里（见 [3.4](../3-isaacsim/3.4-articulation.md)）。

## 用脚本看一个资产

这一节回答：怎么快速知道一个 USD 资产的物理配得全不全？

本站示例 `examples/isaaclab-2.3/2.4-physics-schema/list_physics_schemas.py` 遍历资产，列出每种物理 Schema 的数量与示例路径，统计刚体、关节、驱动、碰撞体，并检查 Articulation 根数量、嵌套刚体、被关闭的碰撞体。运行方式与 [2.2](2.2-usd-concepts.md) 的示例相同，usd-core 与 Isaac Sim 环境都可以（本站实测两者输出一致）。Galbot 的结果如下（节选）：

```text
刚体 78，关节 77（带驱动 27），碰撞体 184
网格碰撞近似方式：{'convexHull': 144}
Articulation 根：['/galbot_one_golf/base_link']
[OK] Articulation 根数量为 1（Isaac Lab 要求恰好一个）
[OK] 嵌套刚体 0 个
[OK] 关闭碰撞的碰撞体 0 个
```

## 和 URDF 的对应

这一节回答：URDF 导入后，各部分变成了什么？

| URDF | USD 中的落点 | Galbot 对照（本站实测） |
|---|---|---|
| `<link>` | `Xform` + `PhysicsRigidBodyAPI` | `left_arm_link1` |
| `<inertial>` 的 `mass` | `physics:mass` | 1.6 → 1.6 |
| `<inertial>` 的 `origin` | `physics:centerOfMass` | (0, 0.00097, −0.01539)，两边一致 |
| `<inertial>` 的 `inertia` 矩阵 | 对角化为 `physics:diagonalInertia` + `physics:principalAxes` | ixx 0.00333 → 对角项 0.00332 |
| `<collision>` | 子 Prim 上的 `PhysicsCollisionAPI`（网格另加 `PhysicsMeshCollisionAPI`） | `collisions/…` 下的网格 |
| `<joint type="revolute/continuous">` | `PhysicsRevoluteJoint` | `left_arm_joint1` |
| `<joint type="prismatic">` / `"fixed"` | `PhysicsPrismaticJoint` / `PhysicsFixedJoint` | Galbot 未使用 |
| `<limit lower/upper>` | `physics:lowerLimit/upperLimit`，**弧度变为度** | ±3.00433 rad → ±172.1352° |
| `<limit velocity>` | `physxJoint:maxJointVelocity`（PhysxSchema） | 1.5 rad/s → 85.94 °/s |
| `<limit effort>` | `drive:…:maxForce` | URDF 60，USD 为 1000，并未照搬 |
| `<mimic>` | `PhysxMimicJointAPI` | 10 个夹爪关节 |

*表 2：URDF 元素与 USD Schema 的对应，依据 Galbot 仓库中同一台机器人的 URDF 与 USD 对照得出[^galbot-urdf]。导入器的具体规则见 [3.5 URDF / MJCF 导入](../3-isaacsim/3.5-urdf-mjcf-import.md)。*

最后一行 `effort` 值得注意：这份 USD 资产没有照搬 URDF 的力矩上限（推断：生成资产时另行设定）。用 URDF 参数做仿真对比时，要以 USD 里的实际值为准。

## 和 Isaac Lab 的对应

这一节回答：Isaac Lab 配置里的 `rigid_props` 之类，改的是什么？

Isaac Lab 的 spawner 配置有一组 `*_props` 字段，每个对应 `isaaclab.sim.schemas` 中的一个配置类，最终写入上面这些 Schema 的属性[^lab-spawner]：

| 配置字段 | 配置类 | 写入的 Schema |
|---|---|---|
| `rigid_props` | `RigidBodyPropertiesCfg` | `UsdPhysics.RigidBodyAPI` + `PhysxSchema.PhysxRigidBodyAPI`[^lab-rigid] |
| `collision_props` | `CollisionPropertiesCfg` | `UsdPhysics.CollisionAPI` + `PhysxSchema.PhysxCollisionAPI`[^lab-collision] |
| `mass_props` | `MassPropertiesCfg` | `UsdPhysics.MassAPI`[^lab-mass] |
| `articulation_props` | `ArticulationRootPropertiesCfg` | `UsdPhysics.ArticulationRootAPI` + `PhysxSchema.PhysxArticulationAPI`[^lab-art] |
| `joint_drive_props` | `JointDrivePropertiesCfg` | `UsdPhysics.DriveAPI`[^lab-drive] |

*表 3：Isaac Lab 配置与 Schema 的对应（v2.3.2）。字段值为 `None` 时不修改资产里已有的值[^lab-cfg]。*

## 常见坑

:::{admonition} 坑一：Articulation 根放错位置或放了多个
:class: warning

Articulation 根不能嵌套[^usd-physics]；Isaac Lab 在一个环境的机器人路径下要求**恰好一个**根，找不到时报 `Failed to find an articulation when resolving`，多于一个时报 `Failed to find a single articulation`[^lab-art-find]。移动机器人一般把根放在底盘连杆上（Galbot 即如此）；固定基座的机械臂可以放在祖先 Prim 上，或用 `fix_root_link` 让 Isaac Lab 加一个固定关节[^lab-cfg]。
:::

:::{admonition} 坑二：刚体嵌套，子连杆"掉下来"
:class: warning

一个刚体的子树里若还有贴了 `PhysicsRigidBodyAPI` 的 Prim，它会成为独立的刚体，与父刚体各自运动，只是变换在层级上相对存放[^usd-physics]。如果中间没有关节连接，它在仿真开始后就会脱离。连杆应当像 Galbot 那样并列放置，由关节连接。示例脚本会检查嵌套刚体。
:::

:::{admonition} 坑三：有碰撞网格却不发生碰撞
:class: warning

光有网格不会参与碰撞，必须贴 `PhysicsCollisionAPI` 并且 `physics:collisionEnabled` 为真[^usd-physics]。自己导出或修改资产后，用示例脚本确认碰撞体数量与开关状态。
:::

:::{admonition} 坑四：把 USD 里的角度当弧度
:class: warning

转动关节的限位在 USD 中以度表示[^usd-physics]，而 Isaac Sim 的 Python API 与 PhysX 使用弧度[^sim-conv]。Isaac Lab 的关节数据从 PhysX 读出，也是弧度（推断：依据上述约定）。直接拿 USD 文件里的 172.1352 当弧度用，会差出约 57 倍。
:::
