## 两种运行环境

这一节回答：`from pxr import Usd` 在哪里跑？

| | 纯 usd-core | Isaac Sim 进程内 |
|---|---|---|
| 安装 | `pip install usd-core`，装好约 150 MB | 已装好的 Isaac Sim 环境 |
| 导入 `pxr` | 直接导入 | 先启动 `SimulationApp`，再导入（直接导入报 `No module named 'pxr'`，本站实测） |
| 启动 | 不到 1 秒 | 约 10 秒（headless） |
| 认识的 Schema | 只有 USD 自带的，如 `UsdPhysics` | 另有 PhysX、Isaac 的扩展 Schema |
| USD 版本 | 随 pip 更新，本站为 26.08 | 随 Isaac Sim 固定，5.1.0 为 24.05 |
| 适合 | 看文件、批量检查、CI | 要用 PhysX 专有属性，或要和仿真一起跑 |

*表 1：两种运行环境（本站实测）。*

usd-core 只含 USD 的核心库，不含可选插件与渲染部分[^usdcore]。差别在扩展 Schema 上：Galbot 夹爪的 mimic 跟随关节，在 usd-core 里 `GetAppliedSchemas()` 返回空列表，但 `physxMimicJoint:*` 属性照样读得到；在 Isaac Sim 里，同一个关节列出 `PhysxJointAPI`、`PhysxMimicJointAPI:rotZ` 等 4 个（本站实测）。

本页的两个脚本两种环境都能跑：先试 `from pxr import Usd`，失败时再启动 `SimulationApp`。

::::{tab-set}
:::{tab-item} usd-core
```bash
uv venv --python 3.11 usd-env && uv pip install --python usd-env/bin/python usd-core
usd-env/bin/python examples/isaaclab-2.3/2.5-usd-python/edit_usd.py
```
:::
:::{tab-item} Isaac Sim 环境
```bash
# 在已激活的 env_isaaclab 中运行；脚本自动 headless 启动 SimulationApp
python examples/isaaclab-2.3/2.5-usd-python/edit_usd.py
```
:::
::::

## 读与遍历

这一节回答：怎么从几千个 Prim 里找到想要的那几个？

```python
stage = Usd.Stage.Open(robot_usd)
prims = list(stage.Traverse(Usd.TraverseInstanceProxies()))       # 进入实例内部，见坑一
revolute = [p for p in prims if p.IsA(UsdPhysics.RevoluteJoint)]   # 按类型筛选
arm = [p for p in revolute if re.fullmatch(r"right_arm_joint\d", p.GetName())]  # 按名字筛选
drive = UsdPhysics.DriveAPI(arm[0], "angular")                      # 多实例 API schema，实例名 angular
drive.GetStiffnessAttr().Get()
```

```text
打开用时 0.03 s；defaultPrim = /galbot_one_golf，upAxis = Z，metersPerUnit = 1.0
按类型：转动关节 77 个，移动关节 0 个
按名字 right_arm_joint\d：7 个
  /galbot_one_golf/joints/right_arm_joint1  限位 [-172.1, 172.1]（度）  stiffness 1e+05  damping 1e+04
```

*`edit_usd.py` 的输出（usd-core，节选）。转动关节的限位单位是度（[2.4](2.4-physics-schema.md) 坑四）。*

读值优先用 Schema 类的方法（`GetLowerLimitAttr()`），少用 `GetAttribute("physics:lowerLimit")` 这样手写属性名：前者拼错名字时直接报 `AttributeError`，后者拼错只会拿到一个无效属性，`Get()` 返回 `None`，不报错（本站实测）。Stage 元数据用 `stage.GetMetadata("upAxis")` 读。

## 修改与保存

这一节回答：改动写进了哪个文件？

`edit_usd.py` 不碰厂商文件，而是新建一个场景：

1. `Usd.Stage.CreateNew("scene.usda")`，引用 Galbot（[2.3](2.3-layers-composition.md) 的 Reference）；
2. 把 `right_arm_joint1` 的刚度改成两倍；
3. 加一个方块，`Apply` 刚体、碰撞、质量三个 API schema，设质量 2 kg；
4. `stage.Save()`，再 `stage.Export("flattened.usda")`。

```text
scene.usda            0.7 KB  合成后 Prim 1512 个
flattened.usda    20580.1 KB  合成后 Prim 1512 个
```

```usda
def Xform "Robot" (
    prepend references = @../third_party/.../galbot_one_golf.usda@
)
{
    over "joints" {
        over "right_arm_joint1" {
            float drive:angular:physics:stiffness = 200000
        }
    }
}
```

*本站实测。下面是 `scene.usda` 的节选，路径有删节。*

- **写到哪一层**：所有 `Set`、`Define`、`Apply` 都写进 Stage 当前的 EditTarget，这里是 `scene.usda`。对关节的修改以 `over` 的形式记下，厂商文件不变（脚本最后用 MD5 核对过）。这正是 2.3 的"本地意见最强"。
- **`Save`**：把有改动的 Layer 写回各自的文件。这里只有 `scene.usda`，0.7 KB。
- **`Export`**：把合成结果压平成一个独立文件，不再依赖原资产，所以有 20 MB。适合交付或存档，不适合继续协作。

要临时改、不想落盘，就把 EditTarget 设为 Session Layer（[2.3](2.3-layers-composition.md)）。

## 常用工具

这一节回答：除了 Python，还有什么能看 USD？

| 工具 | 做什么 | pip 环境里有没有 |
|---|---|---|
| `usdcat` | 把 USD 文件以文本形式打印出来 | 没有。Python 中 `layer.ExportToString()` 可代替 |
| `usdview` | 交互式预览，可浏览场景树、查看属性 | 没有，需完整的 OpenUSD 构建 |
| `usdchecker` | 按规则检查 USD 文件 | 没有。思路同下一节的 `check_asset.py` |
| `usdzip` | 把 USD 与它引用的文件打成 USDZ 包 | 没有 |
| `usdtree` | 打印 Layer 或合成后的树形结构 | 没有。2.2 的 `inspect_usd.py` 可代替 |

*表 2：OpenUSD 自带的命令行工具[^toolset]。"有没有"指 usd-core 与 Isaac Sim 5.1.0 的 pip 环境（本站实测：两者的 bin 目录里都没有这些命令）。*

**用 Isaac Sim 界面。** File → Open 打开 USD 文件后，Stage 窗口列出当前场景中的全部 Prim，Property 面板显示选中 Prim 的详细属性[^sim-gui]。这是最直观的方式，适合边看边改。界面里的修改同样写进当前的 EditTarget。

## 资产检查清单

这一节回答：一个资产检查脚本应该查什么？

把 2.4 的 `list_physics_schemas.py`、6.1.3 的 `compare_usd.py` 里的检查抽出来，就是 `check_asset.py` 的 11 项（含实例内部，见坑一）：

| 类别 | 检查项 | 出问题的后果 |
|---|---|---|
| 文件 | 依赖文件都能找到；没有合成错误 | 部件缺失，或引用到空 Prim |
| 场景 | 有 defaultPrim；单位为米、Z 向上 | 引用后是空的；尺寸或朝向错（2.2） |
| 结构 | Articulation 根恰好一个；没有嵌套刚体；关节两端的 body 都存在 | 机器人散架或无法创建（2.4） |
| 物理 | 限位下限不大于上限；刚体都写了质量；没有被关掉的碰撞体 | 质量由 PhysX 估算，可能与真机差很多（6.1.4） |
| 驱动 | 非固定关节都有 DriveAPI | 关节不受控；在 Isaac Lab 里通常由执行器配置补上（4.7） |

*表 3：资产检查清单。"注意"留给人判断。在 usd-core 环境下，有"失败"时退出码为 1，可以放进 CI；Isaac Sim 环境下退出码总是 0（坑五）。*

| | 厂商 USD | 6.1.2 自转换的 USD |
|---|---|---|
| 失败 | 0 | 0 |
| 注意 | MDL 材质 `OmniPBR.mdl`；未带驱动的关节 50 个（全向轮被动滚子 40 个、mimic 跟随 10 个） | MDL 材质 2 个；合成错误 1 个（`head_link1` 的 visuals）；未带驱动的关节 10 个（mimic 跟随） |

*表 4：两份 Galbot USD 的检查结果（usd-core，本站实测）。在 Isaac Sim 里跑，MDL 材质都能解析，这一项不再出现，其余结果相同。*

表 4 的"注意"都不是问题，但只有人能判断：被动滚子和 mimic 跟随关节本来就不该有驱动；`head_link1` 在 URDF 里就没有视觉网格（[6.1.2](../6-galbot/1-asset/6.1.2-import-urdf.md)）。检查脚本的作用是把这些地方都列出来，而不是替人下结论。

## 常见坑

:::{admonition} 坑一：遍历时漏掉了网格
:class: warning

`stage.Traverse()` 默认不进入实例（instanceable）内部。Galbot 的网格都在实例里，默认遍历只数到 6 个 Mesh，加上 `Usd.TraverseInstanceProxies()` 才数到 190 个（本站实测，2.2 的 `inspect_usd.py`）。
:::

:::{admonition} 坑二：Stage 被释放后，Prim 就失效了
:class: warning

`Usd.Stage.Open(path).GetPrimAtPath("/Robot")` 这样一行写完，Stage 没有变量持有，随即被释放，再用这个 Prim 就报 `RuntimeError: Accessed invalid expired 'Xform' prim </Robot>`（本站实测）。先 `stage = Usd.Stage.Open(path)`，在用完 Prim 之前保持 `stage` 存活。
:::

:::{admonition} 坑三：引用写了绝对路径，场景搬不走
:class: warning

`AddReference(path)` 传入什么，文件里就记什么。传绝对路径，换一台机器就找不到资产。`edit_usd.py` 改用相对于 `scene.usda` 的路径（`os.path.relpath`）。相对路径按 `scene.usda` 所在的目录解析，与运行脚本时的当前目录无关（本站实测：把场景复制到别处、从另一个目录打开，没有合成错误）。
:::

:::{admonition} 坑四：在 usd-core 里按 Schema 名判断 PhysX 属性
:class: warning

usd-core 不认识 PhysX 的扩展 Schema，`GetAppliedSchemas()` 里没有 PhysxMimicJointAPI，按名字判断就会漏判。`check_asset.py` 改为看属性名前缀 `physxMimicJoint:`，两种环境的结果一致。
:::

:::{admonition} 坑五：在 Isaac Sim 环境里用退出码判断成败
:class: warning

启动了 `SimulationApp` 的脚本，退出码总是 0。本站实测：未捕获的异常照样退出码 0；`close()` 会直接结束进程，写在它后面的 `sys.exit(3)` 不会执行。CI 里的资产检查请用 usd-core 环境跑。另外两种环境的 USD 版本不同（表 1），新版的 API 在 Isaac Sim 里可能不存在，例如 `Stage.GetCompositionErrors()`。所以 `check_asset.py` 改为逐个 Prim 读取 `GetPrimIndex().localErrors`。
:::
