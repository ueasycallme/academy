## Kit 是什么

这一节回答：Isaac Sim 底下那一层是什么？

Omniverse Kit 是 NVIDIA 用来构建 Omniverse 应用的 SDK[^kit-overview]。可以把它看成三件事：

- **SDK**：写应用、写扩展用的一套工具与 API；
- **运行时**：把 USD、RTX 渲染器、Carbonite 插件框架、Python 脚本、UI 组合在一起跑起来的内核[^kit-overview]；
- **扩展系统**：功能都以扩展（extension）的形式提供，有版本号，可以按需启用、停用[^kit-overview]。

Isaac Sim 是一个 Kit 应用：它没有一个单独的"主程序"，而是 Kit 内核加上一组扩展，物理（`omni.physx`）、机器人导入、传感器、Isaac Lab 本身都是其中的扩展。

## 应用即一组扩展：`.kit` 文件

这一节回答：一个 Kit 应用由什么决定？

决定一个 Kit 应用的，是一个 `.kit` 文件：它列出依赖的扩展和默认设置，格式与扩展自己的 `extension.toml` 相同[^kit-apps]。Isaac Lab 在 `apps/` 下自带几份，`AppLauncher` 按两个开关选择[^lab-exp]：

| | 不开相机 | `--enable_cameras` |
|---|---|---|
| `--headless` | `isaaclab.python.headless.kit` | `isaaclab.python.headless.rendering.kit` |
| 带界面 | `isaaclab.python.kit` | `isaaclab.python.rendering.kit` |

*表 1：AppLauncher 选择的体验文件（experience file）。用 `--experience` 可以指定别的文件。*

训练时最常用的是第一行的两份。逐节看 `isaaclab.python.headless.kit`[^headless-kit]：

```toml
[package]                          # 应用的名字、版本
title = "Isaac Lab Python Headless"
version = "2.3.2"

[dependencies]                     # 要启用的扩展，{} 表示不限版本
"omni.physx" = {}
"isaacsim.core.api" = {}
"isaaclab" = {order = 1000}        # Isaac Lab 自己的扩展最后加载

[settings.physics]                 # 设置：写进 Kit 的设置树，路径 /physics/updateToUsd
updateToUsd = false
```

*节选并合并了两段 `[dependencies]`，注释为本站所加。原文件 220 行，两段合计列出 19 个扩展。*

相机版只在它之上加东西：`[dependencies]` 第一项就是 `"isaaclab.python.headless" = {}`，即把整个 headless 应用当作一个依赖，再加渲染相关的扩展[^rendering-kit]。

| | `headless.kit` | `headless.rendering.kit` |
|---|---|---|
| 依赖 | 物理、Isaac Sim 核心、Isaac Lab | 整个 headless 应用 + `omni.replicator.core`、材质库、RTX 视口 |
| `/isaaclab/cameras_enabled` | 未设置 | `true` |
| `/app/useFabricSceneDelegate` | `false` | `true` |
| 实际启用的扩展 | 80 个 | 153 个 |
| 启动用时 | 4.0 s | 6.8 s |

*表 2：两份 headless 体验文件的对照。后两行为本站实测（`kit_inspect.py`，RTX 5070）；Kit 共发现 651 个扩展。*

`.kit` 里直接列的只有 19 个，却启用了 80 个：扩展系统会递归地解析依赖的依赖[^kit-apps]。

## 启动时发生了什么

这一节回答：为什么一定要先 `SimulationApp(...)`，再 `import` 别的？

1. **`import isaacsim`**：设置 `EXP_PATH`（体验文件所在目录）等环境变量，把 `isaacsim.simulation_app` 加进 `sys.path`，并引导 Kit 内核[^bootstrap]。pip 安装时，是 Python 进程把 Kit 内核加载进来。
2. **`SimulationApp(config, experience)`**：把体验文件和命令行参数交给 Kit 启动。没指定体验文件时，依次找 `omni.isaac.sim.python.kit`、`isaacsim.exp.base.python.kit`、`isaacsim.exp.base.kit`[^sa]；pip 安装里没有第一个，所以用的是第二个（本站实测 `apps/` 目录）。Isaac Lab 的 `AppLauncher` 则按表 1 选好后传进去[^lab-exp]。
3. **Kit 解析 `[dependencies]`，逐个启用扩展**。扩展启用时，它的 Python 包才加进搜索路径。

所以导入顺序不能颠倒：`kit_inspect.py` 在启动前 `import omni.kit.app`，得到 `ModuleNotFoundError`（本站实测）。官方文档的说法是：Omniverse 层面的导入必须在 `SimulationApp` 实例化之后[^standalone]。旧写法 `from omni.isaac.kit import SimulationApp` 要先 `import isaacsim` 才能用（[0.3](../0-map/0.3-lineage.md)），原因也在第 1 步：`extsDeprecated/omni.isaac.kit` 是在这一步加进 `sys.path` 的[^bootstrap]。

## 事件循环与 `app.update()`

这一节回答：Kit 的"一帧"是什么？

Kit 应用跑在一个循环里，每次 `update()` 推进一帧，各扩展在这一帧里做自己的事（物理步进、渲染等，见 3.1）。`SimulationApp.update()` 就是调用 Kit 应用的 `update()`[^sa]。`kit_inspect.py` 调 3 次，帧号从 13 变为 16（本站实测）。启动阶段 Kit 已经自己跑过十几帧。仿真步、渲染步与 `app.update()` 的关系见 [3.1](../3-isaacsim/3.1-sim-loop.md)。

## 设置系统

这一节回答：`.kit` 里的 `[settings]`、命令行参数、代码里的设置，是一回事吗？

是一回事。Kit 的设置（Carbonite settings）是一棵以路径为键的树，如 `/physics/updateToUsd`。它可以从三处写入[^configuring]：

- `.kit` 文件的 `[settings]` 各节，节名加键名就是路径；
- 命令行 `--/路径=值`。Isaac Lab 里通过 `--kit_args` 传入；
- 代码中 `carb.settings.get_settings().set(路径, 值)`，用 `.get(路径)` 读。

```python
import carb
settings = carb.settings.get_settings()
settings.get("/physics/updateToUsd")        # headless.kit 里写的 false
settings.set("/physics/updateToUsd", True)
```

`kit_inspect.py` 的三种启动方式下，`/physics/updateToUsd` 分别是：默认 `False`；加 `--kit_args="--/physics/updateToUsd=true"` 启动后是 `True`；运行时 `set` 之后立即读到 `True`（本站实测）。这个设置改了以后仿真行为怎样变化，见 [4.4](../4-isaaclab/4.4-simulation-context.md) 表 3。`/persistent/` 下的设置会在两次运行之间保存[^configuring]。

## 常见误解

:::{admonition} 误解一："headless 就是不渲染"
:class: warning

headless 只是不开窗口。`--headless --enable_cameras` 加载的 `headless.rendering.kit` 描述就是"无界面运行、启用渲染"[^rendering-kit]，比不开相机多启用 73 个扩展（表 2）。不需要相机图像时，就不要加 `--enable_cameras`。
:::

:::{admonition} 误解二：".kit 里没写的扩展不会被加载"
:class: warning

`.kit` 只写直接依赖，依赖的依赖会被自动启用：headless 版直接列 19 个，实际启用 80 个（本站实测）。要确认某个扩展是否启用，用 `get_extension_manager().is_extension_enabled(名字)` 查。
:::

:::{admonition} 误解三："`import isaacsim` 只是导入一个普通的包"
:class: warning

它会设置环境变量、改 `sys.path` 并引导 Kit 内核[^bootstrap]，还会替换 `sys.excepthook`：导入出错时，打印"必须先实例化 SimulationApp"的提示[^bootstrap]。
:::

:::{admonition} 误解四："要改设置，就去改 Isaac Lab 的 .kit 文件"
:class: warning

`apps/` 下的文件属于 Isaac Lab 仓库：改了会影响之后的每一次运行，升级 Isaac Lab 时还会产生冲突。临时改用 `--kit_args="--/路径=值"`，长期改动写进自己的体验文件，再用 `--experience` 指定。
:::
