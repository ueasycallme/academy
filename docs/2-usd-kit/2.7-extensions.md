- 会启用一个扩展，会查"某个功能在哪个扩展里"
- 写出一个最小扩展，并在 Isaac Sim 里启用它
:::

:::{admonition} 前置知识
:class: lead-prereq

- [2.6 Omniverse Kit 是什么](2.6-what-is-kit.md)
:::

本页示例在 `examples/isaaclab-2.3/2.7-extensions/`：一个最小扩展 `exts/academy.hello/`、一个反例 `exts/academy.hello_noimport/`，以及启用它们的 `enable_hello.py`。

## 扩展的结构

这一节回答：一个扩展目录里有什么？

扩展（extension）是 Kit 里功能的基本单位：一个目录，带一份 `config/extension.toml` 和一个 Python 包（有的还带 C++ 插件）[^ext-basic]。以 Isaac Sim 的克隆扩展为例（pip 包 `isaacsim/exts/` 下，本站实测）：

```text
isaacsim.core.cloner/
├── config/extension.toml        # 名字、版本、依赖、Python 模块
├── isaacsim/core/cloner/        # Python 包：import isaacsim.core.cloner
│   ├── __init__.py
│   ├── impl/  tests/
│   └── _isaac_cloner.cpython-311-x86_64-linux-gnu.so   # C++ 部分
├── data/  docs/  PACKAGE-LICENSES/
```

`extension.toml` 的主要几节：

| 节 | 作用 | cloner 里写的 |
|---|---|---|
| `[package]` | 版本、标题、描述、分类 | `version = "1.4.10"` |
| `[dependencies]` | 依赖的其他扩展，启用时一并启用 | `omni.physx`、`omni.usd` 等 5 个 |
| `[[python.module]]` | 启用后可以导入的 Python 包 | `isaacsim.core.cloner` |
| `[[test]]` | 跑扩展自带测试时的依赖和参数 | 一长串 `--/路径=值` 设置 |

*表 1：`extension.toml` 的主要节[^ext-basic]。*

**`omni.ext.IExt` 入口**：扩展若要在启用、停用时做事（注册菜单、启动服务等），就在 Python 模块里写一个 `omni.ext.IExt` 的子类，实现 `on_startup(ext_id)` 与 `on_shutdown()`[^ext-basic]。这是可选的：cloner 与 Isaac Lab 都没有 `IExt` 子类，只提供可以导入的库；pip 包 `exts/` 下有 106 个文件写了 `IExt` 子类（本站实测）。

## 启用与停用

这一节回答：怎么让一个扩展生效？

| 方式 | 写法 | 适合 |
|---|---|---|
| 图形界面 | Window → Extensions，列出所有找到的扩展，可直接开关[^ext-basic] | 试用 |
| `.kit` 文件 | `[dependencies]` 里加一行（[2.6](2.6-what-is-kit.md)） | 长期使用 |
| 命令行 | `--enable 名字`；扩展不在默认目录时加 `--ext-folder 目录`[^ext-basic] | 临时 |
| 代码 | `get_extension_manager().set_extension_enabled_immediate(名字, True)`，或 `isaacsim.core.utils.extensions.enable_extension(名字)`[^enable-ext] | 脚本里按需启用 |

*表 2：启用扩展的四种方式。*

Kit 只在扩展搜索路径里找扩展。pip 安装的 Isaac Sim 有这些目录（本站实测数量）：

- `exts/`（94 个）：Isaac Sim 自己的扩展，目录名不带版本号；
- `extscache/`（448 个）：Kit 与 Omniverse 的扩展，如 `omni.physx-107.3.26+…`，目录名带版本号；
- `extsDeprecated/`（70 个）：`omni.isaac.*` 等旧名的弃用扩展（[3.11](../3-isaacsim/3.11-api-map.md)、[0.3](../0-map/0.3-lineage.md)）。
- `extsUser/`（空）：Isaac Sim 自带的 `isaacsim.exp.base*.kit` 把它列在扩展搜索路径里（本站核对），留给用户放自己的扩展。Isaac Lab 的体验文件没有列它。

## Isaac Sim 扩展集的命名

这一节回答：想用某个功能，去哪个扩展找？

Isaac Sim 的扩展名多与它的 Python 包名相同，按"领域.功能"两到三段命名。`exts/` 下的 94 个扩展按第二段分组，最多的几组是：

| 前缀 | 数量 | 内容 | 例子 |
|---|---|---|---|
| `isaacsim.core` | 14 | 仿真世界、Prim 封装、克隆、工具函数 | `core.api`、`core.prims`、`core.cloner` |
| `isaacsim.replicator` | 11 | 合成数据、域随机化 | `replicator.writers` |
| `isaacsim.sensors` | 10 | 相机、接触、IMU、激光雷达 | `sensors.camera`、`sensors.physics` |
| `isaacsim.asset` | 10 | URDF / MJCF 导入、资产生成 | `asset.importer.urdf` |
| `isaacsim.robot` | 9 | 机械臂、轮式机器人 | `robot.manipulators` |

*表 3：Isaac Sim 5.1.0 扩展的主要分组（本站按 pip 包目录统计）。常用包的用途见 [3.11](../3-isaacsim/3.11-api-map.md) 表 1。*

物理、USD、界面等底层功能在 `omni.*` 下（`extscache/` 里，`omni.kit.*` 就有 231 个）。查某个类在哪个扩展：在这几个目录里搜类名；或者启动后 `import` 它，打印 `模块.__file__`，路径里就有扩展目录名。

## 动手：最小扩展

这一节回答：自己写一个扩展最少要什么？

```text
exts/academy.hello/
├── config/extension.toml
└── academy/hello/
    ├── __init__.py          # from .extension import HelloExtension, greet
    └── extension.py         # class HelloExtension(omni.ext.IExt)
```

```toml
[package]
version = "0.1.0"
title = "Academy Hello"

[dependencies]
"omni.usd" = {}

[[python.module]]
name = "academy.hello"
```

```bash
python examples/isaaclab-2.3/2.7-extensions/enable_hello.py   # 在 Isaac Sim / Isaac Lab 环境中
```

```text
add_path 之后立即启用：False
[academy.hello] on_startup：academy.hello-0.1.0
update() 一帧之后再启用：True
调用扩展提供的函数：hello from academy.hello
启用拼错的名字 academy.helo：False
academy.hello_noimport：is_extension_enabled = True
[academy.hello] on_shutdown
```

*本站实测（Isaac Sim 5.1.0），节选。`academy.hello_noimport` 启用后没有打印 `on_startup`，见坑三。*

脚本做了四件事：故意在加目录之前启用一次（失败，用来演示坑一）；用 `add_path` 把 `exts/` 加进搜索路径，`update()` 一帧后启用，触发 `on_startup`；启用后 `import academy.hello`，调用它提供的函数；停用时触发 `on_shutdown`。

## Isaac Lab 也是扩展

这一节回答：Isaac Lab 和扩展有什么关系？

Isaac Lab 的每个包都是一个扩展，`source/isaaclab/config/extension.toml` 就是它的扩展描述[^lab-ext]：

- `[[python.module]]` 为 `isaaclab`，所以启用后可以 `import isaaclab`；
- `[python.pipapi]` 列出它需要的 pip 包（numpy、gymnasium 等）；
- `[core] reloadable = false`：不支持运行中热重载。

[2.6](2.6-what-is-kit.md) 的 headless 体验文件把 `isaaclab`、`isaaclab_tasks` 等写进 `[dependencies]`，并设 `order = 1000` 让它们最后加载。Isaac Lab 没有 `IExt` 子类，它作为库被导入。仓库里各包的分工见 [4.2](../4-isaaclab/4.2-repo-map.md)，自己的项目也按这个结构组织，见 [4.18](../4-isaaclab/4.18-extension-template.md)。

## 常见坑

:::{admonition} 坑一：一个名字启用失败过，加了目录也要等一帧
:class: warning

`enable_hello.py` 第 1 步在加目录之前先启用了一次，失败了；第 2 步 `add_path` 之后立即启用，仍返回 `False`（日志为 `Can't find extension`），`update()` 一帧后再启用才成功（本站实测）。

校验方做了对照，每种情况各跑 3 次：
- **之前没对这个名字启用失败过**：`add_path` 之后立即启用就成功，不需要 `update()`；
- **之前失败过**：立即启用和紧接着重试都失败，`update()` 一帧后才成功。

所以触发条件是"之前对这个名字启用失败过"。机理推断为：失败的查找结果要到下一帧才刷新。

稳妥的写法是先 `add_path` 再启用；万一失败，`update()` 一帧后重试。用命令行 `--ext-folder` 或 `.kit` 指定目录，就不会遇到这个问题。
:::

:::{admonition} 坑二：依赖写成了 Python 模块名
:class: warning

`[dependencies]` 只能写扩展名。本站最初写了 `"omni.kit.app" = {}`：它是 Kit 内核的 Python 模块，不是扩展，结果启用失败，日志为 `dependency: 'omni.kit.app' … can't be satisfied`。不确定时到 `extscache/`、`exts/` 里确认有这个目录。
:::

:::{admonition} 坑三：IExt 子类没被找到，扩展"启用了"却什么都不做
:class: warning

Kit 只在 `[[python.module]]` 指定的模块里找 `IExt` 子类[^ext-basic]。`academy.hello_noimport` 把类写在 `extension.py`，但 `__init__.py` 没有导入它：启用返回成功，`is_extension_enabled` 为 `True`，`on_startup` 却没有执行（本站实测）。要在 `__init__.py` 里 `from .extension import …`。
:::

:::{admonition} 坑四：名字拼错不报异常
:class: warning

`set_extension_enabled_immediate("academy.helo", True)` 只返回 `False`，并在日志里记一条错误，脚本照常往下跑（本站实测）。启用后用 `is_extension_enabled` 检查一次。
:::
