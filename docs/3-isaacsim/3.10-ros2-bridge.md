# ROS 2 Bridge

:::{admonition} 学习目标
:class: lead-goals

- 在 Isaac Sim 5.1 里启用 ROS 2 Bridge，知道它用的是自带的 ROS 2 库还是系统的，以及各自要设哪些环境变量
- 用 Action Graph 把时钟、关节状态、TF、相机发成 ROS 2 话题，并从话题接收关节指令驱动 Galbot
- 说清话题频率与物理步、渲染步的关系，以及外部节点为什么要开 `use_sim_time`
:::

:::{admonition} 前置知识
:class: lead-prereq

- [3.1 仿真循环](3.1-sim-loop.md)（物理步与渲染步）
- [3.2 SimulationApp 与 Python 启动方式](3.2-simulation-app.md)
- 会用 `ros2 topic` 命令；本页不讲 ROS 2 本身
:::

ROS 2 Bridge 让 Isaac Sim 成为 ROS 2 网络里的一个普通节点：仿真里的状态以话题（topic）发出去，外部节点发来的指令写回仿真。本页用 Galbot 固定底座版做一个完整例子，示例代码在 `examples/isaaclab-2.3/3.10-ros2-bridge/`。它和 Isaac ROS（跑在真机上的 NVIDIA 加速 ROS 2 包）是两件事，区别见 [0.4](../0-map/0.4-isaac-names.md)。

## 它是什么、在哪

Bridge 是 Isaac Sim 的一个扩展 `isaacsim.ros2.bridge`（5.1.0 中版本 4.12.4）。它提供一组 OmniGraph 节点，每个节点负责一个话题、服务或辅助功能[^toml]。pip 安装时，它在 `site-packages/isaacsim/exts/isaacsim.ros2.bridge/` 下，`humble/` 和 `jazzy/` 两个子目录是自带的精简 ROS 2 库，`docs/ogn/` 下是每个节点的输入输出说明。

启用方式与其他扩展相同（[2.7](../2-usd-kit/2.7-extensions.md)）：GUI 里在 Extension Manager 勾选；standalone 脚本里在 `SimulationApp` 创建之后调用 `enable_extension("isaacsim.ros2.bridge")`，然后再导入 `isaacsim.ros2.*`，本页示例就是这样做的。用 `isaacsim` 命令打开的完整 GUI 体验文件在 Linux 上把设置 `isaac.startup.ros_bridge_extension` 写成了它，启动时由 `isaacsim.app.setup` 自动启用[^fullkit]；`SimulationApp` 默认用的 Python 体验文件不会，所以脚本里要自己启用。

## 用哪套 ROS 2 库

扩展启动时按下面的顺序决定用哪个 ROS 2 发行版（distro）[^ext]：

1. 读环境变量 `ROS_DISTRO`。没有设置时，读设置项 `ros_distro`（默认 `system_default`），在 Linux 上按 Ubuntu 版本选：22.04 → Humble，24.04 → Jazzy。
2. 起一个子进程，检查这套库能不能加载。加载失败时，打印需要设置的环境变量，然后关掉扩展。
3. 加载成功后，再加载 Python 的 `rclpy`：先试系统的，失败就用扩展自带的。

关键在第 2 步：C++ 动态库要在进程启动之前由 `LD_LIBRARY_PATH` 找到，扩展在 Linux 上不会替你设置[^common]。本站在 Ubuntu 22.04 上用同一个脚本、三种终端环境各跑了一次：

| 终端环境 | Bridge 启动 | Isaac Sim 内的 `rclpy` | 与系统 Humble 节点互通 |
|---|---|---|---|
| 没有任何 ROS 变量 | 失败：回退到自带 Humble，但库找不到；之后创建 ROS 2 节点时报 "unrecognized type" | — | — |
| 自带库：`ROS_DISTRO=humble`、`RMW_IMPLEMENTATION=rmw_fastrtps_cpp`、`LD_LIBRARY_PATH` 加上 `<扩展>/humble/lib` | 成功 | 自带的 `rclpy` 加载成功 | 是 |
| `source /opt/ros/humble/setup.bash` | 成功 | 系统的 `rclpy` 加载失败（它是 Python 3.10 编译的，Isaac Sim 是 3.11），自带的也被 `PYTHONPATH` 里的系统路径挡住 | 是 |

*表 1：三种终端环境下 Bridge 的表现（本站实测，Isaac Sim 5.1.0 pip，系统 ROS 2 Humble，2026-10-10）。*

两种可用的方式里，Action Graph 节点都工作正常，差别只在 Isaac Sim 进程里能不能用 Python 的 `rclpy`。所以：只用 Action Graph 时，source 系统 Humble 最省事；要在 Isaac Sim 的 Python 里写 ROS 2 节点时，用自带库那三行变量，并且不要 source 系统 Humble。两种方式下，系统 Humble 的 `ros2` 命令行都能直接看到 Isaac Sim 发出的话题：FastDDS 和 FastDDS 之间互通。

## 四类话题与一张 Action Graph

Action Graph 是 OmniGraph 的一种：图里的节点在收到执行信号时才运行。Bridge 的发布节点几乎都接同一个信号：`OnPlaybackTick` 在仿真播放时每次应用更新触发一次。本页的图用到这些节点（类型名以 5.1.0 的 `docs/ogn/` 为准）：

| 用途 | 节点类型 | 关键输入 |
|---|---|---|
| 触发 | `omni.graph.action.OnPlaybackTick` | — |
| 时间戳 | `isaacsim.core.nodes.IsaacReadSimulationTime` | 输出仿真时间，接到各发布节点的 `timeStamp` |
| ROS 2 上下文 | `isaacsim.ros2.bridge.ROS2Context` | `domain`；`useDomainIDEnvVar` 为真时读环境变量 `ROS_DOMAIN_ID` |
| 时钟 | `isaacsim.ros2.bridge.ROS2PublishClock` | `topicName`（`clock`） |
| 关节状态 | `isaacsim.ros2.bridge.ROS2PublishJointState` | `targetPrim`：Articulation 根 |
| TF | `isaacsim.ros2.bridge.ROS2PublishTransformTree` | `targetPrims`；`parentPrim` 不填时父坐标系是 `world` |
| 相机 | `isaacsim.core.nodes.IsaacCreateRenderProduct` → `isaacsim.ros2.bridge.ROS2CameraHelper`（`type` = `rgb`）与 `ROS2CameraInfoHelper` | `cameraPrim`、分辨率、`frameId` |
| 关节指令 | `isaacsim.ros2.bridge.ROS2SubscribeJointState` → `isaacsim.core.nodes.IsaacArticulationController` | 订阅节点输出关节名与位置 / 速度 / 力矩指令，控制器按 `robotPath` 写入 |

*表 2：示例用到的节点。*

在 GUI 里可以从 *Window → Graph Editors → Action Graph* 新建一张图，把这些节点拖进去连线；*Tools → Robotics → ROS 2 OmniGraphs* 菜单能一键生成时钟、关节状态、TF、相机等常用的图[^shortcut]。脚本里用 `og.Controller.edit` 一次写出整张图，下面是只发时钟的最小版本，完整的图见示例的 `build_graph()`：

```python
import omni.graph.core as og

keys = og.Controller.Keys
og.Controller.edit(
    {"graph_path": "/World/ros2_graph", "evaluator_name": "execution"},
    {
        keys.CREATE_NODES: [
            ("tick", "omni.graph.action.OnPlaybackTick"),
            ("sim_time", "isaacsim.core.nodes.IsaacReadSimulationTime"),
            ("context", "isaacsim.ros2.bridge.ROS2Context"),
            ("pub_clock", "isaacsim.ros2.bridge.ROS2PublishClock"),
        ],
        keys.CONNECT: [
            ("tick.outputs:tick", "pub_clock.inputs:execIn"),
            ("sim_time.outputs:simulationTime", "pub_clock.inputs:timeStamp"),
            ("context.outputs:context", "pub_clock.inputs:context"),
        ],
        keys.SET_VALUES: [("pub_clock.inputs:topicName", "clock")],
    },
)
```

Galbot 的 Articulation 根不在 `/World/galbot` 本身：Isaac Lab 2.3.2 的转换器把 `ArticulationRootAPI` 加在 `/World/galbot/root_joint` 上（本站实测）。示例按 API 查找根，没有写死路径；关节状态、TF 和控制器都要指向这个根。

## 从 ROS 2 控制 Galbot

订阅节点把收到的 `JointState` 拆成关节名和指令，`IsaacArticulationController` 按关节名把指令写成这几个关节的位置目标。从外部发一条：

```bash
ros2 topic pub --once /joint_command sensor_msgs/msg/JointState \
    "{name: [left_arm_joint1, head_joint1], position: [1.0, 0.5]}"
```

示例每仿真秒打印一次 `left_arm_joint1`：发出指令后的第一次打印是中间值：本站是 0.054 rad，校验方复跑是 0.155 rad，取决于指令落在两次打印之间的哪一刻。第二次打印已是 1.000 rad，也就是说 2 s 仿真时间之内从 0.004 rad 到了 1.000 rad。机器人用 6.1.2 转换时写进 USD 的 PD 增益（400 N·m/rad）跟踪目标。

![左：发指令前；右：发指令后，头部转了 0.5 rad，左臂第一个关节转到 1.0 rad](../_static/img/3.10-joint-command.jpg)

*图 2：从 `/camera/rgb` 收到的两帧（本站实测，仿真时间 68.95 s 与 81.28 s）。截图脚本 `grab_frame.py` 是一个普通的系统 ROS 2 节点。*

这就是"外部控制器驱动仿真机器人"的最小闭环。把 `ros2 topic pub` 换成你的控制节点或策略节点，结构不变；第 6 部分的 [6.7.2](../6-galbot/7-deploy/6.7.2-ros2-closed-loop.md) 会把 Isaac Lab 训练的策略放到这个位置。

## 时序与频率

图由 `OnPlaybackTick` 触发，每次应用更新执行一次，也就是每次 `world.step(render=True)` 执行一次。本例物理步 1/120 s、渲染步 1/60 s，一次 `step(render=True)` 推进 2 个物理步（[3.1](3.1-sim-loop.md#时间参数)），所以每个话题在每 1/60 s 仿真时间发一次。

外部用 `ros2 topic hz` 测到的是墙上时间的频率：

| 话题 | 墙上时间频率 | 每秒仿真时间的消息数 |
|---|---|---|
| `/clock`、`/joint_states` | 77.3–77.7 Hz | 60 |
| `/camera/rgb` | 约 60 Hz（三次实测 57–62 Hz） | — |

*表 3：话题频率（本站实测，RTX 5070，640×480 相机，2026-10-10）。这次仿真比实时快 1.28 倍（89 s 仿真时间用了 69.6 s 墙上时间），77 Hz ≈ 60 × 1.28。不建相机时，3 s 仿真时间只用 0.89 s，频率还会更高。*

所以墙上时间的频率随机器负载变化，不能拿来当控制周期。外部节点要按仿真时间工作，就要开 `use_sim_time`：开了之后，节点的时钟读 `/clock`。本站用 `sim_time_probe.py` 对比了同一时刻的两个节点：

```text
use_sim_time=False node_now=1791608083.740 s | wall 8.0 s: 612 joint_states, stamp span 10.18 s
use_sim_time=True  node_now=66.467 s         | wall 8.0 s: 613 joint_states, stamp span 10.20 s
```

不开时，节点的"现在"是系统时间，而消息时间戳是几十秒的仿真时间。TF 查询、消息同步、超时判断都会因此对不上。8 s 墙上时间里收到的消息覆盖了约 10.2 s 的仿真时间，说明两种时钟走的速度也不一样。

## Isaac Lab 2.3.2 与 ROS 2

Isaac Lab 2.3.2 本身不带 ROS 2 集成。依据如下：
- 它的 Python 源码里没有任何 `rclpy` 或 ROS 2 的调用。唯一带 "ROS" 字样的是装配任务的一个配置，它只是给外部推理节点准备参数[^lab-ros]。
- 它的文档把 ROS 2 支持归在 Isaac Sim 名下[^ecosystem]。
- 仓库里的 `docker/Dockerfile.ros2` 只是在容器里装上 ROS 2 Humble[^docker]。

也就是说，在 Isaac Lab 里用 ROS 2，要么像本页这样启用 Isaac Sim 的 Bridge，要么自己写 `rclpy` 节点。要把训练好的策略当作外部 ROS 2 节点运行，这座桥需要自己搭，见 [6.7.2](../6-galbot/7-deploy/6.7.2-ros2-closed-loop.md)。

## 常见坑

:::{admonition} 坑一：终端里没设 ROS 变量，Bridge 静默关掉
:class: warning

没有 `ROS_DISTRO` 时，扩展回退到自带 Humble，但 `LD_LIBRARY_PATH` 里没有自带库的路径，于是启动失败并关掉自己。之后脚本创建 Bridge 节点时报 `Could not create node using unrecognized type 'isaacsim.ros2.bridge.ROS2Context'`（本站实测）。看到这个报错，先往日志上面找 `ROS2 Bridge startup failed`，再按表 1 设好环境变量后重启进程。
:::

:::{admonition} 坑二：source 了系统 Humble，Isaac Sim 里的 rclpy 用不了
:class: warning

Humble 的 `rclpy` 是给 Python 3.10 编译的，Isaac Sim 5.1 是 Python 3.11。source 之后，`PYTHONPATH` 里的系统路径排在前面，自带的 `rclpy` 也被挡住，日志里出现两次 `Could not import ... rclpy`（本站实测）。Action Graph 不受影响；要在 Isaac Sim 进程里写 Python 节点，就换成表 1 的自带库方式，并开一个没 source 过的终端。
:::

:::{admonition} 坑三：用 step(render=False) 推进，话题不发
:class: warning

`OnPlaybackTick` 跟着应用更新走，而 `world.step(render=False)` 只推进物理，不触发应用更新。本站用 `--physics-only` 跑了 3000 s 仿真时间，话题都在列表里（`world.reset()` 那一次更新创建了它们），但 `ros2 topic echo --once /clock` 10 s 内一条消息也收不到。需要 Bridge 时用 `step(render=True)`，或者换用按物理步触发的节点（推断，本站未测）。
:::

:::{admonition} 坑四：ROS_DOMAIN_ID 不一致，两边互相看不见
:class: warning

把 Isaac Sim 进程的 `ROS_DOMAIN_ID` 设成 7，默认域的终端里 `ros2 topic list` 只有 `/parameter_events` 和 `/rosout`（本站实测）。两边要设同一个值。用 7.1 的远程方式时，跨机器还要考虑网络和 DDS 发现的设置（[7.1](../7-infra/7.1-headless-remote.md)）。
:::

:::{admonition} 坑五：外部节点没开 use_sim_time
:class: warning

见上一节的对比：节点时间与消息时间戳差了五十多年，TF 查询和 `message_filters` 的时间同步都会对不上（推断，本站未单独测）。所有要和 Isaac Sim 对时的节点都加 `--ros-args -p use_sim_time:=true`。
:::

另外，扩展有一项设置 `publish_without_verification`，默认 `false`。注释的意思是：没有订阅者时，发布节点不发布[^toml]。所以只用 `ros2 topic list` 能看到话题，不代表它在发消息；要测频率，就得有一个订阅者在线（`ros2 topic hz` 本身就是订阅者）。
