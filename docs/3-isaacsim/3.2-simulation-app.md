## standalone 脚本的骨架

这一节回答：一个独立运行的 Isaac Sim 脚本长什么样？

standalone 脚本用 `python xxx.py` 直接运行，自己掌控物理与渲染节奏，适合训练与批量生成数据[^sim-workflows]。骨架固定为五步：

```python
from isaacsim import SimulationApp                    # ① 只导入这一个
simulation_app = SimulationApp({"headless": True})    # ② 启动 Kit

from isaacsim.core.api import World                   # ③ 之后才能导入 isaacsim.* / omni.* / pxr
...                                                   # ④ 建场景、reset、循环 step
simulation_app.close()                                # ⑤ 退出
```

**为什么顺序不能换？** Isaac Sim 的功能分散在几百个 Kit 扩展里，每个扩展的 Python 模块在它被 Kit 加载时才加入搜索路径。`import isaacsim` 本身只把 `SimulationApp` 所在的扩展（以及旧名 `omni.isaac.kit`）加入 `sys.path`[^sim-init]；其余模块要等 `SimulationApp` 启动 Kit、加载完扩展之后才找得到。提前导入会报 `ModuleNotFoundError`，并打印一段警告，说明这是 Carbonite 扩展与插件系统的要求[^sim-init]。本站实测：未启动 Kit 时 `from isaacsim.core.api import World` 报 `No module named 'isaacsim.core'`。这也是 [1.9](../1-env/1.9-install-troubleshooting.md) 中 `No module named 'omni'` 一条的根源。

## Isaac Lab 的等价物：AppLauncher

这一节回答：Isaac Lab 的脚本为什么不直接用 SimulationApp？

Isaac Lab 用 `AppLauncher` 包装了 `SimulationApp`。它多做的事情[^lab-launcher]：

- **加命令行参数**：`AppLauncher.add_app_launcher_args(parser)` 往你的 argparse 里加入一组参数（见下文"启动参数"）；也可以用环境变量 `HEADLESS`、`LIVESTREAM`、`ENABLE_CAMERAS` 设置。
- **选体验文件**（experience，即 `.kit` 文件，决定加载哪些扩展和设置）：

| 条件 | 加载的体验文件（`IsaacLab/apps/`） |
|---|---|
| `--headless` | `isaaclab.python.headless.kit` |
| 不加 `--headless`（GUI） | `isaaclab.python.kit` |
| `--enable_cameras` 且 headless | `isaaclab.python.headless.rendering.kit` |
| `--enable_cameras` 且 GUI | `isaaclab.python.rendering.kit` |
| `--experience <文件>` | 用你指定的文件 |

*表 1：AppLauncher 选择体验文件的规则（XR 模式另有两个文件，此处从略）[^lab-exp]。headless 体验文件关闭了限速，见 [3.1](3.1-sim-loop.md)。*

- **启动期间静音**：创建 `SimulationApp` 的过程中，它把 `sys.stdout` 暂时指向 `/dev/null`，除非传了 `--verbose` 或 `--info`[^lab-create]。所以 Isaac Lab 脚本启动时终端比较安静。

## 两个最小示例

这一节回答：最短能跑通的写法是什么？

本站示例目录 `examples/isaaclab-2.3/3.2-simulation-app/` 中有两个脚本，做同一件事：一个 10 cm 的方块从 1 m 高处落到地面，2 秒后打印高度。

- `isaacsim_minimal.py`：只用 Isaac Sim，`SimulationApp` + `World`。
- `isaaclab_minimal.py`：用 `AppLauncher` + Isaac Lab 的 `SimulationContext` 与 `RigidObject`。

Isaac Lab 版的启动部分：

```python
parser = argparse.ArgumentParser(description="最小的 Isaac Lab standalone 脚本")
AppLauncher.add_app_launcher_args(parser)
args = parser.parse_args()
app_launcher = AppLauncher(args)
simulation_app = app_launcher.app

import isaaclab.sim as sim_utils                      # Kit 启动后再导入
from isaaclab.assets import RigidObject, RigidObjectCfg
```

两个脚本都用 `step(render=False)` 推进物理，GUI 下每两步另调一次 `render()` 刷新画面。不用 `step(render=True)`：它一次推进一个 `rendering_dt`，同样的循环次数下仿真时长会翻倍（见 [3.1 时间参数](3.1-sim-loop.md#时间参数)）。逻辑都写在 `main()` 里，结尾是同样的三行：

```python
    sim.clear_all_callbacks()                         # main() 的最后：释放仿真上下文
    sim.clear_instance()
...
main()
sys.stdout.flush()                                    # 输出重定向时不丢
simulation_app.close()
```

本站实测（2026-09-30，RTX 5070，headless，均正常退出，返回码 0）：

| 命令 | 输出 | 总耗时 |
|---|---|---|
| `python isaacsim_minimal.py` | `sim time 2.02 s, cube z = 0.050 m` | 约 11 秒 |
| `python isaaclab_minimal.py --headless` | 同上 | 约 5 秒 |
| `python isaaclab_minimal.py --headless --device cpu` | 同上 | 约 5 秒 |

*表 2：两个示例的实测结果。方块停在 0.05 m（边长的一半），即落到了地面上。耗时含 Kit 启动，缓存已预热。*

## 启动参数

这一节回答：headless、分辨率、设备这些怎么设？

| 想做的事 | Isaac Sim（`SimulationApp` 配置字典） | Isaac Lab（命令行） |
|---|---|---|
| 不开窗口 | `{"headless": True}`（默认值即为 True） | `--headless` |
| 渲染分辨率 | `{"width": 1280, "height": 720}` | AppLauncher 没有分辨率参数，相机图像尺寸在相机配置里设 |
| 物理设备 | `World(device="cuda:0")` 等 | `--device cuda:0` / `--device cpu` |
| 启用相机渲染 | — | `--enable_cameras` |
| 远程查看画面 | — | `--livestream 1`（或 2） |
| 更多日志 | 命令行加 `--info` / `--verbose` | `--info` / `--verbose` |
| 任意 Kit 参数 | `{"extra_args": [...]}` | `--kit_args "--/app/xxx=1 --ext-folder=..."` |

*表 3：常用启动参数。`SimulationApp` 的全部配置项与默认值见源码[^sim-app-cfg]；AppLauncher 的参数定义见源码[^lab-args]，`--kit_args` 会被拆开追加到 `sys.argv`，由 Kit 读取[^lab-kitargs]。*

## 正常退出

这一节回答：脚本怎样才能干净地结束？

1. **释放仿真上下文**：用 Isaac Lab 的 `SimulationContext` 时，`close()` 之前要调用 `clear_all_callbacks()` 与 `clear_instance()`，Isaac Lab 的环境类在 `close()` 里也是这样做的[^lab-envclose]。本站实测：去掉这两行，`isaaclab_minimal.py` 在打印结果后卡在 `close()`，90 秒后被强制结束；而 Isaac Sim 的 `World` 版去掉后仍能正常退出。
2. **刷新输出**：`close()` 前调用 `sys.stdout.flush()`。Kit 退出时不刷新 Python 的输出缓冲，重定向到文件或管道时输出几乎全部丢失（本站实测：管道下脚本自身的输出只剩 1–2 行）。调试时也可以用 `python -u` 或设置 `PYTHONUNBUFFERED=1`，让输出不经缓冲。
3. **从外部结束**：Ctrl+C（SIGINT）可以结束，`SimulationApp` 注册了处理函数[^sim-sigint]；但 SIGTERM 会被忽略（本站实测：发 SIGTERM 60 秒后进程仍在），`timeout` 默认发的就是它。无人值守运行请用 `timeout -s KILL`，详见 [1.9](../1-env/1.9-install-troubleshooting.md)。

## GUI 里的 Script Editor 还是 standalone

这一节回答：两种写代码的方式各适合什么？

Isaac Sim 的 GUI 里有 Script Editor，代码在正在运行的应用里执行，Kit 掌控物理与渲染循环，适合试几行 API、边看边改场景。standalone 脚本由你决定何时推进物理、何时渲染，可以 headless 运行，适合训练和批量任务[^sim-workflows]。因此 Script Editor 里不要调用 `step(render=True)` 之类的方法，源码明确说明它们不适用于扩展工作流[^sim-step]。Isaac Lab 的训练与本站示例都是 standalone 方式。两层的分工见 [0.5 Isaac Sim 与 Isaac Lab 的边界](../0-map/0.5-sim-lab-boundary.md)。

## 常见坑

:::{admonition} 坑一：在 SimulationApp 之前导入了扩展模块
:class: warning

报 `ModuleNotFoundError`，并打印一段 "import statements must take place after the `SimulationApp` class has been instantiated" 的警告[^sim-init]。把所有 `isaacsim.*`、`omni.*`、`pxr` 以及 `isaaclab.sim` 等的导入移到创建 `SimulationApp`（或 `AppLauncher`）之后。
:::

:::{admonition} 坑二：脚本跑完不退出
:class: warning

用了 Isaac Lab 的 `SimulationContext`，却没在 `close()` 前调用 `clear_all_callbacks()` 与 `clear_instance()`（本站实测，见上文）。把它写在 `main()` 里，便于在退出前释放。
:::

:::{admonition} 坑三：输出重定向到文件后是空的
:class: warning

没在 `close()` 前 `sys.stdout.flush()`（本站实测）。用 Isaac Lab 时还要注意：启动阶段的输出被 `AppLauncher` 静音了[^lab-create]，要看启动日志请加 `--info`。
:::

:::{admonition} 坑四：用 SimulationContext 建的物体不动
:class: warning

用 Isaac Sim 的 `SimulationContext`（而不是 `World`）时，`DynamicSphere` 这类场景对象不会被自动初始化：调用 `reset()` 并推进 1200 步后，读到的位置与速度都没有变化；改用 `World` 并通过 `world.scene.add()` 加入后恢复正常（本站实测）。Isaac Sim 原生写法优先用 `World`；Isaac Lab 里用它自己的资产类（`RigidObject`、`Articulation`）。
:::

:::{admonition} 坑五：USD 里读到的位置不变
:class: warning

GPU 管线下，仿真结果不写回 USD 属性：方块下落后，Prim 上的 `xformOp:translate` 仍是初始值（本站实测，见 [3.1](3.1-sim-loop.md)）。读状态要用 `World` 中对象的接口或 Isaac Lab 资产的 `data`。
:::
