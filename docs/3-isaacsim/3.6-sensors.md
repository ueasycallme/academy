# 传感器

## 两类来源

Isaac Sim 的文档把传感器分成几组[^sim-sensors]，按数据从哪来，可以归成两类：

- **RTX 传感器**：相机、RTX 激光雷达（LiDAR）、雷达（radar）。它们由 RTX 渲染器算出来：给传感器建一个渲染产品（render product），再在上面挂标注器（annotator）取数据。没有渲染就没有新数据。激光雷达与雷达还能模拟非可见光材质（如透明、反光表面）的回波[^rtx][^rtx-ann]。另外，Isaac Lab 的渲染体验文件把 Replicator 的 orchestrator 关掉了（v2.3.2 `apps/isaaclab.python.headless.rendering.kit` L100–L101），在 AppLauncher 下用 Replicator 写入器要先重新打开它，见 [3.9 坑一](3.9-replicator.md#坑一在-isaac-lab-的-applauncher-下跑-replicator帧数失控)。
- **物理传感器**（physics-based sensor，Isaac Sim 文档的叫法）：接触、IMU、关节力、射线类激光雷达等。它们读物理引擎的状态，或用物理碰撞体做射线查询，不需要渲染，给出的是仿真内的"真值"[^physics][^physx-lidar]。

```{mermaid}
flowchart TB
    P["PhysX 物理步（每 dt）"] --> V["PhysX 张量视图"]
    V --> S["ContactSensor<br/>Imu<br/>FrameTransformer"]
    V -->|自身位姿| RC["RayCaster<br/>Warp 射线 × 静态网格"]
    P --> R["RTX 渲染<br/>（每 render_interval 步）"]
    R --> CAM["渲染产品 + 标注器<br/>Camera / TiledCamera"]
```

*图 1：Isaac Lab 传感器的数据路径（据 v2.3.2 源码整理，表 1 各行有出处）。经 PhysX 张量视图的几支不需要渲染；经 RTX 渲染的一支，只有渲染的那一步才有新图像。*

## Isaac Sim 机制与 Isaac Lab 类名

Isaac Lab 没有包装 Isaac Sim 的 `isaacsim.sensors.*` 扩展：相机直接调用 Replicator 的渲染产品与标注器，其余传感器直接用 PhysX 的张量视图（tensor view）或 Warp[^imports]。

| Isaac Lab 类 | 靠 Isaac Sim 的什么 | 要渲染 | 源码（v2.3.2） |
|---|---|---|---|
| Camera | 每台相机一个渲染产品 `rep.create.render_product`，按数据类型挂标注器 | 是 | [`camera.py` L439–L485][camera] |
| TiledCamera | 所有相机拼成一个渲染产品 `rep.create.render_product_tiled`，再用 Warp 切回每个环境 | 是 | [`tiled_camera.py` L180–L217、L270][tiled] |
| RayCaster | 初始化时把一个 USD 网格读成 Warp 网格，每次更新用 `raycast_mesh` 求交；自身位姿取自 PhysX 视图（不是刚体时退回 XFormPrim） | 否 | [`ray_caster.py` L164–L200、L300、L341–L384][raycaster] |
| RayCasterCamera | 同 RayCaster，射线按相机内参排布，输出深度图 | 否 | [`ray_caster_camera.py` L293][rccam] |
| ContactSensor | PhysX 张量 API 的刚体接触视图 `create_rigid_contact_view`，读 `get_net_contact_forces` | 否 | [`contact_sensor.py` L286、L373][contact] |
| Imu | PhysX 刚体视图读位姿与速度，加速度由相邻两次更新的速度差分得到 | 否 | [`imu.py` L164、L199–L219][imu] |
| FrameTransformer | PhysX 刚体视图读位姿，再算相对变换 | 否 | [`frame_transformer.py` L257、L377][frame] |

*表 1：Isaac Lab 传感器类与 Isaac Sim 机制的对应。*

Isaac Lab 2.3.2 里没有 RTX 激光雷达的类。要模拟真实激光雷达的材质效应，得直接用 Isaac Sim 的 `isaacsim.sensors.rtx`[^rtx]。

## 时序

传感器有两个"时钟"，读数据时都要想到：

- **物理传感器**跟物理步走。`scene.update(dt)` 每个物理步调用一次，满 `update_period` 就标记过期，读 `data` 时才算（4.8"懒更新"）[^update]。训练里通常每个控制步读一次观测，也就是每 `decimation` 个物理步算一次。
- **相机**跟渲染走。环境的 `step()` 里，第 k 个物理步之后，若 k 是 `sim.render_interval` 的整数倍（且有 GUI 或 RTX 传感器）就渲染一次[^render]。相机的 `data` 读的是标注器里最近一次渲染的结果。

所以"这一帧相机图像是哪个物理步的"，答案是：**最近一次 `render()` 之前的那个物理步**。主线设 `render_interval = decimation`（[4.4](../4-isaaclab/4.4-simulation-context.md)），渲染发生在每个控制步的最后一个物理步之后，图像与同一步的物理观测对得上。两个例外：

- `render_interval` 小于 `decimation` 时，一个控制步里渲染多次，只有最后一次的结果被读到，其余的白花；大于时，有的控制步读到的是上一个控制步的旧图。
- 重置的环境：重置发生在本步渲染之后，默认 `num_rerenders_on_reset = 0`，这些环境读到的是重置前的画面。设成大于 0 会在重置后补渲染，代价是每次重置多渲染几次[^rerender]。

## 代价

相机的代价见 4.8 表 3 与 6.2.2"代价"：建了相机，进程就多出约 2 GB 显存，每步还要加渲染时间；显存预算见 [1.3](../1-env/1.3-hardware.md)。这里只补三种不渲染的传感器。

示例 `examples/isaaclab-2.3/3.6-sensors/cheap_sensors.py` 在每个环境里放一个从 2 m 落下的方块，三种传感器都装在方块上：RayCaster（向下 11 × 11 = 121 条射线，只对地面求交）、Imu、ContactSensor。

```bash
python cheap_sensors.py --headless                  # 1024 个环境
python cheap_sensors.py --headless --no_sensors     # 对照：不建传感器
python cheap_sensors.py --headless --imu_history 1  # Imu 每个物理步都更新（误解三）
```

预期输出（本站实测，2026-10-11，1024 个环境，物理步 1/120 s，不渲染）：

```text
[3.6] RayCaster：update_period 0.0；pos_w (1024, 3)，quat_w (1024, 4)，ray_hits_w (1024, 121, 3)
[3.6] Imu：update_period 0.0；… lin_vel_b (1024, 3)，ang_vel_b (1024, 3)，lin_acc_b (1024, 3)，ang_acc_b (1024, 3)
[3.6] ContactSensor：update_period 0.0；net_forces_w (1024, 1, 3)，net_forces_w_history (1024, 1, 1, 3)
```

| 每个物理步读一次 | 每个物理步 | 比"不读"多 |
|---|---|---|
| 不建传感器（对照） | 0.806 ms | — |
| 建了，不读 | 0.874 ms | 0 |
| 读 RayCaster（121 条射线） | 1.700 ms | +0.83 ms |
| 读 Imu | 1.373 ms | +0.50 ms |
| 读 ContactSensor | 1.062 ms | +0.19 ms |

*表 2：三种传感器的每步代价（本站实测，各 300 个物理步、三轮交替取中位数，RTX 5070 12 GB）。*

这里故意每个物理步都读，是最坏情况；训练中每个控制步读一次，代价要再除以 decimation。与相机比，这些都是零头：4.8 表 3 里，4 个环境的 64×64 TiledCamera 每个物理步就要 7.7 ms。建了传感器、不读，每步只多 0.07 ms，这就是懒更新的效果（4.8）。

## 怎么选

| 用途 | 建议 |
|---|---|
| RL 观测（几百到几千个环境） | 先用物理传感器与 FrameTransformer：几乎不花时间，也没有噪声。要图像就用 TiledCamera，分辨率尽量小（4.8 表 3） |
| 数据采集（合成图像、标注） | 两种相机支持的数据类型相同（RGB、深度、法线、运动向量、语义 / 实例分割）[^cam-types]，按相机数量选，同上一行 |
| 调试可视化 | 传感器的 `debug_vis`；注意它会让懒更新失效，每步都算（4.8） |
| 模拟真实激光雷达 | Isaac Sim 的 RTX 激光雷达（Isaac Lab 2.3.2 没有对应类）；RayCaster 只适合高度图这类"对一个静态网格测距" |

*表 3：按用途选传感器（本站经验）。*

**TiledCamera 还是 Camera**：两者支持的数据类型与 `data` 字段相同，区别只在渲染方式。TiledCamera 把所有环境的相机拼成一张大图一次渲染，环境数从 4 增加到 256，每步只从 7.7 ms 涨到 10.9 ms；Camera 逐台渲染，64 个环境时慢 13 倍（4.8 表 3）。相机多时用 TiledCamera。只有一两台相机（例如单环境调试、离线录制）时，两者差别不大。

## 常见误解

### 误解一："RayCaster 就是激光雷达"

RayCaster 只对配置里的**一个**网格求交，而且按初始化时读到的形状处理，之后网格动了也不知道[^raycast-mesh]。机器人、方块这些动态物体它看不见。射线可以按 `LidarPatternCfg` 排成激光雷达的样子，但看不见动态物体这一点不变。它适合地形高度图；模拟激光雷达要用 RTX 激光雷达。

### 误解二："ContactSensor 能读出力矩"

`data` 里是接触力：`net_forces_w`（每个刚体的合力），配了过滤对象时还有 `force_matrix_w`（按对象分开的力），都是三维的力，没有力矩[^contact-data]。要关节力矩，读 Articulation 的 `data.applied_torque` 等字段，或者用 Isaac Sim 的关节力传感器。

### 误解三："Imu 的加速度和真机 IMU 一样"

Imu 的线加速度不是测量值：它用两次更新之间的速度差除以 `dt` 算出，再加上重力偏置 `gravity_bias`（默认 (0, 0, 9.81)），没有噪声与零偏（bias）[^imu-acc]。这里有个坑：`dt` 是最近一个物理步的步长，而"两次更新之间"是两次**读 `data`** 之间。示例让方块自由下落，理想读数是 0：

```text
[3.6] 自由落体，每 1 个物理步读一次 IMU：lin_acc_b z 的读数（m/s²）第 1 次 +0.00，其余 -0.00 … +0.00（47 次）
[3.6] 自由落体，每 4 个物理步读一次 IMU：lin_acc_b z 的读数（m/s²）第 1 次 -29.43，其余 -29.43 … -29.43（11 次）
```

每 4 步读一次时，速度差是 4 个物理步攒下的，却只除以 1 个物理步：−4 × 9.81 + 9.81 = −29.43。decimation 为 4 的环境每个控制步读一次观测，就是这种情况。要用加速度做观测，就让 Imu 每个物理步都更新：给它设 `history_length > 0`（本站实测：`--imu_history 1` 时每 4 步读一次，读数也是 0.00），或者让场景 `lazy_sensor_update=False`（同一机制，本站未单独测）[^update]。角加速度 `ang_acc_b` 也是这样差分出来的（同一段代码），同样受影响；角速度、`projected_gravity_b` 不受影响：它们是当时的状态，不是差分。

上游已经改了：develop 分支先在 #6439（2026-08-10）改为除以两次采样之间的实际时间，再在 #7416（2026-09-05）改为直接读 PhysX 的 `get_accelerations()`；v3.0.0（及更早的 EA）的 Imu 已经是后者[^imu-up]。v2.3.2 仍是本页描述的差分。

### 误解四："传感器都在 Isaac Sim 的 sensors 扩展里"

Isaac Sim 的 `isaacsim.sensors.physics` 也有接触与 IMU 传感器，但 Isaac Lab 没有用它们。Isaac Lab 的同名类直接读 PhysX 张量视图（表 1）。两套的配置和时序都不同，查文档时别混看。
