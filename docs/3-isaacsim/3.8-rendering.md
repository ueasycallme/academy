## 仿真与渲染是两件事

物理步推进的是状态（位姿、速度、接触），渲染把当前状态画成图像。只要不需要图像，就可以不渲染：

| 场景 | 要渲染吗 |
|---|---|
| 纯状态观测的 RL（主线 reach） | 不要 |
| 相机观测、录训练视频、截图 | 要 |
| 用 Replicator 生成合成数据（[3.9](3.9-replicator.md)） | 要 |

*表 1：什么时候需要渲染。*

Isaac Lab 的环境步里，只有"有 GUI"或"场景里有 RTX 传感器（相机）"时才在物理子步之间调用 `render()`，频率由 `render_interval` 决定（[4.4](../4-isaaclab/4.4-simulation-context.md)）[^env-render]。所以 `--headless` 且不带 `--enable_cameras`、场景里也没有相机时，根本不渲染。带了 `--enable_cameras` 但不建相机，环境步同样不渲染，只是进程多加载了渲染相关的东西，显存与内存会多占（[7.2](../7-infra/7.2-profiling.md)）。

## 两种渲染模式

| 模式 | `/rtx/rendermode` | 用途 | 代价 |
|---|---|---|---|
| RTX 实时 | `RaytracedLighting` | 交互、相机观测、批量出图 | 低：每帧固定的采样与去噪 |
| 路径追踪（Path Tracing） | `PathTracing` | 需要更接近物理的光照时，如参考图像 | 高：采样数（`/rtx/pathtracing/spp`、`totalSpp`）越多越慢 |

*表 2：两种渲染模式。设置值见 Replicator 的 `set_render_rtx_realtime` / `set_render_pathtraced`[^rep-settings]；路径追踪的采样设置见 Omniverse 文档[^pt]。*

Isaac Lab 的渲染体验文件默认是 `RaytracedLighting`（本站读回）。Isaac Sim 5.1.0 自带的渲染设置面板把三个取值对应为：`RaytracedLighting` → "Real-Time"，`PathTracing` → "Interactive (Path Tracing)"，`RealTimePathTracing` → "Real-Time 2.0"[^rtx-ui]。所以默认用的是 Omniverse 当前文档里标为 "RTX Real-Time (Legacy)" 的那种实时模式，不是 "Real-Time 2.0"[^rtx]。

切换方式：

- **脚本**：起 Kit 之后，`carb.settings.get_settings().set_string("/rtx/rendermode", "PathTracing")`；
- **Isaac Lab 配置**：`SimulationCfg.render` 的 `rendering_mode`（`performance` / `balanced` / `quality` 三组预设，来自 `apps/rendering_modes/*.kit`）与 `carb_settings`（任意设置）[^lab-render]；
- **GUI**：视口上方的渲染模式下拉框。

## 代价实测

同一个场景（Galbot、桌子、穹顶光）、同一台 640×480 相机，每个物理步都渲染一次，热身 30 步后计 120 步，每种跑两次：

```bash
python scripts/render_cost.py --headless --mode none
python scripts/render_cost.py --headless --enable_cameras --mode rt
python scripts/render_cost.py --headless --enable_cameras --mode pt     # 每帧 1 个采样
```

| 情况 | 每个物理步 | 按进程显存 | 主机 RSS 峰值 |
|---|---|---|---|
| ① 不渲染（headless，无相机） | 8.37–8.43 ms | 2299 MiB | 3.1 GB |
| ② RTX 实时 | 14.94–15.14 ms | 4618 MiB | 6.3 GB |
| ③ 路径追踪，1 spp | 21.30–22.32 ms | 5075 MiB | 6.4 GB |

*表 3：渲染的代价（本站实测，2026-10-11，同一时段交替运行，两次的范围）。*

在这个场景、这个分辨率下：开实时渲染，每步多约 6.6 ms，显存多约 2.3 GB；换成 1 spp 的路径追踪，比实时再多约 6.8 ms、0.46 GB。路径追踪的采样数提高后会更慢，本页只测了 1 spp。显存的大头是"加载了渲染"本身，与 4.8 表 3 的观察一致。训练时环境每个控制步渲染一次，摊到每个物理步要除以 decimation。

## 材质与光照

**材质**：Omniverse 的材质主要用 MDL（Material Definition Language，材质定义语言）描述外观，OmniPBR 是它的标准材质模板之一[^materials]。在 USD 里，材质是一个 `UsdShade.Material` Prim，几何体通过 `material:binding` 关系指向它（[2.2](../2-usd-kit/2.2-usd-concepts.md#propertyattribute-与-relationship)），与物理属性靠 schema 挂在 Prim 上是同一种思路（[2.4](../2-usd-kit/2.4-physics-schema.md)）。

本项目从 URDF 转来的 Galbot，`render_cost.py` 读出身上有 144 个 `OmniPBR.mdl` 着色器、114 个 `pbr.mdl` 着色器（本站读回，遍历时要用 `Usd.TraverseInstanceProxies()`，因为视觉网格在实例里）。

**缺材质时**：`--broken_mdl` 在桌上放一个方块，材质指向不存在的 `does_not_exist.mdl`。日志报 `C120 could not find module '::does_not_exist'`，方块渲染成纯红色（本站实测）。官方文档没写缺 MDL 时的画面，常说的"粉色"本站没有复现。看到场景颜色异常，先在日志里搜 `MDL` 或 `could not find module`。Omniverse 文档还提醒，MDL 路径要写绝对路径或以 `./` 开头的相对路径才能正确解析[^materials]。

**光源**：Isaac Lab 提供穹顶光（`DomeLightCfg`，从四面八方照，相当于环境光）、平行光（`DistantLightCfg`，太阳光那样的方向光）、球光（`SphereLightCfg`，点状光源）等配置类[^lights]。主线的场景只有一盏穹顶光，在 6.2.1 的场景配置里（[6.2.1](../6-galbot/2-scene/6.2.1-workbench-scene.md)）。

## 常见坑

### 坑一：训练纯状态策略时误开了渲染

只要 `--enable_cameras`，进程就会加载渲染：即使不建相机，显存与内存也多占（7.2）。建了相机，每步还要加上渲染时间（表 3 中 +6.6 ms，接近物理本身的 8.4 ms）。纯状态训练不要带这个参数，也不要在场景里留调试用的相机。

### 坑二：读不到机器人的材质

机器人的视觉网格在实例里，`stage.Traverse()` 不进实例，数出来是 0 个材质。本站第一版就是这样，要用 `Usd.TraverseInstanceProxies()`。

### 坑三：颜色不对，先查材质加载

缺 MDL 时画面不会报错退出，只是颜色变了（本站是纯红色）。错误只在日志里，属于 `rtx.neuraylib` 与 `omni.usd` 的 `USD_MDL` 两条。

### 坑四：以为 headless 下第一帧是黑的

本站 headless 下 `sim.reset()` 后第一次渲染，第 1 帧的平均亮度是 154（0–255），与之后各帧相当，不是黑的。截图发黑时，先确认那一步确实渲染了，即 `sim.step(render=True)` 或环境步里有相机，再怀疑时序。
