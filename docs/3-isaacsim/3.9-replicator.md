本页的 Replicator 指 `omni.replicator.core` 这个合成数据框架，保留英文原名。它与 [3.7](3.7-cloner.md) 里克隆环境用的"复制器"（Cloner 的 replicate_physics）是两回事。

**本页新增示例**：`examples/isaaclab-2.3/3.9-replicator/`（`synth_data.py`、`make_mosaic.py`、README）。

## Replicator 是什么

Replicator 把三件事串成一条流水线：随机化场景、经渲染产品与标注器取出图像和标注、用写入器（writer）存盘[^rep-api]。取数据的底层就是 3.6 讲的渲染产品 + 标注器，Isaac Lab 的相机类用的也是这一套。

| | 随机化什么 | 谁来管 | 在哪一步生效 |
|---|---|---|---|
| Isaac Lab 事件项（6.4.2） | 质量、增益、摩擦、初始状态、观测噪声 | Event Manager | 环境 reset 或间隔触发，影响物理 |
| Replicator 随机化器 | 物体位姿、颜色与材质、光照、相机 | Replicator 的触发器（trigger） | 每生成一帧前，影响画面 |

*表 1：两种随机化的分工。训练视觉策略时两者可以都用：物理随机化让策略对动力学鲁棒，画面随机化让它对外观鲁棒。*

## 四步

示例在 6.2.1 那张桌子上放 3 个 5 cm 方块，用一台在桌角斜上方的相机拍。没有用 6.2.2 的腕部相机：那要跟随手臂运动，就得有 Isaac Lab 环境，本页只做独立脚本（见"与 Isaac Lab 环境共用"）。

```python
with rep.trigger.on_frame(max_execs=args.frames):          # ① 随机化：每生成一帧触发一次
    with cubes:
        rep.modify.pose(position=rep.distribution.uniform(...), rotation=rep.distribution.uniform(...))
        rep.randomizer.color(colors=rep.distribution.uniform((0.1,) * 3, (1.0,) * 3))
    with light:
        rep.modify.attribute("inputs:intensity", rep.distribution.uniform(300.0, 2000.0))
render_product = rep.create.render_product(camera, (640, 480))   # ② 渲染产品
writer = rep.WriterRegistry.get("BasicWriter")                    # ③④ 写入器打开标注器并写盘
writer.initialize(output_dir=out, rgb=True, semantic_segmentation=True, bounding_box_2d_tight=True,
                  colorize_semantic_segmentation=True)
writer.attach([render_product])
rep.orchestrator.run_until_complete(num_frames=200)              # 生成 200 帧后返回
```

`BasicWriter` 每帧写下面这些文件，`frame_padding` 默认 4 位[^basicwriter]：

| 文件 | 格式 | 内容 |
|---|---|---|
| `rgb_0000.png` | PNG，RGBA | 渲染图（本例第 0 帧 140 KB，200 帧平均 176 KB） |
| `semantic_segmentation_0000.png` | PNG，按类别着色 | 每个像素的类别 |
| `semantic_segmentation_labels_0000.json` | JSON | 颜色 → 类别，含 `BACKGROUND`、`UNLABELLED` |
| `bounding_box_2d_tight_0000.npy` | NumPy 结构化数组 | 每个物体一行：`semanticId`、`x_min`、`y_min`、`x_max`、`y_max`、`occlusionRatio` |
| `bounding_box_2d_tight_labels_0000.json` | JSON | `semanticId` → 类别 |
| `bounding_box_2d_tight_prim_paths_0000.json` | JSON | 每个框对应的 prim 路径 |

*表 2：`BasicWriter` 的输出（本站实测，另有一个 `metadata.txt`）。*

**与仿真步的关系**：Replicator 的 orchestrator 自己推进 Kit 的更新（[3.1](3.1-sim-loop.md)）。`run_until_complete(num_frames=N)` 生成 N 帧后返回；`step()` 一次生成一帧，适合每帧之间还要改场景的脚本[^rep-api]。示例默认用前者，`--mode step` 用后者。生成完后，先 `writer.detach()`、销毁渲染产品，再 `wait_until_complete()` 等后台写盘结束，顺序同官方入门示例[^getting-started]。

## 语义标签

分割和框只认带语义标签的 prim。示例用了两种打法：

- **写 USD 属性**：`isaacsim.core.utils.semantics.add_labels(prim, ["cube"])`，写的是 `UsdSemantics.LabelsAPI`。任何能改 USD 的代码都能用，标签随文件保存；
- **`rep.modify.semantics`**：在 Replicator 的图里打，适合对随机生成的一批物体统一打标签。

`--no_labels` 不打标签，跑 5 帧：分割里只有 `BACKGROUND` 与 `UNLABELLED` 两类，框是 0 个，图像照常生成。不报错，只是标注是空的。

```bash
python synth_data.py --frames 200 --out /tmp/synth
```

```text
[3.9] run_until_complete：200 帧，640×480，总计 3.1 s，平均每帧 16 ms；按进程显存 2182 MiB
[3.9] 输出 1201 个文件、35.7 MiB：bounding_box_2d_tight ×200，…，rgb ×200，semantic_segmentation ×200，…
```

200 帧、三种标注，总计 3.1 s，平均每帧 16 ms，输出 1201 个文件、约 36 MiB，按进程显存 2182 MiB（本站实测，2026-10-11，不含启动 Kit 的时间）。场景很简单，复杂场景、更高分辨率、路径追踪都会更慢。

## 与 Isaac Lab 环境共用

本页只做独立脚本。原因是本站实测发现：**Isaac Lab 的渲染体验文件关掉了 Replicator 的 orchestrator**（`exts."omni.replicator.core".Orchestrator.enabled = false`，注释写的是为了运行性能）[^lab-kit]。同一个脚本、同样生成 3 帧，只换启动方式：

| 启动方式 | 输出 |
|---|---|
| Isaac Sim 的 `SimulationApp`（示例默认） | 19 个文件（3 帧 × 6 + `metadata.txt`） |
| Isaac Lab 的 `AppLauncher`（`enable_cameras=True`） | 失控：几秒内写出 3519 个文件，到 43 MiB 时被本站的磁盘上限停掉 |
| `AppLauncher`，加 `kit_args="--/exts/omni.replicator.core/Orchestrator/enabled=true"` | 19 个文件，恢复正常 |

*表 3：只改启动方式的对照（本站实测；日志保留，失控的数据已删）。*

所以要在 Isaac Lab 进程里用 Replicator 采数据，得把这个设置重新打开。重新打开后，`ManagerBasedRLEnv` 与 Replicator 能否在同一个进程里一起正常工作，包括渲染产品是否共享、对训练速度的影响，本站没有测。

## 常见坑

### 坑一：在 Isaac Lab 的 AppLauncher 下跑 Replicator，帧数失控

见表 3。本站第一次就是这样跑的：要 5 帧，90 秒写出约 7.5 万帧、13 GB。生成数据的脚本最好给输出目录设一个磁盘上限，再加超时：超时管不住磁盘，按内存的保护也管不到磁盘。

### 坑二：`run()` 是异步的

`rep.orchestrator.run(num_frames=50)` 立即返回（本站 0.67 s）。脚本接着就退出时，一个文件都没写出来（本站实测：输出目录为空）。要么用 `run_until_complete()`，要么在退出前 `wait_until_complete()`。

### 坑三：`look_at` 相机离场景太近时朝向不对

在桌子附近用 `rep.create.camera(position=…, look_at=…)` 放相机，本站两个近距离位置拍到的都不是桌面。读回相机 Xform，它的 -Z 轴在水平方向上与目标差约 180°。改用远处的位置加长焦（`focal_length=60`）后正常。原因没有查清（推断与相机子 prim 的附加旋转有关）。放好相机后，先渲一帧看一眼再批量生成。

### 坑四：没有标签，标注就是空的

见"语义标签"一节。分割图仍会生成，只是全部算 `UNLABELLED` 或背景，很容易当成"生成成功"。检查标签文件里有没有你的类别。
