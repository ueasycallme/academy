## Observation Manager：组与项

这一节回答：观测怎么拼成张量？

观测按**组**（group）组织，每组是一个 `ObservationGroupCfg` 子类，组里的每个字段是一个 `ObservationTermCfg`[^term-cfg]。`compute()` 返回一个字典，键是组名：

| 组的字段 | 默认 | 含义 |
|---|---|---|
| `concatenate_terms` | True | 把组内各项拼成一个张量；为 False 时返回 `{项名: 张量}` 字典 |
| `concatenate_dim` | -1 | 沿哪一维拼接（不含环境维），图像观测会用到 |
| `enable_corruption` | False | 是否加噪声；为 False 时，初始化阶段会把组内每项的 `noise` 置空 |
| `history_length` | None | 设置后覆盖组内每项的 `history_length` |

| 项的字段 | 默认 | 含义 |
|---|---|---|
| `func` / `params` | 必填 / {} | 观测函数及其参数，返回 (num_envs, 维度) |
| `modifiers` | None | 数据修饰器列表，如归一化、滑动平均 |
| `noise` | None | 噪声配置，见下文 |
| `clip` | None | (min, max)，加噪声之后裁剪 |
| `scale` | None | 标量或与维度等长的元组，裁剪之后相乘 |
| `history_length` | 0 | 保留过去几步；`flatten_history_dim=True`（默认）时展平为 (N, H×D) |

*表 1：观测组与观测项的配置字段（v2.3.2）[^term-cfg]。*

每一项按固定的流水线处理，然后拼接[^compute]：

```{mermaid}
flowchart LR
    F[func] --> M[modifiers] --> N[noise] --> C[clip] --> S[scale] --> H[history] --> K[拼接]
```

*图 1：单个观测项的处理顺序，自左向右。noise 仅在 `enable_corruption=True` 时生效，history 仅在 `history_length > 0` 时启用，最后按定义顺序拼接。先加噪声再裁剪和缩放，这样噪声的幅度对应物理量本身[^compute]。*

**拼接顺序就是项在类里的定义顺序**：Manager 按配置对象的 `__dict__` 遍历[^prepare]，在子类 `__post_init__` 里新加的项排在最后。Cartpole 的 `policy` 组是 `joint_pos_rel`（2）+ `joint_vel_rel`（2）= 4 维。

## 常用观测函数

这一节回答：`mdp` 里有哪些现成的观测？

| 函数 | 内容 | 形状 |
|---|---|---|
| `joint_pos_rel` | 关节位置减默认位置 | (N, 关节数) |
| `joint_vel_rel` | 关节速度减默认速度 | (N, 关节数) |
| `joint_pos_limit_normalized` | 关节位置归一化到 [-1, 1] | (N, 关节数) |
| `base_lin_vel` / `base_ang_vel` | 根部线速度 / 角速度，根坐标系下 | (N, 3) |
| `projected_gravity` | 重力方向在根坐标系下的投影，表示姿态 | (N, 3) |
| `last_action` | 上一步的原始动作；给 `action_name` 时只取该动作项 | (N, 动作维度) |
| `generated_commands` | 某个指令项当前的指令（[4.13](4.13-command-manager.md)） | (N, 指令维度) |

*表 2：`isaaclab.envs.mdp` 中常用的观测函数（v2.3.2）[^obs-fn]。关节类函数默认取 `robot` 的全部关节，用 `asset_cfg` 可以只选部分关节。*

## 两组观测：policy 与 critic

这一节回答：为什么有的任务定义两组观测？

PPO 这类 actor-critic 算法里有两个网络：策略（actor）部署时要在真机上运行，只能用真机也拿得到的量；价值网络（critic）只在训练时用，可以额外看仿真中才有的**特权信息**（privileged information），如物体的真实位姿、摩擦系数。两者输入不同，就叫**非对称 actor-critic**（asymmetric actor-critic）。做法是再定义一个 `critic` 组，由 RL 库的配置决定哪个网络读哪组：RSL-RL 在 `obs_groups` 中写 `{"policy": ["policy"], "critic": ["policy", "privileged"]}` 这类映射[^obs-groups]。官方例子见 UR10e 齿轮装配任务：`critic` 组比 `policy` 组多了齿轮的位姿，且不加噪声[^gear]。为什么这样设计，见 [5.6 观测设计](../5-rl/5.6-observation-design.md)。

## 噪声

这一节回答：怎么给观测加噪声？

噪声配置在 `isaaclab.utils.noise`[^noise]：

- **`UniformNoiseCfg(n_min, n_max)`**：均匀分布，别名 `AdditiveUniformNoiseCfg`，任务中常写作 `Unoise`。
- **`GaussianNoiseCfg(mean, std)`**：高斯分布，别名 `AdditiveGaussianNoiseCfg`。
- **`ConstantNoiseCfg(bias)`**：常量偏置。
- 三者都有 `operation` 字段，可取 `"add"`（默认）、`"scale"`、`"abs"`。
- 需要"每回合采样一次偏置"这类有状态的噪声，用 `NoiseModelCfg` / `NoiseModelWithAdditiveBiasCfg`。

噪声只在所在组 `enable_corruption=True` 时生效。官方运动任务训练时打开，`_PLAY` 配置里关闭（如 `AnymalCFlatEnvCfg_PLAY` 中的 `self.observations.policy.enable_corruption = False`）[^play]。**回放、评估时应关闭噪声**。

## Action Manager：从策略输出到关节目标

这一节回答：一个动作数值是怎么变成关节目标的？

策略输出一个 (N, 总动作维度) 的张量，Action Manager 按动作项的定义顺序把它切开，分给各项[^am]。动作项是类（`ActionTermCfg.class_type`），常用的有：

| 配置类 | 写入什么 | 说明 |
|---|---|---|
| `JointPositionActionCfg` | 关节位置目标 | 绝对位置；`use_default_offset=True`（默认）时偏移取默认关节位置 |
| `RelativeJointPositionActionCfg` | 关节位置目标 | 目标 = 处理后动作 + **当前**关节位置 |
| `JointVelocityActionCfg` | 关节速度目标 | `use_default_offset` 时偏移取默认关节速度 |
| `JointEffortActionCfg` | 关节力 / 力矩 | Cartpole 用的就是它 |
| `JointPositionToLimitsActionCfg` | 关节位置目标 | 把 [-1, 1] 映射到关节软限位 |
| `DifferentialInverseKinematicsActionCfg` | 关节位置目标 | 输入末端位置或位姿（绝对或相对），经微分逆运动学换算 |
| `BinaryJointPositionActionCfg` | 关节位置目标 | 二值夹爪：输入 < 0 为闭合，否则张开 |

*表 3：常用动作项（v2.3.2）[^actions-cfg]。另有 `OperationalSpaceControllerActionCfg`、`NonHolonomicActionCfg`、`SurfaceGripperBinaryActionCfg` 等。*

关节类动作项（前四行）的换算是同一个仿射变换[^joint-actions]：

$$
a_{\text{proc}} = \operatorname{clip}\left(a_{\text{raw}} \cdot s + o\right)
$$

- $a_{\text{raw}}$：策略输出中属于该动作项的部分。
- $s$：`scale`，标量或按关节名的字典。
- $o$：`offset`。位置、速度动作在 `use_default_offset=True` 时，$o$ 被**替换为**资产的默认关节位置 / 速度，配置里写的 `offset` 不再起作用；相对位置动作在 `use_zero_offset=True`（默认）时 $o = 0$。
- $\operatorname{clip}$：按 `ActionTermCfg.clip`（关节名正则 → 区间）裁剪，未设置则不裁剪。
- $a_{\text{proc}}$：写入资产的目标值；相对位置动作还要再加上当前关节位置。

例：本站示例把 Cartpole 换成 `JointPositionActionCfg(scale=0.5)`，原始动作 1.0 → 目标 0.5 m（默认位置为 0）。

**两个阶段**：`process_action()` 每个环境步调用一次，完成上面的换算；`apply_action()` 在 decimation 循环里每个物理步调用一次，把 $a_{\text{proc}}$ 写成关节目标[^am][^step]，对应 [0.6](../0-map/0.6-one-step.md) 中的"一次动作，多次物理步"。目标写入之后，由执行器模型换算成力（[4.7](4.7-actuators.md)）。

## 选哪种动作空间

这一节回答：位置控制还是力矩控制？

- **学习难度**：对腿式运动等任务，比较研究发现输出 PD 位置目标比直接输出力矩学得更快、更稳[^peng]。原因是 PD 控制器本身就提供了稳定作用，策略只需给出"去哪"。
- **sim2real**：力矩控制对电机模型、摩擦、延迟的误差更敏感；位置控制把这部分交给底层 PD，更容易迁移。这是社区经验，不是定论，也取决于真机的底层控制接口。官方运动任务多用 `JointPositionActionCfg(scale=0.5, use_default_offset=True)`[^loco]。
- **scale 的直觉**：策略输出大致在 [-1, 1] 附近，scale 决定一个单位对应多大的关节变化，应与关节行程、执行器能力相称。

## 示例

本站示例 `examples/isaaclab-2.3/4.10-observation-action/obs_action_demo.py` 继承官方 Cartpole：

- **观测**：给 `policy` 组的 `joint_pos_rel` 加高斯噪声（std 0.05），打开 `enable_corruption`，末尾加 `last_action`；另建不加噪声的 `critic` 组。
- **动作**：可选换成 `JointPositionActionCfg`（scale 0.5）。

示例固定随机种子（`--seed`，默认 42），重复运行输出相同。用固定动作 1.0 运行 60 个环境步（1 秒），本站实测（16 个环境，每次 6–8 秒）：

| 运行方式 | 观测空间 | 处理后动作 | env 0 小车位置 |
|---|---|---|---|
| 默认（力动作） | policy (5,)，critic (4,) | 100.0（N） | 0.226 → 2.973（本回合第 31 步） |
| `--action position` | 同上 | 0.5（m） | 0.226 → 0.128，没有去 0.5 |
| `--action position --kp 1000` | 同上 | 0.5（m） | 0.226 → 0.498，到达 0.5 |
| `--no_noise` | 同上 | 100.0（N） | 0.226 → 0.402（本回合第 6 步） |

*表 4：示例输出（种子 42）。policy 与 critic 组关节位置的最大差：有噪声时为 0.11–0.13，`--no_noise` 时为 0。力动作的两行，本回合步数少于 60，说明小车在 60 步内越过 ±3 m、被重置过；噪声会消耗随机数，所以两次重置后的起点不同，这两行只看处理后动作。*

第二行说明：Cartpole 小车执行器的 stiffness 是 0（原本为力控制设计），位置目标不起作用。换动作项时要同时检查执行器增益（[4.7](4.7-actuators.md)）。

## 常见坑

:::{admonition} 坑一：观测顺序变了，但策略没有重训
:class: warning

策略网络只认输入向量的位置。增删、调换观测项，或在子类里追加项（会排到最后），都会改变向量布局；用旧检查点推理不会报错（维度相同时），只是行为异常。改观测后要重训，或者核对 `group_obs_term_dim` 与训练时一致。
:::

:::{admonition} 坑二：scale 与关节限位、执行器不匹配
:class: warning

scale 过大，目标超出关节限位或执行器能力，动作大部分时间被截断；scale 过小，策略需要输出很大的值才够得到目标。位置动作还要求执行器有刚度（见表 4 第二行）。
:::

:::{admonition} 坑三：回放或部署时忘了关噪声
:class: warning

训练配置里的噪声会原样带到回放中，表现变差却找不到原因。用 `_PLAY` 配置，或设 `enable_corruption=False`。另外，噪声配置在 Manager 初始化时就按 `enable_corruption` 决定去留[^prepare]，环境创建后再改这个开关不起作用。
:::

:::{admonition} 坑四：以为 `offset` 写了就生效
:class: warning

位置、速度动作默认 `use_default_offset=True`，会用默认关节状态覆盖 `offset`[^joint-actions]。要用自定义偏移，先把它设为 False。
:::
