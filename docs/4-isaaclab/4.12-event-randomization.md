# Event Manager 与域随机化

:::{admonition} 学习目标
:class: lead-goals

- 会用事件在启动、重置、定时三个时机改动仿真
- 知道哪些随机化必须在仿真开始前做、哪些建议只在启动时做
- 能说出 interval 事件的逐环境计时与全局计时的区别
:::

:::{admonition} 前置知识
:class: lead-prereq

- [4.9 Manager-based 环境：总览](4.9-manager-based-env.md)
- [4.5 InteractiveScene：场景作为配置](4.5-interactive-scene.md)
:::

事件（event）在 [0.6 锚点图](../0-map/0.6-one-step.md) 中出现在两处：重置分支里的 reset 事件，以及每步末尾、计算观测之前的 interval 事件。另有两个只在环境构造时执行一次的时机。

## 事件项与四种时机

这一节回答：事件在什么时候被调用？

事件项用 `EventTermCfg` 配置[^term-cfg]：

- **`func(env, env_ids, **params)`**：直接修改仿真，没有返回值。
- **`mode`**：触发时机。
- **`interval_range_s`**：仅 interval 模式使用，每次触发后从该区间均匀采样下一次的间隔（秒）。
- **`is_global_time`**：仅 interval 模式使用。False（默认）时每个环境独立计时；True 时所有环境共用一个计时器，同时触发。
- **`min_step_count_between_reset`**：仅 reset 模式使用，距上次触发不足这么多环境步就跳过，用来减少昂贵事件的调用次数；默认 0，即每次重置都调用。

`ManagerBasedRLEnv` 会触发四种 `mode`[^em-doc][^env][^rlenv]：

```{mermaid}
flowchart LR
    A[创建 Event Manager] --> B[prestartup] --> C["sim.reset()"] --> D[startup] --> E["训练循环<br/>reset / interval"]
```

*图 1：事件时机，自左向右。prestartup 与 startup 都只执行一次，区别在于仿真是否已经开始。*

| mode | 时机 | `env_ids` | 典型用途 |
|---|---|---|---|
| `prestartup` | 构造环境时，`sim.reset()` **之前** | None（所有环境） | 修改 USD 属性，如随机缩放 |
| `startup` | 所有 Manager 创建完、仿真已开始，执行一次 | None | 质量、摩擦等物理参数的随机化 |
| `reset` | `_reset_idx` 中 `scene.reset` 之后 | 本步要重置的环境 | 随机化初始状态 |
| `interval` | 每个环境步末尾、计算观测之前 | 计时到点的环境 | 周期性推一下机器人 |

*表 1：四种 mode（v2.3.2）[^em-doc][^env][^rlenv]。`interval` 由 Event Manager 自己计时，其余三种由环境类在上述位置调用；也可以自定义 mode，但需要自己在环境里触发。*

**interval 的计时细节**[^em-apply]：逐环境计时时，每个环境重置都会重新采样剩余时间；全局计时基于仿真时间，不随重置清零。所以逐环境计时的间隔下限如果比回合还长，这个事件**永远不会触发**（见示例表 2）。

## 常用事件函数

这一节回答：`mdp` 里有哪些现成的事件？

| 类别 | 函数 | 作用对象与取值方式 |
|---|---|---|
| 重置 | `reset_joints_by_offset` / `reset_joints_by_scale` | 关节：默认位置、速度加上（或乘以）区间内的随机数 |
| 重置 | `reset_root_state_uniform` | 根：默认位姿加上按 x、y、z、roll、pitch、yaw 分别采样的偏移，并设初速度 |
| 重置 | `reset_scene_to_default` | 场景中所有资产回到默认状态（`DefaultEventManagerCfg` 默认只含此项） |
| 物理参数 | `randomize_rigid_body_mass` | 刚体质量：先恢复默认质量，再按 `operation`（add / scale / abs）施加随机数；可选重算惯量 |
| 物理参数 | `randomize_rigid_body_material` | 静、动摩擦系数与恢复系数：预先采样 `num_buckets` 组材质，再随机分给各碰撞形状 |
| 物理参数 | `randomize_actuator_gains` / `randomize_joint_parameters` | 执行器 stiffness、damping / 关节摩擦、armature、限位等 |
| 扰动 | `push_by_setting_velocity` | 把根速度设为随机值，效果类似一次推搡 |
| 扰动 | `apply_external_force_torque` | 给刚体施加随机外力与力矩，写入后持续作用 |
| USD 属性 | `randomize_rigid_body_scale` | 刚体的 `xformOp:scale`，只能在仿真开始前 |

*表 2：`isaaclab.envs.mdp` 中的常用事件函数（v2.3.2）[^events]。环境创建后第一次 `reset()` 时，`reset_joints_by_offset` / `reset_joints_by_scale` 随机出的关节速度会被夹成 0，见 {ref}`4.6 常见坑四 <first-reset-velocity>`。官方运动任务的组合是：startup 随机化摩擦、底座质量与质心，reset 随机化根状态与关节，interval 每 10–15 s 推一次[^loco]。*

## 哪些随机化只能在启动时做

这一节回答：为什么有些事件放在 reset 里会出问题？

要分两种情况：

- **必须在仿真开始前（prestartup）**：改 USD 属性、需要物理引擎重新解析的随机化，如 `randomize_rigid_body_scale`。它在仿真运行时被调用会直接抛出 `RuntimeError`；它也不支持 Articulation；按环境各不相同时，还要把 `replicate_physics` 设为 False，与 [4.5 常见坑三](4.5-interactive-scene.md#常见坑) 相同[^scale]。官方 Dexsuite 任务就用 `mode="prestartup"` 随机缩放物体[^dexsuite]。
- **建议只在 startup 做**：`randomize_rigid_body_mass`、`randomize_rigid_body_material`、隐式执行器的 `randomize_actuator_gains` 都在 CPU 上读写 PhysX 张量，源码注释建议只在初始化时使用，否则开销显著。材质还有一个硬约束：PhysX 场景中最多 64000 种物理材质，所以材质组只在初始化时采样一次[^events-note]。放进 reset 功能上能用，只是慢。

:::{note}
`randomize_rigid_body_scale` 的注释写的是 "usd" 模式，但 v2.3.2 的环境类只触发名为 `"prestartup"` 的模式[^env]。写成 `mode="usd"` 的事件不会被调用，应以 `"prestartup"` 为准。
:::

## 为什么要域随机化

这一节回答：随机化这些参数有什么用？

仿真永远不会与真机完全一致：质量、摩擦、执行器响应都有误差。**域随机化**（domain randomization）让策略在一族参数下都能完成任务，真机参数只要落在这个范围内，策略就能迁移过去。主线项目的做法见 [6.4.2 域随机化](../6-galbot/4-task/6.4.2-domain-randomization.md)，迁移检查见 [6.7.3 sim2real 清单](../6-galbot/7-deploy/6.7.3-sim2real-checklist.md)。

本站没有真机数据（D-004），范围只能凭经验选定。以下原则是经验性的：先以标称值为中心取较小的范围（如质量 ±10–20%），确认策略能学会，再逐步放宽；每次只放宽一类参数，观察奖励是否明显下降。

外观上的随机化（纹理、颜色、光照）用于视觉策略，由 Replicator 完成，见 [3.9 Replicator 与合成数据](../3-isaacsim/3.9-replicator.md)。

## 示例

本站示例 `examples/isaaclab-2.3/4.12-event-randomization/event_demo.py` 继承官方 Cartpole，加三项事件：

- startup：小车与摆杆的质量各乘 [0.5, 1.5] 内的随机数；
- reset：沿用官方的 `reset_cart_position`、`reset_pole_position`；
- interval：一个只计数的自定义事件，间隔 1–2 s，分别用逐环境计时和全局计时。

用零动作运行 300 步（5 s）。本站实测（8 个环境，种子 42，每次约 8 秒，两次运行输出一致）：

| 输出 | 默认（回合 5 s） | `--episode_s 1.0` |
|---|---|---|
| env 0–3 的小车质量（默认 1.0 kg） | 1.415、1.459、1.101、1.294 | 同左 |
| env 0–3 的初始小车位置（m） | 0.975、−0.742、0.124、0.044 | 同左 |
| 运行期间重置次数 / 质量是否改变 | 8 次 / 否 | 40 次 / 否 |
| interval 触发次数（逐环境计时） | 3、3、3、3、3、4、3、3 | 全为 0 |
| interval 触发次数（全局计时） | 全为 3 | 全为 3 |

*表 3：示例输出。质量在启动时随机一次，之后重置多次也不变；回合（1 s）短于间隔下限（1 s 起）时，逐环境计时的事件一次也没有触发。*

## 常见坑

:::{admonition} 坑一：在 reset 里做只能在启动前做的随机化
:class: warning

`randomize_rigid_body_scale` 这类改 USD 的事件必须用 `prestartup`，放在 reset 或 startup 会报错。质量、材质放在 reset 里虽然能运行，但每次重置都在 CPU 上读写全部环境的物理张量，训练会明显变慢。
:::

:::{admonition} 坑二：interval 的逐环境计时与全局计时
:class: warning

逐环境计时（默认）每次重置都重新计时。回合比间隔短，事件就永远不触发，而且不会有任何提示（表 3）。需要"按真实时间定期发生"的事件，设 `is_global_time=True`，或者把间隔设得比回合短。
:::

:::{admonition} 坑三：随机范围过大，策略学不会
:class: warning

范围一开始就很大，任务可能在部分参数下根本无法完成，奖励长期上不去。先用小范围训练成功，再逐步放宽；也可以用课程项（[4.11](4.11-reward-termination-curriculum.md)）随训练进度放宽范围。
:::
