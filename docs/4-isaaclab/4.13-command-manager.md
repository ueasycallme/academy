## 职责与位置

这一节回答：指令由谁生成，谁在读？

机械臂要去的目标位姿、四足要跟的速度，都是**指令**（command）。它由 Command Manager 生成，观测、奖励、终止只是读出它：

- 观测项 `generated_commands` 只做一件事：`env.command_manager.get_command(名字)`[^gen-cmd]；
- 奖励项如 `position_command_error` 也调用 `get_command`，再和末端位置比较[^reach-rew]。

它在环境里的位置[^rl-env]：

- **创建**：`load_managers()` 里第一个创建，因为后面的观测项要引用它；
- **每步**：`step()` 里先算终止、奖励，再重置该重置的环境，然后 `command_manager.compute(dt)`，最后算观测；
- **重置**：`_reset_idx()` 里调用 `command_manager.reset(env_ids)`，返回的指标写进 `extras["log"]`。

## `CommandTerm` 的生命周期

这一节回答：一个指令项什么时候换目标？

每个指令项都是 `CommandTerm` 的子类，基类维护两个计数[^cmd-mgr]：`time_left`（离下次重采样还剩几秒）和 `command_counter`（本回合已采样几次）。

| 方法 | 谁调用 | 做什么 |
|---|---|---|
| `reset(env_ids)` | 环境重置时 | 取这些环境 `metrics` 的平均值返回（用于日志）并清零；`command_counter` 归零；立刻重采样 |
| `compute(dt)` | 每个环境步 | 先 `_update_metrics()`；`time_left -= dt`；对 `time_left <= 0` 的环境重采样；最后 `_update_command()` |
| `_resample(env_ids)` | 上面两处 | 从 `resampling_time_range` 均匀抽一个新的 `time_left`，调 `_resample_command`，计数加一 |
| `_resample_command(env_ids)` | 子类实现 | 生成新目标 |
| `_update_command()` | 子类实现 | 两次重采样之间每步修正指令（如速度指令里按朝向误差算角速度），不需要就留空 |
| `_update_metrics()` | 子类实现 | 更新 `self.metrics` 里的张量，如位置误差 |

*表 1：`CommandTerm` 的方法（v2.3.2 `command_manager.py`[^cmd-mgr]）。*

`metrics` 是给人看的：环境重置时，Command Manager 把各项以 `Metrics/<指令名>/<指标名>` 的键写进 `extras["log"]`[^cmd-mgr]，训练日志里的 `Metrics/ee_pose/position_error` 就来自这里。注意它是**重置那一刻**的值在重置环境上的平均，不是整个回合的平均（[6.5.1](../6-galbot/5-train/6.5.1-train-reach-rsl-rl.md) 读训练曲线时用到了这一点）。

## 内置指令项

这一节回答：Isaac Lab 自带哪些指令？

| 指令项 | 输出维度 | 坐标系 | 重采样之间 | 典型任务 |
|---|---|---|---|---|
| `NullCommand` | 无（读取即报错） | — | — | 不需要指令的任务 |
| `UniformPoseCommand` | 7：位置 + 四元数 (w, x, y, z) | 机器人根坐标系 | 不变 | 机械臂 reach |
| `UniformVelocityCommand` | 3：x、y 线速度，绕 z 角速度 | 机器人根坐标系 | 可按朝向误差改角速度；部分环境置零 | 四足、人形速度跟踪 |
| `UniformPose2dCommand` | 4：位置 + 朝向 | 位置相对根，朝向为相对朝向 | 随机器人运动换算 | 导航 |
| `TerrainBasedPose2dCommand` | 同上 | 同上 | 同上；目标从地形的平坦区域采样 | 崎岖地形导航 |

*表 2：内置指令项（v2.3.2 `envs/mdp/commands/`[^cmds]）。*

`UniformPose2dCommand` 初始化的是 `metrics["error_pos"]`，更新时写的却是 `error_pos_2d`[^pose2d-metric]，所以日志里 `Metrics/<名>/error_pos` 恒为 0，应看 `error_pos_2d`。

几个开关：

- `UniformPoseCommandCfg.make_quat_unique`：把四元数实部取正，避免同一姿态有两种表示[^cmds]；
- `debug_vis=True` 时，位姿指令画两个坐标系标记：目标位姿与当前末端位姿[^cmds]；
- `UniformVelocityCommandCfg.heading_command`：为 True 时，按朝向误差乘 `heading_control_stiffness` 算角速度；`rel_standing_envs` 是重采样时被设成"站着不动"（指令全零）的环境比例[^cmds]。

## 主线案例：reach 的 `ee_pose`

这一节回答：一个指令怎么同时被观测和奖励引用？

官方 `Isaac-Reach-Franka-v0` 只定义一个指令项 `ee_pose`[^reach-cfg]：

```python
ee_pose = mdp.UniformPoseCommandCfg(
    asset_name="robot", body_name="panda_hand",       # body_name 在 Franka 子配置里填
    resampling_time_range=(4.0, 4.0),                 # 固定 4 s 换一次目标
    ranges=mdp.UniformPoseCommandCfg.Ranges(pos_x=(0.35, 0.65), pos_y=(-0.2, 0.2), pos_z=(0.15, 0.5), ...),
)
```

观测 `pose_command`、奖励 `end_effector_position_tracking` 等都以 `command_name="ee_pose"` 引用它[^reach-cfg]。Galbot 的 reach（[6.4.1](../6-galbot/4-task/6.4.1-reach.md)）沿用同样的结构，换成以 TCP 计算误差的子类，目标范围来自 6.4.1 的 `workspace.py` 工作空间测量。

## 自定义指令项

这一节回答：自己写一个指令项最少要什么？

`examples/isaaclab-2.3/4.13-command-manager/command_demo.py` 给 Cartpole 加一个"小车目标位置"：

```python
class CartTargetCommand(CommandTerm):
    @property
    def command(self):                       # (num_envs, 1)
        return self.target
    def _resample_command(self, env_ids):     # 在 target_range 内均匀采样
        self.target[env_ids, 0] = torch.empty(len(env_ids), device=self.device).uniform_(*self.cfg.target_range)
    def _update_metrics(self):                # 小车与目标的距离
        self.metrics["error"] = (self.robot.data.joint_pos[:, self.joint_id] - self.target[:, 0]).abs()
    def _update_command(self):
        pass

@configclass
class CartTargetCommandCfg(CommandTermCfg):
    class_type: type = CartTargetCommand      # 配置与实现在这里绑定
    target_range: tuple[float, float] = (-1.0, 1.0)
```

*节选。必须实现的是 `command` 属性与三个下划线方法；`debug_vis` 可以不实现：基类检测到没有实现时，`set_debug_vis` 直接返回 False[^cmd-mgr]。*

再在环境配置里设 `self.commands.cart_target = CartTargetCommandCfg(resampling_time_range=(1.0, 2.0))`，观测加 `generated_commands`，奖励按误差扣分。零动作跑 6 s（16 个环境）：

```bash
python examples/isaaclab-2.3/4.13-command-manager/command_demo.py --headless
```

```text
  t=1.083 s  env 2: 目标 +0.224 → -0.283 m，新 time_left 1.225 s，counter 2
  ↳ 这一步奖励读到的目标 +0.224（旧），观测里的目标 -0.283（新）
  t=5.000 s  env 0: 目标 -0.707 → -0.384 m，新 time_left 1.221 s，counter 1
  t=5.000 s  重置 16 个环境，extras['log']['Metrics/cart_target/error'] = 0.888 m
由 time_left 触发的重采样 44 次，间隔 1.067–2.000 s（配置 1.0–2.0 s，步长 0.0167 s）
```

*本站实测（节选，种子 42，三次运行输出一致；约 13 s，进程显存峰值 2315 MiB，RTX 5070）。*

- 重采样间隔落在配置的 1–2 s 内，并按环境步取整；
- 5 s 超时重置时，`command_counter` 归零再采样，变回 1；
- 重采样的那一步，**奖励读到的还是旧目标，观测已经是新目标**：`step()` 中奖励在 `compute(dt)` 之前算，观测在之后算[^rl-env]。

## 常见误解

:::{admonition} 误解一："把目标直接写进观测项就行"
:class: warning

观测项每步都会重新计算，写在里面的随机目标会每步一变；而且奖励、终止拿不到同一个目标。指令要有自己的状态（`time_left`、计数、指标），所以单独由一个 Manager 管理。
:::

:::{admonition} 误解二："指令每步都重新采样"
:class: warning

只有 `time_left` 用完或环境重置时才重采样（表 1）。`_update_command()` 每步都调用，但内置的位姿指令里它什么也不做[^cmds]。
:::

:::{admonition} 误解三："指令是世界坐标系下的"
:class: warning

内置的位姿、速度指令都在机器人根坐标系下（表 2）。奖励函数里要先用根位姿换算到世界系，再和末端位置比较，`position_command_error` 就是这样做的[^reach-rew]。
:::

:::{admonition} 误解四："日志里的指令误差是整个回合的平均"
:class: warning

是重置那一刻的值（上文），不包括回合中途的误差。比如回合中途换了目标、还没走到的那一段，就不计入（推断，依据是表 1 中 `reset()` 只取当时的 `metrics`）。
:::
