## 注册：`gym.register`

这一节回答：一个任务 ID 背后登记了什么？

Isaac Lab 用 Gymnasium 的注册表管理任务[^gym-reg]。官方 Cartpole 在所在目录的 `__init__.py` 里注册[^cartpole-init]：

```python
gym.register(
    id="Isaac-Cartpole-v0",
    entry_point="isaaclab.envs:ManagerBasedRLEnv",
    disable_env_checker=True,
    kwargs={
        "env_cfg_entry_point": f"{__name__}.cartpole_env_cfg:CartpoleEnvCfg",
        "rsl_rl_cfg_entry_point": f"{agents.__name__}.rsl_rl_ppo_cfg:CartpolePPORunnerCfg",
        "skrl_cfg_entry_point": f"{agents.__name__}:skrl_ppo_cfg.yaml",
        # 另有 rl_games、sb3 等入口，节选
    },
)
```

- **`id`**：任务 ID，即 `--task` 后面的字符串。
- **`entry_point`**：环境类，写成 `"模块:类名"`。Manager-based 任务都指向 `ManagerBasedRLEnv`，Direct 任务指向自己的环境类。
- **`disable_env_checker=True`**：关闭 Gymnasium 的环境检查器；官方任务都这样写。
- **`kwargs["env_cfg_entry_point"]`**：环境配置类，也写成 `"模块:类名"`。
- **`kwargs["<库>_cfg_entry_point"]`**：各 RL 库的算法配置，Python 类或 YAML 文件都可以。训练脚本用 `--agent` 选择读哪一个，RSL-RL 的默认值是 `rsl_rl_cfg_entry_point`[^train]。

## 发现：`import isaaclab_tasks`

这一节回答：注册代码是什么时候执行的？

`gym.register` 写在各任务包的 `__init__.py` 里，**只有这个包被导入时才会执行**。`isaaclab_tasks/__init__.py` 最后调用 `import_packages`，递归导入所有子包（跳过 `utils`、`.mdp` 等），于是所有官方任务在 `import isaaclab_tasks` 时一次注册完[^tasks-init][^importer]。训练、回放等脚本开头都有这一行[^train]。

外部项目的任务不在 `isaaclab_tasks` 里，必须让脚本导入你的包，注册才会发生。官方扩展模板的做法是在自己的脚本里 `import <项目名>.tasks`（见 [4.18](4.18-extension-template.md)）。

:::{note}
Gymnasium 支持 `gym.make("模块:任务ID")`，会先导入该模块[^gym-find]。但 Isaac Lab 的 `parse_env_cfg` 和训练脚本的 Hydra 入口在查注册表之前会先去掉冒号前的模块名[^parse]，所以这种写法**不能**代替导入。本站实测 `academy_tasks:Academy-Cartpole-v0` 同样报 `NameNotFound`。
:::

## 从字符串到环境对象

这一节回答：`--task` 字符串是怎么一步步变成环境的？

```{mermaid}
flowchart LR
    A["任务 ID"] --> B["gym.spec<br/>查注册表"] --> C["导入<br/>env_cfg_entry_point"] --> D["gym.make<br/>(task, cfg)"] --> E["env.unwrapped"]
```

*图 1：从任务 ID 到环境对象，自左向右。*

- **`parse_env_cfg(task, device, num_envs)`**：内部调用 `load_cfg_from_registry(task, "env_cfg_entry_point")`，导入配置类并实例化，再按参数覆盖设备与环境数[^parse]。训练脚本改用 `@hydra_task_config` 做同样的事，并额外合并命令行覆盖[^hydra]。注意：命令行覆盖在 `__post_init__` 之后生效，由其他字段派生的值不会跟着变（见 [4.3 常见坑三](4.3-configclass.md#常见坑)）。
- **`gym.make(task, cfg=env_cfg)`**：按 `entry_point` 实例化环境，把配置对象传进去。
- **`env.unwrapped`**：`gym.make` 返回的是包了一层 `OrderEnforcing` 的对象（本站实测），各 Manager、`scene`、`step_dt` 等要通过 `env.unwrapped` 访问。

## 命名约定

这一节回答：官方任务 ID 怎么读？

官方任务大致按 `Isaac-<任务>-<变体>-<机器人>-v<版本>` 命名，如 `Isaac-Reach-Franka-v0`、`Isaac-Velocity-Rough-Anymal-C-v0`；Direct 任务再加 `-Direct`，如 `Isaac-Cartpole-Direct-v0`[^envs-list]。这是从官方任务列表归纳出的惯例，不是强制规则。

**`-Play` 变体**注册同一个任务的回放配置，如 `Isaac-Velocity-Flat-Anymal-C-Play-v0` 指向 `AnymalCFlatEnvCfg_PLAY`[^anymal]：环境数更少、关闭观测噪声、去掉随机推搡。RSL-RL 的 `play.py` 会把任务 ID 中的 `-Play` 去掉，得到训练任务名，用于查找预训练检查点[^play]。

## 列出与查看任务

这一节回答：有哪些任务，某个任务的配置在哪个文件？

`./isaaclab.sh -p scripts/environments/list_envs.py --keyword Cartpole` 打印一张表，列出任务 ID、`entry_point` 和 `env_cfg_entry_point`[^list]。本站实测列出 32 个 ID 含 Cartpole 的任务，其中一行：

```text
| 28 | Isaac-Cartpole-v0 | isaaclab.envs:ManagerBasedRLEnv | isaaclab_tasks.manager_based.classic.cartpole.cartpole_env_cfg:CartpoleEnvCfg |
```

`env_cfg_entry_point` 的模块路径就对应源码文件（`isaaclab_tasks/manager_based/classic/cartpole/cartpole_env_cfg.py`）。注意：`list_envs.py` 只列出 ID 中含 `Isaac` 的任务，而且只导入 `isaaclab_tasks`，自己注册的任务不会出现在表里[^list]。

## Gym 接口：批量的五元组

这一节回答：`step()` 返回的是什么？

Isaac Lab 环境继承 `gym.Env`，而不是 `gym.vector.VectorEnv`，但它本身就是批量的（`is_vector_env = True`）[^rlenv-doc]。本站实测 `Academy-Cartpole-v0`（64 个环境）：

| 返回值 | 类型与形状 |
|---|---|
| `obs` | `dict`：`{"policy": Tensor(64, 4) float32 cuda:0}`，每个观测组一项 |
| `rew` | `Tensor(64,)` float32 |
| `terminated` / `truncated` | `Tensor(64,)` bool（含义见 [4.11](4.11-reward-termination-curriculum.md)） |
| `extras` | `dict`，重置时写入 `extras["log"]`（`Episode_Reward/*` 等） |

*表 1：`step()` 的返回值。`env.action_space` 为 (64, 1)，`single_action_space` 为 (1,)。*

与标准 Gymnasium 向量环境的差别：

- **数据留在 GPU 上**：返回的是 torch 张量，不是 NumPy 数组。
- **step 内自动重置**：结束的环境在同一次 `step()` 里就被重置，返回的 `obs` 已是新回合的第一个观测。官方建议只在创建后调用一次 `reset()`[^rlenv-doc]。
- **交给适配层**：各 RL 库对向量环境的约定不同，由 [4.16](4.16-rl-wrappers.md) 的适配层负责转换。

## 实操：注册 `Academy-Cartpole-v0`

这一节回答：怎么注册并运行自己的任务？

本站示例 `examples/isaaclab-2.3/4.15-task-registration/`：

- `academy_tasks/__init__.py` 注册 `Academy-Cartpole-v0` 与 `Academy-Cartpole-Play-v0`；
- `academy_tasks/cartpole_cfg.py` 继承官方 `CartpoleEnvCfg`，只把 `pole_pos` 的权重改为 −2.0；`_PLAY` 版把环境数改为 16；
- `run_task.py` 导入 `academy_tasks` 后，依次执行查注册表、`parse_env_cfg`、`gym.make`、`step`。

本站实测（每次 4–8 秒，返回码 0）：

| 运行方式 | 结果 |
|---|---|
| 默认 | 注册表中有该 ID；配置类为 `academy_tasks.cartpole_cfg.AcademyCartpoleEnvCfg`，权重 −2.0；五元组见表 1 |
| `--task Academy-Cartpole-Play-v0` | 配置类为 `…AcademyCartpoleEnvCfg_PLAY`，环境数 16 |
| `--no_import` | 注册表中没有该 ID；`parse_env_cfg` 报 `NameNotFound: Environment 'Academy-Cartpole' doesn't exist` |
| `--no_import --task academy_tasks:Academy-Cartpole-v0` | 同上，报 `NameNotFound` |

*表 2：示例输出。*

这只是演示：任务包放在示例目录里，靠 `sys.path` 导入。正式项目应做成可安装的扩展包，结构见 [4.18](4.18-extension-template.md)。

## 常见坑

:::{admonition} 坑一：没有导入任务包，找不到任务
:class: warning

报 `NameNotFound` 或 `gymnasium.error.NameNotFound`，多半是注册代码没执行：自己的脚本没有 `import isaaclab_tasks` 或你的任务包。`模块:ID` 的写法在 Isaac Lab 脚本里也不能代替导入（表 2 第四行）。
:::

:::{admonition} 坑二：入口字符串写错
:class: warning

`entry_point` 和 `*_cfg_entry_point` 的格式是 `"模块路径:名称"`，冒号不能写成点。字符串直到 `gym.make` 或 `parse_env_cfg` 时才被解析：注册时不会报错，写错了要到运行时才以 `ModuleNotFoundError` 或 `AttributeError` 的形式出现。
:::

:::{admonition} 坑三：`-Play` 与训练配置混用
:class: warning

`-Play` 配置环境少、关闭了噪声与扰动，用它训练会得到偏弱的策略；反过来，用训练配置回放，数千个环境同时渲染，而且观测噪声仍然开着（[4.10](4.10-observation-action.md)）。训练用不带 `-Play` 的 ID，回放用带 `-Play` 的 ID。
:::

:::{admonition} 坑四：在 `list_envs.py` 里找不到自己的任务
:class: warning

它只列出 ID 含 `Isaac` 的任务，且没有导入你的包[^list]。可以自己用 `gym.registry` 检查（示例第一行输出）。
:::
