# RL 库适配层

:::{admonition} 学习目标
:class: lead-goals

- 知道 Isaac Lab 支持哪四个 RL 库，各自的特点与版本约束
- 说出适配层（wrapper）在环境和 RL 库之间做了哪些转换
- 读懂 `train.py` / `play.py` 的骨架，知道日志和导出文件在哪
:::

:::{admonition} 前置知识
:class: lead-prereq

- [4.15 任务注册与 Gym 接口](4.15-task-registration.md)
- [4.11 Reward / Termination / Curriculum Manager](4.11-reward-termination-curriculum.md)（失败与超时）
:::

在 [0.6 锚点图](../0-map/0.6-one-step.md) 中，**适配层**（wrapper）位于 RL 库与环境之间：它把 Isaac Lab 环境的批量张量接口，改写成某个 RL 库期望的接口。

## 四个库的对照

这一节回答：该用哪个库，它们差在哪？

| | RSL-RL | skrl | RL-Games | Stable-Baselines3 |
|---|---|---|---|---|
| 版本约束（`isaaclab_rl` extras） | `rsl-rl-lib==3.1.2` | `skrl>=1.4.3` | `isaac-sim/rl_games` 的 `python3.11` 分支 | `stable-baselines3>=2.6` |
| 算法（官方表） | PPO、蒸馏 | 很多（Isaac Lab 脚本用 PPO、AMP、IPPO、MAPPO） | PPO、SAC、A2C | 很多 |
| GPU 向量化训练 | 是 | 是 | 是 | 否 |
| 多 GPU（`--distributed`） | 是 | 是 | 是 | 否 |
| 深度学习框架 | PyTorch | PyTorch、JAX | PyTorch | PyTorch |
| 算法配置格式 | Python configclass | YAML | YAML | YAML |
| 官方任务中带该库配置的数量 | 96 | 97 | 62 | 10 |

*表 1：四个 RL 库的对照（v2.3.2）。版本约束取自 `isaaclab_rl/setup.py`，与 [1.1](../1-env/1.1-compat-matrix.md) 的表一致[^setup]；算法、向量化、多 GPU、框架取自官方对照表[^frameworks]；配置格式取自任务注册时的入口[^cartpole-init]；最后一行由本站脚本统计：在全部 168 个 `Isaac-*` 任务 ID（含 43 个 `-Play`）中，注册了 `<库>_cfg_entry_point` 的个数。*

官方在 RTX 4090 上用 `Isaac-Humanoid-v0` 跑 6550 万步，RL-Games、skrl、RSL-RL 都约 200 秒，Stable-Baselines3 为 287 秒[^frameworks]。

## 适配层做了什么

这一节回答：环境的输出要经过哪些转换才能交给 RL 库？

四个适配层都在 `isaaclab_rl` 中，都包在 `gym.make` 返回的环境外面[^wrappers]：

| 职责 | `RslRlVecEnvWrapper` | `SkrlVecEnvWrapper` | `RlGamesVecEnvWrapper` | `Sb3VecEnvWrapper` |
|---|---|---|---|---|
| 观测 | 观测字典包成 `TensorDict` | 由 skrl 的 `wrap_env(env, "isaaclab")` 处理：取 `policy` 组展平为张量 | 按 `obs_groups` 整理成 `obs` / `states`，并按 `clip_obs` 裁剪 | 转成 NumPy |
| 动作 | 可选 `clip_actions` 裁剪 | 同左（skrl 内部） | 按 `clip_actions` 裁剪，并移到仿真设备 | NumPy 转回张量 |
| 张量位置 | 留在 GPU | 留在 GPU（JAX 时转换） | 在仿真设备与 RL 设备之间搬运 | 拷到 CPU |
| 结束标志 | `dones = terminated \| truncated` | 分别返回 terminated 与 truncated | `dones = terminated \| truncated` | `dones` 加上每个环境的 info |
| 超时信息 | `extras["time_outs"]`（`is_finite_horizon=False` 时） | 即 truncated 本身 | 同 RSL-RL | `info["TimeLimit.truncated"]` |
| 日志 | 原样传出 `extras["log"]` | 同左 | 把 `log` 改名为 `episode` | 按 SB3 格式统计回合回报与长度 |

*表 2：四个适配层的职责（v2.3.2）[^rslrl-w][^skrl-w][^rlg-w][^sb3-w]。skrl 一列的观测、结束标志与超时取自 skrl 库自身的 `IsaacLabWrapper`（本站环境为 skrl 2.1.0）[^skrl-lib]。超时信息的用途是价值自举，见 [4.11](4.11-reward-termination-curriculum.md)。*

一个值得注意的细节：SB3 要求回合结束时在 `info["terminal_observation"]` 中给出"重置前的最后一个观测"，但 Isaac Lab 在 `step()` 内已完成重置，拿不到这个观测。适配层的类注释说明了这一限制，实际传的是重置后的观测[^sb3-w]。

## `train.py` 的骨架

这一节回答：训练脚本按什么顺序做事？

以 `scripts/reinforcement_learning/rsl_rl/train.py` 为例[^train]：

1. **解析参数**：`--task`、`--num_envs`、`--seed`、`--max_iterations`、`--video`、`--distributed` 等，再加上 `AppLauncher` 的参数（`--headless`、`--device`）。
2. **启动仿真应用**：`AppLauncher(args_cli)`，之后才能导入 Isaac Lab 的其余模块（[3.2](../3-isaacsim/3.2-simulation-app.md)）。
3. **取配置**：`@hydra_task_config(task, agent)` 从注册表读出环境配置与 agent 配置（[4.15](4.15-task-registration.md)），合并命令行覆盖，再用命令行参数更新 agent 配置。命令行覆盖在 `__post_init__` 之后生效，派生值不会跟着变（见 [4.3 常见坑三](4.3-configclass.md#常见坑)）。
4. **种子与日志目录**：用 `agent_cfg.seed` 覆盖 `env_cfg.seed`；日志目录为 `logs/rsl_rl/<experiment_name>/<时间戳>[_<run_name>]`。
5. **建环境**：`gym.make(task, cfg=env_cfg)`；多智能体环境先转成单智能体接口；需要录像时包一层 `gym.wrappers.RecordVideo`。
6. **包适配层**：`RslRlVecEnvWrapper(env, clip_actions=…)`，**必须是最外层**。
7. **建 runner 并训练**：`OnPolicyRunner(env, agent_cfg.to_dict(), log_dir, device)`，可选加载检查点，保存 `params/env.yaml`、`params/agent.yaml`，然后 `runner.learn(max_iterations, init_at_random_ep_len=True)`。
8. **收尾**：`env.close()`，`simulation_app.close()`。

逐行解读见 [9.4 训练脚本 train.py 做了什么](../9-source/9.4-train-script.md)。其他三个库的 `train.py` 结构相同，只是第 6、7 步换成各自的适配层与训练入口。

## `play.py`：回放与导出

这一节回答：训练好的策略怎么回放、怎么导出？

`rsl_rl/play.py` 的检查点有三个来源：`--checkpoint` 指定的文件、`--use_pretrained_checkpoint` 下载的官方预训练模型，或默认在日志目录中按 `load_run` / `load_checkpoint` 找最新的一个[^play]。加载后：

- 调用 `runner.get_inference_policy()` 得到推理策略，在环境中循环运行。不加 `--video` 时一直运行到手动结束；加 `--video` 时录满 `--video_length` 步（默认 200）后自行退出[^play-video]。
- 每次启动都把策略导出到检查点所在目录的 `exported/` 下：`policy.pt`（TorchScript）和 `policy.onnx`。

回放细节见 [6.6.1](../6-galbot/6-eval/6.6.1-play-replay.md)，导出后的部署见 [6.7.1](../6-galbot/7-deploy/6.7.1-policy-export.md)。

## agent 配置：`RslRlOnPolicyRunnerCfg`

这一节回答：训练参数写在哪？

| 字段 | 含义 | Cartpole 的值 |
|---|---|---|
| `num_steps_per_env` | 每次迭代每个环境采集的步数 | 16 |
| `max_iterations` | 训练迭代次数 | 150 |
| `save_interval` | 每隔多少次迭代保存一次检查点 | 50 |
| `experiment_name` / `run_name` | 日志目录名 | `cartpole` / 空 |
| `seed` / `device` | 随机种子 / 训练设备 | 42 / `cuda:0` |
| `clip_actions` | 适配层裁剪动作的范围，None 为不裁剪 | None |
| `obs_groups` | 观测组到 actor / critic 的映射（[4.10](4.10-observation-action.md)） | 未设置（`{}`）：critic 缺省时先找同名观测组，没有则用 `policy`[^obs-groups] |
| `policy` | 网络：`actor_hidden_dims`、`critic_hidden_dims`、`activation`、`init_noise_std` 等 | [32, 32]、elu |
| `algorithm` | PPO 超参：`learning_rate`、`gamma`、`lam`、`clip_param`、`num_learning_epochs`、`num_mini_batches`、`entropy_coef` 等 | 1e-3、0.99、0.95、0.2、5、4、0.005 |
| `logger` | tensorboard（默认）、wandb 或 neptune | tensorboard |

*表 3：RSL-RL agent 配置的主要字段（v2.3.2）[^rlcfg][^cartpole-agent]。PPO 各超参的含义见 [5.3](../5-rl/5.3-ppo.md)。*

## 实测：训练与日志目录

这一节回答：跑一次训练会留下什么？

与 [1.4](../1-env/1.4-install-51-232.md) 的验证命令相同：

```bash
./isaaclab.sh -p scripts/reinforcement_learning/rsl_rl/train.py --task Isaac-Cartpole-v0 --headless --max_iterations 100
```

本站实测（RTX 5070，2026-09-30）：返回码 0，含启动共 20 秒，其中训练 12 秒（`Training time: 12.01 seconds`）；最后一次迭代 `Mean episode length: 300.00`，`Total timesteps: 6553600`（= 4096 个环境 × 16 步 × 100 次迭代）。日志目录：

```text
logs/rsl_rl/cartpole/2026-09-30_20-40-54/
├── events.out.tfevents.…     # TensorBoard 日志
├── model_0.pt  model_50.pt  model_99.pt   # 按 save_interval 保存，最后一次必存
├── params/
│   ├── env.yaml             # 实际使用的环境配置（含命令行覆盖）
│   └── agent.yaml           # 实际使用的 agent 配置
├── git/IsaacLab.diff        # 训练时仓库的未提交改动
└── exported/                # 运行 play.py 后生成：policy.pt、policy.onnx
```

之后运行 `play.py --task Isaac-Cartpole-v0 --headless --num_envs 16`：它加载 `model_99.pt`，生成 `exported/policy.pt`（16 KB）与 `policy.onnx`（6 KB），然后持续回放（未加 `--video`），本站在 60 秒时手动结束。

## 选哪个库

这一节回答：本站为什么用 RSL-RL，什么时候该换？

以下建议中，带脚注的是官方对照表的说法，其余为本站经验。

- **本站主线用 RSL-RL**（经验）：配置是 Python configclass，与环境配置同一种写法，可以用 Hydra 统一覆盖；运动与操作类官方任务大多附带它的配置；`play.py` 直接导出 JIT 与 ONNX，便于部署。官方表中它的文档评价为"Low"，本站用源码阅读弥补。
- **需要 JAX 或多智能体算法（IPPO、MAPPO）、AMP 时**，用 skrl：官方表中只有它支持 JAX 与多智能体专用算法[^frameworks]。
- **需要 SAC 等离策略算法，或沿用 IsaacGymEnvs 的训练配置时**，用 RL-Games。
- **原型验证、需要 SB3 生态的算法时**，用 Stable-Baselines3，但它不做 GPU 向量化训练，数据要拷到 CPU，速度最慢[^frameworks]。

## 常见坑

:::{admonition} 坑一：RL 库版本与 Isaac Lab 不匹配
:class: warning

`rsl-rl-lib` 被精确锁定为 3.1.2[^setup]。手动升级后，runner 的配置字段或 API 可能对不上。用 `./isaaclab.sh -i rsl_rl` 或 `pip install isaaclab_rl[rsl-rl]` 按约束安装，不要单独升级。
:::

:::{admonition} 坑二：忽略 `num_envs × num_steps_per_env`
:class: warning

每次迭代的样本数 = `num_envs` × `num_steps_per_env`（Cartpole 为 4096 × 16 = 65536），再被 `num_mini_batches` 等分。减少环境数（如调试时用 64）却不改其他参数，每次迭代的样本变少、小批量变小，训练曲线会与官方大不相同。样本数也要能被 `num_mini_batches` 整除。
:::

:::{admonition} 坑三：适配层的顺序
:class: warning

`RecordVideo` 等 Gymnasium 包装器要包在 RL 库适配层**之前**（更靠内），适配层必须是最外层，这是官方四个 `train.py` 的共同写法[^train]。反过来，适配层改写后的接口已不是标准 Gymnasium 接口，外层包装器会出错。
:::

:::{admonition} 坑四：在环境配置里设了种子，却没有生效
:class: warning

`train.py` 用 `agent_cfg.seed` 覆盖 `env_cfg.seed`[^train]。要改种子，用 `--seed` 或 `agent.seed=…`。
:::
