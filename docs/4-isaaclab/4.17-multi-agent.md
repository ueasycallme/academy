## 接口差异

多智能体（multi-agent）环境里有好几个各自出动作的"智能体"。Isaac Lab 2.3.2 用 `DirectMARLEnv` 表示它，写法沿用 Direct 环境（4.14），区别在于几乎所有量都按智能体名索引[^marl-env][^marl-cfg]：

| | `DirectRLEnv` | `DirectMARLEnv` |
|---|---|---|
| 智能体列表 | 无 | 配置的 `possible_agents`，如 `["cart", "pendulum"]` |
| 观测 / 动作空间 | `observation_space` / `action_space` | `observation_spaces` / `action_spaces`：按智能体名的字典 |
| 全局状态 | `state_space`（给非对称 critic） | 同名字段：0 表示不构造；-1 表示把所有智能体的观测拼起来；其他值表示自定义 |
| `_pre_physics_step(actions)` | 一个张量 | 字典：智能体名 → 动作 |
| `_get_observations()` | `{"policy": …}` | 字典：智能体名 → 观测 |
| `_get_rewards()` | 一个张量 | 字典：智能体名 → 奖励 |
| `_get_dones()` | （终止，超时）两个张量 | 两个字典，各按智能体名 |
| 什么时候重置一个环境 | 终止或超时 | **所有智能体都终止，或所有智能体都超时**（对各智能体取"与"）[^marl-reset] |

*表 1：两种 Direct 环境的接口对照（v2.3.2）。decimation 循环、事件、噪声等与 4.14 表 1 相同。*

最后一行容易忽略：只要有一个智能体还没结束，这个环境就不会重置（坑二）。

## 官方例子

| 任务 | 智能体 | 一句话 |
|---|---|---|
| `Isaac-Cart-Double-Pendulum-Direct-v0` | `cart`（观测 4 维、动作 1 维）、`pendulum`（观测 3 维、动作 1 维） | 小车推车、第二节摆自己出力，一起把双摆立住；`state_space = -1` |
| `Isaac-Shadow-Hand-Over-Direct-v0` | `right_hand`、`left_hand` | 两只灵巧手传递物体；`state_space = 290` |

*表 2：v2.3.2 自带的两个多智能体任务[^tasks]。*

`marl_shapes.py` 在双摆上建 16 个环境，打印两种用法的形状（本站实测）：

```text
[4.17] MARL：obs {cart: (16, 4)，pendulum: (16, 3)}；state (16, 7)；rew {cart: (16,)，pendulum: (16,)}；terminated {cart: (16,)，pendulum: (16,)}
[4.17] 拼成单智能体：obs {policy: (16, 7)}；动作 (16, 2)；rew (16,)；terminated (16,)
```

用 Isaac Lab 自带的 skrl 训练脚本，`--algorithm` 选算法，各训 100 次迭代（每次 16 步，4096 个环境，种子 42）：

```bash
python scripts/reinforcement_learning/skrl/train.py --task Isaac-Cart-Double-Pendulum-Direct-v0 --headless \
    --algorithm MAPPO --max_iterations 100 --seed 42      # 或 IPPO；PPO 时先拼成单智能体
```

| 算法 | 训练时间 | 按进程显存 | 最后一次迭代的总奖励均值 |
|---|---|---|---|
| IPPO | 14.0 s | 2975 MiB | 513 |
| MAPPO | 14.4 s | 2997 MiB | 453 |
| PPO（拼成单智能体） | 11.1 s | 2973 MiB | 556 |

*表 3：双摆短训（本站实测，2026-10-11，skrl 2.1.0，各跑一次）。只训了 100 次迭代、一个种子，三者的奖励差别不能说明谁更好；这张表只说明三条路都能跑通、代价相近。*

## 算法支持

- **skrl**：支持 IPPO 与 MAPPO。IPPO 让每个智能体用自己的观测独立学习，各有策略与价值网络；MAPPO 用一个集中的价值函数，以全局状态为输入，指导所有智能体的策略更新[^skrl-ippo][^skrl-mappo]。Isaac Lab 的 skrl 训练脚本用 `--algorithm IPPO / MAPPO` 选，配置在任务的 `skrl_ippo_cfg.yaml`、`skrl_mappo_cfg.yaml`[^skrl-train]。
- **rsl_rl 等单智能体库**：不能直接接收多智能体环境。把双摆直接交给 `RslRlVecEnvWrapper`，报 `ValueError: The environment must be inherited from ManagerBasedRLEnv or DirectRLEnv.`（本站实测）。Isaac Lab 的 rsl_rl、skrl（选 PPO 时）训练脚本遇到多智能体环境，会先调用 `multi_agent_to_single_agent` 把它拼成单智能体[^rsl-train]。

`multi_agent_to_single_agent` 怎么拼[^marl-util]：

- 观测按 `possible_agents` 的顺序拼接；`state_as_observation=True` 时直接用全局状态；
- 动作切开，分给各智能体；
- 奖励求和；
- 终止与超时都取"与"。

## 怎么选

| 情形 | 适合 |
|---|---|
| 拼成一个大动作（单智能体） | 各部分始终一起行动、观测可以共享，只是为了分工写奖励。最简单，所有库都能用 |
| 多智能体、共享价值（MAPPO） | 各部分只看自己的局部观测，但训练时可以用全局信息 |
| 多智能体、各自独立（IPPO） | 各部分在部署时彼此看不到对方，或者以后要换掉其中一方 |

*表 4：三种做法（本站经验）。*

主线 Galbot 的双臂若要一起做任务，两只手臂由同一台机器人的同一个控制器驱动，观测天然共享，属于第一种：拼成一个 14 维的动作即可（本站没有实现）。

## 常见坑

### 坑一：把多智能体环境直接交给 rsl_rl 的封装

报错原文见上文。自己写训练脚本时，记得先 `multi_agent_to_single_agent(env)`，Isaac Lab 自带的 `train.py` 已经这样做了。

### 坑二：一个智能体结束了，环境却没重置

重置条件对各智能体取"与"（表 1 最后一行）。如果任务的意思是"任何一方失败就结束"，`_get_dones()` 要给所有智能体返回同一个终止张量。双摆就是这样写的：两个智能体共用同一个出界判断[^tasks]。

### 坑三：拼接顺序以 `possible_agents` 为准

拼成单智能体时，观测按 `possible_agents` 的顺序拼接，与 `_get_observations()` 返回字典的键顺序无关[^marl-util]。导出策略、部署到机器人时，按这个顺序拼观测（同 6.7.2 坑一）。

### 坑四：日志里只有合计的奖励

本站读了 IPPO、MAPPO 两次训练的 TensorBoard 日志，奖励曲线只有所有智能体合在一起的 `Reward / Total reward`，没有按智能体分开的。想看每个智能体的奖励各是多少，要在环境里自己写进 `extras`。
