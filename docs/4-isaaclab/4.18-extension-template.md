# 扩展模板：在 Isaac Lab 之外组织你的项目

:::{admonition} 学习目标
:class: lead-goals

- 用官方模板生成一个独立于 Isaac Lab 仓库的项目
- 看懂生成项目的结构，知道任务、资产、脚本各放在哪里
- 在项目里注册任务并训练，不改 Isaac Lab 源码
:::

:class: lead-prereq

- [4.2 Isaac Lab 仓库地图](4.2-repo-map.md)

## 为什么不直接改 Isaac Lab 仓库

这一节回答：把任务写进 `isaaclab_tasks` 有什么问题？

- **升级**：改过的 Isaac Lab 仓库每次升级都要合并冲突；独立项目只需在新版本上重新安装、跑一遍测试。
- **协作**：团队只需共享自己的项目仓库，不必分发一份改过的 Isaac Lab。
- **版本管理**：项目有自己的 git 历史与版本号，训练日志中记录的是项目自己的改动。

官方模板生成器把"外部项目"（External）标为推荐选项[^cli]。

## 生成项目：`./isaaclab.sh --new`

这一节回答：模板生成器会问什么？

在 Isaac Lab 仓库根目录运行 `./isaaclab.sh --new`（或 `-n`）。它先安装生成器依赖（InquirerPy、rich、Jinja2），然后逐个提问[^sh][^cli]：

1. **Task type**：`External`（推荐，项目在 Isaac Lab 仓库之外）或 `Internal`（任务直接生成到 `source/isaaclab_tasks` 里）。如果 Isaac Lab 是用 pip 装进 site-packages 的，则不问这一项，只能选 External。
2. **Project path**：外部项目的父目录，不能位于 Isaac Lab 仓库内。
3. **Project name**：必须是合法的 Python 标识符（字母、数字、下划线），它同时是包名。
4. **Isaac Lab workflow**（可多选）：`Direct | single-agent`、`Direct | multi-agent`、`Manager-based | single-agent`。
5. **RL library**（可多选）：`rl_games`、`rsl_rl`、`skrl`、`sb3`；只选了多智能体时只有 skrl。
6. **RL algorithms**：某个库有多种算法时再问，如 skrl 的 AMP、PPO、IPPO、MAPPO。

生成器只支持交互式提问，没有命令行参数。它把回答整理成一个字典，交给 `tools/template/generator.py` 的 `generate()`[^cli][^gen]。本站为了能复现，直接用同样的字典调用 `generate()`：外部项目，名称 `academy_demo`，Manager-based 与 Direct 两种单智能体写法，RSL-RL 的 PPO。这相当于在交互界面中做同样的选择，但走的是生成器的内部函数，不是官方文档记载的用法。

生成的任务 ID 为 `Template-<名称>-v0`（Manager-based）和 `Template-<名称>-Direct-v0`（Direct）；Internal 任务以 `Isaac-` 开头[^gen]。本站实测生成 `Template-Academy-Demo-v0` 与 `Template-Academy-Demo-Direct-v0`，生成器还会在项目目录里执行 `git init`。

## 项目结构

这一节回答：生成的项目里有什么？

本站实测生成的目录（省略 `.gitignore` 等仓库配置文件）：

```text
academy_demo/
├── README.md
├── pyproject.toml                 # 代码风格配置（从 Isaac Lab 复制）
├── scripts/
│   ├── list_envs.py               # 只列出 ID 含 "Template-" 的任务
│   ├── zero_agent.py  random_agent.py
│   └── rsl_rl/                    # train.py、play.py、cli_args.py
├── source/academy_demo/           # 可安装的 Python 包
│   ├── setup.py  pyproject.toml
│   ├── config/extension.toml      # 包的元数据与依赖声明
│   ├── docs/CHANGELOG.rst
│   └── academy_demo/
│       ├── __init__.py            # 导入 tasks 与 ui_extension_example
│       ├── ui_extension_example.py
│       └── tasks/
│           ├── __init__.py        # import_packages：递归导入并注册
│           ├── manager_based/academy_demo/
│           │   ├── __init__.py    # gym.register("Template-Academy-Demo-v0")
│           │   ├── academy_demo_env_cfg.py
│           │   ├── agents/rsl_rl_ppo_cfg.py
│           │   └── mdp/rewards.py
│           └── direct/academy_demo/
│               ├── __init__.py    # gym.register("Template-Academy-Demo-Direct-v0")
│               ├── academy_demo_env.py  academy_demo_env_cfg.py
│               └── agents/rsl_rl_ppo_cfg.py
└── .vscode/                       # tasks.json 与 tools/setup_vscode.py
```

与 Isaac Lab 仓库（[4.2](4.2-repo-map.md)）对照：

| 项目中 | 对应 Isaac Lab 中 | 差别 |
|---|---|---|
| `source/<包名>/<包名>/tasks/` | `source/isaaclab_tasks/isaaclab_tasks/` | 结构相同，也用 `import_packages` 递归注册[^tasks-init] |
| `scripts/rsl_rl/train.py` 等 | `scripts/reinforcement_learning/rsl_rl/` | 复制而来，只多一行 `import <包名>.tasks`[^gen] |
| `scripts/list_envs.py` | `scripts/environments/list_envs.py` | 导入换成自己的包，过滤词由 `"Isaac"` 换成 `"Template-"` |
| `config/extension.toml`、`setup.py` | 各包的同名文件 | 依赖声明 `isaaclab`、`isaaclab_tasks` 等，不写版本 |

*表 1：生成项目与 Isaac Lab 仓库的对应（模板 v2.3.2）。*

生成脚本能找到你的任务，靠的就是这一行 `import <包名>.tasks`（发现机制见 [4.15](4.15-task-registration.md)）。

## 安装与运行

这一节回答：生成之后怎么跑起来？

在项目根目录、用装有 Isaac Lab 的 Python 环境执行（项目 README 的步骤）：

```bash
python -m pip install -e source/academy_demo     # editable 安装
python scripts/list_envs.py
python scripts/rsl_rl/train.py --task=Template-Academy-Demo-v0 --headless --num_envs 1024 --max_iterations 20
```

本站实测（clean14 环境，2026-09-30）：

- **安装**：2 秒完成。
- **列出任务**：`list_envs.py` 列出两个 `Template-Academy-Demo-*` 任务。
- **训练**：两个任务各训练 20 次迭代，都返回 0。
  - Manager-based 版含启动 15 秒，`Total timesteps: 327680`（1024 × 16 × 20）。
  - Direct 版 11 秒。
- **日志位置**：日志写在**当前目录**下的 `logs/rsl_rl/<experiment_name>/`。模板给所有任务的 `experiment_name` 都写成 `cartpole_direct`[^gen-agent]，所以两个任务的日志混在同一个目录里，生成后应改成各自的名字。

模板任务本身是一个 Cartpole，用来验证项目能跑通。

## 在项目里加资产与任务

这一节回答：自己的机器人和任务放在哪里？

以下是本站的约定（经验），第 6 部分按此组织：

- **机器人配置**（`ArticulationCfg`）：放在包内单独的模块，如 `source/<包名>/<包名>/assets/galbot.py`，任务配置从这里导入。写法见 [6.1.6](../6-galbot/1-asset/6.1.6-articulation-cfg.md)。
- **USD 与网格文件**：放在包内的数据目录，如 `source/<包名>/data/`，路径用相对包的位置计算，不写绝对路径；大文件用 Git LFS 或另行下载。
- **任务**：在 `tasks/manager_based/` 或 `tasks/direct/` 下新建子目录，在子目录的 `__init__.py` 里 `gym.register`，`import_packages` 会自动发现它。ID 可去掉 `Template-` 前缀，但要同步修改 `scripts/list_envs.py` 的过滤词。第一个任务见 [6.4.1](../6-galbot/4-task/6.4.1-reach.md)。

## 与 Isaac Lab 版本绑定

这一节回答：怎么保证项目和 Isaac Lab 版本对得上？

模板**没有**声明依赖哪个 Isaac Lab 版本：`setup.py` 的 `install_requires` 只有 `psutil`，`extension.toml` 中 `isaaclab` 等依赖不写版本[^gen-files]。v2.3.2 对应的包版本是 `isaaclab` 0.54.2、`isaaclab_tasks` 0.11.12、`isaaclab_rl` 0.4.7（各包 `config/extension.toml`），本站实测环境中的版本相同。

本站的做法（经验）：

- 在项目 README 与 `extension.toml` 的注释里写明所用的 Isaac Lab tag（如 v2.3.2）和 Isaac Sim 版本。
- 升级 Isaac Lab 时逐项检查：
  - 复制来的 `scripts/` 是否要按新版本重新复制（官方脚本会变，如 `train.py` 的参数）；
  - RL 库版本约束是否变化（[4.16](4.16-rl-wrappers.md)）；
  - 自己用到的配置字段、`mdp` 函数是否改名；
  - 重新跑 `list_envs.py` 和一次短训练。
- 迁移到 Isaac Lab 3.0 时变化较大，见 [8.4 2.3 → 3.0 迁移指南](../8-frontier/8.4-migration-23-30.md)。

## 示例

本站示例 `examples/isaaclab-2.3/4.18-extension-template/academy_demo/` 是上面生成的项目的精简版：

- **只保留 Manager-based 任务**：去掉了 Direct 任务、`.vscode/`、Docker 与代码风格配置、`zero_agent.py` / `random_agent.py`。
- **只改了一处**：`experiment_name` 由 `cartpole_direct` 改为 `academy_demo`。

本站把它复制到别处重新 editable 安装，`list_envs.py` 列出 1 个任务；训练 20 次迭代返回 0，日志写入 `logs/rsl_rl/academy_demo/`。

## 常见坑

:::{admonition} 坑一：editable 安装后移动了项目目录
:class: warning

`pip install -e` 记录的是项目的绝对路径。移动或重命名项目目录后，`import <包名>` 失败，与 Isaac Lab 仓库移动后的情况相同（见 [1.9](../1-env/1.9-install-troubleshooting.md)）。移动后在新位置重新执行 `pip install -e`。
:::

:::{admonition} 坑二：任务没被发现
:class: warning

- 用 Isaac Lab 仓库里的 `scripts/…/train.py` 训练自己的任务：那份脚本只导入 `isaaclab_tasks`，找不到你的 ID。应该用项目自己的 `scripts/`。
- 新任务目录缺少 `__init__.py`，或目录名命中了 `import_packages` 的黑名单（`utils`、`.mdp`），注册代码不会执行。
- 改了 ID 前缀后，`list_envs.py` 不再列出它（过滤词是 `"Template-"`）。
:::

:::{admonition} 坑三：VS Code 找不到 `isaaclab` 或 Isaac Sim 的模块
:class: warning

编辑器需要知道 Isaac Sim 各扩展的路径才能跳转、补全。按项目 README，在 VS Code 中运行任务 `setup_python_env`（调用 `.vscode/tools/setup_vscode.py`），输入 Isaac Sim 的安装路径；它会生成 `.vscode/.python.env` 并写入 `python.analysis.extraPaths`。另外要把 VS Code 的解释器选为装有 Isaac Lab 的那个环境。
:::

:::{admonition} 坑四：多个任务的日志混在一起
:class: warning

见上文：模板的 `experiment_name` 全是 `cartpole_direct`，而且日志写在当前目录。生成后先改 `experiment_name`，并固定在项目根目录运行脚本。
:::
