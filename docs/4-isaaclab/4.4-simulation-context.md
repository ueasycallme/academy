## `SimulationCfg`：全局参数

这一节回答：仿真的全局参数写在哪？

| 字段 | 默认 | 含义 | 对应概念 |
|---|---|---|---|
| `dt` | 1/60 | 物理步长（秒） | [3.1 时间参数](../3-isaacsim/3.1-sim-loop.md#时间参数) |
| `render_interval` | 1 | 每隔几个物理步渲染一次；`rendering_dt = dt × render_interval` | 3.1 |
| `gravity` | (0, 0, −9.81) | 重力加速度（m/s²） | [3.3](../3-isaacsim/3.3-rigid-collision.md) 场景参数 |
| `device` | `"cuda:0"` | 物理设备，`"cpu"`、`"cuda"` 或 `"cuda:N"` | 3.1 GPU 管线 |
| `use_fabric` | True | 直接读物理缓冲，不与 USD 同步（见下文） | 3.1 |
| `physx` | `PhysxCfg()` | PhysX 求解器与 GPU 缓冲区（见下一节） | 3.3 |
| `physics_material` | `RigidBodyMaterialCfg()` | 默认物理材质：静 / 动摩擦 0.5，恢复系数 0 | 3.3 |
| `render` | `RenderCfg()` | 渲染设置（抗锯齿、阴影等），默认都不改 | — |
| `physics_prim_path` | `"/physicsScene"` | PhysicsScene 的 Prim 路径 | 2.4 |
| `enable_scene_query_support` | False | 是否支持射线、重叠等场景查询；开 GUI 时会被强制打开 | — |
| `create_stage_in_memory` | False | 在内存中建 Stage | — |
| `logging_level` / `save_logs_to_file` / `log_dir` | `"WARNING"` / True / None | Isaac Lab 日志 | [1.9](../1-env/1.9-install-troubleshooting.md) |

*表 1：`SimulationCfg` 的字段与默认值（v2.3.2）[^simcfg]。*

## `PhysxCfg`：常调的字段

这一节回答：求解器和 GPU 缓冲区在哪里调？

| 字段 | 默认 | 说明 |
|---|---|---|
| `solver_type` | 1 | 0 为 PGS，1 为 TGS（见 3.3） |
| `min_position_iteration_count` / `max_…` | 1 / 255 | 场景内各物体设定的迭代次数，取最大值后夹在这个区间内 |
| `min_velocity_iteration_count` / `max_…` | 0 / 255 | 同上，速度迭代 |
| `bounce_threshold_velocity` | 0.5 | 相对速度低于它的接触不反弹（m/s） |
| `friction_offset_threshold` / `friction_correlation_distance` | 0.04 / 0.025 | 摩擦相关距离阈值 |
| `enable_ccd` / `enable_stabilization` | False / False | 连续碰撞检测（GPU 管线不支持）/ 额外稳定化 |
| `solve_articulation_contact_last` | False | 在 Articulation 求解中把接触放到最后，利于夹取（仅 Isaac Sim 5.1） |
| `gpu_max_rigid_contact_count` | 2²³ | GPU 管线的刚体接触数上限 |
| `gpu_max_rigid_patch_count` | 5 × 2¹⁵ | 接触面片数上限 |
| `gpu_found_lost_pairs_capacity` | 2²¹ | 新增 / 丢失碰撞对的缓冲区 |
| `gpu_found_lost_aggregate_pairs_capacity` / `gpu_total_aggregate_pairs_capacity` | 2²⁵ / 2²¹ | 聚合体（Articulation 等）的碰撞对缓冲区 |
| `gpu_heap_capacity` / `gpu_temp_buffer_capacity` / `gpu_collision_stack_size` | 2²⁶ / 2²⁴ / 2²⁶ | GPU 内存池 |

*表 2：`PhysxCfg` 的常调字段（v2.3.2）[^physxcfg]。*

GPU 缓冲区在仿真开始时一次分配，不会增长；超出时 PhysX 报 `PhysX error: the application need to increase the PxgDynamicsMemoryConfig::foundLostPairsCapacity parameter to …` 之类的错误[^lab-trouble]。报错中的参数名去掉前缀、改成下划线形式，就是 `PhysxCfg` 中的对应字段（如 `foundLostPairsCapacity` 对应 `gpu_found_lost_pairs_capacity`），按报错给出的数值调大即可；排查思路见 [1.9](../1-env/1.9-install-troubleshooting.md)。

## `SimulationContext`：在 Isaac Sim 之上多做了什么

这一节回答：Isaac Lab 的 `SimulationContext` 与 Isaac Sim 的是什么关系？

`isaaclab.sim.SimulationContext` 是 Isaac Sim `isaacsim.core.api.SimulationContext` 的子类，构造时把 `SimulationCfg` 转成父类参数：`physics_dt=cfg.dt`、`rendering_dt=cfg.dt × cfg.render_interval`、`backend="torch"`、`device=cfg.device`[^simctx]。它继承了父类的**单例**机制：同一进程里再次创建时返回已有实例[^sim-singleton]，所以要换配置必须先释放旧实例。

主要方法的语义与 [3.1](../3-isaacsim/3.1-sim-loop.md) 一致，Isaac Lab 做了补充[^simctx]：

- `reset()`：stop 再 play、初始化物理视图，然后额外渲染两次以准备渲染缓冲。
- `step(render=True)`：Timeline 暂停时只渲染不推进，直到恢复播放；之后调用父类推进物理。
- `render()`：按渲染模式（无渲染、部分渲染、完整渲染）刷新画面，不推进物理。

释放按 [3.2](../3-isaacsim/3.2-simulation-app.md) 的退出三步：`clear_all_callbacks()`、`clear_instance()`，然后 flush 输出、关闭应用。

## `device`：数据在哪里

这一节回答：`cuda:0` 和 `cpu` 各意味着什么？

`device` 为 `cuda:*` 时，Isaac Sim 启用 GPU 管线：GPU 宽相与 GPU 动力学、Fabric，关闭 CCD，结果留在 GPU 上；为 `cpu` 时用 CPU 求解（见 [3.1](../3-isaacsim/3.1-sim-loop.md)）。Isaac Lab 资产的 `data` 张量放在同一设备上，训练脚本可用 `--device` 切换[^train]。本站示例在两种设备上结果一致，只是张量分别位于 `cuda:0` 与 `cpu`（见下文示例）。

## `use_fabric`：与 USD 同步吗

这一节回答：Fabric 是什么，开关它有什么差别？

**Fabric** 是 Omniverse 的运行时场景数据层：可以从 USD Stage 填充，也可以直接写入不存在于 USD 中的数据，并按需把数据提供给物理、渲染等系统，适合物理仿真这类每帧都在变的数据[^fabric]。

Isaac Lab 的 `use_fabric=True`（默认）表示不再把状态逐帧同步回 USD，而是直接读物理缓冲，以适应大规模并行[^simcfg]。源码注释另有两点[^simcfg]：

- 开启时，GUI 不会实时显示物理参数的变化；
- GPU 仿真时必须开启，因为位姿是通过 Fabric 传给渲染器的；在 GPU 仿真时关闭它，仿真仍在运行，画面却不再更新。

对 USD 属性本身而言，Isaac Lab 的所有体验文件都设置了 `physics.updateToUsd = false`[^kit]，但这只是原因之一。本站实测（方块下落 1 秒，`data.root_pos_w` 在所有组合下都是 4.889 m），Prim 上 `xformOp:translate` 的高度如下：

| 设备 | `use_fabric` | `updateToUsd` 为 false（体验文件默认） | `updateToUsd` 改为 true |
|---|---|---|---|
| cuda:0 | True | 10.000 | 10.000 |
| cuda:0 | False | 10.000 | 10.000 |
| cpu | True | 10.000 | 10.000 |
| cpu | False | 10.000 | **4.889** |

*表 3：USD 属性是否跟随仿真（本站与校验方分别实测，结果一致）。`updateToUsd` 用 `--kit_args="--/physics/updateToUsd=true"` 改回 true。*

只有 `updateToUsd=true`、`use_fabric=False`、CPU 三者同时满足时，USD 属性才会跟随仿真。GPU 管线下无论怎么设置都不会更新，与 [3.1](../3-isaacsim/3.1-sim-loop.md) 在纯 Isaac Sim 中观察到的一致。Isaac Lab 默认的 GPU 与 Fabric 设置下，读状态始终用资产的 `data`（见 [4.6](4.6-assets.md)）。

## 在环境配置里的位置

这一节回答：写环境时，`SimulationCfg` 放在哪？

环境配置 `ManagerBasedRLEnvCfg` 与 `DirectRLEnvCfg` 都有一个 `sim: SimulationCfg` 字段，环境基类据此创建 `SimulationContext`[^envcfg]。环境步长由 `decimation` 与 `sim.dt` 共同决定：一个环境步 = `decimation × sim.dt`，例如 Cartpole 为 2 × 1/120 = 1/60 秒（见 [0.6](../0-map/0.6-one-step.md)）[^cartpole]。官方任务一般在 `__post_init__` 里设置 `sim.dt` 与 `sim.render_interval = decimation`；命令行覆盖 `decimation` 时不会同步更新后者，见 [4.3 常见坑三](4.3-configclass.md#常见坑)。

## 最小示例

这一节回答：怎样只用 `SimulationContext` 跑一个场景？

本站示例 `examples/isaaclab-2.3/4.4-simulation-context/sim_cfg_demo.py` 在 [3.2](../3-isaacsim/3.2-simulation-app.md) 示例的基础上，把 `dt`、`render_interval`、`gravity`、`use_fabric` 做成命令行参数，让一个方块在 10 m 高处自由下落 1 秒。本站实测（RTX 5070，headless，每次约 5 秒，均返回码 0）：

| 参数 | 设备 | 步数 | `data` 中的 z | USD 中的 z |
|---|---|---|---|---|
| 默认（dt = 1/120，g = 9.81） | cuda:0 | 120 | 4.889 m | 10.000 m |
| `--no_fabric` | cuda:0 | 120 | 4.889 m | 10.000 m |
| `--device cpu` | cpu | 120 | 4.889 m | 10.000 m |
| `--dt 0.005 --gravity -1.62` | cuda:0 | 200 | 9.170 m | 10.000 m |

*表 4：示例输出。仿真时间比步数 × dt 多约 2 个物理步（`reset()` 过程中推进的，本站实测）；按 122 步的离散积分计算，z 正好是 4.889 m，与连续公式 10 − ½gt² 的差异来自离散化。*

## 常见坑

:::{admonition} 坑一：同一进程里第二个 SimulationContext 没有生效
:class: warning

`SimulationContext` 是单例，第二次创建返回的是已有实例[^sim-singleton]，新配置不会生效。在同一个脚本里换配置，要先 `clear_all_callbacks()`、`clear_instance()`。
:::

:::{admonition} 坑二：GPU 仿真关掉 Fabric 后画面不动
:class: warning

`use_fabric=False` 且 `device` 为 GPU 时，仿真在后台照常运行，但渲染器收不到位姿更新，画面停住[^simcfg]。需要画面时保持默认的 `use_fabric=True`。
:::

:::{admonition} 坑三：读 USD 属性得不到最新状态
:class: warning

USD 属性只有在 `updateToUsd=true`、`use_fabric=False`、CPU 三者同时满足时才会跟随仿真；Isaac Lab 的默认设置（体验文件中 `updateToUsd=false`[^kit]、GPU、Fabric 开启）下，它停在初值（本站实测，见表 3）。状态一律从资产的 `data` 读。
:::

:::{admonition} 坑四：GPU 缓冲区不足
:class: warning

环境数或物体数增加后出现 `PhysX error … increase the PxgDynamicsMemoryConfig::…Capacity`，按报错中的参数名调大 `PhysxCfg` 中对应的 `gpu_*` 字段[^physxcfg][^lab-trouble]。
:::
