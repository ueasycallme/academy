## `InteractiveSceneCfg`

这一节回答：一个场景怎么写成配置？

场景配置继承 `InteractiveSceneCfg`，实体（资产、传感器、地形、灯光）以类属性的形式声明，场景的全局选项是它的字段[^scene-cfg]：

| 字段 | 默认 | 含义 |
|---|---|---|
| `num_envs` | 必填（`MISSING`） | 环境数量 |
| `env_spacing` | 必填（`MISSING`） | 环境原点之间的距离（m） |
| `replicate_physics` | True | 各环境使用相同的资产实例，物理解析更快；需要各环境资产不同时设为 False |
| `filter_collisions` | True | 不同环境之间不发生碰撞 |
| `lazy_sensor_update` | True | 传感器只在访问 `data` 时才更新 |
| `clone_in_fabric` | False | 在 Fabric 中克隆，建场景更快，但之后只能通过 USDRT 访问 Stage |

*表 1：`InteractiveSceneCfg` 的字段（v2.3.2）[^scene-cfg]。*

Cartpole 的场景只有三个实体：地面、Cartpole 机器人、一盏穹顶灯[^cartpole]。

## Prim 路径约定

这一节回答：几千个环境在 USD 里是怎么摆的？

所有环境都放在 `/World/envs` 下，依次命名为 `env_0`、`env_1`……。配置里写的 `{ENV_REGEX_NS}` 会被替换成正则路径 `/World/envs/env_.*`[^scene]，于是 `"{ENV_REGEX_NS}/Robot"` 变成 `/World/envs/env_.*/Robot`，一条路径表达式对应所有环境里的机器人（路径语法见 [2.2](../2-usd-kit/2.2-usd-concepts.md)）。

```text
/World
├── ground                 全局实体：路径不含 {ENV_REGEX_NS}，只生成一份
├── light
└── envs
    ├── env_0
    │   ├── Robot          先在 env_0 中生成
    │   └── Cube
    ├── env_1              由 env_0 克隆而来
    └── …
```

*本站示例场景的 Prim 树（节选）。*

地面、灯光这类所有环境共用的东西，路径写成 `/World/ground` 这样的绝对路径，不带环境前缀，只生成一份。如果把地面写进 `{ENV_REGEX_NS}`，每个环境都会多出一块地面。

## 克隆机制

这一节回答：场景是怎么变成 N 份的？

`InteractiveScene` 的构造过程[^scene]：

1. 用 Isaac Sim 的 `GridCloner` 定义 `/World/envs`，生成 `env_0`…`env_{N-1}` 的路径，并按 `env_spacing` 摆成网格；
2. 只在 `env_0` 里按配置生成各实体（把 `{ENV_REGEX_NS}` 替换成 `env_0` 所在的正则路径）；
3. 把 `env_0` 克隆到其余环境；
4. 按 `filter_collisions` 过滤环境之间的碰撞，与 `collision_group = -1` 的全局实体（如需要与所有环境碰撞的地面）仍可碰撞[^asset-cfg]。

Cloner 本身见 [3.7 场景组装与 Cloner](../3-isaacsim/3.7-cloner.md)。`replicate_physics=True` 时，所有环境共享同一套物理解析结果，构建更快，但各环境的资产必须一样。需要在 USD 层面让各环境不同（如随机缩放、随机纹理、随机颜色）时，要设为 False，否则这些事件会报错或不按预期工作[^events]。

本站实测环境间碰撞过滤：把 16 个环境的间距设为 0，让所有环境的方块落在同一位置。`filter_collisions=True` 时 16 个方块互不干扰，都停在 0.050 m；设为 False 后它们互相碰撞、叠在一起，最高到 0.278 m。

## 运行时访问

这一节回答：场景建好后，怎么拿到里面的东西？

| 用法 | 得到 |
|---|---|
| `scene["robot"]` | 按配置中的属性名取实体，如 `Articulation` |
| `scene.articulations` / `scene.rigid_objects` / `scene.sensors` | 按类型分组的字典 |
| `scene.keys()` | 所有实体名 |
| `scene.env_origins` | 各环境原点，形状 (num_envs, 3) |
| `scene.env_ns` / `scene.env_regex_ns` | `/World/envs` / `/World/envs/env_.*` |

*表 2：常用的运行时接口[^scene]。*

场景还有三个方法，环境在每一步的固定位置调用它们[^rlenv][^env]：

- `write_data_to_sim()`：把各资产缓存的目标（如关节位置目标）写入物理引擎，在每个物理步之前调用；
- `update(dt)`：从物理引擎读回状态，更新各资产的 `data`，在每个物理步之后调用；
- `reset(env_ids)`：重置指定环境中各实体的内部状态，在环境重置时调用。

这就是 [0.6](../0-map/0.6-one-step.md) decimation 循环中"写入 → 推进 → 读回"的三步。

## `SceneEntityCfg`：在任务里引用实体

这一节回答：观测、奖励这些函数怎么知道要用哪个关节？

Manager 的配置项用 `SceneEntityCfg` 指定作用对象：`name` 是场景中的实体名，`joint_names`、`body_names` 可以写正则，选出关节或刚体的子集[^sec]。例如 Cartpole 的 `pole_pos` 奖励用 `SceneEntityCfg("robot", joint_names=["cart_to_pole"])` 只看摆杆关节[^cartpole]。

环境初始化时，Manager 调用 `resolve(scene)`，按名字在实体上查找，把名字解析成索引写回 `joint_ids`、`body_ids`；运行时直接用这些索引切片张量，不再做字符串匹配[^sec]。

## 示例

这一节回答：自己搭一个场景，实际是什么样？

本站示例 `examples/isaaclab-2.3/4.5-interactive-scene/scene_demo.py` 的场景含地面、灯、Cartpole 和每个环境一个方块。本站实测（`--num_envs 16`，RTX 5070，headless，约 7 秒，返回码 0）：

```text
env_ns = /World/envs, env_regex_ns = /World/envs/env_.*
robot prim_path = /World/envs/env_.*/Robot
/World/envs 下的环境 Prim 数 = 16，前三个：['env_0', 'env_1', 'env_2']
env_origins 形状 (16, 3)，前三行：[[6.0, -6.0, 0.0], [6.0, -2.0, 0.0], [6.0, 2.0, 0.0]]
scene.keys() = ['terrain', 'robot', 'cube', 'ground', 'light']
robot 关节 = ['slider_to_cart', 'cart_to_pole']，joint_pos 形状 (16, 2)
```

`--device cpu` 下结果相同。

## 常见坑

:::{admonition} 坑一：路径里写死了 env_0
:class: warning

写成 `"/World/envs/env_0/Robot"`，只会有一个环境里有机器人，其余环境是空的（推断：路径表达式只匹配到 env_0）。每个环境都要有的实体，路径一律以 `{ENV_REGEX_NS}` 开头[^asset-base]。
:::

:::{admonition} 坑二：把全局实体放进了环境命名空间
:class: warning

地面、灯光、大型静态场景写成 `"{ENV_REGEX_NS}/Ground"`，会被克隆 N 份，白白增加 Prim 与碰撞体数量。所有环境共用的东西写绝对路径（如 `/World/ground`）。需要它与所有环境发生碰撞时，把 `collision_group` 设为 −1[^asset-cfg]。
:::

:::{admonition} 坑三：replicate_physics=True 时做 USD 层面的逐环境随机化
:class: warning

`randomize_rigid_body_scale`、`randomize_visual_texture_material`、`randomize_visual_color` 等事件要求 `replicate_physics=False`；纹理随机化在开启复制时会直接抛出 `RuntimeError`[^events]。做这类随机化时关闭物理复制，代价是场景构建变慢[^scene-cfg]。
:::
