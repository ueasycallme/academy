## 三类资产与配置

这一节回答：Isaac Lab 用哪些类表示仿真里的东西？

| 资产 | 配置 | 表示 |
|---|---|---|
| `Articulation` | `ArticulationCfg` | 机器人等用关节连起来的多刚体（见 [3.4](../3-isaacsim/3.4-articulation.md)） |
| `RigidObject` | `RigidObjectCfg` | 单个刚体，如被抓取的物体 |
| `DeformableObject` | `DeformableObjectCfg` | 可变形体 |
| `RigidObjectCollection` | `RigidObjectCollectionCfg` | 一组刚体，统一管理 |
| （无运行时类） | `AssetBaseCfg` | 只生成、不参与状态读写的东西，如地面、灯光 |

*表 1：资产类型（v2.3.2）[^lab-assets]。*

所有资产配置都继承 `AssetBaseCfg`，其中 `prim_path` 为必填（见 [4.5](4.5-interactive-scene.md)），此外还有三块[^asset-cfg][^art-cfg]：

- **`spawn`**：怎么生成 Prim，是一个 spawner 配置。机器人通常用 `UsdFileCfg` 引用 USD 文件，也可以用 `UrdfFileCfg`、`MjcfFileCfg` 在加载时转换（见 [3.5](../3-isaacsim/3.5-urdf-mjcf-import.md)）；配置中的 `rigid_props`、`articulation_props` 等会写入物理 Schema（见 [2.4](../2-usd-kit/2.4-physics-schema.md)）。
- **`init_state`**：默认状态。根的 `pos`、`rot`（四元数，w 在前）、`lin_vel`、`ang_vel`；关节的 `joint_pos`、`joint_vel`，以关节名正则为键，默认 `{".*": 0.0}`。
- **`actuators`**：关节分组及执行器模型，`ArticulationCfg` 中为必填（见 [4.7](4.7-actuators.md)）。

## `ArticulationData`：读状态

这一节回答：机器人状态放在哪、是什么形状、在哪个坐标系？

资产的状态都在 `data` 属性里，为 torch 张量，第一维是环境数 N[^art-data]。常用字段：

| 字段 | 形状 | 坐标系 / 说明 |
|---|---|---|
| `root_pos_w` / `root_quat_w` | (N, 3) / (N, 4) | 世界系；根连杆坐标系的位置、姿态，四元数 (w, x, y, z) |
| `root_lin_vel_w` / `root_ang_vel_w` | (N, 3) | 世界系；根的线速度与角速度 |
| `root_lin_vel_b` / `root_ang_vel_b` | (N, 3) | 基座系：根的速度在根坐标系中的表示 |
| `root_state_w` | (N, 13) | 世界系；`[pos, quat, lin_vel, ang_vel]`，位姿取根连杆坐标系，速度取质心 |
| `projected_gravity_b` | (N, 3) | 重力方向在基座系中的投影，常用于姿态观测 |
| `body_pos_w` / `body_quat_w` / `body_state_w` | (N, 刚体数, 3 / 4 / 13) | 世界系；每个刚体 |
| `joint_pos` / `joint_vel` / `joint_acc` | (N, 关节数) | 关节空间；转动关节为弧度 |
| `default_root_state` | (N, 13) | **环境系**；来自 `init_state` |
| `default_joint_pos` / `default_joint_vel` | (N, 关节数) | 来自 `init_state` |
| `joint_pos_limits` | (N, 关节数, 2) | `[下限, 上限]` |
| `joint_stiffness` / `joint_damping` | (N, 关节数) | 写入仿真的驱动增益 |
| `joint_pos_target` / `joint_effort_target` 等 | (N, 关节数) | 最近一次设定的目标 |
| `applied_torque` | (N, 关节数) | 执行器输出的关节力矩 |

*表 2：`ArticulationData` 的常用字段（v2.3.2）[^art-data]。`RigidObject` 的 `data` 有对应的根与刚体字段，没有关节字段。*

**惰性读取**：大部分字段在被访问、且缓存的时间戳落后于仿真时间戳时，才从 PhysX 视图取数（例如 `joint_pos`）[^art-data]。例外是 `joint_vel`：`update()` 每个物理步都会读取关节速度，用差分算出 `joint_acc`[^art-update]。这一点也写在 [0.6](../0-map/0.6-one-step.md) 的"常见误解"中。

本站示例实测（Cartpole，4 个环境，环境 1 的原点为 (2, 2, 0)）：`default_root_state[1, :3]` 为 (0, 0, 2)，是环境系；`root_pos_w[1]` 为 (2, 2, 2)，是世界系，两者相差一个环境原点。

## 写入接口

这一节回答：想改机器人的状态或给它指令，用哪个方法？

| 方法 | 作用 | 典型用途 |
|---|---|---|
| `set_joint_position_target()` / `set_joint_velocity_target()` / `set_joint_effort_target()` | 只设目标，缓存在资产内 | 每一步施加动作 |
| `write_data_to_sim()` | 把缓存的目标（经执行器模型）写入仿真 | 每个物理步之前，由场景统一调用 |
| `write_joint_state_to_sim()` / `write_joint_position_to_sim()` 等 | 立即把关节状态写进仿真，相当于"瞬移" | 重置 |
| `write_root_state_to_sim()` / `write_root_pose_to_sim()` / `write_root_velocity_to_sim()` | 立即写根状态（世界系） | 重置 |

*表 3：写入接口（v2.3.2）[^art]。*

"设目标"交给驱动去追，关节按物理规律运动过去；"直接写状态"跳过物理，瞬间改变状态。所以前者用在每一步：动作项会调用 `set_joint_position_target()` 等[^joint-actions]；后者用在重置：如事件 `reset_joints_by_offset` 调用 `write_joint_state_to_sim()`[^events]。在一步中间直接写状态会破坏物理连续性。

## 数据什么时候是新的

这一节回答：一步里读到的是哪一刻的状态？

`update(dt)` 推进资产内部的时间戳，使下一次访问 `data` 时重新从 PhysX 取数[^art-update]。在环境的 decimation 循环中，每个物理步之后都会由 `scene.update(dt)` 调用它（见 [4.5](4.5-interactive-scene.md)），所以观测计算时读到的是最后一个物理步之后的状态。

本站示例实测：给小车施加推力、推进 0.5 秒但不调用 `update()`，读到的小车位置仍是 0.0000；调用一次 `update()` 后变为 1.4895。

另有一个看起来像"数据没更新"、实际原因不同的现象：环境第一次 `reset()` 后关节速度全为 0，见{ref}`常见坑四 <first-reset-velocity>`。

还有一个与读回时机无关的现象：有重力时，机器人静止，读回的关节速度也不为 0。GPU 与 CPU 管线都有，官方 Franka 也有；直接从 PhysX 读的值与 `data.joint_vel` 相同，所以不是更新时机的问题。它的量级、与 dt 的关系以及对训练的影响见 [6.1.5 的"静止时的速度读数"](../6-galbot/1-asset/6.1.5-joint-drive-tuning.md)。

## 名字到索引

这一节回答：怎么找到某个关节在张量里的位置？

`find_joints()` 与 `find_bodies()` 接受名字或正则，返回索引列表与匹配到的名字[^art]。例如 Cartpole 的关节是 `['slider_to_cart', 'cart_to_pole']`，`find_joints("slider_.*")` 返回 `([0], ['slider_to_cart'])`（本站实测）。

`joint_names` 的顺序由物理引擎解析 Articulation 时决定，不一定与 URDF 中书写的顺序相同（推断：依据名字来自 PhysX 视图）。因此任务代码里一律按名字查索引，不要写死数字；Manager 中用 `SceneEntityCfg` 完成这一步（见 [4.5](4.5-interactive-scene.md)）。`find_joints` 默认按资产自身的顺序返回，传 `preserve_order=True` 才按你给出的名字顺序返回[^art]。

## `isaaclab_assets`：官方预置配置

这一节回答：常见机器人的配置从哪里拿？

`isaaclab_assets/robots/` 下有官方整理好的机器人配置，例如 `cartpole.py` 中的 `CARTPOLE_CFG`、`franka.py` 中的 `FRANKA_PANDA_CFG`，以及把肩、前臂增益调高、关闭重力的 `FRANKA_PANDA_HIGH_PD_CFG`[^lab-assets-robots]。用法是在场景配置里 `.replace(prim_path="{ENV_REGEX_NS}/Robot")`（见 [4.3](4.3-configclass.md)）。自己的机器人照同样的结构写一份 `ArticulationCfg`，Galbot 的写法见 [6.1.6](../6-galbot/1-asset/6.1.6-articulation-cfg.md)。

## 示例

这一节回答：实际读写一次是什么样？

本站示例 `examples/isaaclab-2.3/4.6-assets/articulation_data_demo.py` 加载 4 个 Cartpole，打印 `data` 字段的形状与坐标系，给小车施加 50 N 的推力并步进。本站实测（RTX 5070，headless，约 6 秒，返回码 0）节选：

```text
body_names  = ['slider', 'cart', 'pole']
body_pos_w           (4, 3, 3)
joint_pos_limits     (4, 2, 2)
joint_stiffness[0] = [0.0, 0.0], joint_damping[0] = [10.0, 0.0]
推进 0.5 s 后未 update：cart 位置 0.0000（推进前 0.0000）
调用 update() 之后：     cart 位置 1.4895
再推进 0.5 s：cart 位置 [3.992…]（到达 ±4 m 的限位附近）
```

## 常见坑

:::{admonition} 坑一：默认关节位置越限
:class: warning

`init_state.joint_pos` 中有关节超出限位时，`Articulation` 初始化即抛出 `ValueError: The following joints have default positions out of the limits`[^art-validate]（见 [3.4 常见坑三](../3-isaacsim/3.4-articulation.md#常见坑)）。
:::

:::{admonition} 坑二：环境系与世界系混用
:class: warning

`default_root_state` 在环境系，`root_pos_w` 与 `write_root_*_to_sim()` 用世界系[^art-data][^art]。重置根位置时，要把默认状态加上 `scene.env_origins` 再写入，否则所有机器人都会被放到世界原点附近（本站实测两者相差一个环境原点）。
:::

:::{admonition} 坑三：读到了没 update 的旧数据
:class: warning

自己写仿真循环时，`sim.step()` 之后没调用 `update()`（或 `scene.update()`），`data` 仍返回上一次的缓存（本站实测，见上文）。在环境类里由框架负责调用，自己写的循环要记得加。
:::

(first-reset-velocity)=
:::{admonition} 坑四：第一次 `reset()` 后，关节速度全是 0
:class: warning

- **现象**：官方 Cartpole 的 reset 事件会给关节速度加上随机偏移（小车 ±0.5、摆杆 ±0.25π），但环境创建后第一次 `env.reset()` 返回的观测中，两个速度都是 0；位置则正常随机。之后在 `step()` 内发生的重置，以及第二次 `reset()`，速度都正常随机（本站实测，GPU 与 CPU 管线相同）。
- **原因**（已由源码证实）：
  - `reset_joints_by_offset` 与 `reset_joints_by_scale` 会把采样出的速度按 `data.soft_joint_vel_limits` 夹紧[^events-clamp]。
  - 这个缓冲在 `Articulation` 初始化时建为全 0[^vel-lim-init]，只在 `write_data_to_sim()` 调用执行器模型时才填入各执行器的速度上限[^vel-lim-fill]。
  - 第一次 `reset()` 中，reset 事件运行在 `scene.write_data_to_sim()` **之前**[^env-reset]，此时上限仍是 0，速度被夹成 0 后写进了 PhysX。
  - 所以观测里的 0 就是 PhysX 中的真实速度，不是缓存没更新。
- **影响**：只影响各环境的第一个回合的初始速度。训练本身影响很小，但 RSL-RL 的适配层在创建时就会调用一次 `reset()`[^rsl-reset]，所以每个环境的第一个回合都从零速度开始。更要注意的是"`reset()` 之后立刻读状态做断言或记录"的代码，例如检查初始速度分布、录制示教起点。
- **对策**：先执行一次 `env.step()`（或第二次 `reset()`）再依赖初始速度；自己写的重置事件要夹紧速度时，用 `data.joint_vel_limits`（初始化时即从 PhysX 读入）代替 `soft_joint_vel_limits`（推断，未在上游验证）。
- **范围**：`DirectRLEnv.reset()` 同样在 `_reset_idx` 之后才 `write_data_to_sim()`[^direct-reset]；Direct 任务若在 `events` 里用这两个函数，会有同样的现象（由源码推知，未实测）。
- **上游**：截至 2026-09-30，在 Isaac Lab 的 issues 与 PR 中按 `soft_joint_vel_limits`、`reset_joints_by_offset velocity zero` 搜索，未找到对应条目。

探针脚本 `examples/isaaclab-2.3/4.6-assets/first_reset_velocity.py` 打印了各时刻的速度上限与观测。
:::
