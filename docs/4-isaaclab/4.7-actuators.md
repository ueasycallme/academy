## 隐式与显式

这一节回答：两类执行器的根本区别是什么？

- **隐式**（`ImplicitActuator`）：把 stiffness、damping 写进 PhysX 的关节驱动，目标位置、速度原样交给 PhysX，PD 由物理引擎在求解中完成（见 [3.4](../3-isaacsim/3.4-articulation.md)）。Isaac Lab 只按同一公式估算一个力矩，供奖励等使用[^pd-impl]。
- **显式**（`IdealPDActuator` 及其子类）：在 Python 中算出力矩并截断，作为力矩目标写入；此时写入 PhysX 的 stiffness、damping 被置为 0[^pd-ideal][^art-proc]。

| | 隐式 | 显式 |
|---|---|---|
| 谁算 PD | PhysX，在求解器内部 | Isaac Lab，每个物理步之前算一次 |
| 对大增益、大步长 | 稳定 | 容易振荡，本站实测见下文 |
| 可建模的电机特性 | 只有增益与限位 | 力矩-速度曲线、延迟、查表、神经网络 |
| 典型用途 | 大多数机械臂、刚度较高的关节 | 需要逼近真实电机的足式机器人等 |

*表 1：隐式与显式执行器的对比。稳定性一栏的原因推断为：隐式 PD 在求解器内部与接触、约束一起求解，显式 PD 在一个物理步内保持力矩不变。*

本站示例实测（Cartpole 小车关节，1 m 阶跃目标）：常规增益（stiffness 200，damping 20，dt 1/120）下两种模型的响应接近，0.25 秒时都已到 1 m 附近。把增益提高到 stiffness 20000、damping 200，步长改为 0.02 秒后，隐式执行器 0.24 秒时稳定在 1.000 m；`IdealPDActuator` 在 0.1 秒时冲到 1.838 m，2 秒时仍在振荡（0.876 m）。

## 模型一览

这一节回答：`isaaclab.actuators` 里有哪些模型？

| 模型（配置类） | 计算方式 | 关键参数 | 官方使用实例 |
|---|---|---|---|
| `ImplicitActuator`（`ImplicitActuatorCfg`） | PhysX 关节驱动 | stiffness、damping、effort_limit_sim、velocity_limit_sim | Cartpole、Franka |
| `IdealPDActuator`（`IdealPDActuatorCfg`） | Python 中算 PD，按力矩上限截断 | stiffness、damping、effort_limit | — |
| `DCMotor`（`DCMotorCfg`） | 理想 PD，按直流电机的力矩-速度曲线截断 | 另加 `saturation_effort`、velocity_limit | ANYmal、Unitree |
| `DelayedPDActuator`（`DelayedPDActuatorCfg`） | 理想 PD，命令延迟若干物理步（每个环境随机） | `min_delay`、`max_delay` | Spot |
| `RemotizedPDActuator`（`RemotizedPDActuatorCfg`） | 延迟 PD，力矩上限随关节角查表插值 | `joint_parameter_lookup` | Spot |
| `ActuatorNetMLP` / `ActuatorNetLSTM`（对应 Cfg） | 用神经网络由位置误差、速度预测力矩 | `network_file`；MLP 另有缩放与输入顺序参数 | Unitree / ANYmal |

*表 2：执行器模型（v2.3.2）[^pd-cfg][^net]。官方使用实例指 `isaaclab_assets` 中的机器人配置。*

显式 PD 的力矩：

$$
\tau = K_p\,(q^* - q) + K_d\,(\dot q^* - \dot q) + \tau_{ff}
$$

其中 $\tau$ 为关节力矩（N·m，平移关节为 N），$K_p$、$K_d$ 为 stiffness、damping，$q^*$、$\dot q^*$ 为目标位置与速度，$q$、$\dot q$ 为当前值，$\tau_{ff}$ 为前馈力矩（effort 目标）。`IdealPDActuator` 将结果截断到 $[-\tau_{\lim},\ \tau_{\lim}]$，$\tau_{\lim}$ 即 `effort_limit`[^pd-ideal]。

`DCMotor` 的截断区间随速度变化：

$$
\tau_{\max} = \min\!\left(\tau_{\mathrm{sat}}\left(1 - \frac{\dot q}{\dot q_{\max}}\right),\ \tau_{\lim}\right),\qquad
\tau_{\min} = \max\!\left(\tau_{\mathrm{sat}}\left(-1 - \frac{\dot q}{\dot q_{\max}}\right),\ -\tau_{\lim}\right)
$$

其中 $\tau_{\mathrm{sat}}$ 为 `saturation_effort`（零速时电机能给出的最大力矩），$\dot q_{\max}$ 为 `velocity_limit`（零力矩时的最大转速），$\dot q$ 为当前关节速度。转得越快，同方向能给的力矩越小[^dc]。

## 配置方式

这一节回答：`actuators` 字典怎么写？

`ArticulationCfg.actuators` 是一个字典，每项是一组关节及其执行器配置，`joint_names_expr` 用正则选出这组关节。例如 Cartpole 分成 `cart_actuator` 与 `pole_actuator` 两组[^cartpole]。每组的主要字段[^base-cfg]：

| 字段 | 作用 |
|---|---|
| `stiffness` / `damping` | 增益，单位按弧度（见 [3.4 坑二](../3-isaacsim/3.4-articulation.md#常见坑)）；为 None 时用 USD 中的值 |
| `effort_limit_sim` | 写入 PhysX 的力矩上限，求解器用它截断；隐式执行器未设置时取 USD 中的值，显式执行器默认 1e9（不在 PhysX 层截断） |
| `effort_limit` | 显式执行器在模型内截断用的力矩上限；未设置时取 USD 中的值。隐式执行器上与 `effort_limit_sim` 等价 |
| `velocity_limit_sim` | 写入 PhysX 的关节速度上限 |
| `velocity_limit` | 显式执行器模型内使用；隐式执行器只应设置 `velocity_limit_sim`，两者都设且不相等时报错 |
| `armature` / `friction` | 关节惯量、摩擦（见 [3.4](../3-isaacsim/3.4-articulation.md)） |

*表 3：执行器配置的主要字段（v2.3.2）[^base-cfg][^base][^pd-impl]。旧资料中常见只写 `effort_limit` 的写法，在 v2.3.2 中对显式执行器只约束模型内的截断，不约束 PhysX。*

字段值可以是一个数，也可以是 `{关节名正则: 值}` 的字典。**与 URDF 转换器不同**，这里的字典不允许同一关节被两个键匹配：Isaac Lab 用 `resolve_matching_names_values` 解析，重叠时直接报错[^string]。本站实测：`stiffness={".*": 200, "slider_.*": 200}` 报 `ValueError: Multiple matches for 'slider_to_cart': '.*' and 'slider_.*'!`。[3.5](../3-isaacsim/3.5-urdf-mjcf-import.md) 中转换器那种"后键覆盖前键"的写法，在执行器配置里不适用。

## 执行器参数与 USD 驱动参数

这一节回答：配置里的值和 USD 里的 DriveAPI 值谁说了算？

创建 `Articulation` 时，Isaac Lab 先从仿真中读出 USD 里的默认增益、限位等，作为各执行器的默认值；配置中写了的字段覆盖默认值；然后隐式执行器把最终的 stiffness、damping 写回 PhysX，显式执行器写 0，两者都写入 `effort_limit_sim`、`velocity_limit_sim`、armature、friction[^art-proc]。所以：

- 配置里写了，以配置为准，USD 里的值被覆盖；
- 配置里没写（None），沿用 USD 中的值。

这也是 [2.4](../2-usd-kit/2.4-physics-schema.md) 中 Galbot 那处不一致的处理方式：URDF 的 effort 为 60，厂商 USD 的 `maxForce` 为 1000。在 Isaac Lab 中给这些关节写上 `effort_limit_sim`，就不再依赖 USD 里的值。

## 参数从哪里来

这一节回答：stiffness、力矩上限这些数，该填多少？

- **厂商手册**：电机的额定与峰值力矩、最大转速、减速比，可直接给出 `effort_limit`、`velocity_limit`，以及 `DCMotor` 的 `saturation_effort`。
- **系统辨识**：在真机上做阶跃、扫频等实验，拟合增益、摩擦、延迟。方法见 [6.3.2](../6-galbot/3-sim-align/6.3.2-sim-vs-real.md)。
- **ActuatorNet**：需要真机上"命令、位置误差、速度、实际力矩"的成对数据训练网络，数据要求最高。
- **没有真机数据时**（本站 D-004 的情况）：用厂商给出的限位，增益取保守值，优先用隐式执行器保证稳定，并在训练中对增益、延迟做域随机化（见 [4.12](4.12-event-randomization.md)）。这一条是经验性做法（推断），实际效果要在真机上验证。

Galbot 关节驱动的调参见 [6.1.5](../6-galbot/1-asset/6.1.5-joint-drive-tuning.md)。

## 示例

这一节回答：两种模型的响应实际差多少？

本站示例 `examples/isaaclab-2.3/4.7-actuators/actuator_step_demo.py` 让同一个 Cartpole 小车关节分别使用 `ImplicitActuatorCfg` 与 `IdealPDActuatorCfg`，跟踪 1 m 的阶跃目标。本站实测（RTX 5070，headless，每次 6–9 秒，均返回码 0）：

| 设置 | t = 0.1 s | 0.25 s | 0.5 s | 2.0 s |
|---|---|---|---|---|
| 隐式，Kp 200，Kd 20，dt 1/120 | 0.424 | 0.987 | 0.997 | 0.968 |
| IdealPD，同上 | 0.459 | 1.001 | 0.992 | 0.979 |
| 隐式，Kp 20000，Kd 200，dt 0.02 | 1.082 | 1.000（0.24 s） | 1.000 | 1.000 |
| IdealPD，同上 | 1.838 | 1.080（0.24 s） | 0.955 | 0.876 |

*表 4：小车位置（m）。常规增益下的缓慢漂移来自没有控制的摆杆。IdealPD 运行时，写入 PhysX 的刚度与阻尼均为 0，与"显式执行器写 0"一致。*

## 常见坑

:::{admonition} 坑一：显式执行器只设了 effort_limit_sim
:class: warning

显式执行器在模型内按 `effort_limit` 截断，它未设置时取 USD 中的值；`effort_limit_sim` 只在 PhysX 层截断[^base-cfg]。本站示例中 `IdealPDActuator` 只设了 `effort_limit_sim=400`，模型输出的 `applied_torque` 峰值却达 1000 N。要约束电机输出，两个字段都要设，或至少设 `effort_limit`。
:::

:::{admonition} 坑二：正则键重叠
:class: warning

执行器配置的字典中，一个关节被两个键匹配会直接报 `ValueError: Multiple matches`（本站实测）[^string]。按关节分组时，保证各键互不重叠。
:::

:::{admonition} 坑三：大增益配显式执行器
:class: warning

显式 PD 在一个物理步内保持力矩不变，增益过大或步长过大时会振荡甚至发散（本站实测，见表 4）。高刚度关节优先用隐式执行器；必须用显式模型时，减小 `sim.dt` 或降低增益。
:::

:::{admonition} 坑四：隐式执行器设了 velocity_limit
:class: warning

隐式执行器应只设 `velocity_limit_sim`。只设 `velocity_limit` 时会给出警告，且该值不生效；两者都设却不相等时直接报错[^pd-impl]。
:::
