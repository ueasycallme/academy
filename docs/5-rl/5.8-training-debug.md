# 训练不收敛怎么排查

:::{admonition} 学习目标
:class: lead-goals

- 训练出问题时，按固定顺序排查，而不是先调超参
- 用现成的脚本和几行代码检查环境本身
- 由日志里的症状查到可能的原因
:::

:::{admonition} 前置知识
:class: lead-prereq

- [5.3 PPO 工作流程](5.3-ppo.md)（日志怎么读）
- 第 4 部分各页的常见坑
:::

本页是参考页：训练出问题时回来查。

## 排查顺序

这一节回答：从哪里查起？

```{mermaid}
flowchart LR
    A["环境自检"] --> B["观测与动作"] --> C["奖励与终止"] --> D["算法信号"] --> E["超参数"]
```

*图 1：排查顺序，自左向右。越靠左越常见、越便宜。*

**先怀疑环境，后怀疑算法。** PPO 与官方超参数在大量任务上验证过；新写的任务出问题，多半是环境本身的错：观测有误、动作尺度不对、奖励符号反了、终止条件写错。环境没确认之前调超参，往往只是在掩盖问题（经验性）。

## 环境自检清单

这一节回答：训练前该确认哪些事？

每一条都不需要训练，几秒到几十秒就能做完。

1. **零动作与随机动作能跑起来**。在 Isaac Lab 仓库根目录运行（外部项目用项目自己的 `scripts/`，见 [4.18](../4-isaaclab/4.18-extension-template.md)）：

   ```bash
   ./isaaclab.sh -p scripts/environments/zero_agent.py --task <任务 ID> --num_envs 16 --headless
   ./isaaclab.sh -p scripts/environments/random_agent.py --task <任务 ID> --num_envs 16 --headless
   ```

   两个脚本都是无限循环，看到启动时各 Manager 的 Term 表、没有报错后手动结束即可（[4.9](../4-isaaclab/4.9-manager-based-env.md)）。零动作下机器人应当保持在默认姿态附近；如果零动作就自己飞走或抖动，先查执行器增益与默认关节位置（[4.7](../4-isaaclab/4.7-actuators.md)）。

2. **观测的量级合理、没有 NaN**。本站脚本 `examples/isaaclab-2.3/5.8-training-debug/check_env.py` 用随机动作运行若干步，逐步检查观测与奖励有无 NaN / Inf（出现时报告步数与环境编号），最后打印各观测维度的最小、最大值，每步奖励的范围，以及各终止项的触发次数：

   ```bash
   python examples/isaaclab-2.3/5.8-training-debug/check_env.py --headless --task Isaac-Cartpole-v0
   ```

   本站实测 Cartpole 200 步：没有 NaN；摆杆角速度的最大、最小值正好是 ±8.0，就是它的速度上限。观测贴着某个整齐的数值不动，往往说明撞上了限位。看各维观测是否在预期量级内：角度在几弧度以内，速度不应上千。量级相差很大时，考虑开观测归一化（[5.2](5.2-policy-value.md)）。

3. **动作尺度与关节限位匹配**：`scale` 乘以 1 之后的目标，是否在关节行程内；位置动作的执行器是否有刚度（[4.10 常见坑二](../4-isaaclab/4.10-observation-action.md#常见坑)）。

4. **reset 后的状态合理**：初始状态是否真的随机、是否落在期望范围内。注意要看第二个回合起的状态：第一次 `reset()` 时，reset 事件设的随机关节速度会被夹成 0（[4.6 常见坑四](../4-isaaclab/4.6-assets.md#常见坑)）。

5. **关掉噪声与随机化做对照**：把观测组的 `enable_corruption` 设为 False、去掉域随机化事件，看能否学会。能学会，说明问题出在随机化范围上（[4.12](../4-isaaclab/4.12-event-randomization.md)）。

## 症状 → 可能原因 → 怎么查

这一节回答：看到某个现象，该查什么？

| 症状 | 可能原因 | 怎么查 |
|---|---|---|
| 回报始终不涨 | 奖励符号反了；任务项被惩罚项淹没 | 看 `Episode_Reward/*` 的符号与量级，哪一项主导（[4.11](../4-isaaclab/4.11-reward-termination-curriculum.md)） |
| 回合长度一直很短 | 终止条件太严或写错；初始状态就触发终止 | 看 `Episode_Termination/*` 哪一项占比高；零动作跑一次，看多少步后结束 |
| 回合总是跑满、但行为不对 | 奖励能被"钻空子"，如原地不动也能拿存活分 | `play.py` 看行为；检查各奖励项是否真的鼓励任务目标（[5.5](5.5-reward-design.md)） |
| 回报涨了、行为仍不对 | 奖励与想要的行为不一致 | 同上；比较各分项奖励随训练的变化 |
| 超时被当成失败 | 超时项忘了写 `time_out=True` | 看 Termination Manager 表的 Time Out 列（[4.11](../4-isaaclab/4.11-reward-termination-curriculum.md)） |
| noise std 越来越大 | 策略找不到方向，靠增大随机性；熵系数过大 | 看回报是否停滞；检查 `entropy_coef`（[5.3](5.3-ppo.md)） |
| noise std 很快塌到很小，回报停在低位 | 过早收敛到差的策略 | 看是否一开始就有容易拿的奖励；可适当增大 `entropy_coef` |
| value loss 暴涨 | 奖励量级突变或过大；观测出现极端值 | 看 `Episode_Reward/*` 量级；按自检第 2 条查观测 |
| 出现 NaN，训练中断 | 除零、开方负数、物理爆炸 | 见下文"NaN 专项" |
| 学习率一直被压在 1e-5 | 每次更新 KL 都远超 `desired_kl` | 看 TensorBoard 的 `Loss/learning_rate`；检查观测与奖励量级（[5.3](5.3-ppo.md)） |
| 回放效果比训练差很多 | 用训练配置回放，观测噪声仍开着；或配置不一致 | 用 `-Play` 配置；确认 `enable_corruption=False`（[4.10](../4-isaaclab/4.10-observation-action.md)、[4.15](../4-isaaclab/4.15-task-registration.md)） |
| 换了 num_envs 结果变了 | 每次迭代的批量与小批量随之改变 | 同时看批量大小；按新的批量调整迭代数（[5.4](5.4-parallel-envs.md)） |
| 命令行改了参数却没生效 | 覆盖发生在 `__post_init__` 之后，派生值没跟着变 | 看 `params/env.yaml`；同时覆盖派生字段（[4.3 常见坑三](../4-isaaclab/4.3-configclass.md#常见坑)） |
| 改了环境配置里的种子却没生效 | `train.py` 用 agent 的种子覆盖环境种子 | 用 `--seed` 或 `agent.seed=…`（[4.16](../4-isaaclab/4.16-rl-wrappers.md)） |
| 改了奖励权重、训练行为完全变了 | 奖励乘了 dt，改 decimation 或 dt 也会改变奖励尺度 | 看 `step_dt`；同一对比中保持时间参数不变（[4.11](../4-isaaclab/4.11-reward-termination-curriculum.md)） |
| 位置动作下机器人不动 | 执行器刚度为 0 | 检查执行器配置（[4.7](../4-isaaclab/4.7-actuators.md)、[4.10](../4-isaaclab/4.10-observation-action.md)） |
| `reset()` 后立刻读到的速度全为 0，第一个回合初始状态不随机 | 第一次 reset 时速度上限尚未填入，速度被夹成 0 | 从第二个回合起再检查；见 [4.6 常见坑四](../4-isaaclab/4.6-assets.md#常见坑) |
| 训练中途报错退出 | 显存不足；物理爆炸产生的 NaN | 看报错信息；按进程测显存（[1.3](../1-env/1.3-hardware.md)）；减少 num_envs |

*表 1：常见症状与排查方向。"可能原因"是经验性的，按从常见到少见排列；"怎么查"链接到本站已实测核实的页面。*

## 日志里的信号

这一节回答：日志里哪几项最值得看？

- **分项奖励**（`Episode_Reward/*`）：各项的相对量级，判断谁在主导。
- **终止原因占比**（`Episode_Termination/*`）：失败类下降、超时上升，通常是好迹象。
- **noise std**：应平稳下降；一直上升或骤降都要警惕。
- **学习率**（TensorBoard `Loss/learning_rate`）：adaptive 模式下反映 KL 的大小；长期贴着上限或下限都说明更新幅度不正常。

各项的含义见 [5.3](5.3-ppo.md)。

## 回放排查

这一节回答：怎么看策略实际在做什么？

```bash
./isaaclab.sh -p scripts/reinforcement_learning/rsl_rl/play.py --task <任务 ID>-Play-v0 --num_envs 16
./isaaclab.sh -p scripts/reinforcement_learning/rsl_rl/play.py --task <任务 ID>-Play-v0 --num_envs 16 --headless --video --video_length 200
```

- 第一条打开图形界面，直接看行为。
- 第二条在无界面时录一段视频，存到检查点所在日志目录下的 `videos/play/`。加 `--video` 时脚本会自动开启相机渲染，并在录满 `--video_length` 步后自行退出；不加时会一直回放，需要手动结束[^play]。本站用 `Isaac-Cartpole-v0`（它没有 `-Play` 变体）实测：22 秒后返回 0，生成 `rl-video-step-0.mp4`（约 0.5 MB）。
- 回放用带 `-Play` 的任务 ID：环境更少、关闭观测噪声与随机推搡（[4.15](../4-isaaclab/4.15-task-registration.md)）。
- 如果任务没有注册 `-Play` 变体，要自己确认噪声已关。

## NaN 专项

这一节回答：训练里出现 NaN，怎么找源头？

常见来源（经验性）：

- **除零**：奖励或观测里有除以距离、除以速度的运算。
- **越界的数学运算**：如 `acos` 的输入略超出 [−1, 1]、对负数开方。
- **物理爆炸**：步长过大、增益过高、初始状态互相穿透，导致速度或位置变成极大值，再变成 NaN。

定位方法：按自检第 2 条，每步检查观测与奖励有无 NaN，找到第一次出现的步数与环境编号，再看那个环境的关节状态；逐项调用奖励函数，看是哪一项先出问题。物理爆炸时，先减小 `sim.dt` 或执行器增益做对照。

## 什么时候该调超参数

这一节回答：环境确认无误后，先调哪几个？

环境自检全部通过、日志信号也看不出环境问题时，再调超参数。先调影响最直接的几个（经验性）：

- `num_steps_per_env` 与 `num_envs`（每次迭代的数据量）；
- `learning_rate` / `desired_kl`；
- `entropy_coef`；
- 网络规模。

每次只改一个，用同一个种子对比。主线任务的调参实践见 [6.5.2](../6-galbot/5-train/6.5.2-hyperparameters.md)。

## 求助前准备什么

这一节回答：在论坛或 issue 里提问，需要附上什么？

- **版本信息**：Isaac Sim、Isaac Lab（tag）、RL 库版本、GPU 与驱动。
- **任务配置**：训练日志目录下的 `params/env.yaml` 与 `params/agent.yaml`，它们记录了实际生效的配置。
- **日志片段**：出问题前后若干次迭代的完整输出。
- **最小复现**：能复现问题的最短命令，最好基于官方任务，只改一两处。
