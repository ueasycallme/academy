## 机器人概览

这一节回答：这台机器人由什么组成？

Galbot One Golf 是一台轮式双臂机器人。以下数字全部由本站脚本 `scripts/galbot_joint_stats.py` 从固定 commit 的预置 URDF 统计得出[^urdf]：

| 部件 | 可动关节 | 说明 |
|---|---|---|
| 全向轮底盘 | 4 个主动轮关节 + 40 个被动滚子关节 | 仅在 `galbot_one_golf.urdf` 中；固定底座版把 4 个轮关节改为固定、去掉滚子 |
| 腿 / 躯干升降 | 5 | `leg_joint1`–`5` |
| 头 | 2 | `head_joint1`–`2` |
| 左臂、右臂 | 各 7 | `left_arm_joint1`–`7`、`right_arm_joint1`–`7` |
| 左、右夹爪 | 各 6 | 其中 5 个是 mimic 关节，跟随 `*_gripper_joint`，独立自由度各 1 |

*表 1：Galbot One Golf 的部件与关节（commit 2d496b0）。全身共 103 个关节：33 个 revolute、44 个 continuous、26 个 fixed，与 [3.4 表 1](../../3-isaacsim/3.4-articulation.md) 一致。*

传感器以固定连杆的形式出现在 URDF 中：底盘激光雷达 `chassis_lidar`，以及左右手腕相机 `*_wrist_camera_link`。两只夹爪各有一个工具中心点（TCP）连杆 `*_gripper_tcp_link`。机器人的根连杆是 `base_link`。

## 仓库结构

这一节回答：仓库里每个目录是做什么的？

| 目录 | 内容 |
|---|---|
| `xacro/` | 机器人描述的源文件：整机 `robot.xacro`，以及各部件 |
| `urdf/` | 两个预置 URDF：`galbot_one_golf.urdf`（轮式底盘）与 `galbot_one_golf_fixed_base.urdf`（固定底座） |
| `mjcf/` | MuJoCo 模型：轮式、固定底座、虚拟平面底座三个变体 |
| `usd/` | USD 模型：入口 `galbot_one_golf.usda`，以及 `payloads/`、`Textures/` 和示例场景 `env/` |
| `meshes/` | 视觉与碰撞网格 |
| `scripts/` | `create_description.py`（由 xacro 生成 URDF），以及检查 TCP 坐标系与夹爪碰撞体的脚本 |
| `config/` | 生成 MJCF 所用的关节参数与附录（`config/mjcf/`），以及 RViz 配置 |
| `launch/` | ROS 2 的显示用 launch 文件 |

*表 2：仓库目录（commit 2d496b0），依据仓库 README 的"Package Layout"一节与实际目录[^readme]。*

## 三种格式的角色

这一节回答：URDF、MJCF、USD，哪个是源头？

- **xacro 是源**。`scripts/create_description.py` 由它生成 URDF，运行时会交互式询问末端执行器、轮子配置和输出路径[^readme]。
- **URDF 由 xacro 生成**，是本站主线导入 Isaac Sim 的起点（[6.1.2](6.1.2-import-urdf.md)）。
- **MJCF 由 URDF 转换而来**，用 `urdf-to-mjcf` 加上 `config/mjcf/` 中的参数生成，命令见仓库的 `docs/mjcf.md`[^mjcf-doc]。
- **USD 是厂商提供的另一份模型**。仓库说明了入口文件，但没有说明它由什么工具、从哪份描述生成。它与自己从 URDF 导入的结果有哪些不同，见 [6.1.3](6.1.3-vendor-vs-imported-usd.md)。

本站主线不从 MJCF 出发：Galbot 的 MJCF 在 Isaac Sim 5.1 上需要手动启用导入扩展，转换后得到两个 Articulation 根，而且转换失败时返回码仍为 0（[3.5](../../3-isaacsim/3.5-urdf-mjcf-import.md)）。

## 一处出入：被动滚子关节

这一节回答：预置 URDF 里到底有没有被动滚子？

仓库 README 写道，预置 URDF 省略了全向轮的被动滚子关节[^readme-roller]。但在固定 commit 上核对，两个预置文件并不一样：

- `galbot_one_golf.urdf` **包含** 40 个被动滚子关节（`wheel_1_passive_0_joint` 至 `wheel_4_passive_9_joint`，每个轮 10 个，类型为 continuous），加上 4 个主动轮关节，共 44 个 continuous 关节[^urdf]。
- `galbot_one_golf_fixed_base.urdf` 确实**没有**滚子：连杆由 104 个减到 64 个，4 个轮关节改为 fixed。

原因可以从生成脚本看出：xacro 的 `enable_passive_wheels` 默认为 false[^xacro]，而 `create_description.py` 提供"Continuous wheel joints + passive rollers"选项[^create]；仓库里的轮式预置显然是用这个选项生成的（推断，依据是文件中确实存在这些关节）。所以结论是：**README 的这句话对固定底座版成立，对轮式预置不成立。**

对后续导入的影响：从轮式 URDF 导入时，会多出 40 个没有驱动的被动关节。本站在 [3.5](../../3-isaacsim/3.5-urdf-mjcf-import.md) 的转换中看到的正是 40 个零增益的滚子关节。主线的 reach 任务用固定底座（D-003），从 `galbot_one_golf_fixed_base.urdf` 出发，就不会遇到它们。

## 许可与署名

这一节回答：本站怎样使用这个仓库？

Galbot 描述仓库以 Apache License 2.0 发布[^license]，版权归原作者。本站不分发它的任何文件：页面只引用短片段，主线项目用脚本从 GitHub 克隆并固定到 commit `2d496b0`；转换得到的 USD 等派生物在读者本机生成，也不提交。

## 搭建项目骨架

这一节回答：第 6 部分的代码放在哪里？

第 6 部分的全部代码放在同一个外部项目 `examples/isaaclab-2.3/6-galbot-project/` 中，包名 `galbot_academy`，每一页往里加文件。它由 Isaac Lab v2.3.2 的模板生成器生成（Manager-based 单智能体、RSL-RL 的 PPO），再按 [4.18](../../4-isaaclab/4.18-extension-template.md) 的方式精简。精简与修改的细节见项目 README。

**本页新增的文件：**

| 文件 | 作用 |
|---|---|
| `scripts/fetch_galbot.sh` | 克隆 Galbot 描述仓库并固定到 `2d496b0` |
| `source/galbot_academy/galbot_academy/assets/paths.py` | 资产目录约定：环境变量 `GALBOT_DESCRIPTION_DIR`（默认 `<项目根>/third_party/galbot_one_golf_description`）与 `GALBOT_GENERATED_DIR`（默认 `<项目根>/generated`） |
| `scripts/galbot_joint_stats.py` | 统计两个预置 URDF 的关节（表 1 的来源），不需要 Isaac Sim |
| `.gitignore` | 忽略 `third_party/`、`generated/`、`logs/` |

**验证**（在项目根目录，用装有 Isaac Lab 的 Python 环境）：

```bash
bash scripts/fetch_galbot.sh
python -m pip install -e source/galbot_academy
python scripts/galbot_joint_stats.py
python scripts/list_envs.py
```

本站实测：克隆约 6 秒、约 76 MB；统计脚本的输出与表 1 一致；`list_envs.py` 返回 0，打印空表，因为此时还没有任务。

## 常见坑

:::{admonition} 坑一：把 Isaac Lab 自带的 Galbot 当成 One Golf
:class: warning

Isaac Lab 2.3.2 的 `isaaclab_assets` 中有 `GALBOT_ONE_CHARLIE_CFG`，官方的 `Isaac-Stack-Cube-Galbot-*` 任务用的也是它[^charlie]。那是另一个型号（One Charlie），资产来自 Nucleus，与本站使用的 One Golf 描述仓库无关。
:::

:::{admonition} 坑二：`list_envs.py` 列出了官方的 Galbot 任务
:class: warning

模板的 `list_envs.py` 按子串过滤任务 ID。改成"含 `Galbot-`"会把 `Isaac-Stack-Cube-Galbot-*` 也列出来。本项目改为"以 `Galbot-` 开头"，并约定自己的任务 ID 都用这个前缀。
:::

:::{admonition} 坑三：没有固定 commit
:class: warning

描述仓库仍在更新，比如 CHANGELOG 中记录过根连杆与 TCP 坐标系的修改[^changelog]。直接用最新的 `main`，关节名、坐标系、质量都可能与本站页面对不上。用 `fetch_galbot.sh` 固定到 `2d496b0`，升级时再逐项核对。
:::

:::{admonition} 坑四：重定向输出时看不到表格
:class: warning

`list_envs.py` 打印表格后立即关闭仿真应用。本站实测：把输出重定向到文件时，文件里没有表格；设 `PYTHONUNBUFFERED=1` 后表格正常写出。[1.9](../../1-env/1.9-install-troubleshooting.md) 也建议无人值守运行时设这个变量。
:::
