# 对比厂商 USD 与自导入 USD

:::{admonition} 学习目标
:class: lead-goals

- 用脚本按同一组维度比较两份机器人 USD
- 说出 Galbot 厂商 USD 与自导入 USD 的关键差异，以及在 Isaac Lab 里最终生效的是哪个值
- 为自己的机器人做"用哪份资产"的判断
:::

:::{admonition} 前置知识
:class: lead-prereq

- [2.4 Schema：USD 如何描述物理](../../2-usd-kit/2.4-physics-schema.md)
- [6.1.2 从 URDF 导入 Isaac Sim](6.1.2-import-urdf.md)
:::

Galbot 仓库自带一份 USD（`usd/galbot_one_golf.usda`，下称"厂商版"）；[6.1.2](6.1.2-import-urdf.md) 从 URDF 转出了自己的一份（下称"自导入版"）。本页比较两者，决定主线用哪一份。**本页在项目中新增两个脚本**：

- `scripts/compare_usd.py`：静态比较，只需 usd-core；
- `scripts/hold_pose.py`：在 Isaac Lab 里保持零位的稳定性测试。

## 对比维度

这一节回答：两份 USD 差在哪？

```bash
python scripts/compare_usd.py            # 不需要 Isaac Sim；默认比较厂商版与 generated/ 下的两份自导入版
```

| 维度 | 厂商版 | 自导入版（轮式 URDF） | 自导入版（固定底座 URDF，主线） |
|---|---|---|---|
| defaultPrim | `/galbot_one_golf` | 同左 | 同左 |
| 变体集（默认选择） | Physics（physx）、Sensor（none）、Robot（none）、ROS（none） | Physics、Sensor、Robot（转换器生成） | 同左 |
| 实例（instance）Prim | 190 | 110 | 66 |
| Articulation 根 | `base_link`（浮动） | `root_joint`（固定到世界） | 同左 |
| 刚体 / 转动关节 | 78 / 77 | 78 / 77 | 34 / 33 |
| 带驱动的关节 | 27 | 67（含 40 个零增益滚子） | 23 |
| mimic 关节 | 10（固有频率 0） | 10（改为 1000） | 10（改为 1000） |
| `left_arm_joint1` 的 stiffness / damping | 100000 / 10000（每度） | 6.98 / 0.698（每度） | 同左 |
| `left_arm_joint1` 的 maxForce | 1000 | 60 | 60 |
| 总质量 | 95.184 kg | 95.184 kg | 95.184 kg |
| 碰撞体 | 184 个，网格为凸包 | 同左 | 同左 |
| 自碰撞 | 关闭 | 关闭 | 关闭 |
| 材质数 | 222 | 227 | 227 |
| 单位与朝向 | 1 m，Z 向上 | 同左 | 同左 |
| 用到的图层文件 / 大小 | 12 个 / 6.4 MB | 5 个 / 7.4 MB | 5 个 / 7.4 MB |

*表 1：三份 USD 的统计（本站实测，`compare_usd.py`；实例内部的 Prim 也计入物理统计）。厂商版的 stiffness 与 damping 以"每度"为单位，换算成每弧度分别约为 5.73×10⁶ 与 5.73×10⁵（[3.4](../../3-isaacsim/3.4-articulation.md)）。*

质量与碰撞体完全一致，说明两份资产来自同一套网格与惯性参数。差别集中在**关节驱动**和**组织方式**上。

## 关键差异

这一节回答：哪些差异会影响仿真？

**力矩上限：60 还是 1000。** URDF 中 `left_arm_joint1` 的 `effort` 是 60，厂商 USD 的 `maxForce` 是 1000（2.4 的发现）。逐个关节对照可以看出规律：

- 厂商版给腿和双臂的 19 个关节**统一**设为 maxForce 1000、stiffness 100000/°；
- URDF 按关节给出 169、84、60、30、10 等不同的值；
- 夹爪则反过来，厂商版为 10，URDF 为 50；头部两者都是 4。

统一的大数更像是"让关节几乎刚性地跟住目标"的设置，按关节区分的 URDF 值更接近各关节的额定力矩。所以本站认为 URDF 的值更可信（推断，依据是上述规律；本站没有真机数据可以核对，D-004）。

**在 Isaac Lab 里生效的是谁：USD 里写的那个。** `hold_pose.py` 用 `ImplicitActuatorCfg` 且不设增益与上限时，读出的 `left_arm_joint1`：

- 厂商版：stiffness 5729578 N·m/rad，力矩上限 1000 N·m；
- 自导入版：stiffness 400，力矩上限 60。

也就是说，不在 `ArticulationCfg` 里显式设置时，USD 中的值就是最终值。显式执行器只设 `effort_limit_sim` 时，模型内部仍按 USD 的值截断（[4.7](../../4-isaaclab/4.7-actuators.md)）。所以，无论选哪份资产，都要在 [6.1.6](6.1.6-articulation-cfg.md) 的执行器配置里明确写出力矩上限与增益。

**驱动增益。** 厂商版的腿、臂增益约为自导入版的 1.4 万倍。它让关节几乎不受重力影响（下一节），但这么大的刚度不代表真实电机，也会让策略学到真机做不到的响应（[3.4](../../3-isaacsim/3.4-articulation.md)）。

**碰撞体。** 两者都是 184 个碰撞体、144 个网格凸包。仓库 README 提到厂商版为指尖单独设了摩擦 1.5 的物理材质；自导入版没有这一步，要在 [6.1.4](6.1.4-collision-mass-inertia.md) 自己补上。

**组织方式。** 厂商版用变体集切换物理（none / physics / physx）、传感器、机器人配置与 ROS 2 接口（各有 none 与启用两档）。它可能由 Isaac Sim 6 导出（推断，依据只是文件 `doc` 注释里的源路径含 `galbot_one_golf_isaac6`，仓库没有说明生成工具与版本）。自导入版是转换器的标准结构（[3.5](../../3-isaacsim/3.5-urdf-mjcf-import.md)），每次都能从 URDF 重新生成。

## 各自能不能直接用

这一节回答：两份资产放进 Isaac Lab，能不能站稳？

```bash
python scripts/hold_pose.py --headless --usd generated/galbot_fixed_base/galbot.usd
python scripts/hold_pose.py --headless --usd third_party/galbot_one_golf_description/usd/galbot_one_golf.usda --fix_root
```

所有驱动关节以 0 为目标保持 5 秒，再把右夹爪主动关节驱动到 0.8 rad：

| 资产 | 根 | 5 s 内驱动关节最大偏离 | mimic 最大跟随误差 | 结果 |
|---|---|---|---|---|
| 自导入版（固定底座 URDF） | 固定 | 0.036 rad（`right_arm_joint2`） | 0.004 rad | 稳定 |
| 厂商版 | 用 `fix_root_link` 固定 | 0.003 rad | 0.0006 rad | 稳定 |
| 厂商版 | 浮动，立在地面上 | 0.002 rad | 0.0009 rad | 稳定，根高度不变 |
| 自导入版（轮式 URDF） | 固定，放在 z=0（有地面） | — | — | **出现 NaN**（离地后稳定，见下） |

*表 2：保持零位的实测（本站，GPU，dt = 1/120 s，每次约 14–25 秒）。*

- 厂商版几乎纹丝不动，这是超大刚度的结果。它的 mimic 约束固有频率为 0，实测表现为刚性约束，跟随误差比自导入版还小。
- 自导入版在 400 N·m/rad 的初始增益下有约 0.04 rad 的下垂，细调在 [6.1.5](6.1.5-joint-drive-tuning.md)。
- 从轮式 URDF 转出的版本在保持零位时出现 NaN。原因是根固定在 z=0、又有地面，滚子的碰撞体一开始就压进地面；滚子阻尼不是原因（阻尼扫描的结果不单调）。把根抬高 5 cm 或不放地面即稳定，结果与固定底座版逐位相同。实现方与校验方各自独立实测，详见 [6.1.2](6.1.2-import-urdf.md) 的"被动滚子"一节。

## MJCF 这条路

这一节回答：为什么不从 MJCF 出发？

Galbot 的 MJCF 在 Isaac Sim 5.1 上需要手动启用导入扩展，转换得到两个 Articulation 根，而且转换失败时返回码仍为 0（[3.5](../../3-isaacsim/3.5-urdf-mjcf-import.md)）。这条路的问题比 URDF 多，而 URDF 本身就是 MJCF 的源头（[6.1.1](6.1.1-galbot-repo.md)），所以本站主线不走 MJCF。厂商版的 `payloads/Physics/` 目录下另有一个 `mujoco.usda`，但它不在 Physics 变体的选项中，与本站无关。

## 本项目的选择

这一节回答：主线用哪一份？

**主线用自导入版（固定底座 URDF）**，理由：

- **可控**：每个参数都来自 URDF 或转换脚本，改动写在代码里；
- **可复现**：任何人从固定 commit 的 URDF 重新转换，得到同样的结果；
- **与上游同步**：描述仓库更新 URDF 后重新转换即可；厂商 USD 的生成过程仓库没有说明；
- **参数更可信**：力矩上限按关节区分，没有统一的超大刚度。

厂商版更合适的场景：

- 需要现成的外观、传感器与 ROS 2 变体做演示或数字孪生（[6.7.2](../7-deploy/6.7.2-ros2-closed-loop.md)）；
- 需要关节刚性跟随目标的遥操作回放；
- 需要轮式底盘的完整模型，而又不想自己处理被动滚子。

## 通用的取舍原则

这一节回答：换一台机器人，怎么判断？

- **可控性**：参数能否追溯到来源、能否在代码里修改。
- **可复现**：资产能否由脚本从源文件重新生成。
- **与上游同步**：源文件更新后，重新生成的成本多高。
- **外观质量**：材质、贴图、传感器配置是否完整。

前三条影响训练的可信度，第四条影响演示效果。训练用资产优先满足前三条（经验性）。

## 常见误解

:::{admonition} 误解一：厂商 USD 一定比自己转的好
:class: warning

厂商 USD 在外观与集成上往往更完整，但物理参数可能是为演示设定的，比如 Galbot 厂商版统一的 1000 N·m 与超大刚度。用于训练前，要逐项核对驱动与力矩上限。
:::

:::{admonition} 误解二：两份资产的物理行为相同
:class: warning

质量与碰撞体相同，关节驱动却差了四个数量级（表 1）。同一个策略放在两份资产上，关节响应完全不同。
:::

:::{admonition} 误解三：在 ArticulationCfg 里不写力矩上限，就用 URDF 的值
:class: warning

生效的是 USD 里的 `maxForce`（表 2 上方的读数）。用厂商版而不设上限，每个臂关节可以输出 1000 N·m。
:::
