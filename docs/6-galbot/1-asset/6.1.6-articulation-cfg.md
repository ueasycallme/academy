# 制作 Isaac Lab 的 ArticulationCfg

:::{admonition} 学习目标
:class: lead-goals

- 把前几页的结论收成一份可复用的机器人配置 `GALBOT_ONE_GOLF_CFG`
- 为 reach 选一个在重力下撑得住、又离开关节限位的默认姿态
- 保证执行器各组互不重叠，并知道 Isaac Lab 在哪种重叠下报错、哪种下不报错
- 用 `.replace()` 派生变体
:::

:::{admonition} 前置知识
:class: lead-prereq

- [4.6 Assets](../../4-isaaclab/4.6-assets.md)：`ArticulationCfg` 的结构、`isaaclab_assets` 官方配置
- [6.1.4](6.1.4-collision-mass-inertia.md)、[6.1.5](6.1.5-joint-drive-tuning.md)：自碰撞与驱动参数的结论
:::

**本页在项目中新增三个文件、修改一个**：

- `source/galbot_academy/galbot_academy/assets/galbot.py`：`GALBOT_ONE_GOLF_CFG` 与轮式变体；
- `scripts/check_actuator_groups.py`：检查每个关节恰好被一组执行器匹配（只需 usd-core）；
- `scripts/verify_galbot_cfg.py`：生成多台机器人，验证默认姿态与关节跟踪，另有几种报错演示；
- 修改 `scripts/convert_galbot.py`：加 `--floating_base`，为移动底盘单独转换一份根不固定的资产。

## 配置放在哪

这一节回答：机器人配置写在项目的什么位置？

放在 `galbot_academy/assets/galbot.py`，与参数表 `drives.py`（6.1.5）、过滤对 `physics.py`（6.1.4）同在 `assets/` 下。之后的场景和任务只写一行：

```python
from galbot_academy.assets.galbot import GALBOT_ONE_GOLF_CFG
robot = GALBOT_ONE_GOLF_CFG.replace(prim_path="{ENV_REGEX_NS}/Robot")
```

写法与 `isaaclab_assets` 里的官方配置相同（[4.6](../../4-isaaclab/4.6-assets.md)）：模块级常量，`prim_path` 留给使用方填。Isaac Lab 2.3.2 恰好自带一份 Galbot 配置 `GALBOT_ONE_CHARLIE_CFG`[^official]，但它对应的是 **Galbot One Charlie** 型号，USD 来自 Nucleus，关节组成（如吸盘关节）与限位都可能与本站的 One Golf 不同，不能直接拿来用。本页把它当对照。

## spawn：从哪个 USD 生成、改哪些属性

这一节回答：`UsdFileCfg` 里每一项为什么这样写？

| 字段 | 本项目 | 理由 |
|---|---|---|
| `usd_path` | `generated/galbot_fixed_base/galbot.usd` | 6.1.2 转换的产物，目录可由 `GALBOT_GENERATED_DIR` 改 |
| `articulation_props` | `enabled_self_collisions=True` | 6.1.4 的决定，依赖写进资产的 7 对过滤对 |
| 求解器迭代次数 | 位置 16、速度 1 | 转换器写入的 32 / 1 太慢；对比见下一节 |
| `rigid_props` | 不设 | 没有需要改的刚体属性 |
| `collision_props` | 不设 | 碰撞体在实例内部，spawn 阶段改不到（6.1.4） |
| `activate_contact_sensors` | False | reach 不用接触；[6.2.2](../2-scene/6.2.2-wrist-camera.md) 加传感器时再开 |

*表 1：spawn 的取值。*

**与官方配置的一处关键不同：重力。** 官方 Charlie 配置在 `rigid_props` 里写了 `disable_gravity=True`[^official]，机器人各连杆不受重力。官方用这份配置做堆叠任务，手臂由 RMPflow 或关节目标驱动，增益注释为"用 Gain Tuner 从 USD 读取"；关掉重力后手臂不下垂，增益不必对抗重力（推断，依据是配置本身与使用它的任务）。本项目不照搬：6.1.4、6.1.5 的实验都在重力下进行，参数表就是按重力下能保持住来定的；关掉重力会让腿的承重问题（6.1.5 表 5）在仿真里消失，却不会在真机上消失。

## 求解器迭代次数

这一节回答：为什么不沿用 USD 里的迭代次数，选多少？

URDF 转换器把 Articulation 的求解器迭代次数写成位置 32、速度 1。迭代次数越多，关节与接触约束解得越准，每个物理步也越慢（[3.3](../../3-isaacsim/3.3-rigid-collision.md) 表 1）。沿用它时，[6.2.1](../2-scene/6.2.1-workbench-scene.md) 的场景在 1024 个环境下每秒只有 44 个物理步，后面的训练会很慢。本节比较三档：

```bash
python scripts/scene_bench.py --headless --num_envs 1024 --solver_iters 16 1   # 另两档：32 1、8 0
python scripts/step_response.py --headless --seconds 3 --solver_iters 16 1
python scripts/gravity_torques.py --headless --solver_iters 16 1
python scripts/probe_stuck_joint.py --headless --solver_iters 16 1
```

| 位置 / 速度迭代 | 1024 环境每秒物理步 | 默认姿态保持误差 | 阶跃稳态误差（K400 D40） | 64 组姿态：臂误差 95% 分位 / 最大 | 6.1.4 的卡住探针 |
|---|---|---|---|---|---|
| 32 / 1（USD） | 44 | 0.0509 | 0.0317 | 0.0413 / 0.0807 | 卡在 1.449 rad，速度上限 2 或力矩上限 ×1.2 解开 |
| **16 / 1** | **74–75** | 0.0527（+3.5%） | 0.0321（+1.3%） | 0.0435 / 0.1393 | 本实验的轨迹下未触发（最大误差 0.146 rad）；不代表消除了卡住的机制，见 [6.1.4](6.1.4-collision-mass-inertia.md) |
| 8 / 0 | 118–120 | 0.0563（+10.6%） | 0.0328（+3.5%） | 0.0484 / 0.7304 | 卡在另一个关节（1.409 rad），力矩上限 ×1.2 不能解开 |

*表 2：求解器迭代次数对比（rad，本站实测，每档 3 次，除吞吐外逐位相同，吞吐在 3 次间相差约 1%；按进程显存各档相同：1024 环境 2987 MiB，单台 2315 MiB）。阶跃响应的超调与调节时间三档几乎相同（K400 D40 超调 2.0 / 2.0 / 1.9%，调节 0.417 s）。*

判据：保持误差与阶跃响应变差不超过 10%，在此前提下吞吐最高。

- **8 / 0 不合格**：默认姿态保持误差变差 10.6%，随机姿态的最大误差从 0.08 增大到 0.73 rad，6.1.4 的卡住现象也更难解开。官方 Franka 与 Kinova 用的正是 8 / 0[^iters]，但这些数说明它不适合 Galbot：Galbot 的连杆更多，还有 mimic 约束与自碰撞。这条原因是推断。
- **16 / 1 合格**：各项变差都在 4% 以内，吞吐提高约 70%。随机姿态的最大误差出现在同一个姿态上（第 24 台），延长保持到 8 s、16 s 仍为 0.139 rad，是稳态的；32 / 1 下这个姿态也有 0.081 rad，而它只需 4.7 N·m 的重力力矩，所以是这个姿态本身的特殊情况，不是 16 / 1 带来的普遍退化（推断）。UR10 的官方配置也用 16 / 1[^iters]。

**本项目选 16 / 1**，写在 `GALBOT_ONE_GOLF_CFG` 的 `articulation_props` 里。6.1.5 的实验用的是 USD 的 32 / 1，结论按表 2 的差别仍然成立。

## init_state：默认姿态

这一节回答：机器人开始时摆成什么样？

零位不合适：腿 1–3 的零位正好是关节下限，上半身压在限位上（6.1.5）。把腿稍微抬离限位也不行：`verify_galbot_cfg.py --demo legs_low` 把 `leg_joint1`–`3` 设为 0.1 / 0.2 / 0.1，其余照默认姿态，保持 3 s 后 `leg_joint2` 塌回下限（误差 0.200 rad），`leg_joint3` 偏离 1.11 rad（本站实测，求解器迭代 16 / 1）。

官方 Charlie 配置的腿姿是 0.8 / 2.3 / 1.55 / 0，三个关节互相抵消，让躯干直立。它在 Golf 的限位内，本页把它与官方的头、双臂姿态一起作为候选，在本机器人上重新验证：

```bash
python scripts/verify_galbot_cfg.py --headless
```

```text
fixed：4 台，关节 33，刚体 34，根固定 True
保持默认姿态 3 s：数值有限 True，根高度变化 0.0000 m
  误差最大的 5 个关节：right_arm_joint1 0.0527，leg_joint5 0.0344，left_arm_joint1 0.0278，leg_joint2 0.0160，right_arm_joint3 0.0127
  末 0.5 s |关节速度| 最大的 3 个：right_gripper_r_inner_knuckle_joint 0.190，right_gripper_r_finger_joint 0.140，right_gripper_joint 0.140
  重力力矩 / 力矩上限 最大的 3 个：leg_joint3 0.49，leg_joint5 0.45，right_arm_joint1 0.33
  right_arm_link7 相对根的位置 [0.507, -0.251, 1.447] m
```

*本站实测（求解器迭代 16 / 1），约 13 秒，返回码 0，按进程显存 2315 MiB；3 次逐位相同。*

- 所有关节都在限位内且离开了限位；重力力矩最多占上限的 49%（零位时 `leg_joint2` 是 97%，靠限位托住）；
- 保持 3 s 后最大误差 0.053 rad，是重力下的正常下垂（6.1.5）；自碰撞打开时没有被顶开或抖动；
- 末段夹爪关节的速度读数在 0.1–0.2 rad/s，位置并不在变。这是有重力时静止读数不为 0 的现象（[6.1.5](6.1.5-joint-drive-tuning.md)"静止时的速度读数"），不是配置错误；
- 右臂末端在根前方 0.5 m、高 1.45 m 处，正对身体前方，适合做 reach。

## actuators：分组与互斥

这一节回答：执行器怎么分组，怎么保证不重叠？

`actuators=make_actuators()`，各组来自 6.1.5 的参数表：腿 5、头 2、双臂 14、夹爪主动关节 2，另有一组只覆盖 10 个 mimic 跟随关节、增益沿用 USD（为 0），让每个关节都有归属。用脚本检查每个关节恰好被一组匹配：

```bash
python scripts/check_actuator_groups.py
```

```text
可动关节 33 个；各组匹配数：{'legs': 5, 'head': 2, 'arms': 14, 'grippers': 2, 'mimic': 10}
结果：每个关节恰好被一组匹配
```

为什么要自己查？因为 Isaac Lab 只查一半：

:::{admonition} 对照：转换器的字典与 ArticulationCfg 的分组
:class: note

- **URDF 转换器的增益字典**：按顺序应用，后面的键覆盖前面的（6.1.2）。
- **同一执行器组里的多个正则**匹配到同一个关节：抛 `ValueError: Multiple matches for 'right_arm_joint1': …`[^match]。
- **不同执行器组**匹配到同一个关节：**不报错**。各组分别解析自己的正则[^groups]，后处理的组覆盖前面的设置。本站实测：再加一组只含 `right_arm_joint1`、stiffness 1 的执行器，PhysX 中该关节的 stiffness 变成了 1，没有任何提示。

所以"重叠即报错"只对组内成立。跨组重叠要靠 `check_actuator_groups.py` 这样的检查兜底。
:::

## 选哪只手臂

这一节回答：reach 用哪只手？

**右臂**（`REACH_ARM = "right"`）。6.1.4、6.1.5 的实验都在右臂上做，默认姿态里右臂正好伸在身体前方。reach 中其余关节（左臂、头、腿、夹爪）不受策略控制，目标保持为默认关节位置，由各自的驱动维持。验证脚本给右臂每个关节在默认值上加 ±0.3 rad 的目标，3 s 后最大误差 0.053 rad、平均 0.012 rad，与重力下垂同量级。

## 变体：.replace() 派生

这一节回答：轮式版怎么写？

```python
GALBOT_ONE_GOLF_WHEELED_CFG = GALBOT_ONE_GOLF_CFG.replace(
    spawn=GALBOT_ONE_GOLF_CFG.spawn.replace(usd_path=".../galbot_wheeled_floating/galbot.usd"),
    init_state=GALBOT_ONE_GOLF_CFG.init_state.replace(pos=(0.0, 0.0, 0.04)),
    actuators={**make_actuators(), "wheels": ..., "rollers": ...},
)
```

要点有三：

- **根不固定的资产要单独转换**：`convert_galbot.py --variant wheeled --floating_base`。不能拿 6.1.2 的固定根轮式版、用 `fix_root_link=False` 关掉根关节。这份资产的 Articulation 根就在那个固定关节上，本站实测会报 `RuntimeError: Failed to create articulation at: …/root_joint`。
- **初始高度**：滚子碰撞球在根高度 0 时最低到 z = −0.032 m（6.1.2），所以放在 0.04 m 让它落到地上。实测落地后根高度变化 6 mm。
- **主动轮**用速度控制（stiffness 0），被动滚子沿用 USD。

本部分只用固定底座版。轮式版只验证到"能生成、能站住、右臂能跟踪"。有一个已知问题：静置时被动滚子转速达到 200–320 rad/s，6.4.5 要先解决它。轮子的阻尼 10 是占位值，未验证。

## 常见坑

:::{admonition} 坑一：USD 路径不对
:class: warning

还没运行 6.1.2 的转换，或 `GALBOT_GENERATED_DIR` 指错，spawn 时会报 `FileNotFoundError: USD file not found at path at: '…'`。先确认 `generated/galbot_fixed_base/galbot.usd` 存在。报错之后，进程退出时还会打出一段 `Exception ignored in: <function AssetBase.__del__ …> AttributeError: … '_prim_deletion_callback_id'`，这是对象没初始化完就被回收的连带输出，可以忽略。
:::

:::{admonition} 坑二：执行器组之间正则重叠，没有任何报错
:class: warning

见上面的对照框。后加入的组悄悄覆盖了前面组的增益，训练效果变差却查不出原因。每次改分组后运行 `check_actuator_groups.py`。
:::

:::{admonition} 坑三：默认姿态越限
:class: warning

默认关节位置超出限位时，`sim.reset()` 报 `ValueError: The following joints have default positions out of the limits`（本站实测：把 `leg_joint1` 设为 1.2，超过上限 0.937）[^limits]。默认姿态也不要正好压在限位上：Galbot 的零位就是这样，看起来稳，其实是限位在托着。
:::

:::{admonition} 坑四：执行器配置与 USD 驱动值不一致时，以为生效的是 USD
:class: warning

`actuators` 里写了数值的字段覆盖 USD，写 `None` 才沿用 USD（[4.7](../../4-isaaclab/4.7-actuators.md)）。官方 Charlie 配置全部写 `None`，用的是 USD 里调好的增益；本项目全部写数值，用的是 6.1.5 的参数表。混用时，逐个关节读回 `robot.root_physx_view.get_dof_stiffnesses()` 核对。
:::

:::{admonition} 坑五：用 collision_props 改碰撞体
:class: warning

碰撞体在实例内部，spawn 阶段的 `collision_props` 对它们不生效，只打印一条 WARNING（6.1.4）。要改碰撞体，在转换阶段改资产；要随机化接触偏移，在运行时用事件项改（[6.4.2](../4-task/6.4.2-domain-randomization.md)）。
:::
