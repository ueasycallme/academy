# 物理参数调优

:::{admonition} 学习目标
:class: lead-goals

- 用一个固定的"稳定性探针"（stability probe）比较物理参数，而不是凭感觉调
- 知道物理步长、求解器迭代次数、接触偏移、GPU 缓冲上限各自改了会怎样，代价是多少
- 知道哪些参数改了策略就要重训
:::

**本页在项目中新增**：`scripts/sweep_physics.py`（稳定性探针）、`scripts/plot_sweep.py`（画图，不需要 Isaac Sim）、`scripts/pick_place_teacher.py`（从 `record_pick_place.py` 抽出的示教控制器，录制行为不变）。

**边界**：本站没有真机（D-004）。下面只比较仿真内的稳定性与代价，不说哪组参数"更像真机"。

## 稳定性探针

探针的做法是：同一个场景、同一个控制器、同一串随机种子，只改一项参数，看抓取还稳不稳、慢了多少。

- **场景与控制器**：6.4.6 的 pick-place 环境（1 个环境），示教控制器以 60° 接近角做 20 次抓取放置。种子固定为 0，所以每组的方块与放置垫位置序列相同。
- **成功**：放置成功判据连续保持 10 个控制步。
- **滑移**：从举起到放下，方块中心在 TCP 坐标系里的位置相对举起时刻的最大偏移（6.4.6 坑二用的也是这个坐标系）。只统计成功回合。
- **异常标记**：NaN、弹飞（方块速度 > 2 m/s）、穿透（方块中心低于桌面静止高度 1 cm 以上而没有掉下桌）、掉落、某一段超时。
- **代价**：每个控制步的墙上时间（wall-clock time，含 `torch.cuda.synchronize()`），取 20 次的中位数。只有 1 个环境，它反映的是单步延迟，不能直接换算成多环境训练的吞吐（推断）。

```bash
python scripts/sweep_physics.py --headless                                   # 主线默认：dt 1/120，decimation 4，迭代 16 / 1
python scripts/sweep_physics.py --headless --dt 1/240 --decimation 8         # 每次只改一项
python scripts/sweep_physics.py --headless --mode buffers --num_envs 1024 \
    --gpu_max_rigid_patch_count 4096 --gpu_max_rigid_contact_count 16384
```

每次尝试打印一行，最后两行汇总：

```text
[sweep] 汇总：成功 20 / 20；成功回合的滑移 中位 0.50 cm、最大 0.85 cm
[sweep] 汇总：每控制步墙上时间 中位 42.56 ms；标记 无
```

一组 20 次约 8 分钟。同一组参数重跑，逐次的步数与滑移相同（本站重跑了主线默认的前 2 次核对）。

## 物理步长

物理步长（physics time step，`sim.dt`）改了，`decimation` 要一起改，让控制频率保持 30 Hz（一个控制步 = `decimation × dt`，见 [4.4](../../4-isaaclab/4.4-simulation-context.md#在环境配置里的位置)）。

| dt × decimation | 控制频率 | 成功 | 滑移中位 / 最大 | 每控制步 |
|---|---|---|---|---|
| 1/60 × 2 | 30 Hz | 20 / 20 | 0.32 / 0.47 cm | 28.7 ms |
| **1/120 × 4（主线）** | 30 Hz | 20 / 20 | 0.50 / 0.85 cm | 42.6 ms |
| 1/240 × 8 | 30 Hz | 20 / 20 | 0.27 / 0.61 cm | 81.9 ms |
| 1/240 × 4 | **60 Hz** | **0 / 20** | — | 38.8 ms |

*表 1：物理步长扫描（本站实测，每组 20 次）。*

前三行在这个场景里都稳定，滑移都在 1 cm 以内，且不随 dt 单调变化，20 次样本分不出高低。代价近似与每个控制步里的物理子步数成正比：1/240 × 8 是主线的 1.9 倍。

第四行只改了 dt，没改 decimation：控制频率变成 60 Hz，20 次全部停在合拢段。示教控制器给合拢段的上限是 90 个控制步：30 Hz 下是 3 s，主线实测合拢用 75 步（2.5 s，重跑的 2 次都是）；60 Hz 下只剩 1.5 s。超时时夹爪读数约 1.35 rad，还没满足"连续 5 步变化 < 0.002 rad"的夹紧判据。夹爪合拢要的是仿真时间，控制器却按步数计时，这就是 dt 与 decimation 必须同步的原因（见坑一）。

另一个副作用：PhysX 自动选取的接触偏移随 dt 变化。dt 1/240 时机器人形状的最小值从 1.36 mm 降到 0.34 mm，方块从 1.36 mm 降到 1.00 mm（探针读回）。dt 1/60 时机器人与方块的形状全部读回 5.45 mm（校验方复跑读回）；表 1 第三行的 dt 也是 1/240，偏移应当同样变小（推断，那一组没有读回）。所以"改 dt"不是纯粹的单因素。

## 求解器迭代次数

位置迭代（position iteration）和速度迭代（velocity iteration）是求解器（solver）在每个物理步里的两类迭代次数。探针把它们同时写在机器人的 `articulation_props` 和方块的 `rigid_props` 上，两边用同一组值；PhysX 还会把它夹在 `PhysxCfg` 的上下限之间（4.4 表 2）。

| 位置 / 速度迭代 | 成功 | 滑移中位 / 最大 | 每控制步 |
|---|---|---|---|
| 1 / 1 | **0 / 20**（全部搬运段超时） | — | 15.7 ms |
| 4 / 1 | 20 / 20 | 0.86 / 1.43 cm | 21.0 ms |
| 8 / 1 | 20 / 20 | 0.37 / 0.50 cm | 28.2 ms |
| **16 / 1（主线）** | 20 / 20 | 0.50 / 0.85 cm | 42.6 ms |
| 16 / 0 | 20 / 20 | 0.45 / 0.70 cm | 40.6 ms |
| 16 / 4 | 20 / 20 | 0.61 / 0.87 cm | 47.3 ms |

*表 2：迭代次数扫描（本站实测，每组 20 次）。*

位置迭代 1 时手指夹不住：方块留在桌上，手空着去了放置点，"滑移"到了 85–115 cm。位置迭代 4 已经能完成全部 20 次，滑移比 8、16 大。8 与 16 分不开，而 16 每步多花 51%。速度迭代 0 / 1 / 4 之间也看不出差别。

## 接触偏移与静止偏移

接触偏移（contact offset）决定两个形状相距多远时开始生成接触，静止偏移（rest offset）决定它们停在多远（[3.3](../../3-isaacsim/3.3-rigid-collision.md#接触参数与物理材质)）。一对形状起作用的是两边之和。

本项目机器人的碰撞体在实例里，spawn 阶段的 `collision_props` 对它不生效（[6.1.4 坑一](../1-asset/6.1.4-collision-mass-inertia.md#常见坑)）。探针改为在运行时用 PhysX 视图的 `set_contact_offsets` / `set_rest_offsets` 设置，写法同 Isaac Lab 的事件项 `randomize_rigid_body_collider_offsets`[^offsets]，并在开始和结束时读回。

| 接触 / 静止偏移（机器人与方块全部形状） | 成功 | 滑移中位 / 最大 | 每控制步 | 标记 |
|---|---|---|---|---|
| **自动值（主线）**：接触 1.36–5.26 mm / 0 | 20 / 20 | 0.50 / 0.85 cm | 42.6 ms | 无 |
| 2 mm / 0 | 20 / 20 | 0.42 / 0.54 cm | 42.2 ms | 无 |
| 20 mm / 0 | 20 / 20 | 0.22 / 0.40 cm | 63.9 ms | 无 |
| 20 mm / 5 mm | **0 / 20** | — | 59.6 ms | 第一段 hover 超时 16、搬运段超时 2、掉落 2（同时标了弹飞、穿透） |

*表 3：偏移扫描（本站实测，每组 20 次；偏移为读回值，开始与结束一致）。*

接触偏移从自动值改到 2 mm，结果几乎不变。改到 20 mm，滑移变小，但每步慢了 50%：一对形状相距 4 cm（两边之和）就开始生成接触，参与求解的接触多了（推断，没有统计接触数）。滑移小不等于更准，只说明夹持在仿真里更紧。

静止偏移设为 5 mm 后，20 次全部失败，16 次连第一段（移到方块斜上方）都没走完。静止偏移作用在机器人全部 184 个形状上，开了自碰撞的连杆两两之间（关节直接相连与过滤对除外）都要保持 10 mm 的间隙，互相顶开，手臂跟不上 IK 目标（推断，没有单独做只改方块的对照）。

## GPU 缓冲

`gpu_max_rigid_contact_count`、`gpu_max_rigid_patch_count` 是 GPU 管线为接触与接触面片（patch）预留的缓冲大小，默认 2²³ 与 5 × 2¹⁵（4.4 表 2）[^buffers]。`buffers` 模式让多个环境零动作（夹爪张开）跑 150 步。

| 环境数 | 缓冲（面片 / 接触） | PhysX 错误 | NaN 环境 |
|---|---|---|---|
| 1 / 64 / 1024 | 默认 163840 / 8388608 | 无 | 0 |
| 64 | 4096 / 16384 | 无 | 0 |
| 1024 | 4096 / 16384 | 接触、面片溢出各 602 条 | 49 / 1024 |

*表 4：缓冲上限与环境数（本站实测）。*

溢出时 PhysX 每个物理步各打印一条 `Contact buffer overflow detected, please increase its size to at least N`（面片同理），150 个控制步 × 4 个子步约 600 条。本例接触缓冲的 N 为 69436–79872，即每个环境约 70 个接触；面片缓冲的 N 为 5065–5229，约 5 千。处理方法是按报错里的 N 把对应字段调大。零动作下接触最少，训练中抓取、碰撞时会更多。缓冲留余量，靠的是这条报错，不是零动作测出的数。

## 结论与主线取舍

本项目保持主线默认：dt 1/120、decimation 4、位置 / 速度迭代 16 / 1、偏移用 PhysX 自动值、GPU 缓冲用 Isaac Lab 默认值。依据如下：

- 表 1–表 3 里，主线默认在 20 次探针中没有失败，也没有异常标记。
- 降到位置迭代 8 或 dt 1/60 每步省约 1/3，在 20 次里看不出变差，但这只是一个场景、一个控制器、20 个样本。要换，先用更多场景（例如训练好的策略）复核。

哪些改了要重训：

- **dt 与 decimation**：策略看到的是控制步之间的变化，改了动力学就变了。控制频率变了，动作的含义（每步多远）也变了，必须重训。
- **迭代次数、偏移**：改的是接触与关节约束的解，同样改变策略看到的动力学。改了以后至少重新评估（6.6.2），差异超出区间就重训。
- **GPU 缓冲**：不溢出时不影响结果，不需要重训。

## 常见坑

### 坑一：改 dt 不改 decimation

表 1 第四行：只把 dt 从 1/120 改成 1/240，控制频率从 30 Hz 变成 60 Hz，示教控制器 20 次全部失败。凡是按步数写的东西都跟着变了：相对动作每步的位移、控制器与脚本里按步数写的超时和判据。命令行覆盖 `decimation` 时还要同步 `sim.render_interval`（[4.3 坑三](../../4-isaaclab/4.3-configclass.md#常见坑)）。

### 坑二：偏移用 spawn 配置改了却没生效

机器人的碰撞体在实例里，`collision_props` 只打印一条 WARNING（`Could not perform 'modify_collision_properties'`），实际值不变。本页第一轮扫描就踩了这个坑：三组偏移只改到了方块。改完一定读回。

### 坑三：缓冲溢出只在多环境时出现

同一组缓冲，64 个环境没事，1024 个环境出错并产生 NaN（表 4）。用少量环境调试通过后，加到训练规模要再看一遍日志里有没有 `buffer overflow`。

### 坑四："迭代越多越稳"不总成立

表 2 里，位置迭代 8 与 16 在滑移上分不开，速度迭代 4 也没有比 1 更好，代价却分别多 51% 和 11%。迭代够用之后，多出来的只是时间。
