# 仿真与真机行为对比

:::{admonition} 学习目标
:class: lead-goals

- 知道比较仿真与真机时测什么：阶跃响应的几个指标，各自对哪些参数敏感
- 用 `step_response.py` 在仿真里测一个关节，看刚度、延迟分别怎样改变曲线
- 用 `fit_actuator.py` 从一条响应曲线反推 stiffness、damping、延迟，并知道拟合在什么情况下不可信
:::

:::{admonition} 前置知识
:class: lead-prereq

- [4.7 执行器](../../4-isaaclab/4.7-actuators.md)：隐式与显式执行器、`DelayedPDActuator`
- [6.1.5 关节驱动参数](../1-asset/6.1.5-joint-drive-tuning.md)：本页沿用它的阶跃实验与 `right_arm_joint2`
- [6.3.1 物理参数调优](6.3.1-physics-tuning.md)
:::

:::{important}
**本站没有真机。** 本页讲的是方法：测什么、怎么测、怎么拟合。"真机侧"的步骤只给通用做法，标"未验证（本站无真机）"。方法是否有效，本页用**仿真对仿真**（sim-to-sim）来演示：拿一组执行器参数生成"伪真机"曲线，再从网格里把它找回来。这只说明拟合方法本身能用，**不代表任何真机结论**。
:::

## 测什么

| 激励 | 指标 | 定义 | 主要对什么敏感 |
|---|---|---|---|
| 单关节阶跃 | 上升时间 | 10% → 90% 的时间 | stiffness ÷ 惯量 |
| | 超调 | 超过终值的百分比 | damping 与 stiffness 的比例 |
| | 稳态误差 | 终值与目标之差 | 重力 ÷ stiffness |
| | 延迟 | 指令发出到开始动的时间 | 通信与控制周期 |
| 正弦扫频（sine sweep，只讲） | 幅频、相频 | 各频率下输出与输入的幅值比、相位差 | 带宽、延迟（高频处相位落后最明显） |
| 静态负载（只讲） | 位置偏差 | 挂不同重物时停在哪 | stiffness、摩擦 |

*表 1：比较仿真与真机的常用指标。*

阶跃最简单，本页只做阶跃。

## 仿真侧：刚度与延迟怎样改变曲线

沿用 6.1.5 的做法：固定底座的 Galbot 先在零位保持 3 s，再给 `right_arm_joint2` 一个阶跃。这次阶跃只有 **0.05 rad**：这个关节的力矩上限 60 N·m、速度上限 1.5 rad/s，0.5 rad 的阶跃会顶到上限（坑一）。**读数时机**：每个物理步 `write_data_to_sim → sim.step → robot.update` 之后读一次 `joint_pos`，采样间隔就是 dt = 1/120 s，不靠传感器的懒更新（[3.6](../../3-isaacsim/3.6-sensors.md)）。

```bash
python scripts/step_response.py --headless --actuator implicit --gains 200:40,400:40,800:40 --step 0.05 --csv cmp_implicit.csv
python scripts/step_response.py --headless --actuator delayed --gains 400:40 --delays 0,1,2,3 --step 0.05 --csv cmp_delayed.csv
python scripts/plot_step.py cmp_implicit.csv cmp_delayed.csv --step 0.05 --xmax 0.8 --out step_compare.png
```

```{figure} ../../_static/img/6.3.2-step-compare.png
:alt: 左：隐式 PD 刚度 200、400、800 的阶跃响应；右：显式 PD 延迟 0 到 3 个物理步的阶跃响应
:width: 100%

图 1：`right_arm_joint2` 阶跃 0.05 rad（本站实测，2026-10-12）。曲线的终值高于虚线：阶跃目标是"起点 + 0.05"，而起点本身已在重力下垂，到稳态还要再多垂一份。隐式三组的"稳态误差 × K"都约为 14.2 N·m。
```

| 执行器 | K / D | 延迟（物理步） | 上升 | 超调 | 2% 调节 | 稳态误差 | 最大力矩 | 最大速度 |
|---|---|---|---|---|---|---|---|---|
| 隐式 | 200 / 40 | — | 0.375 s | 0.4% | 0.575 s | +0.0710 rad | 13.7 N·m | 0.35 rad/s |
| 隐式（项目的手臂参数） | 400 / 40 | — | 0.192 s | 2.7% | 0.592 s | +0.0356 rad | 22.2 N·m | 0.45 rad/s |
| 隐式 | 800 / 40 | — | 0.100 s | 5.0% | 0.342 s | +0.0178 rad | 42.2 N·m | 0.66 rad/s |
| 显式 `DelayedPDActuator` | 400 / 40 | 0 | 0.200 s | 0.8% | 0.317 s | +0.0247 rad | 16.5 N·m | 0.53 rad/s |
| 同上 | 400 / 40 | 3 | 0.200 s | 0.8% | 0.342 s | +0.0247 rad | 16.5 N·m | 0.53 rad/s |

*表 2：阶跃指标（本站实测）。延迟 1、2 步介于 0 与 3 之间。*

两点：

- **延迟只是平移**：每多 1 个物理步（8.3 ms），曲线整体右移 8.3 ms，上升时间、超调都不变。这里上升时间约 0.2 s，延迟 3 步只占一成多，所以影响很小；增益越高、响应越快，同样的延迟越要紧。
- **隐式与显式不是同一个模型**：K、D 相同，隐式的上升时间 0.192 s、超调 2.7%，显式（延迟 0）是 0.200 s、0.8%。隐式由 PhysX 在求解器里算驱动力，显式由 Isaac Lab 每步算出力矩再施加（4.7），拟合时用哪种模型，就要用同一种去比（坑二）。

## 真机侧怎么测（未验证，本站无真机）

通用做法是用 ROS 2 给一个关节发目标、同时记录关节状态：

1. 接口沿用 [6.7.2](../7-deploy/6.7.2-ros2-closed-loop.md) 的消息与关节顺序，按 [6.7.1](../7-deploy/6.7.1-policy-export.md) 的接口说明核对单位与顺序；记录时用状态消息自带的时间戳，不用收到消息的时刻。
2. 从零位出发，阶跃取小幅（本页的 0.05 rad 量级），其他关节保持；急停在手边。限位、速度、力矩的核对按 [6.7.3](../7-deploy/6.7.3-sim2real-checklist.md) 的清单。
3. 同一个阶跃重复几次，再换一个幅度，作为第二种激励。
4. 把记录整理成与 `step_response.py --csv` 相同的格式：第一列时间，第二列"相对起点的位置"。采样间隔要与仿真的 dt 对齐，否则先插值。

以上都没有在真机上做过。

## 拟合

用实验数据反推模型参数，叫系统辨识（system identification）。`fit_actuator.py` 做的是其中最简单的一种：网格搜索。先用 `step_response.py --grid` 在一个进程里放上每个候选组合各一台机器人（本页 7 个 K × 5 个 D × 4 个延迟，共 140 台，按进程显存 2389 MiB），一次跑出所有候选曲线；再把它们逐点与测量曲线比较：

$$
J(K, D, \text{延迟}) = \frac{1}{M}\sum_{m=1}^{M} \frac{\text{RMSE}\big(q^{\text{候选}}_m(t) - q^{\text{测量}}_m(t)\big)}{A_m}
$$

其中 $M$ 是激励的种数，$A_m$ 是第 $m$ 种激励的实际幅度。取 J 最小的那组。

```bash
python scripts/step_response.py --headless --actuator delayed --grid "300,400,500,600,700,800,900;10,20,30,40,50;0,1,2,3" --step 0.05 --csv grid_005.csv
python scripts/fit_actuator.py --pair ref_005.csv:grid_005.csv --noise 0.002 --truth 600:30:2
```

**sim-to-sim 演示**：伪真机用 `DelayedPDActuator`，K = 600、D = 30、延迟 2 步，阶跃 0.05 rad，并给测量曲线加高斯噪声，模拟编码器噪声：

| 设置 | 拟合结果（K / D / 延迟） | 20 个噪声种子里完全找回 |
|---|---|---|
| 无噪声 | 600 / 30 / 2 | — |
| 噪声 0.002 rad | 600 / 30 / 2 | 20 / 20 |
| 噪声 0.005 rad | 600 / 30 / 2 | 19 / 20（K、D 都对，有 1 次延迟错 1 步） |
| 噪声 0.01 rad | 600 / 30 / 2 | 14 / 20（K、D 对 17 次） |
| 噪声 0.01 rad，再加一个 0.02 rad 的阶跃 | 600 / 30 / 2 | 14 / 20（K、D 对 19 次） |
| 伪真机换成隐式执行器（真值 600 / 30 / 0），候选仍是显式 | **500 / 20 / 1** | — |

*表 3：sim-to-sim 拟合（本站实测，2026-10-12）。这是仿真对仿真，不代表真机。*

**拟合不唯一时**：噪声大了以后，最先错的是延迟（无噪声时延迟差 1 步，J 只从 0 变成 0.017）。再加一种激励，K、D 稳了一些，延迟没有。要定准延迟，应换一种对延迟更敏感的激励，例如高频的正弦（表 1）。另外，脚本会报出"J 不超过最小值 1.1 倍"的候选个数：个数多，就说明这组数据定不住参数。

## 拟合结果放哪

拟合出的 K、D 写回 `assets/drives.py` 的驱动参数表（[6.1.5](../1-asset/6.1.5-joint-drive-tuning.md)）。延迟要改用 `DelayedPDActuatorCfg`，写在 `ArticulationCfg.actuators` 里。这些都会改变策略看到的动力学，按 [6.3.1 结论](6.3.1-physics-tuning.md)，改了就要重新评估；超出区间，就重训。

## 常见坑

### 坑一：大阶跃时，曲线由上限决定

把阶跃加到 0.5 rad，伪真机的力矩打到 60 N·m、速度打到 1.5 rad/s，都是上限。这时如果候选模型的速度上限设错了（1.0，而伪真机是 1.5），拟合会落在 700 / 20 / 0，J 在最小值 1.1 倍以内的候选有 56 个。同样的错误设置用 0.05 rad 的阶跃去拟合，结果仍是 600 / 30 / 2（本站实测）。大阶跃的曲线主要反映上限，K、D 只能去"凑"上限的差别。先用不顶上限的小阶跃拟合 K、D，再单独去核对上限。

### 坑二：拟合用的模型与被测对象不是一种

伪真机用隐式执行器、候选用显式执行器时，拟合结果是 500 / 20 / 1，比真值低 17% / 33%，还多出一步延迟（表 3）。J 照样有一个最小值，拟合也照样会给出结果，看不出不对。真机与任何仿真模型都不是"同一种"，所以拟合出的参数是"让这个模型最像真机"的参数，不是真机的物理量（推断）。

### 坑三：按控制步采样

本页按物理步（120 Hz）采样。只按控制步（30 Hz，每 4 个物理步取一次）去拟合，噪声 0.002 rad 时，20 次里有 1–2 次把延迟估成 3 步，K、D 不受影响（本站实测）。延迟比一个控制步还短时，按控制步采样看不清它。

### 坑四：拿一个关节的结果套全臂

本页只测了 `right_arm_joint2`。各关节的惯量、负载、减速比都不同，一个关节的 K、D、延迟不能直接套到其他关节。每个关节都要测，至少每类关节（大关节、腕关节）测一个（推断）。
