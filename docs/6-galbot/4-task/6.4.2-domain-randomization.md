## 为什么 reach 也要随机化

这一节回答：仿真里的参数是固定的，为什么还要随机？

Galbot 的质量、驱动增益都来自 URDF 与本站的经验取值（[6.1.5](../1-asset/6.1.5-joint-drive-tuning.md)），与真机必然有差。只在一组精确参数上训练，策略可能依赖这组参数的细节，比如"刚度正好 400 时，给这么大的偏移刚好到位"。让每个环境的参数在标称值附近各不相同，策略就只能学到对参数不敏感的做法（[4.12](../../4-isaaclab/4.12-event-randomization.md)）。这也是部署前的准备，见 [6.7.3](../7-deploy/6.7.3-sim2real-checklist.md)。

## 加了哪些

这一节回答：每一项随机的是什么，在什么时机，范围多大？

| 项 | 事件函数 | mode | 范围 | 理由 |
|---|---|---|---|---|
| 右臂连杆质量 | `randomize_rigid_body_mass` | startup | ×[0.9, 1.1]，重算惯量 | URDF 质量只是建模值 |
| 右臂驱动刚度、阻尼 | `randomize_actuator_gains` | startup | ×[0.8, 1.2] | 标称 400 / 40 是仿真内自洽的经验值 |
| 右臂关节 armature | `randomize_joint_parameters` | startup | +[0, 0.005] kg·m² | 标称为 0，缩放无效，所以用加法 |
| 初始关节位置 | `reset_joints_by_offset` | reset | ±0.2 rad（同 6.4.1） | 起点多样 |
| 初始关节速度 | 同上 | reset | ±0.1 rad/s | 起点不总是静止 |
| 观测噪声 | 观测项的 `noise` | 每步 | 关节位置、速度各 ±0.01 | 与 Franka reach 相同（[4.10](../../4-isaaclab/4.10-observation-action.md)） |

*表 1：Galbot-Reach-DR-v0 的随机化（函数名与参数名以 v2.3.2 源码为准[^events]）。*

只随机右臂：其余关节不受策略控制，随机它们只会改变"站姿"，与 reach 无关。关节摩擦没有加：资产里没有设置摩擦，又没有任何数据给出量级，本站不猜（经验性取舍）。

```python
arm_gains = EventTerm(func=mdp.randomize_actuator_gains, mode="startup",
                      params={"asset_cfg": ARM, "stiffness_distribution_params": (0.8, 1.2),
                              "damping_distribution_params": (0.8, 1.2), "operation": "scale"})
```

## 哪些只能在启动时做

这一节回答：为什么质量、增益放在 startup，而不是每次 reset？

[4.12](../../4-isaaclab/4.12-event-randomization.md) 已经讲了规则，落到本页：

- 质量、隐式执行器的增益、armature 这三个函数都在 CPU 上读写 PhysX 张量，源码注释建议只在初始化时调用[^events]。放在 startup，每个环境在整个训练中各自固定一组参数；1024 个环境就是 1024 组。
- 它们改的是 PhysX 里的参数，不改 USD，所以在 `replicate_physics=True`（默认）下可以用。要随机缩放连杆尺寸、换材质贴图这类改 USD 的随机化，才需要 `prestartup` 与 `replicate_physics=False`（[4.5](../../4-isaaclab/4.5-interactive-scene.md)）。
- 初始状态与观测噪声每次 reset、每一步都会重新采样，代价很小。

## 范围怎么定

这一节回答：没有真机数据，范围取多大？

原则（D-004）：以标称值为中心，取保守的比例范围，并标明是经验值。

- 质量 ±10%：连杆质量是 CAD 估算，误差通常不会大到成倍（推断）；
- 增益 ±20%：增益本身就是本站定的，比质量更没有依据，所以范围更宽；
- 初始状态：位置 ±0.2 rad、速度 ±0.1 rad/s，在 6.1.5 测得的跟踪能力以内。

范围过大的后果是：一部分环境的参数离标称值太远，同一个动作在不同环境里效果相差很大，策略学到的是一个保守的平均做法，在标称模型上的精度反而下降。所以范围宁小勿大，等有了真机辨识数据再按实测调整。

## 验证生效

这一节回答：怎么确认随机化真的发生了？

```bash
python scripts/check_dr.py --headless
python scripts/check_env.py --headless --task Galbot-Reach-DR-v0 --steps 400
```

`check_dr.py` 生成 8 个环境，从仿真读回参数：

| 检查 | 读回的值（8 个环境） | 设定 |
|---|---|---|
| 右臂连杆质量 / 标称 | 0.905 … 1.099；`right_arm_link3` 的 8 个环境各不相同（1.312 … 1.572 kg） | ×[0.9, 1.1] |
| 右臂刚度 / 400、阻尼 / 40 | 0.804 … 1.197、0.803 … 1.189 | ×[0.8, 1.2] |
| 右臂 armature | 0.0001 … 0.0049 kg·m² | +[0, 0.005] |
| 第二次 reset 后右臂位置偏移、速度 | −0.194 … 0.188 rad，−0.099 … 0.098 rad/s | ±0.2 rad，±0.1 rad/s |
| 观测 joint_pos 项减去不带噪声的原值 | −0.0092 … 0.0097 | ±0.01 |
| `-Play` 配置 | 噪声关；质量、增益、armature 三项为 None；初始姿态扰动保留 | — |

*表 2：随机化读回（本站实测，种子 0，3 次结果逐位相同；每次约 10 秒，按进程显存 2315 MiB）。质量、刚度、阻尼、armature 都是从 PhysX 视图读回的值，不是配置里的数。*

初始速度要看第二次 reset：第一次 `reset()` 时，reset 事件设的初速度会被夹成 0（4.6 {ref}`常见坑四 <first-reset-velocity>`）。随机动作跑 400 步没有 NaN，每步奖励在 [−0.0060, −0.0011]（约 34 秒，2315 MiB）。

## 对训练的影响

这一节回答：加了随机化，训练会怎样？

预期（未实测，推断）：同样的迭代数下，加随机化后奖励上升略慢、最终的位置误差略大，因为策略要同时应付一组参数而不是一个；换来的是对参数偏差不那么敏感。实际差多少，在 [6.5.2](../5-train/6.5.2-hyperparameters.md) 用 `Galbot-Reach-v0` 与 `Galbot-Reach-DR-v0` 做对照训练。

## -Play 配置

这一节回答：回放时关掉哪些？

`GalbotReachDREnvCfg_PLAY` 关掉观测噪声（`enable_corruption = False`）以及质量、增益、armature 三项随机化，保留初始姿态的扰动。回放的目的是看策略在标称模型上的表现、录视频；噪声与参数扰动会让画面里的动作带上与策略无关的抖动。要评估鲁棒性时，反过来用训练配置回放（[6.6.1](../6-eval/6.6.1-play-replay.md)）。

## 常见坑

:::{admonition} 坑一：对标称为 0 的参数做缩放
:class: warning

本资产的 armature 默认为 0（表 2 读回的最小值 0.0001 就来自加法），关节摩擦在 USD 里也没有设置。对 0 做 `operation="scale"`，乘出来仍是 0，随机化等于没做，也不报错。对这类参数用 `"add"`，并先读一次默认值确认。
:::

:::{admonition} 坑二：在 Manager 之外直接调用 Term 函数
:class: warning

写检查脚本时直接调用 `mdp.joint_pos_rel(env, SceneEntityCfg("robot", joint_names=[...]))`，返回的是全部 33 个关节，而不是指定的 7 个：`SceneEntityCfg` 要先 `resolve(env.scene)` 才会把名字换成下标，Manager 会替你做这一步，自己调用时不会。本站的 `check_dr.py` 起初就踩了这个坑。
:::

:::{admonition} 坑三：用第一次 reset 的状态检查初速度
:class: warning

第一次 `reset()` 后初速度全为 0，看起来像速度随机化没生效。要看第二次 reset 起的状态（4.6）。
:::

:::{admonition} 坑四：startup 随机化以为每个回合都会变
:class: warning

startup 事件只执行一次，每个环境的质量、增益在整个训练里固定。想每个回合都换一组，要改成 reset 模式，代价是每次重置都在 CPU 上读写物理参数（4.12）。
:::
