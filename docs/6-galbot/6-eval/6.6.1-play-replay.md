# play 脚本与策略回放

:::{admonition} 学习目标
:class: lead-goals

- 加载训练好的策略，看着 Galbot 的右臂去够目标，并录下视频
- 用一个脚本拿到最基本的定量指标：误差的中位数、分位数和达标比例
- 知道回放与训练表现不一致时先查什么
:::

**本页在项目中新增 / 修改**：

- 修改 `scripts/eval_reach.py`：多打印一行位置误差的均值与最大值；
- 新增 `scripts/check_export.py`：离线核对导出的 `policy.pt` / `policy.onnx`。

本页回放的检查点是 6.5.1 种子 42 的 `model_999.pt`（运行目录 `2026-10-08_15-12-57_seed42`，评估中位数 2.73 cm）。主线配置的熵系数是 0.001（[6.5.2](../5-train/6.5.2-hyperparameters.md) 的"训练预算与消融结论"）。

## play 命令

这一节回答：怎么把训练好的策略跑起来？

```bash
# 带界面：看机器人动（不会自动结束，关窗口即退出）
python scripts/rsl_rl/play.py --task Galbot-Reach-Play-v0 --checkpoint logs/rsl_rl/galbot_reach/<日期_时间>_seed42/model_999.pt

# headless 录一段视频后自动退出
python scripts/rsl_rl/play.py --task Galbot-Reach-Play-v0 --headless --video --video_length 360 --checkpoint …/model_999.pt
```

- **用哪个检查点**：`--checkpoint` 直接给路径最稳妥。不给时，脚本在 `logs/rsl_rl/galbot_reach/` 下按目录名排序取最后一个运行、其中编号最大的检查点[^ckpt]，也就是"最近一次训练"，未必是你想要的那次（坑一）。
- **`-Play` 变体改了什么**：`Galbot-Reach-Play-v0` 只把环境数从 1024 改为 16，便于看清。观测噪声与域随机化在 `Galbot-Reach-v0` 里本来就是关着的。官方 Franka 的 Play 变体还会关掉观测噪声、调小环境间距[^franka-play]，自己写任务时要对照训练变体检查这几项。
- **两种方式**：带界面时，脚本一直运行到关窗口；headless 不加 `--video` 时，同样会一直运行，只能 Ctrl-C 结束（坑二）。

## 看什么

这一节回答：画面上什么算"学会了"？

reach 的指令项开了 `debug_vis`（[6.4.1](../4-task/6.4.1-reach.md)），画面里每个环境有两个坐标系标记[^cmds]：

- **目标位姿**：指令采样出的 TCP 目标，每 4 s 换一次，一个回合 12 s 换三次；
- **当前位姿**：TCP 现在的位置与朝向。Galbot 的 TCP 由 `right_arm_link7` 加偏移算出，标记画在 TCP 上，而不是 link7 的原点（6.4.1 的 `TcpPoseCommand`）。

学会了的样子是：目标一换，右臂平稳地移过去，两个标记在约 0.5 s 内重新重合，之后保持不动（图 1）；三个坐标轴的朝向也大致对齐。

策略这时输出的是**动作均值**，没有训练时的探索噪声（[5.2](../../5-rl/5.2-policy-value.md)）：`play.py` 用的是 `get_inference_policy`[^play]。所以回放比训练时的动作更平稳，误差也更小。

## 录视频

这一节回答：视频怎么录，存在哪？

`--video` 打开录像，`--video_length` 是录多少个环境步（默认 200）；加了 `--video` 会自动启用相机渲染（`enable_cameras`）[^play]。视频存在**检查点所在运行目录**的 `videos/play/` 下[^play]。录满 `--video_length` 步后，脚本自动退出。

录像包装器 `gym.wrappers.RecordVideo` 包在 rsl_rl 适配层**之内**，原因见 [4.16](../../4-isaaclab/4.16-rl-wrappers.md) 的常见坑。

```text
logs/rsl_rl/galbot_reach/2026-10-08_15-12-57_seed42/videos/play/rl-video-step-0.mp4   1.2 MB，359 帧，30 fps，1280×720
```

*本站实测：`--video_length 360`（一个回合 12 s），用时 37 s；进程显存峰值 4755 MiB，主机内存峰值 8.4 GB。开了渲染，主机内存比 1024 个环境的训练（约 5.9 GB）还高，在 16 GB 的机器上不要和别的仿真同时跑。*

![回放视频的四个关键帧](../../_static/img/6.6.1-keyframes.jpg)

*图 1：前景机器人在第 4 s 换目标前后的四帧（第 118、123、135、150 帧，裁剪）。换目标前两个标记重合；换目标后 0.1 s，新目标标记跳到上方，TCP 标记还在原处；0.5 s 后两者重新重合，之后保持不动。*

## 最基本的定量评估

这一节回答：不看视频，怎么用数字说它好不好？

`eval_reach.py`（6.5.1 写的评估脚本）跑 256 个环境、每个环境 3 段目标，在每段末尾记 TCP 误差，共 768 个样本：

```bash
python scripts/eval_reach.py --headless --checkpoint logs/rsl_rl/galbot_reach/2026-10-08_15-12-57_seed42/model_999.pt
```

```text
  位置误差：中位数 2.73 cm，90% 分位 6.31 cm，< 2 cm 32.2%，< 5 cm 80.9%
  位置误差：均值 3.29 cm，最大 11.29 cm
  姿态误差：中位数 0.068 rad，90% 分位 0.116 rad
  误差 > 5 cm 且最后 0.5 s 内右臂关节位置变化 < 0.01 rad 的样本（停住但没到）：7 / 768
```

*本站实测，与 6.5.1 的评估逐位一致；进程显存峰值 2473 MiB，主机内存峰值 4.3 GB。*

均值比中位数大，说明有少数样本误差很大，把平均值拉高了。所以合格线用中位数与分位数，不用均值（6.5.1 坑二）。分布、失败案例、按目标位置分组等更完整的评估留给 [6.6.2](6.6.2-evaluation.md)。

## 导出策略

这一节回答：`exported/` 里那两个文件是做什么的？

`play.py` 每次运行都会在检查点旁边写一个 `exported/` 目录[^play]：

- `policy.pt`：TorchScript（JIT）格式，可以脱离 rsl_rl 与 Isaac Lab，只用 PyTorch 加载；
- `policy.onnx`：ONNX 格式，可以用 ONNX Runtime、TensorRT 等推理引擎加载，常用于部署到机器人上。

两者都只含 actor（策略网络；训练时开了观测归一化，就连同归一化一起），不含 critic[^exporter]。`check_export.py` 不启动 Isaac Sim，离线核对两个文件：

```text
exported/policy.pt：36.1 KB
exported/policy.onnx：26.2 KB
TorchScript 与检查点 actor 的输出最大差：0.00e+00（256 个随机观测）
ONNX 结构检查通过；输入 [('obs', [1, 28])]，输出 [('actions', [1, 7])]
```

*本站实测。ONNX 的输入是固定的批大小 1；本机环境没有装 onnxruntime，所以只做了结构检查，没有比较数值。* 部署的完整流程见 [6.7.1](../7-deploy/6.7.1-policy-export.md)。

## 回放与训练表现不一致时

这一节回答：训练曲线很好，回放却不行，先查什么？

| 现象 | 先查 | 说明 |
|---|---|---|
| 回放比训练日志里的误差小 | 正常 | 两个可能原因（推断，未分开测）：训练时动作带探索噪声，回放取均值（[5.2](../../5-rl/5.2-policy-value.md)）；日志取平均、评估看中位数，本页评估的均值 3.29 cm 就比中位数 2.73 cm 大（[6.5.3](../5-train/6.5.3-experiment-management.md)） |
| 回放明显更差 | Play 变体与训练变体的差别 | 环境数、观测噪声、随机化、episode 长度是否一致 |
| 动作幅度不对 | 动作尺度 | 训练改过 `scale`，回放和评估也要改（[6.5.2](../5-train/6.5.2-hyperparameters.md) 坑四） |
| 输入看起来"不对" | 观测归一化 | 训练时开了归一化，导出与部署时要带上同一份统计量 |
| 加载就报错 | 检查点与代码版本 | 网络结构或观测维度变了，旧检查点无法加载（[6.5.3](../5-train/6.5.3-experiment-management.md)） |

*表 1：回放与训练不一致时的排查顺序。系统的排查方法见 [5.8](../../5-rl/5.8-training-debug.md)。*

## 常见坑

:::{admonition} 坑一：不指定检查点，回放的不是你想要的那次
:class: warning

本站目录下最新的运行是 6.5.2 之后被否决的熵系数 0.01 那次训练。实测三种写法：
- 不给 `--checkpoint`：加载 `2026-10-09_00-02-49_seed43/model_999.pt`，即最新的运行；
- `--load_run seed42`：报错 `No runs present … match: 'seed42'`。`load_run` 用 `re.match` 从目录名开头匹配，而目录名以日期开头[^ckpt]；
- `--load_run '.*seed42'`：两个目录都匹配，取最新的 `2026-10-08_23-35-21_seed42`，又是被否决的那次。

所以总是用 `--checkpoint` 写完整路径，或者 `--load_run` 写完整的目录名。
:::

:::{admonition} 坑二：headless 回放不会自己结束
:class: warning

`play.py` 的主循环是 `while simulation_app.is_running()`，只有加了 `--video` 时，录满 `--video_length` 步才会跳出[^play]。headless 下不加 `--video`，就会一直运行，只能 Ctrl-C 结束。
:::

:::{admonition} 坑三：每次回放都会覆盖 exported/
:class: warning

`play.py` 每次运行都把策略重新导出到检查点旁边的 `exported/`[^play]。拿 `policy.onnx` 去部署时，确认它导出自哪个检查点：同一个运行目录里，回放过哪个检查点，`exported/` 里就是哪个。
:::

:::{admonition} 坑四：录视频时主机内存不够
:class: warning

开了渲染的回放，主机内存峰值 8.4 GB，比训练还高（上文实测）。在 16 GB 的机器上，和其他仿真进程同时跑就可能内存不足。录视频时，确认没有别的 Isaac Sim 进程在运行。
:::
