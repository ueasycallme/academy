# headless 与远程运行

:::{admonition} 学习目标
:class: lead-goals

- 说清 `--headless` 关掉了什么、没关掉什么
- 在只能 SSH 的 GPU 机器上训练、回放、录视频，断线不丢任务
- 需要看画面时，用 livestream 把仿真画面传到本地
:::

:::{admonition} 前置知识
:class: lead-prereq

- [3.2 SimulationApp 与 Python 启动方式](../3-isaacsim/3.2-simulation-app.md)、[2.6 Omniverse Kit 是什么](../2-usd-kit/2.6-what-is-kit.md)
- [6.5.1 训练 reach](../6-galbot/5-train/6.5.1-train-reach-rsl-rl.md)、[6.6.1 回放与录视频](../6-galbot/6-eval/6.6.1-play-replay.md)
:::

本页以主线 Galbot reach 项目为例。本站只有一台机器，"远程"用 SSH 连回本机来模拟；凡是需要第二台机器才能验证的说法，都标"未验证"并引官方文档。

## headless 到底关掉了什么

这一节回答：加了 `--headless`，什么没了，什么还在？

`--headless` 关掉的是**窗口**：不创建 GUI，也不渲染视口。渲染器本身是否加载，取决于 `--enable_cameras`。AppLauncher 按这两个开关选体验文件（[3.2](../3-isaacsim/3.2-simulation-app.md) 表 1、[2.6](../2-usd-kit/2.6-what-is-kit.md) 表 1）：

- 只加 `--headless`：不加载渲染相关的扩展，物理照常；
- `--headless --enable_cameras`：没有窗口，但渲染器在，相机观测、录视频（[6.6.1](../6-galbot/6-eval/6.6.1-play-replay.md)）、Replicator 都能用。`play.py` 加 `--video` 时会自动打开 `--enable_cameras`。

同一个训练（Galbot reach，1024 个环境，100 次迭代），本站实测：

| | `--headless` | 带界面（本机桌面开窗口） |
|---|---|---|
| 体验文件 | `isaaclab.python.headless.kit` | `isaaclab.python.kit` |
| 每次迭代 | 1.49 s | 2.67 s（+79%） |
| 显存峰值 | 3041 MiB | 5744 MiB |
| 主机内存峰值 | 5.9 GB | 9.6 GB |

*表 1：headless 与带界面训练的对照（RTX 5070；每次迭代取最后 50 次的平均）。带界面时每一步都要渲染视口。*

训练时开着窗口，代价是慢近八成、多占约 2.7 GB 显存和 3.7 GB 主机内存。窗口只在要看的时候开，正式训练用 `--headless`。

## SSH 场景的三件事

这一节回答：在远程机器上跑，要注意什么？

**① 没有显示器时忘了加 `--headless`。** 本站实测与常见的说法不同：Isaac Sim 5.1.0 下**不会失败**。`SimulationApp` 发现 Linux 上没有 `DISPLAY` 时，会自动加上 `--no-window`，并打印一条警告[^sa-display]：

```text
[Warning] [simulation_app.simulation_app] DISPLAY environment variable is not set, running in headless mode with --no-window flag. ...
[Warning] [carb.windowing-glfw.plugin] GLFW initialization failed.
```

*本站实测：`env -u DISPLAY` 运行 `train.py`、不加 `--headless`，训练照常进行；GLFW 的警告会重复十几次，可以忽略。*

但这时 AppLauncher 不知道你想要 headless，仍按"带界面"选择体验文件 `isaaclab.python.kit`（[2.6](../2-usd-kit/2.6-what-is-kit.md) 表 1），加载的扩展比 `headless.kit` 多。所以在服务器上仍应显式加 `--headless`。

**② 长任务不随断线死掉。** SSH 断开时，前台进程会收到挂断信号（SIGHUP）而退出。本站约定：

```bash
setsid nohup python scripts/rsl_rl/train.py --task Galbot-Reach-v0 --headless --seed 42 --run_name base_s42 \
    > train_s42.log 2>&1 < /dev/null &
```

- `setsid` 让进程脱离当前终端会话，`nohup` 忽略挂断信号，输出重定向到文件；
- 用 `tail -f train_s42.log` 看进度。Isaac Lab 的训练脚本会在退出前刷新输出，自己写的脚本要照 CONVENTIONS 第 5 节在 `close()` 前 `sys.stdout.flush()`，否则重定向后日志会丢（[3.2](../3-isaacsim/3.2-simulation-app.md)）。

`tmux` / `screen` 也能做到，而且可以随时重新接上终端看实时输出。本机没有安装 tmux，所以本站用不需要额外安装的 `setsid` + `nohup`（tmux 的用法未验证）。

本站直接给训练进程发挂断信号（`kill -HUP`）来对照：普通启动的训练立即退出（返回码 129，即 128 + 信号 1）；用 `nohup` 启动的，进程的忽略信号集合里有 SIGHUP，收到后照常运行。真实的 SSH 断线没有实测：本机不允许用公钥 SSH 登录自己，本站也没有为此改动 SSH 配置。

**③ 取回结果。** TensorBoard 在远程机器上起，本地用 SSH 端口转发看：

```bash
# 远程机器上
tensorboard --logdir logs/rsl_rl/galbot_reach --port 6006
# 本地
ssh -L 6006:localhost:6006 <用户>@<远程机器>
# 然后本地浏览器打开 http://localhost:6006
```

训练产物用 `rsync -av <用户>@<远程机器>:<项目>/logs/rsl_rl/galbot_reach/<运行> logs/rsl_rl/galbot_reach/` 拉回本地。只拉需要的运行，检查点和 TensorBoard 文件不大（[6.5.3](../6-galbot/5-train/6.5.3-experiment-management.md) 表 1）。端口转发与 rsync 的命令是标准 OpenSSH 用法，本站未验证（原因同上）。

## livestream：把画面传到本地

这一节回答：远程机器没有显示器，又想看机器人在干什么，怎么办？

Isaac Sim 5.1.0 用 WebRTC 把渲染画面推流到客户端，客户端是官方的 **Isaac Sim WebRTC Streaming Client**（Linux、Windows、macOS 版，从官方下载页获取）[^ls]。Isaac Lab 用 `--livestream` 或环境变量 `LIVESTREAM` 打开它，取值如下[^lab-ls]：

| 取值 | 含义 | AppLauncher 做了什么 |
|---|---|---|
| 0 | 关闭（默认） | — |
| 1 | WebRTC，公网 | 启用 `omni.services.livestream.nvcf`，并设 `publicEndpointAddress` 为环境变量 `PUBLIC_IP`（默认 `127.0.0.1`）、端口 49100 |
| 2 | WebRTC，内网 | 只启用 `omni.services.livestream.nvcf` |

*表 2：livestream 的取值（Isaac Lab v2.3.2 `app_launcher.py`）。命令行 `--livestream` 优先于环境变量。*

- 开了 livestream，主机上一定是 headless：AppLauncher 会把 `headless` 强制设为 True[^lab-ls]；
- 主机要开放 **TCP 49100** 与 **UDP 47998**[^ls]；
- 同一时刻只能有**一个客户端**连接；GPU 必须带硬件视频编码器 NVENC，A100 不支持[^ls]。

本站实测：在本机开 `--livestream 2` 训练 100 次，不连客户端：

| | headless | headless + `--livestream 2` |
|---|---|---|
| 体验文件 | `isaaclab.python.headless.kit` | `isaaclab.python.kit`（带界面的那份） |
| 每次迭代 | 1.49 s | 2.67 s（+79%） |
| 显存峰值 | 3041 MiB | 5840 MiB |
| 主机内存峰值 | 5.9 GB | 9.5 GB |

*表 3：livestream 的开销（1024 个环境，Galbot reach，RTX 5070；没有客户端连接）。启动约 10 s 后 TCP 49100 开始监听；UDP 47998 没有观察到，可能要等客户端连上才打开（推断）。*

开销来自两处：AppLauncher 在开 livestream 时选的是带界面的体验文件（判断条件是 "headless 且没开 livestream"）[^lab-exp]；渲染器每步都要渲染一帧供推流。即使没有人在看，这些开销也照样存在（坑三）。

本站没有下载官方客户端，没有连接测试，延迟体感未验证。

远程连不上时，按顺序查（未验证，依据官方文档[^ls]）：

1. 服务端是否真的在监听：`ss -tlnp | grep 49100`；
2. 防火墙是否放行 TCP 49100、UDP 47998（云主机还有安全组）；
3. 跨公网时是否用了取值 1，并把 `PUBLIC_IP` 设成客户端能访问到的地址；只在内网时用 2；
4. 是否已经有一个客户端连着。

## 容器与集群

这一节回答：多台机器、多个人共用时呢？

服务器和集群上更常见的是容器：宿主只装驱动与容器工具，Isaac Sim 与 Isaac Lab 都在镜像里，环境可以复现。Isaac Sim 官方提供 NGC 镜像，容器里用 `runheadless.sh` 推流（[1.7](../1-env/1.7-install-methods.md) 表 1）。容器化的做法见 [1.6 容器化环境](../1-env/1.6-container.md)。集群调度（Slurm、Kubernetes 等）见 Isaac Lab 的部署文档[^lab-deploy]，本站不展开。

## 常见坑

:::{admonition} 坑一：服务器上没加 `--headless`，以为没事
:class: warning

没有 `DISPLAY` 时，Isaac Sim 会自动转成无窗口模式，不报错（上文实测）。但 AppLauncher 仍选带界面的体验文件，加载更多扩展，也更占内存。启动日志里看到 `DISPLAY environment variable is not set` 这条警告，就补上 `--headless`。
:::

:::{admonition} 坑二：断线后训练没了
:class: warning

在 SSH 里直接前台运行，终端断开时进程会收到挂断信号而退出。长任务一律用 `setsid nohup … &` 启动，或放进 tmux。本站实测：直接发 SIGHUP，普通启动的训练立即退出，`nohup` 启动的照常运行（上文）。
:::

:::{admonition} 坑三：livestream 开着跑长训练
:class: warning

开了 livestream，即使没有客户端连接，每次迭代也慢 79%，显存多 2.7 GB，主机内存多 3.6 GB（表 3）。看完画面就停掉这个进程，正式训练不要带 `--livestream`。
:::

:::{admonition} 坑四：录视频、开 livestream 时主机内存不够
:class: warning

需要渲染的进程，主机内存都比纯训练高：录视频峰值 8.4 GB（[6.6.1](../6-galbot/6-eval/6.6.1-play-replay.md)），livestream 训练 9.5 GB（表 3），纯训练 5.9 GB。在 16 GB 的机器上，不要让两个这样的进程同时跑。
:::
