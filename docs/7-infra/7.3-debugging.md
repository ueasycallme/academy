# 调试技巧

:::{admonition} 学习目标
:class: lead-goals

- 任务能跑但行为不对时，知道先缩小、再看张量、再画出来
- 在 Isaac Lab 进程里用 `breakpoint()` 停下来，或用 VS Code attach
- 知道各种日志在哪，怎样不让警告把有用的输出淹没
:::

:class: lead-prereq

- [5.8 训练不收敛怎么排查](../5-rl/5.8-training-debug.md)：本页讲手段，5.8 讲训练前要查什么

**本页在项目中新增**：`scripts/debug_step.py`。它把环境缩到 1 个，逐步打印观测各项、奖励各项、指令，并检查 NaN；可选在第 1 步后停进 pdb，或等调试器 attach。

## 先缩小再看

这一节回答：行为不对时，第一步做什么？

把问题缩到能看清的规模：

- **环境数 1**：`--num_envs 1`。4096 个环境的张量打印出来没法看，单个环境的每个数都能对上物理意义；
- **固定种子**：`--seed 42`，让每次运行看到同一个初始状态；
- **关掉随机化**：用不带随机化的任务（`Galbot-Reach-v0` 而不是 `-DR-v0`），先排除"随机到了一个怪参数"；
- **少走几步**：`debug_step.py` 默认零动作走 3 步，几秒就能看完一轮。

有一类问题只在多个环境时才出现：对 `env_ids` 子集的索引写错、张量形状碰巧能广播而没有报错。这类问题缩到 1 个环境会被藏起来，所以单环境看完后，再用 2 个环境复查一次（`--num_envs 2`，看两个环境的数值是否各自合理）。第 6 部分实际遇到的问题，如重置只恢复写到的关节（[4.12](../4-isaaclab/4.12-event-randomization.md) 坑四），在 1 个环境时就能看到。

## 看张量

这一节回答：环境内部的数，从哪里取出来看？

```bash
python scripts/debug_step.py --headless          # Galbot-Reach-v0，1 个环境，零动作 3 步
```

```text
环境数 1，step_dt 0.0333 s，动作维数 7
reset 之后：
  观测组 policy（28 维）
    joint_pos        tensor([ 0.045, -0.196, -0.041, -0.184, -0.137, -0.007,  0.094], device='cuda:0')
    joint_vel        tensor([0., 0., 0., 0., 0., 0., 0.], device='cuda:0')
    pose_command     tensor([ 0.519, -0.318,  1.260,  0.706, -0.595, -0.221,  0.314], device='cuda:0')
    actions          tensor([0., 0., 0., 0., 0., 0., 0.], device='cuda:0')
第 1 步：总奖励 -0.0030，terminated False，truncated False
    奖励 end_effector_position_tracking               -0.05760
    奖励 end_effector_position_tracking_fine_grained  +0.00063
    奖励 end_effector_orientation_tracking            -0.03197
    奖励 action_rate                                  -0.00000
    奖励 joint_vel                                    -0.00074
    观测中有 NaN：{'policy': False}
```

*本站实测（节选），用时约 17 s，显存峰值 2299 MiB，主机内存峰值 3.4 GB。*

取数的几个入口：

- **观测**：`env.step()` 返回的 `obs` 是按组的字典；组内各项按定义顺序拼接，每项的维度在 `env.observation_manager.group_obs_term_dim` 里，脚本据此把 28 维拆回 4 项。`joint_pos` 是相对默认姿态的值（`joint_pos_rel`），所以 reset 后不为 0：重置事件加了 ±0.2 rad 的随机偏移（[6.4.1](../6-galbot/4-task/6.4.1-reach.md)）。
- **奖励各项**：每个 Manager 都有 `get_active_iterable_terms(env_idx)`，返回某个环境各项的名字与值[^iter]。奖励项的值是"函数值 × 权重"，**没有乘 dt**[^reward]，所以几项相加再乘 `step_dt`，才等于这一步的总奖励：上例 −0.0897 × 0.0333 ≈ −0.0030。
- **指令**：`env.command_manager.get_command("ee_pose")`，在根坐标系下（[4.13](../4-isaaclab/4.13-command-manager.md)）。
- **原始缓冲**：`env.obs_buf`、`env.reward_buf` 是最近一次 `step()` 的结果[^rl-env]。

打印前设 `torch.set_printoptions(precision=3, sci_mode=False, linewidth=140)`，小数对齐、不用科学计数，一行放得下一个观测项。出现 NaN 时的排查顺序见 [5.8](../5-rl/5.8-training-debug.md) 的"NaN 专项"：先查初始状态与接触（第 6 部分轮式版的 NaN 就是轮子被压进地面，D-026），再查参数。

## 把目标和末端画出来

这一节回答：数字看不出问题时，怎么看空间关系？

指令项打开 `debug_vis=True`，就会画出目标位姿与当前位姿两个坐标系标记（[4.13](../4-isaaclab/4.13-command-manager.md)）。Galbot reach 默认打开，标记画在 TCP 上（6.4.1 的 `TcpPoseCommand`）。标记由 `VisualizationMarkers` 绘制：给它一组位置和朝向，每帧更新[^markers]。自己的任务想画别的东西，比如工作空间边界、接触点，也用它。

![回放中目标与 TCP 两个标记的四帧](../_static/img/6.6.1-keyframes.jpg)

*图 1：离屏渲染的帧，取自 6.6.1 的回放录像（`--headless --video`，没有打开窗口）。换目标后 0.1 s，两个标记分开（第 2 帧）；0.5 s 后重新重合。*

没有显示器时，用 `--video` 录一段、或用 livestream（[7.1](7.1-headless-remote.md)）看标记。

## 断点与调试器

这一节回答：能不能在 Isaac Lab 进程里停下来逐行看？

**`breakpoint()`。** 在脚本里写 `breakpoint()`，运行到那里就进入 pdb。headless 模式、终端的标准输入可用时就能用：

```bash
python scripts/debug_step.py --headless --breakpoint
```

```text
-> for step in range(1, args.steps + 1):
(Pdb) p env.num_envs
1
(Pdb) p env.episode_length_buf
tensor([1], device='cuda:0')
(Pdb) c
```

*本站实测：在 Kit 进程里 pdb 正常工作（本例用管道送入命令）。*

停在断点时，**仿真不会自己往前走**：Isaac Lab 的仿真只在 `env.step()` 里推进（[3.1](../3-isaacsim/3.1-sim-loop.md)），你在 pdb 里看多久，物理状态就停在那一刻多久。

**VS Code attach（debugpy）。** debugpy 不在 Isaac Lab 的依赖里，要另外装：`pip install debugpy`（本站为 1.8.22）。在脚本开头监听端口、等调试器连接：

```python
import debugpy
debugpy.listen(("127.0.0.1", 5678))
debugpy.wait_for_client()   # VS Code attach 之后才往下走
```

VS Code 的 `launch.json` 里加一个 attach 配置：

```json
{"name": "Attach Isaac Lab", "type": "debugpy", "request": "attach", "connect": {"host": "127.0.0.1", "port": 5678}}
```

`debug_step.py --debugpy` 就是这样写的。本站用一个最小的调试协议客户端验证过：它连上后完成握手，脚本随即继续往下运行。VS Code 界面本身的操作没有实测，IDE 的配置细节见 [1.8 开发工具链](../1-env/1.8-dev-tools.md)。

## 日志在哪

这一节回答：出了问题，去哪里找记录？

| 日志 | 位置（pip 安装） | 内容 |
|---|---|---|
| Kit 日志 | `<环境>/…/site-packages/isaacsim/kit/logs/Kit/Isaac-Sim/5.1/` | Kit 与各扩展的全部输出，包括终端里看不到的 |
| Isaac Lab 运行日志 | `/tmp/isaaclab/logs/` | Isaac Lab 自己的日志 |
| 训练日志 | `logs/rsl_rl/<实验名>/<运行>/` | TensorBoard 事件、配置快照（[6.5.3](../6-galbot/5-train/6.5.3-experiment-management.md)） |

*表 1：日志位置（[1.4](../1-env/1.4-install-51-232.md) 表 1、[1.7](../1-env/1.7-install-methods.md) 表 4）。*

终端里的启动输出很少，这是有意为之：AppLauncher 在启动 Kit 期间把标准输出导到 `/dev/null`，除非加了 `--verbose` 或 `--info`[^launcher]。想看启动细节就加 `--info`；看完整的扩展加载过程加 `--verbose`。反过来，嫌警告太多时去 Kit 日志里按关键字搜，比在终端里翻更快。

## 一套顺序

这一节回答：拿到一个"行为不对"的任务，按什么顺序查？

| 症状 | 先做什么 | 用哪个脚本 |
|---|---|---|
| 一启动就报错 | 读完整报错；加 `--info` 看启动过程 | — |
| 机器人姿态不对、塌了 | 缩到 1 个环境，零动作看能否站住 | `hold_pose.py`、`check_env.py` |
| 观测或奖励的数看着不对 | 1 个环境逐项打印 | `debug_step.py` |
| 目标是否可达不确定 | 检查目标采样范围 | `check_reach_targets.py`、`workspace.py` |
| 出现 NaN | 先查初始状态与接触，再查参数 | 5.8"NaN 专项" |
| 训练不收敛 | 按 5.8 的训练前检查清单 | 5.8 |
| 训练好了但回放不对 | 对照训练与回放的差别 | `eval_reach.py`、6.6.1 表 1 |

*表 2：症状 → 先做什么 → 用哪个脚本。脚本都在 6-galbot 项目的 `scripts/` 下；训练前要查的项目见 [5.8](../5-rl/5.8-training-debug.md) 的"环境自检清单"。*

## 常见坑

:::{admonition} 坑一：打印整个张量
:class: warning

`print(obs)` 在 4096 个环境时会输出几万个数，终端被刷屏，有用的东西反而看不到。先 `--num_envs 1`，或者只打印 `obs["policy"][0]`。
:::

:::{admonition} 坑二：带界面运行时用 breakpoint()
:class: warning

pdb 停住时，整个 Kit 主循环都停了，界面也会卡住不响应（推断：界面与仿真在同一个主循环里，[2.6](../2-usd-kit/2.6-what-is-kit.md)）。本站只验证了 headless 下的 pdb。要在带界面时停下来看，用 VS Code attach 更合适。
:::

:::{admonition} 坑三：随机化没关，问题复现不出来
:class: warning

带随机化的任务每次初始参数都不同，上一次看到的现象这次可能没有。先在不带随机化的任务上，固定种子复现，再打开随机化。
:::

:::{admonition} 坑四：把奖励项的值当成这一步的奖励
:class: warning

`get_active_iterable_terms` 给的奖励项值是"函数值 × 权重"，没有乘 `step_dt`。要和训练日志或总奖励比较，先乘上 `step_dt`（上文实测的验算）。
:::
