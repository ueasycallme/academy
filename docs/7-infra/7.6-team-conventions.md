## 项目结构

以 4.18 的模板为底，本项目现在的样子（省略了部分文件）：

```text
6-galbot-project/
├── source/galbot_academy/galbot_academy/     # 可安装的包：别人 import 的东西
│   ├── assets/        galbot.py（ArticulationCfg）、paths.py、physics.py、omni_base.py …
│   ├── scenes/        reach.py、lift.py、sensors.py：几个任务共用的场景
│   └── tasks/
│       ├── manager_based/<任务>/              # reach、lift、pick_place、base_vel
│       │   ├── __init__.py                    # gym.register
│       │   ├── <任务>_env_cfg.py              # 环境配置及其变体
│       │   ├── mdp/                           # 任务专用的观测、奖励、终止函数
│       │   └── agents/                        # rsl_rl / robomimic 配置
│       └── direct/reach/                      # Direct 写法（6.4.4）
├── scripts/           # 命令行入口：转换、训练、评估、探针、画图
├── tests/             # unit/（无 GPU）、gpu/、regression/（7.4）
├── ros2/              # 部署侧，不依赖 Isaac Sim（6.7）
├── README.md  DATA.md  CONTRIBUTING.md
└── generated/  datasets/  logs/              # 都不进 git（7.5）
```

**放包里还是 `scripts/`**：会被别的代码 import 的放包里，例如资产配置、任务、`omni_base.body_to_wheel`。只在命令行运行的放 `scripts/`。两边都要用的工具，比如示教控制器 `pick_place_teacher.py`，本项目放在 `scripts/` 里由同目录脚本导入，测试通过 `tests/conftest.py` 把 `scripts/` 加进路径。这是本项目的折中做法：代码量再大一些，就该挪进包里。

## 配置怎么改

4.3 讲了三种改配置的方式。本项目各有实例：

| 方式 | 本项目的例子 | 适合 |
|---|---|---|
| `.replace()` | `GALBOT_ONE_GOLF_WHEELED_CFG = GALBOT_ONE_GOLF_CFG.replace(spawn=…, init_state=…, actuators=…)`；`scenes/reach.py` 里 `GALBOT_ONE_GOLF_CFG.replace(prim_path="{ENV_REGEX_NS}/Robot")` | 从一份预置派生，只改几个字段 |
| 子类 + `__post_init__` | `GalbotReachEnvCfg_PLAY` 先 `super().__post_init__()`，再把环境数改成 16；`GalbotReachDREnvCfg` 打开观测噪声 | 长期存在、要注册成任务的变体 |
| 子类替换整组字段 | `DREventCfg(EventCfg)` 加三项 startup 事件，`GalbotReachDREnvCfg` 用 `events: DREventCfg = DREventCfg()` 换掉父类那组 | 往某一组里加项 |
| 实例化后赋值 / Hydra 覆盖 | 评估脚本把指令范围设成固定值；6.4.5 用 `env.rewards…std=0.25` 做实验 | 一次性的实验与脚本参数，**不进主线** |

本项目的变体链是：`Reach` → `Reach-Play`；`Reach` → `Reach-DR` → `Reach-DR-Play`。`Reach-Direct` 不继承，它是另一套 `DirectRLEnvCfg`，只共用资产配置与数值（6.4.4）。

两条规矩：

- **用命令行覆盖做出来的结果，要成为主线，就写回配置文件。** 否则别人照 README 跑，复现不出来。
- **知道哪些字段改了必须重训**：dt、decimation、执行器参数、动作的 `scale` 与 `clip`、观测项（[6.3.1 结论](../6-galbot/3-sim-align/6.3.1-physics-tuning.md)）。这些字段改了，旧检查点照样能加载、能跑，只是结果不再可信。

## 命名

| 对象 | 规则 | 本项目实例 |
|---|---|---|
| 任务 id | `Galbot-<任务>[-<变体>]-v<N>`；回放用 `-Play`（4.15） | `Galbot-Reach-DR-Play-v0`、`Galbot-PickPlace-IK-Rel-Mimic-v0` |
| 实验名 | rsl_rl 配置里的 `experiment_name`，一个任务一个 | `galbot_reach`、`galbot_base_vel` |
| 运行目录 | `--run_name` 写种子或改动，目录自动加时间戳 | `2026-10-11_23-24-41_clip_limits` |
| 检查点 | 不改名，在记录表里写"运行目录 + 迭代数" | `…_seed42/model_999.pt` |
| 数据文件 | `<任务>[_<阶段>].hdf5`，放 `datasets/` | `galbot_pick_place_annotated.hdf5` |
| 评估 CSV | `<运行目录名>_<检查点>_<评估种子>.csv`，放回运行目录 | 7.5 起的约定（`DATA.md`），之前的 CSV 没按它命名 |

## 提交前检查什么

清单写在项目的 [`CONTRIBUTING.md`](https://github.com/ueasycallme/academy/blob/main/examples/isaaclab-2.3/6-galbot-project/CONTRIBUTING.md) 里，分环境、代码、测试、数字与文档四组。其中三条最容易被跳过：

- **版本**：`check_versions.py` 只读包的元数据，在本站环境里全部一致，返回 0；在没装 Isaac 的系统 Python 里，六个包全报"未安装"，返回 1（本站实测）。
- **无 GPU 测试**：本页加了 3 个用例，`tests/unit/` 现在系统 Python 下是 16 passed、1 skipped（本站实测）。
- **显存按进程测**：整卡读数会把同一张卡上别的进程也算进去，机器有人共用时尤其不准。按进程测，4096 个环境的 Cartpole 训练是 2905 MiB（[5.4](../5-rl/5.4-parallel-envs.md)）；测法见 [7.2](7.2-profiling.md)。

## 评审仿真代码多看什么

普通 Python 评审看逻辑、命名、异常处理。仿真代码还要多看五项，下面每一项都是本站真实出过的问题：

| 看什么 | 本站的例子 |
|---|---|
| 随机性 | 只用一个评估种子就下结论；同一个检查点、同一个种子重复评估，成功率也会差 1–2 个百分点（[6.6.2 坑三](../6-galbot/6-eval/6.6.2-evaluation.md)、[6.4.5 表 5](../6-galbot/4-task/6.4.5-base-navigation.md)） |
| 设备 | 照官方示例用 `--device cpu` 标注 GPU 上录的示范，10 条全部失败（[6.4.7 坑一](../6-galbot/4-task/6.4.7-mimic.md)） |
| 形状 | 重新导出了动态批维度的 ONNX，节点里还断言输入是 `[1, 28]`（[6.7.1 坑一](../6-galbot/7-deploy/6.7.1-policy-export.md)） |
| 单位 | `clip` 作用在缩放之后，写成 (−1, 1) 实际把轮速限在了 ±1 rad/s，训练照常收敛，速度永远跟不上（[6.4.5 坑三](../6-galbot/4-task/6.4.5-base-navigation.md)） |
| 坐标系 | 遥操作的 W 键是机器人根坐标系的 +x，不是屏幕里的"前"（[4.20 坑二](../4-isaaclab/4.20-teleop-devices.md)） |

*表 3：评审清单。*

这五类问题有个共同点：代码不报错，训练也照常收敛，错误只体现在数字上。所以评审时不能只读代码，还要看评估输出。

## 常见坑

### 坑一：在脚本里改模块级的预置配置，任务看不到

`GALBOT_ONE_GOLF_CFG` 是模块级对象，任务配置类在**导入时**就用它 `.replace()` 出一份副本，作为类的默认值。本站实测：导入任务后再把预置的手臂刚度改成 7，新建的 reach 配置仍是 1600，base_vel 配置仍是 400。反过来也安全：reach 的 `__post_init__` 把刚度改成 1600，不会影响预置和别的任务（configclass 在实例化时深拷贝[^cc]）。所以要改，就改任务配置的实例，或者写一个新的变体。

### 坑二：任务 id 重复注册，只有一行警告

同一个 id 注册两次，gymnasium 只打印 `WARN: Overriding environment Galbot-Reach-v0 already in registry.`，后注册的覆盖前一个（本站实测）。两个人各自加了同名任务，谁的包后导入，就用谁的配置。新 id 先查 `gym.registry`。

### 坑三：配置里写死绝对路径

`params/env.yaml` 会把 USD 的绝对路径原样记下来（7.5 坑四）。如果代码里也写死路径，换一个人就跑不起来。本项目统一通过 `generated_asset_dir()` 取资产目录，可以用环境变量 `GALBOT_GENERATED_DIR` 改。

### 坑四：每人装的版本不一样

Isaac Lab 不会把自己的版本写进训练日志（6.5.3 坑二）；而 rsl_rl 版本由 `isaaclab_rl` 钉死在 3.1.2[^rsl-pin]，换了 Isaac Lab，它会跟着变。两人结果对不上时，先比 `check_versions.py` 的输出。
