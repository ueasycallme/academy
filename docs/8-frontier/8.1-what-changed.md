## 一张总图

这一节回答：3.0 的分层和 2.3 有什么不同？

2.3 的分层见 [0.2](../0-map/0.2-layers.md) 图 1：Isaac Lab 只有一条路，下面一定是 Isaac Sim，再下面是 Kit 与 PhysX。3.0 的 Isaac Lab 下面有了几条路：

```{mermaid}
flowchart TB
    LAB["Isaac Lab 3.0<br/>统一的资产 / 传感器 / 场景 API"]
    SIM["Isaac Sim 6.2<br/>（Kit + PhysX + RTX）"]
    NEWTON["Newton<br/>（MJWarp、Kamino 等求解器）"]
    OVPX["OvPhysX<br/>（不带 Kit 的 PhysX）"]
    WARP["NVIDIA Warp"]
    GPU["GPU 驱动 / CUDA"]

    LAB -- "physics=isaacsim_physx" --> SIM
    LAB -. "physics=newton_mjwarp<br/>（Kit-less）" .-> NEWTON
    LAB -. "physics=ovphysx<br/>（Kit-less）" .-> OVPX
    SIM --> GPU
    NEWTON --> WARP
    OVPX --> GPU
    WARP --> GPU
```

*图 1：Isaac Lab 3.0 的分层，底层在下。箭头表示"构建在……之上"（D-010）；实线需要 Isaac Sim，虚线不需要。默认走哪条由任务的 `PresetCfg.default` 决定：v3.0.0 注册的 45 个官方 `Isaac-*` 任务里，44 个默认 Newton（其中 37 个是 `newton_mjwarp`），没有一个默认 Isaac Sim PhysX；94 个社区贡献的 `IsaacContrib-*` 任务里，33 个默认 `isaacsim_physx`，44 个不提供预设[^defaults]（[8.7](8.7-isaaclab-cli.md#train--play参数分三层)）。官方文档 Visualization 页仍写"多数任务默认 PhysX"[^most-physx]，与 v3.0.0 的代码不一致。渲染器也可以独立选择，图中略去（见"Kit-less"一节）。依据：Physics Backends[^backends]。*

## 四个变化

### 多物理后端

这一节回答：为什么要把物理引擎做成可替换的？

- **2.3.2**：物理只有 PhysX 一个。物理配置 `PhysxCfg` 直接放在核心包 `isaaclab.sim` 的 `SimulationCfg` 里[^232-physx]，`Articulation` 等资产类的实现也直接调用 PhysX 的张量接口。想换引擎，就得改核心代码。
- **3.0**：核心包 `isaaclab` 只定义资产、传感器的接口。具体实现放在 `isaaclab_physx`、`isaaclab_newton`、`isaaclab_ov` 等后端包里。你写 `Articulation(cfg)` 时，一个工厂类按当前的物理后端（backend），延迟导入对应包里的实现[^factory]。任务通过 `physics=` 预设选后端，例如 `isaacsim_physx`、`newton_mjwarp`、`ovphysx`；不写时用任务自己的默认，官方任务多数是 Newton（图 1）[^presets]。
- **对你的代码**：`from isaaclab.assets import Articulation` 这样的导入不用改；`PhysxCfg` 要改从 `isaaclab_physx.physics` 导入[^migr]。细节见 [8.2](8.2-multi-backend.md)。

### Newton

这一节回答：Newton 是什么？

- **2.3.2**：没有 Newton。
- **3.0**：Newton 是一个基于 Warp 的物理框架，在 Isaac Lab 里作为一个后端，不需要 Isaac Sim[^backends]。它不等于某一个求解器：Newton 里有 MJWarp（MuJoCo 的 Warp 版）、Kamino、VBD、MPM 等多种求解器，其中 MJWarp 是主要的已验证路径，Kamino 仍是实验性的[^newton-guide][^ga]。EA 文档曾把 Newton 整体标为 beta，正式版文档不再这样标。
- **对你的代码**：只有任务提供了 Newton 预设才能用；资产往往要按 Newton 的要求处理过[^newton-guide]。细节见 [8.3](8.3-newton.md)。

### Kit-less

这一节回答：不启动 Omniverse Kit，还能做什么？

- **2.3.2**：任何 Isaac Lab 程序都要先通过 AppLauncher 启动 Kit（[3.2](../3-isaacsim/3.2-simulation-app.md)、[2.6](../2-usd-kit/2.6-what-is-kit.md)），训练前要先装好整个 Isaac Sim。
- **3.0**：用 Newton 或 OvPhysX 作物理后端时，可以完全不启动 Kit，甚至不装 Isaac Sim[^backends][^ga]。渲染也可以独立选择：Newton Warp 渲染器与 OVRTX 不需要 Kit；Isaac RTX 渲染、直播推流（livestream）仍需要 Kit[^renderers][^ga]。
- **对你的代码**：任务本身不用为此改写，但带相机、依赖 Kit 扩展或 Isaac Sim 专有功能的部分，只能走带 Kit 的路径。

### Warp 原生数据路径

这一节回答：为什么数据类型和四元数顺序都变了？

- **2.3.2**：资产数据（如 `robot.data.root_pos_w`）直接返回 `torch.Tensor`[^232-data]，四元数按 `(w, x, y, z)` 排列[^232-quat]。
- **3.0**：数据属性返回 `ProxyArray`。它包着一个 Warp 数组 `wp.array`，用 `.torch` 可以零拷贝地拿到 Torch 张量[^factory]；四元数改为 `(x, y, z, w)`[^ga-quat]。改动的理由是 Warp、PhysX、Newton 都用 XYZW，统一以后内部不再来回转换[^migr]。仿真数据经 `SceneDataProvider` 统一交给渲染器和可视化器，它们不用知道背后是哪个物理引擎[^factory]。
- **对你的代码**：读数据处加 `.torch`；所有写死的四元数（初始姿态、目标姿态）都要改顺序。官方提供了一个查找脚本。清单见 [8.4](8.4-migration-23-30.md)。

## 哪些没变

这一节回答：学 2.3 是不是白学了？

| 2.3.2 | 3.0 |
|---|---|
| `ManagerBasedRLEnv` 与 `DirectRLEnv` 两种写法 | 两个类仍在 `isaaclab.envs` 里[^ga-envs] |
| Manager 与 Term（观测、动作、奖励、事件、指令……） | `isaaclab.managers` 下的各个 Manager 都还在[^ga-managers] |
| `configclass` 写配置 | 仍是 `isaaclab.utils.configclass` |
| rsl_rl / skrl / rl_games / sb3 的适配层 | `isaaclab_rl` 下仍有这四个，另增 TorchRL[^ga-rl] |
| 任务按写法分目录：`manager_based/`、`direct/`[^232-tasks] | **改为按任务分目录**：`core/cartpole/` 里同时放 Manager-based 与 Direct 两种实现；任务名去掉了 `-v0`，如 `Isaac-Cartpole`、`Isaac-Cartpole-Direct`[^ga-cartpole] |

*表 1：主要概念的对照。第 4 部分讲的环境写法，第 5 部分讲的 RL 概念，在 3.0 里都还适用；变的是安装方式、导入路径、数据类型与四元数顺序（[8.4](8.4-migration-23-30.md)）。*

## 版本与状态

这一节回答：3.0 现在到哪一步了？

```{mermaid}
flowchart LR
    B1["v3.0.0-beta<br/>2026-03-16<br/>多后端架构首发<br/>Isaac Sim 6.0"] --> B2["v3.0.0-beta2<br/>2026-06-16<br/>Newton 扩展、Kit-less 稳定<br/>统一命令"] --> P1["beta2.patch1<br/>2026-06-30<br/>支持 Isaac Sim 6.0.1"] --> EA["v3.0.0-EA<br/>2026-09-16<br/>只修 bug、稳定性<br/>Isaac Sim 6.1"] --> GA["v3.0.0 正式版<br/>2026-10-19<br/>Isaac Sim 6.2"]
```

*图 2：3.0 的发布时间线（自左向右）。依据：tag 内的发布说明[^rn]、GitHub 上的 EA 发布页[^ea]与正式版发布页[^ga]。*

- 正式版相对 EA 主要是依赖升级（Isaac Sim 6.2、Warp 1.17、Newton 1.6.1、RSL-RL 5.5.1）与稳定性修复，另有少量会影响已有脚本的改动，如 `AppLauncher` 弃用、`--cpu` 删除，见 [8.4](8.4-migration-23-30.md)[^ga]。
- 3.0 要求 Python 3.12，默认用 `uv` 安装，训练入口统一为 `isaaclab train`，与 2.3 的环境不能共用[^migr]。
- 正式版发布页的要点里还有几项本站没有展开：Isaac Capture 遥操作、LEAPP 模型导出、可变形体与粒子示例、浏览器里的交互演示，见发布页[^ga]与迁移文档对应小节[^migr]。
- 本站的主线仍是 5.1 + 2.3.2。什么时候该切换，按 [1.2](../1-env/1.2-version-decision.md) 的决策树判断。

## 常见误解

:::{admonition} 误解一："3.0 就是把 PhysX 换成了 MuJoCo"
:class: warning

PhysX 仍在，经 Isaac Sim 或 OvPhysX 两条路都能用；官方任务的默认后端多数换成了 Newton（图 1），但它不等于 MuJoCo：MJWarp 只是 Newton 里的一种求解器[^backends]。
:::

:::{admonition} 误解二："3.0 不再需要 Isaac Sim"
:class: warning

只有走 Newton 或 OvPhysX 的 Kit-less 路径时才不需要。Isaac Sim 的 PhysX、Isaac RTX 渲染、livestream、ROS 桥接、XR 遥操作都还要 Isaac Sim[^renderers][^ga]；社区贡献任务里也有不少默认 `isaacsim_physx`（图 1）。后端支持按任务而定，用 `isaaclab train --task <任务> --help` 查[^backends]。
:::

:::{admonition} 误解三："2.3 的任务代码在 3.0 上原样能跑"
:class: warning

写法的骨架不变，但导入路径（如 `PhysxCfg`）、数据访问（要加 `.torch`）、四元数顺序、按索引写入的方法名都变了[^migr]。尤其是四元数：顺序写错了不会报错，只会让姿态悄悄变成错的。迁移步骤见 [8.4](8.4-migration-23-30.md)。
:::
