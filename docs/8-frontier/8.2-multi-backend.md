## 抽象边界

这一节回答：任务代码写的是 `Articulation(cfg)`，最后是谁在算物理？

```{mermaid}
%%{init: {"flowchart": {"rankSpacing": 26, "nodeSpacing": 22, "padding": 6}}}%%
flowchart TB
    TASK["任务配置<br/>PresetCfg：physics= / renderer= 预设"]
    CORE["Isaac Lab 核心<br/>Articulation、ContactSensor 等工厂类<br/>SimulationContext · PhysicsManager 接口"]
    PX["isaaclab_physx"]
    NW["isaaclab_newton"]
    OV["isaaclab_ov"]
    E1["PhysX（经 Isaac Sim / Kit）"]
    E2["Newton（MJWarp、Kamino 等求解器）"]
    E3["OvPhysX（不用 Kit）"]
    TASK --> CORE
    CORE --> PX
    CORE --> NW
    CORE --> OV
    PX --> E1
    NW --> E2
    OV --> E3
```

*图 1：3.0 的多后端分层（箭头表示"构建在……之上"，D-010）。任务只和核心层打交道；选哪个后端包、哪个引擎，由预设在启动时决定。渲染器、可视化器另走一条选择线（下文）。*

边界由三样东西划定：

1. **工厂类**（factory class）：`Articulation`、`ContactSensor`、它们的 `*Data` 等都继承 `FactoryBase`。构造时，`_get_backend()` 读当前 `SimulationContext` 的物理管理器名，得到 `physx`、`newton` 或 `ovphysx`；再按模块路径约定拼出 `isaaclab_physx.assets.articulation` 之类的模块名，惰性导入（lazy import，用到时才导入），返回那个后端的实现[^factory][^arch]。还没有仿真上下文时，默认按 `newton` 处理。
2. **物理管理器**（physics manager）：每个后端实现 `PhysicsManager`，负责初始化、`step()`、`reset()`、`close()`，并在场景构建、物理就绪、停止时发出事件[^arch]。`SimulationCfg.physics` 决定用哪个管理器[^simcfg]。
3. **Schema 写入的钩子**（hook）：把配置写进 USD 的核心代码不导入任何后端；后端在包导入时往 `backend_hooks.py`（EA 时名为 `_backend_hooks.py`）的注册表里登记自己的行为（例如哪些关节驱动要跳过）[^hooks]。这个模块特意不导入 `pxr`、`omni`。

数据接口也统一了：资产和传感器的 `data.*` 返回 `ProxyArray`，用 `.torch` 或 `.warp` 零拷贝地取张量（[8.4](8.4-migration-23-30.md)）。选择只发生在构造时，不在仿真的热路径（hot path，每步都要执行的代码）上加分支[^arch]。

## 三种物理后端

| 后端 | 运行条件 | 求解器 |
|---|---|---|
| Isaac Sim PhysX | Isaac Sim 与 Kit | 默认 TGS，可选 PGS |
| Newton | 只要 Warp，不需要 Isaac Sim（Kit-less） | MJWarp（主要的已验证路径）、Kamino（实验性）、VBD、MPM |
| OvPhysX | 额外安装 `ovphysx`，不用 Kit，不能与 Kit 同进程 | PhysX，场景设置主要来自 USD |

*表 1：三种物理后端（依据 Physics Backends[^backends]、Newton 指南[^newton-guide]与正式版发布页[^ga]）。EA 文档另有一列成熟度（PhysX 成熟、Newton beta、OvPhysX experimental），正式版文档去掉了。*

文档特别说明：后端（backend）是接入 Isaac Lab、管理仿真生命周期的那一层；求解器（solver）是推进物理状态的数值方法。所以 Newton 不等于 MJWarp。换求解器时，参数不能按数值照搬，要重新调[^backends]。

## 预设：一个任务，几套配置

这一节回答：`physics=newton_mjwarp` 到底改了什么？

预设（preset）是写在任务配置里的一组命名选项。任务把某个字段写成 `PresetCfg` 的子类，每个属性是一个选项，`default` 是不指定时用的那个[^presetcfg]：

```python
@configclass
class ReachPhysicsCfg(PresetCfg):             # 官方 reach 任务
    isaacsim_physx: PhysxCfg = PhysxCfg(bounce_threshold_velocity=0.2)
    newton_mjwarp: NewtonCfg = NewtonCfg(solver_cfg=MJWarpSolverCfg(njmax=100, nconmax=20, ...), ...)
    default: NewtonCfg = newton_mjwarp
```

命令行的 `physics=NAME` 是一个选择器（selector）：它把名字 `NAME` 应用到配置里每一个有这个选项的 `PresetCfg` 字段，不论字段是什么类型；类型只决定这个预设在 `--help` 里列在 physics 还是 renderer 一栏[^target][^pick]。单个字段也能这样写：`preset(default=..., newton_mjwarp=...)` 生成一个只有两个选项的预设[^presetcfg]。本站的 Galbot 就用它给两个后端指定不同的 USD 文件（[8.5](8.5-galbot-reach-30.md)）：USD 路径是字符串字段，不是物理配置，也会跟着 `physics=newton_mjwarp` 一起换。

内置的物理预设名：

| 预设 | 含义 |
|---|---|
| `isaacsim_physx` | 经 Isaac Sim 的 PhysX |
| `physx` | 自动选择：需要 Kit 时用 Isaac Sim 的 PhysX；不需要、且任务提供了 OvPhysX 选项时，用 OvPhysX |
| `newton_mjwarp` | Newton + MJWarp |
| `newton_kamino` | Newton + Kamino（实验性） |
| `ovphysx` | OvPhysX |

*表 2：物理预设（Backends and Presets[^presets]；`physx` 的选择逻辑见源码[^auto]）。旧名 `newton`、`kamino` 是 `newton_mjwarp`、`newton_kamino` 的弃用别名[^target]。有的任务还有组合预设，如可变形体任务的 `newton_mjwarp_vbd_proxy`。*

这条"自动选择"在实际使用中容易踩坑。纯 headless 训练里没有东西需要 Kit，`physics=physx` 会选到 OvPhysX；没装 `ov[ovphysx]` 时，启动就报 `ModuleNotFoundError`。要用 Isaac Sim 自带的 PhysX，就明确写 `physics=isaacsim_physx`。另外，不写 `physics=` 时用的是任务自己的 `default`，各任务不同，Cartpole（Direct）的默认是 `newton_mjwarp`，不是 PhysX[^cartpole-default]；官方任务的默认多数是 Newton（[8.1](8.1-what-changed.md) 图 1）。两点都是本站实测，见 [8.7 常见坑](8.7-isaaclab-cli.md#常见坑)。

**边界**：预设只能在任务列出的选项里选，没有列出的名字会在配置校验时报错；一个任务支持哪些预设，用 `isaaclab train --task <任务> --help` 看，或用 `isaaclab list_envs --show_presets` 列出所有任务能用的组合，`[default]` 标出默认[^presets]。"任务不变、预设换引擎"的意思是配置换了，任务的观测、动作、奖励不变；但换引擎后结果不一定一样，可能要改资产、重调参数（下一节）。

## 渲染器与可视化器

物理、渲染、可视化是三个独立的选择[^arch]。

**渲染器**（renderer，给相机传感器出图，供训练用）有三种，用 `renderer=` 选，预设名为 `isaacsim_rtx`、`ovrtx`、`newton_renderer`，另有自动选择的 `rtx`[^presets][^renderers]：

- **Isaac RTX**：需要 Isaac Sim，传感器保真度最高，配 PhysX；
- **OVRTX**：不需要 Isaac Sim（要装 `isaaclab_ov` 与 `ovrtx`），RTX 画质，配 Newton；
- **Newton Warp**：不需要 Isaac Sim 的轻量光栅化（rasterization）渲染器，配 Newton，适合重吞吐的训练，输出比 RTX 少（没有运动向量等）。

**可视化器**（visualizer，给人看的实时窗口，用 `--viz` 选择）有五种[^viz]：

- **Newton GL**：轻量的 OpenGL 窗口，启动快；
- **Viser**：网页界面，支持录制与回放；
- **Newton RTX**：RTX 画质，实验性；
- **Rerun**：网页界面，支持录制与回放，界面选项较少；
- **Kit**：Isaac Sim 的界面，RTX 画质，工具最全，启动最慢。

所以 Kit-less 不等于没有画面：Newton Warp、OVRTX 两个渲染器和除 Kit 外的四个可视化器都不需要 Isaac Sim。

## 实测：Cartpole 换预设

这一节回答：同一个任务换物理预设，开销差多少？

```bash
isaaclab train --rl_library rsl_rl --task Isaac-Cartpole-Direct --max_iterations 100 --seed 42 physics=newton_mjwarp
```

| 预设 | 墙上时间（启动 + 100 次迭代） | 训练用时 | 每次迭代（中位数） | 按进程显存 | 主机 RSS 峰值 |
|---|---|---|---|---|---|
| `isaacsim_physx` | 19–21 s | 11.1–11.2 s | 0.11 s | 3286 MiB | 4.8 GB |
| `newton_mjwarp` | 17–19 s | 8.6–8.7 s | 0.08 s | 756 MiB | 2.4 GB |
| `newton_kamino` | 30–50 s | 21.7–36.9 s | 0.21 s | 918 MiB | 2.4–3.4 GB |
| `physx`（自动） | 失败 | — | — | — | — |
| `ovphysx` | 失败 | — | — | — | — |

*表 3：Isaac-Cartpole-Direct，4096 个环境，100 次迭代，种子 42（本站实测，1.5 路线 A，RTX 5090 32 GB，2026-10-23，每个预设连续跑 3 次；不是按独占计时规则做的测量；测量期间本站没有别的 GPU 任务与构建，但从 Kamino 第 2 次起，GPU 上另有一个常驻的远程桌面进程（约 650 MiB），对数字的影响没有单独测）。Kamino 第一次的墙上时间 50 s、训练 36.9 s，后两次 30、31 s 与 21.7、21.8 s，第一次多出的是 Warp 编译内核；其余预设 3 次之间相差不到 2 s。*

- **显存差别最大**：PhysX 要加载 Isaac Sim 与 Kit，进程显存是 Newton 的 4 倍多。
- **Kamino 在 Cartpole 上每次迭代比 MJWarp 慢约 2.6 倍**（EA 时约 5 倍），只是这一个任务上的观察。
- **`physx` 与 `ovphysx` 失败的原因相同**：`ModuleNotFoundError: No module named 'ovphysx'`。本机没有装 OvPhysX 的运行时；而这条命令里没有任何需要 Kit 的组件（Kit 相机、`--viz kit`、指定 experience、livestream 等），`physx` 就自动选了 OvPhysX[^auto][^kitsrc]。想用 Isaac Sim 的 PhysX，要明确写 `physics=isaacsim_physx`。

## 对自己代码的影响

这一节回答：写任务时，哪些写法换后端也能用，哪些会绑死后端？

以 [8.5](8.5-galbot-reach-30.md) 的 Galbot reach 为例：

- **后端无关**：管理器、mdp 函数、`data.*.torch` 读状态、命令与奖励的写法，两个后端都没改；
- **会绑死后端的**：
  - 求解器迭代次数写在 `PhysxArticulationRootPropertiesCfg` 里，只对 PhysX 生效；
  - Newton 的 `nconmax` / `njmax` 要按机器人另调，照搬官方 Franka 的值会在第一步出错；
  - 资产本身：5.1 转换的 USD 在 Newton 下用不了，要给 Newton 单独指定 3.0 转换的资产（用 `preset()` 按后端选路径）。
- **结果**：同一任务在两个后端上训练，结果不一样，跨后端评估也会变差（8.5 表 4）。

## 常见误解

:::{admonition} 误解一："Newton 就是 MJWarp"
:class: warning

Newton 是后端，MJWarp 只是它的一个求解器，另有 Kamino、VBD、MPM 等[^backends]。预设名把两者都写出来：`newton_mjwarp`、`newton_kamino`。
:::

:::{admonition} 误解二："换个预设就能无损换引擎"
:class: warning

预设只换配置。资产要兼容（8.5：5.1 的资产在 Newton 下报错或丢碰撞体），求解器参数要重调，训练结果也会变；官方文档同样提醒换求解器要重新调参[^backends]。
:::

:::{admonition} 误解三："Kit-less 就没有画面"
:class: warning

Newton Warp、OVRTX 渲染器能给相机出图，Newton GL、Viser、Rerun 等可视化器能实时看，都不需要 Isaac Sim[^renderers][^viz]。
:::

:::{admonition} 误解四："physics=physx 就是 Isaac Sim 的 PhysX"
:class: warning

`physx` 是自动选择。配置和命令行里没有需要 Kit 的组件时，它会选 OvPhysX；有的话选 Isaac Sim 的 PhysX（例如加 `--viz kit`，推断，本站未实测）[^kitsrc]。没有 Kit 时没装 `ovphysx` 就直接报错（表 3）。要固定用 Isaac Sim 的 PhysX，写 `isaacsim_physx`。
:::
