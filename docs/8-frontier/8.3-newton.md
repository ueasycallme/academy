## Newton 是什么

Newton 是一个开源的 GPU 物理仿真引擎，用 NVIDIA Warp 写成，面向机器人与仿真研究。它由 Disney Research、Google DeepMind 与 NVIDIA 发起，2025 年 9 月 29 日由 Linux Foundation 宣布接收为基金会项目，代码以 Apache-2.0 许可发布[^lf][^readme]。它的前身是 Warp 里已弃用的 `warp.sim` 模块，并把 MuJoCo Warp 集成为主要求解器；README 强调的特点是 GPU 计算、OpenUSD 支持、可微分（differentiable）、可扩展[^readme]。

在 Isaac Lab 3.0 里，Newton 是三个物理后端之一（[8.2](8.2-multi-backend.md)）。它替换的只是"算物理"这一层：用 Newton 时不需要 Isaac Sim 与 Kit（Kit-less），但它不提供 Isaac Sim 的界面、RTX 渲染、Replicator 等。要渲染，用 Newton Warp 或 OVRTX 渲染器（8.2）。

EA 文档特别说明：Newton 不等于 MJWarp。Newton 是后端，MJWarp 是它承载的求解器之一[^ea-backends]。

## 与 PhysX 的对比

| 方面 | PhysX（Isaac Lab 3.0 的 `isaacsim_physx`） | Newton |
|---|---|---|
| 实现与运行 | PhysX SDK，GPU 上运行，经 Isaac Sim 与 Kit 接入[^ea-backends] | Python + Warp 内核，GPU 上运行（macOS 上只用 CPU）[^readme] |
| 是否需要 Isaac Sim | 需要[^ea-backends] | 不需要（Kit-less）[^ea-backends] |
| 数据路径 | PhysX 的张量视图[^native] | Warp 原生数组，Newton 的 Model / State[^native] |
| 求解器 | TGS（默认）、PGS[^ea-backends] | MuJoCo（MJWarp）、Kamino、Featherstone、XPBD、VBD、半隐式（semi-implicit）、隐式 MPM、Style3D 等[^solvers] |
| 物体类型 | 刚体、关节；可变形体的支持未核对 | 刚体、关节；布料与软体（VBD）、MPM（实验性）[^ea-backends] |
| 读 USD | 经 Isaac Sim | 自带 USD 导入器（`newton.ModelBuilder.add_usd`）[^native] |
| 成熟度（EA 文档） | 成熟的参照实现 | Beta；任务与组件覆盖更窄，按任务而定[^ea-backends] |

*表 1：PhysX 与 Newton 的对比（Newton 1.5.2，Isaac Lab v3.0.0-EA）。*

## MuJoCo Warp

MuJoCo Warp（MJWarp）是 MuJoCo 物理引擎的 GPU 版本，用 Warp 重写，由 Google DeepMind 与 NVIDIA 维护，属于 Newton 项目[^mjwarp]。MuJoCo 文档对它的定位是：适合强化学习这类高吞吐的批量仿真，单步延迟（latency）通常比 CPU 版 MuJoCo 高，实时控制仍应用 MuJoCo[^mjwarp-doc]。

在 Newton 里，`SolverMuJoCo` 在构造时由 Newton 的模型生成 MuJoCo 的模型，再交给 MJWarp 步进[^solver-mujoco]。所以用 MJWarp 时，接触和约束按 MuJoCo 的方式处理，参数也是 MuJoCo 的那一套（例如 `nconmax`、`njmax`、`cone`、`integrator`）。这也解释了 MJCF 的意义：Galbot 描述仓库同时提供了 MJCF（[6.1.1](../6-galbot/1-asset/6.1.1-galbot-repo.md)），但 Isaac Lab 的任务仍以 USD 为入口，Newton 从 USD 读模型（导入 MJCF 见 [3.5](../3-isaacsim/3.5-urdf-mjcf-import.md)）。

## 把资产搬到 Newton

EA 文档 *Prepare an Asset for Newton with MJWarp* 列了六类准备工作[^prep]。下表对照本站 Galbot 的实测（[8.5](8.5-galbot-reach-30.md)）：

| 文档要求 | Galbot 的情况 |
|---|---|
| 用 3.0 的导入器生成多物理资产（multi-physics asset），保留 `run_asset_transformer` 与 `run_multi_physics_conversion` | 5.1 转换的 USD 不行：有一处悬空引用，Newton 直接报组合错误；修掉后，144 个碰撞体因为 `CollisionAPI` 加在 Xform 上而被忽略。用 3.0 的导入器重新转换后可用 |
| 通用属性与求解器专有属性分开写 | 求解器迭代次数写在 `PhysxArticulationRootPropertiesCfg`，只对 PhysX 生效；Newton 一侧没有对应设置 |
| 检查机械模型：质量、惯量、碰撞体、关节 | 3.0 资产的碰撞 API 在 Mesh 上；刚体变为嵌套结构；mimic 每侧只剩 2 个跟随关节，对 reach 无影响 |
| 碰撞、接触与摩擦：先核对碰撞形状、接触位置与数量，再看 MuJoCo 的接触维度 `condim`，最后才调摩擦；不要照搬 PhysX 的摩擦数值 | 碰撞形状：两版资产都是 184 个碰撞体（144 个网格凸包 + 40 个球体）；5.1 资产里那 144 个的 `CollisionAPI` 在 Xform 上，Newton 忽略它们，3.0 资产在 Mesh 上，正常（本站用 pxr 遍历实例代理计数）；接触容量要加到 `nconmax` 400 / `njmax` 2000（下文）；摩擦没有核对，reach 不与物体接触 |
| 执行器与限值：MJWarp 不执行 `joint_velocity_limit`（Kamino 执行），需要速度上限时要在任务或控制里实现 | 本站没有单独验证；reach 用隐式 PD，没有依赖速度上限 |
| 两个后端各跑一次同样的冒烟测试 | 零动作保持 2 s：关节最大偏离 PhysX 0.034 rad、Newton 0.033 rad，TCP 位置相差约 6 mm |

*表 2：EA 文档的资产准备要求与 Galbot 的对照。*

另外两点是 8.5 实测发现、文档没有写到的：

- **接触与约束容量**：照搬官方 Franka reach 的 `nconmax` 20 / `njmax` 100，Galbot 第一步就非法内存访问；加到 400 / 2000 后正常。调参文档说明了这两个量的含义：`nconmax` 限制每个环境的接触点数，`njmax` 限制约束行（constraint rows）数，接触、关节限位、驱动、等式与 mimic 约束都占行[^tune-mjwarp]。
- **建场景偶发崩溃**：Newton 解析 Galbot 的 USD 时，约一半的启动会崩溃（8.5 表 3），原因没有查。

## 求解器调参入口

EA 的 `solver-tuning/` 目录下每个求解器一篇，都要求先能建出任务，再固定一个可复现的问题去调[^tuning]：

- **tune_mjwarp**：MJWarp，主要的已验证路径；容量、接触、积分器等；
- **tune_kamino**：Kamino，beta，通过 `newton_kamino` 预设选择；
- **tune_vbd**：VBD，用于布料与软体；
- **tune_physx**：PhysX，作对照。

本页不展开调参。

## 实测

| 场景 | PhysX | Newton（MJWarp） | 来源 |
|---|---|---|---|
| Cartpole，4096 个环境，每次迭代 | 0.10 s | 0.08 s（Kamino 0.43 s） | 8.2 表 3 |
| Cartpole，按进程显存 | 2876 MiB | 360 MiB | 8.2 表 3 |
| Galbot reach，1024 个环境，每次迭代 | 1.51 s | 0.53 s | 8.5 表 2 |
| Galbot reach，主机 RSS | 7.8 GB | 2.9 GB | 8.5 表 2 |
| Galbot reach，评估中位数（种子 42） | 5.17 cm | 5.67 cm | 8.5 表 2 |

*表 3：本站在两个后端上的实测（RTX 5070，2026-10-10）。*

Newton 在这两个任务上更快、更省主机内存；但在 Galbot 上，它有建场景时偶发崩溃的问题，同种子也不能逐位复现（8.5）。

## 常见误解

:::{admonition} 误解一："Newton 就是 MuJoCo"
:class: warning

Newton 是引擎框架，MJWarp 是它的主要求解器之一，另有 Kamino、Featherstone、XPBD、VBD 等[^solvers][^ea-backends]。换求解器，参数要重调。
:::

:::{admonition} 误解二："用 Newton 就不需要 USD 了"
:class: warning

Newton 不需要 Isaac Sim，但仍然从 USD 读模型（自带导入器）。Isaac Lab 的任务照旧用 USD 资产；而且资产要按 Newton 的要求准备，PhysX 能用的 USD 不一定能用（表 2）。
:::

:::{admonition} 误解三："Newton 更快，所以都应该换过去"
:class: warning

本站的两个任务上 Newton 确实更快，但它是 beta：在 Galbot 上建场景时约一半会崩溃，同种子不能逐位复现，资产要重新导入，参数要重调（8.5）。PhysX 仍是 EA 文档所说的参照实现[^ea-backends]。
:::
