:class: warning

本页内容基于 Isaac Lab **v3.0.0-EA**（2026-09-16）的官方迁移文档与源码，**本站没有安装、运行 3.0**，所有"3.0 里怎么写"都来自文档与源码，没有实测。GA 之前仍可能变动，最后核对日期 2026-10-09。

## 迁移清单总表

这一节回答：从 2.3.2 到 3.0，要改哪些东西？

以官方迁移文档 *Migrating to 3.0*[^migr] 为骨架，按类别列出。"性质"一栏：**机械**指照着替换即可；**重测**指改完要重新验证行为；**行为**指不改不会报错，但结果会悄悄变。

| 类别 | 2.3.2 | 3.0 EA | 性质 | 来源（迁移文档行号） |
|---|---|---|---|---|
| 安装 | Python 3.11，conda，`./isaaclab.sh --install` | Python 3.12，`uv`；新建环境，不在 2.x 环境里升级 | 机械 | L43–80 |
| 脚本入口 | `scripts/reinforcement_learning/rsl_rl/train.py` | `isaaclab train --rl_library rsl_rl`，`play` 同理；各库自带的 train / play 脚本已删除 | 机械 | L2150–2228 |
| 续训 / 回放参数 | `--resume --load_run`，`--use_pretrained_checkpoint` | 统一为 `--checkpoint <路径>`（或 `latest`、`best`、`pretrained`） | 机械 | L2229–2270 |
| 录视频 | `gym.wrappers.RecordVideo` 包装环境 | 环境配置里加 `VideoRecorderCfg` | 重测 | L2517–2546 |
| 物理配置 | `sim_utils.PhysxCfg` | `isaaclab_physx.physics.PhysxCfg`；多后端的任务用 `PresetCfg` | 机械 | L83–140、L414–470 |
| Schema 配置类 | `ArticulationRootPropertiesCfg`、`CollisionPropertiesCfg` 等 | 拆成通用基类 + PhysX 子类（如 `PhysxArticulationRootPropertiesCfg`）；旧名作为弃用别名，4.0 删除 | 机械 | L256–302 |
| 关节驱动字段 | `max_velocity`、`max_effort` | `max_joint_velocity`、`max_force` | 机械 | L330–352 |
| 执行器限值字段 | `effort_limit`、`effort_limit_sim`、`velocity_limit_sim` | `actuator_effort_limit`、`joint_effort_limit`、`joint_velocity_limit`；旧名 3.x 内仍可用 | 机械 | L823–858 |
| 显式执行器的力矩上限 | 求解器的力矩上限被抬到 1e9，只由执行器模型截断 | 求解器保留配置的 `joint_effort_limit`，模型输出会被**再截断一次** | 行为 | L859–866 |
| 执行器组的运行时属性 | `effort_limit_sim`、`armature`、`friction` 等组属性 | 已删除；从 `ArticulationData` 读，用 `write_*_to_sim_index` 写 | 机械 | L867–898 |
| 资产 / 传感器数据 | `data.*` 是 `torch.Tensor` | `data.*` 是 `ProxyArray`，用 `.torch` 取张量 | 机械 | L1898–2041 |
| 四元数顺序 | `(w, x, y, z)` | `(x, y, z, w)`；`convert_quat` 删除；`isaaclab.utils.math` 的四元数函数全部按 XYZW | 行为 | L1583–1897 |
| 写入仿真 | `write_*_to_sim(data, env_ids)` | 拆成 `write_*_to_sim_index` 与 `write_*_to_sim_mask`；旧方法删除 | 机械 | L2042–2128 |
| Isaac Sim API | `isaacsim.core.*` 等模块 | Isaac Sim 6.0 起弃用；优先用 Isaac Lab 自己的替代接口 | 重测 | L583–723 |
| 其他改名 | `XformPrimView`；`Imu`；接触力属性名；关节力矩数据 | `FrameView`；`Pva`（另有轻量 `Imu`）；新的接触力属性名；`JointWrenchSensor` | 机械 | L779、L1221、L1321、L1366 |

*表 1：迁移清单（依据 Isaac Lab v3.0.0-EA 文档 `migrating_to_isaaclab_3-0.rst`）。本站项目没用到的 Surface Gripper、Deformable、Ray Caster、URDF / MJCF 导入器、遥操作等改动没有列出，见原文对应小节。*

**文档未列、源码可见**（推断，依据是两个 tag 的源码对比）：

- `isaaclab_tasks` 的目录由 `manager_based/`、`direct/` 改为按任务分的 `core/<任务>/`，同一个任务的两种写法放在一起[^ea-core]；
- 官方任务名去掉了 `-v0`，如 `Isaac-Cartpole-v0` 变为 `Isaac-Cartpole`[^ea-cartpole]。自己注册的任务名不受影响，但脚本里写死的官方任务名要改。

## 四元数 WXYZ → XYZW

这一节回答：四元数的改动会影响哪些地方，怎么查？

这是最危险的一项：顺序错了不会报错，只会让姿态变成另一个姿态。影响面[^migr]：

- **资产数据**：`root_quat_w`、`body_quat_w` 以及所有包含姿态的状态量，在 3.0 里都是 XYZW；
- **数学函数**：`isaaclab.utils.math` 里的 `quat_mul`、`quat_apply`、`quat_from_euler_xyz`、`euler_xyz_from_quat`、`quat_from_matrix`、`matrix_from_quat` 等全部按 XYZW 输入输出（2.3.2 为 WXYZ[^232-quat]，EA 为 XYZW[^ea-quat]）；
- **配置里写死的值**：`init_state` 的 `rot`、目标姿态、控制器参数。

自查方法：官方提供 `scripts/tools/find_quaternions.py`[^findq]，只对自己的代码运行（`--path <你的项目>`），不要对 Isaac Lab 自带的包运行。它会标出单位四元数 `(1, 0, 0, 0)`，并给出一个可以自动修正单位四元数的选项；**非单位四元数要逐个人工检查**，因为有些四元素元组并不是四元数（例如颜色）。另外再搜一遍 `quat`、`rot=` 与四元素元组，作为补充。

## `torch.Tensor` → `ProxyArray`

这一节回答：读数据的代码要怎么改？

3.0 里资产与传感器的 `data.*` 返回 `ProxyArray`，它包着一个 Warp 数组；`.torch` 返回零拷贝的 Torch 张量，`.warp` 返回底层的 `wp.array`[^proxy][^migr]。读者代码里最常见的三种情形：

| 情形 | 2.3.2 | 3.0 EA |
|---|---|---|
| 索引、切片 | `robot.data.body_pos_w[:, idx]` | `robot.data.body_pos_w.torch[:, idx]` |
| 交给 Torch 函数 | `torch.mean(robot.data.joint_pos, dim=1)` | 直接传入也能用，但会发一次弃用警告，以后会删；建议写 `.torch` |
| 复制、建同形状张量 | `x.clone()`、`torch.zeros_like(x)` | `x.torch.clone()`、`torch.zeros_like(x.torch)` |

*表 2：三种常见情形（依据迁移文档 L1898–2041）。取了 `.torch` 之后就是普通的 Torch 张量，`.to(device)` 等用法照旧；`ProxyArray` 本身的设备迁移，文档没有说明，本页不写。*

Warp kernel 的调用不用改：`ProxyArray` 实现了 `__cuda_array_interface__`，可以直接传给 `wp.launch()`[^migr]。性能方面，官方文档只说明是零拷贝，本站没有数字。

## 迁移步骤

这一节回答：按什么顺序做？

1. **先装好 3.0 环境**：新建 Python 3.12 环境，不要在 2.3 的环境里升级（[1.5](../1-env/1.5-install-61-30.md)）；
2. **先跑官方的同类任务**：如 `Isaac-Reach-Franka`，确认环境本身没问题；
3. **再改自己的项目**：按表 1 的顺序，先安装与入口、配置与导入，再处理数据访问与四元数，最后是训练与录像。每改完一类就跑一次冒烟测试（如 6.4.1 的 `reach_smoke.py`）；
4. **四元数单独核对**：跑查找脚本，逐个检查非单位四元数；用 [7.3](../7-infra/7.3-debugging.md) 的 `debug_step.py` 打印指令与末端姿态，确认对得上；
5. **重新训练并评估**：旧检查点不能直接用（表 3 最后一行），按 6.5.1 的合格线重新评估。

## 常见坑

:::{admonition} 坑一：非单位四元数没改
:class: warning

查找脚本只能自动修正单位四元数，其余的要人工判断[^migr]。像 `REACH_EE_OFFSET_ROT` 这样的偏移量漏改了，不会报错，但 TCP 的朝向会错，训练出来的策略也就对不上真正的末端。
:::

:::{admonition} 坑二：显式执行器被截断两次
:class: warning

3.0 不再把显式执行器所驱动关节的求解器力矩上限抬高。资产里写的关节力矩上限如果比执行器模型的上限小，输出会被求解器再截断一次[^migr]。按文档，把 `joint_effort_limit` 设得不小于 `actuator_effort_limit`。本站主线用隐式执行器，不受影响。
:::

:::{admonition} 坑三：以为换个后端任务就能跑
:class: warning

后端支持是按任务给的，不是所有任务都有 Newton 预设[^backends]。已知限制里还有：Surface Gripper 只能在 CPU 上用 `isaacsim_physx`；Windows 的 uv / pip 安装不带 Pinocchio，Pink IK 任务跑不了[^rn]。先用 `--help` 看任务支持哪些 `physics=` 选项。
:::

:::{admonition} 坑四：依赖 ProxyArray 的兼容行为
:class: warning

把 `ProxyArray` 直接传给 Torch 函数、`wp.to_torch(proxy_array)` 这两种写法现在能用，但会发弃用警告，文档说以后会删[^migr]。迁移时一次改成 `.torch`，免得下个版本再改一遍。
:::
