# 在 3.0 上跑 Galbot reach

:::{admonition} 基于 v3.0.0 正式版
:class: note

## 迁移实录

这一节回答：照着 8.4 改，实际改了什么？

| 改动 | 2.3.2 | 3.0 | 8.4 表 1 |
|---|---|---|---|
| 四元数顺序 | TCP 偏移 `(0, 0, 1, 0)`（WXYZ） | `(0, 1, 0, 0)`（XYZW） | 四元数顺序 |
| 资产数据 | `robot.data.body_pos_w[:, i]` | `robot.data.body_pos_w.torch[:, i]` | 资产 / 传感器数据 |
| 执行器限值 | `effort_limit_sim`、`velocity_limit_sim` | `joint_effort_limit`、`joint_velocity_limit` | 执行器限值字段 |
| 求解器迭代 | `ArticulationRootPropertiesCfg(...)` | `PhysxArticulationRootPropertiesCfg(...)` | Schema 配置类 |
| 物理配置 | 默认 `PhysxCfg` | 任务里加 `PresetCfg`，含 `isaacsim_physx` 与 `newton_mjwarp` 两个预设 | 物理配置 |
| 任务名 | `Galbot-Reach-v0` | `Galbot-Reach` | 脚本入口一节 |
| 训练入口 | 模板生成的 `scripts/rsl_rl/train.py` | `isaaclab train --rl_library rsl_rl` | 脚本入口 |

*表 1：按 8.4 清单做的改动，都与 8.4 表 3 的预计一致。`scenes/reach.py` 里桌面的 `CollisionPropertiesCfg` 没改，旧名在 3.x 内仍可用，reach 也不用桌面。*

**8.4 之外**，本站还遇到 5 处，已补进 [8.4 表 1](8.4-migration-23-30.md#迁移清单总表) 的最后 5 行：Kit 启动前加载 `pxr`、`--headless` 删除、rsl_rl 网络配置改为 `actor` / `critic`、自写脚本要调用 `handle_deprecated_rsl_rl_cfg`、`UniformPoseCommand` 拆出 `_compute_error`。其中最费时的是第一条：报错不指向任务代码，只是 Kit 起不来。本站逐个导入任务模块、看 `'pxr' in sys.modules`，才定位到 mdp 的 `import *`、继承命令实现类、运行时导入 `Articulation` 这三处，改成官方的写法（字符串 `class_type`[^cmdcfg]、按需取用）。

代码改动：12 个文件，按 diff 计约 180 行（加上删除，不含注释与空行），另新增 1 个文件。其中一部分是裁掉子集用不到的内容（轮式版、域随机化任务）。

**从 EA 到正式版**，本站又改了 4 个脚本：正式版删除了 `isaaclab_tasks.utils.hydra.hydra_task_config` 装饰器，`check_hold.py`、`eval_reach.py`、`print_ordering.py`、`step_response_30.py` 一导入就报 `ImportError`，改成显式调用 `resolve_task_config(task, agent)`[^resolve]，每个脚本改 3 行。任务包本身与训练命令不用改。资产转换脚本仍用 `AppLauncher`，正式版里照样能跑，只多打印一行弃用警告（[8.4](8.4-migration-23-30.md)），本站没有改它。

## 资产

这一节回答：6.1.2 转换出的 USD 在 3.0 下能直接用吗？

**PhysX 后端：能。** 用 Isaac Sim 5.1 转换出的 USD（mimic 约束调硬、7 对自碰撞过滤，6.1.2、6.1.4）直接加载，不用改。零动作保持 2 s：关节最大偏离 0.034 rad，TCP 相对机器人根在 (0.679, −0.075, 1.44) m（`scripts/check_hold.py`，正式版实测）。

**Newton 后端：5.1 转换的资产不能用。** 下面是本站在 3.0 EA 上用 `scripts/check_hold.py` 做冒烟（4 个环境，零动作 2 s）的结果，不是训练。正式版上原样的 5.1 资产仍报同一个组合错误（本站实测）；第 2 点没有在正式版上重测：

1. **悬空引用（dangling reference）。** `head_link1` 的 `visuals` 引用了 `galbot_physics.usd` 里并不存在的 `</visuals/head_link1>`。PhysX 只打印警告，Newton 的 USD 导入器把它当作组合错误（composition error），直接抛 `RuntimeError: USD stage has composition errors`。在更强的层里覆盖（停用该 Prim、写空的 references）都去不掉，因为这个引用写在被引用的层里。
2. **碰撞体的位置。** 在资产副本的 `galbot_physics.usd` 里补一个空的 `/visuals/head_link1` 后，组合错误没了，能步进，但 Newton 对 144 个碰撞体都报 `CollisionAPI applied to an unknown UsdGeomGPrim type`，这些碰撞体被忽略；夹爪指节偏离 0.35 rad，mimic 联动也没起作用。原因是 5.1 的转换器把 `CollisionAPI` 加在 Xform 上，网格放在子节点里，Newton 不认这种写法。

官方文档的建议是用 3.0 的转换器重新导入，并保留 `run_asset_transformer`、`run_multi_physics_conversion`，生成中性物理（neutral physics，不属于任何引擎的 USD Physics 属性）、PhysX、MuJoCo 三份属性[^prep]。本站照做（`scripts/convert_galbot_30.py`，转换参数同 6.1.2；正式版上重新转换一次，结果与 EA 相同），新资产与旧资产有三处不同：

- 组合错误为 0，碰撞 API 加在 Mesh 上；
- 刚体变为嵌套结构（`Geometry/base_link/leg_link1/…/right_arm_link7`），所以写过滤对的函数改为按刚体名查找；
- mimic 关系改用 Newton 的属性来写：每侧 5 个跟随关节（follower joint）都写了 `newton:mimicJoint`，其中只有 2 个另写了 `newton:mimicCoef1`（本站用 pxr 遍历统计）；PhysX 一侧的 mimic 约束为 0 个。reach 不用夹爪，这一点对本任务没有影响。

## 训练与评估

这一节回答：同样的命令口径，两个后端训出来怎样？

```bash
isaaclab train --rl_library rsl_rl --task Galbot-Reach --external_callback galbot_academy.register_tasks \
    --seed 42 --run_name physx_s42 physics=isaacsim_physx            # PhysX；种子 43 同理
isaaclab train --rl_library rsl_rl --task Galbot-Reach --external_callback galbot_academy.register_tasks \
    --seed 42 --run_name newton_s42 physics=newton_mjwarp            # Newton
python scripts/eval_reach.py --checkpoint <运行目录>/model_999.pt physics=isaacsim_physx   # 或 newton_mjwarp
```

Newton 一列的接触与约束容量（`nconmax` 400、`njmax` 2000）写在任务的 `newton_mjwarp` 预设里，命令行不用另加；原因见下一节。

| 项 | 2.3.2（6.5.1，RTX 5070） | 3.0，PhysX | 3.0，Newton |
|---|---|---|---|
| 启动与收尾（墙上时间 − 训练用时） | 未记录 | 18 s | 11 s |
| 墙上时间（1000 次迭代） | 1548 s | 1403 s | 372 s |
| 每次迭代（中位数） | 1.52 s（采集 1.47 s，更新 0.06 s） | 1.38 s（采集 1.307 s，更新 0.073 s） | 0.36 s（采集 0.296 s，更新 0.059 s） |
| 按进程显存 | 3041 MiB | 3332 MiB | 5566 MiB |
| 主机 RSS 峰值 | 约 5.9 GB | 7.0 GB | 2.8 GB |
| 评估，种子 42：中位数 / < 5 cm / 姿态 | 2.73 cm / 80.9% / 0.068 rad | 5.36 cm / 46.6% / 0.063 rad | 3.49–3.56 cm / 74.2%–74.6% / 0.151–0.157 rad |
| 评估，种子 43：中位数 / < 5 cm / 姿态 | 2.91 cm / 83.7% / 0.142 rad | 4.78 cm / 51.6% / 0.107 rad | 未训 |
| 代码改动 | — | 约 180 行（EA 时）＋正式版 4 个脚本各 3 行 | 另加 1 个转换脚本，资产重转 |

*表 2：三列对照（1024 个环境，1000 次迭代；评估 256 个环境 × 3 段目标，脚本与指标同 6.5.1；每个检查点评估 3 次，PhysX 三次逐位一致，Newton 给出范围）。3.0 两列在 RTX 5090 上测，2026-10-23；耗时、显存、RSS 按独占计时规则测：PhysX 取种子 43 那次（种子 42 那次开跑时 GPU 上有一个外部的远程桌面进程，途中退出，按规则作废，那次训练用时 1391.9 s），Newton 取种子 42 那次（第一次启动就成功）。2.3 列取自 6.5.1 的两个种子（RTX 5070；主机 RSS 取自 6.5.2，6.5.1b 实测），硬件不同，耗时不宜直接比较。EA 时（RTX 5070）评估结果为：PhysX 种子 42 5.17 cm / 48.4%，种子 43 5.00 cm / 50.0%；Newton 种子 42 5.67 cm / 41.4%。*

观察到的：

- **PhysX：两个种子的结果仍低于 2.3 的两个种子**（中位数 5.36、4.78 cm 对 2.73、2.91 cm），都没过 6.5.1 的合格线（中位数 ≤ 3 cm，< 5 cm ≥ 80%），与 EA 时同一量级。
- **Newton：比 EA 时好得多**，中位数从 5.67 cm 降到 3.5 cm 左右，< 5 cm 从 41% 升到 74%，但仍没过合格线。每次迭代比 3.0 的 PhysX 快约 3.8 倍，主机内存少 4.2 GB，显存多 2.2 GB。
- **Newton 同种子评估不能逐位复现**：同一个检查点评估 3 次，中位数在 3.49–3.56 cm 之间。PhysX 后端的评估 3 次逐位一致。训练能否逐位复现，正式版上没有重测（EA 时校验方的重训从第 0、1 次迭代起就有微小差别）。

差异原因没有查。PhysX 一侧与 EA 基本一致，仍低于 2.3。8.10 的对照仍然成立：2.3 的检查点转换格式、把观测里的目标四元数改回 WXYZ 后，在 3.0 PhysX 上为 2.75 cm / 81.5%，与 6.5.1 一致，说明 3.0 的 PhysX 在这个任务上没有拖后腿，差异更可能在训练一侧（rsl_rl 3.1.2 → 5.5.1、torch 2.7 → 2.11、迁移后的任务代码、3.0 的环境层；推断，见 [8.10](8.10-physx-newton-transfer.md#同一个检查点两个后端)）。Newton 一侧从 EA 到正式版变好的原因也没有查；这期间 Newton 从 1.5.2 升到 1.6.1、Warp 从 1.16 升到 1.17、rsl_rl 从 5.4.1 升到 5.5.1，而同样升级了 rsl_rl 的 PhysX 一侧没有变好，所以 Newton 自身的变化可能性更大（推断）。8.4 的提示仍然成立：2.3 训的检查点不能直接拿来用，因为观测里目标姿态的四元数顺序变了，检查点格式也不同（转换方法见 8.10）。

## Newton 后端的两个问题

这一节回答：用 3.0 转换的资产后，Newton 还会遇到什么？

**问题一：默认容量不够。** 以下是 EA 时的实测，正式版上只验证了 400 / 2000 能用，没有重测 20 / 100。官方 reach 的 Newton 预设是 `nconmax` 20、`njmax` 100（运行中 MJWarp 会把 20 自动提到 54，日志有警告）。用这组值时，环境一建好、第一步就报 `CUDA error: an illegal memory access was encountered`；把两者加到 400 / 2000，同样的冒烟能正常保持 2 s，关节最大偏离 0.033 rad，TCP 位置与 PhysX 相差约 6 mm。两组只差这两个值，所以本站认为是容量不够（对照实验；20 / 100 一侧只有 1 次建成场景，见表 3）。

**问题二：建场景时偶发崩溃（EA 时）。** 正式版上本站 13 次启动全部一次成功（见表 3 最后一行）。EA 时两种容量下都出现：进程在 Newton 解析机器人 USD 时退出，表现有三种：段错误、`malloc(): unaligned tcache chunk detected`、`UsdPhysics.LoadUsdPhysicsFromRange` 处的 `MemoryError`。本站按启动次数统计：

| 容量 | 启动次数 | 建场景时崩溃 | 建成后 |
|---|---|---|---|
| 20 / 100 | 4 | 3 | 1 次，第一步非法内存访问 |
| 400 / 2000 | 14 | 7 | 7 次，全部正常运行 |
| 400 / 2000（正式版） | 13 | 0 | 13 次，全部正常运行 |

*表 3：本站 Newton 的启动结果，只统计 3.0 转换的资产。前两行是 EA 时（RTX 5070）的统计；最后一行是正式版（RTX 5090，2026-10-23）：冒烟 1 次、关节顺序 1 次、训练 1 次、评估 9 次、阶跃响应 1 次，每次的日志单独保存（含冒烟、训练、评估三种启动；每次的日志单独保存）。20 / 100 一行中，有 2 次是早期版本的 `check_hold.py`，没有打印配置，按当时预设里的值（20 / 100）计。训练那次前两次启动崩溃、第三次跑完；在 Newton 上的 2 次评估都是第一次就建成功。校验方另有 7 次启动（400 / 2000）：评估 5 次 0 次崩溃，训练 2 次 1 次崩溃。20 / 100 那一行有 1 次是加了 `CUDA_LAUNCH_BLOCKING=1`、1 个环境的调试运行。*

400 / 2000 下按启动方式看：评估（`eval_reach.py`，256 个环境）两边合计 7 次都没有崩溃；用 `isaaclab train` 启动的训练（16 或 1024 个环境）合计 11 次中 7 次在建场景时崩溃；`check_hold.py`（4 个环境）3 次中 1 次。这只是观察，原因没有查。同一环境里的官方 `Isaac-Reach-Franka`（默认就是 Newton）跑了两次（各训练 2 次迭代），都没有崩溃，所以只能说与这台机器人的资产有关（推断）。官方文档也说后端支持按任务而定[^backends]。正式版上这个问题没有再出现，原因同样没有查；在自己的机器人上用 Newton，仍建议把启动包在重试里。

## 策略互通

官方文档的说法：检查点只是"有序观测 → 动作"的映射，不包含物理引擎；两个后端的动作、观测、策略状态（归一化统计、循环状态等）、时序、机构、回合定义都一致时才能互通，而且只能期望行为相似、轨迹不同[^transfer]。它还特别指出 mimic 关节在两个后端里的驱动方式不同。

本站的实测（种子 42，同一评估脚本）：

| 检查点 → 评估后端 | 中位数 | < 5 cm | 姿态误差中位数 | 最大误差 |
|---|---|---|---|---|
| PhysX → PhysX | 5.36 cm | 46.6% | 0.063 rad | 19.7 cm |
| PhysX → Newton | 7.70–7.96 cm | 26.6%–28.3% | 0.144–0.150 rad | 72.0–148.0 cm |
| Newton → Newton | 3.49–3.56 cm | 74.2%–74.6% | 0.151–0.157 rad | 10.2–10.7 cm |
| Newton → PhysX | 5.70 cm | 40.5% | 0.204 rad | 14.5 cm |

*表 4：跨后端评估（RTX 5090，2026-10-23；每格评估 3 次，在 Newton 上评估的给出范围，在 PhysX 上评估的 3 次逐位一致）。*

两个方向都能用，但都比在训练所用的后端上差：PhysX 检查点换到 Newton，中位数多约 2.4 cm；Newton 检查点换到 PhysX，中位数多约 2.2 cm、< 5 cm 少 34 个百分点；换到 Newton 后还出现了个别很大的误差（最大 148 cm）。

## 常见坑

:::{admonition} 坑一：配置模块提前加载 pxr，Kit 起不来
:class: warning

报错不指向你的代码，而是一串扩展加载失败，最后是 `omni.usd` 缺属性。检查办法：在 3.0 环境里只导入你的任务包，看 `'pxr' in sys.modules`。配置里要用到的实现类，一律写成字符串 `class_type`。
:::

:::{admonition} 坑二：外部回调返回空列表，physics= 被吞掉
:class: warning

`--external_callback` 的返回值会与剩余参数取交集，再交给 Hydra[^cb]。返回 `[]` 会把 `physics=...` 等覆盖项全部丢掉；返回 `None` 才保留全部（`list_intersection` 对 `None` 原样返回[^isect]）。
:::

:::{admonition} 坑三：以为 PhysX 能用的 USD，Newton 也能用
:class: warning

PhysX 容忍的问题，Newton 会直接报错（悬空引用），或者静默地忽略（碰撞 API 加在 Xform 上，碰撞体全部不算数）。后一种更危险：能跑，但机器人没有碰撞体。要上 Newton，先用 3.0 的转换器重新导入。本站用 3.0 转换器重新导入的这份资产只有碰撞体、没有可见网格，在 Rerun / Viser 里看不见机器人（[8.8 坑三](8.8-kitless.md#常见坑)）；正式版重新转换的结果相同：184 个几何体都带 `CollisionAPI`，用途（purpose）都是 `guide`，没有用于显示的网格（本站用 pxr 遍历统计）。
:::

:::{admonition} 坑四：照搬官方预设的 nconmax / njmax
:class: warning

官方 reach 的 Newton 预设按 Franka 定，`nconmax` 20、`njmax` 100。碰撞体多、开自碰撞的机器人用它会在第一步非法内存访问，报错不提容量。本站加到 400 / 2000 后正常。
:::

:::{admonition} 坑五：四元数常量忘了改
:class: warning

TCP 偏移这类常量不是单位四元数，查找脚本不会自动报出来（8.4）。本站改完后用 `check_hold.py` 核对 TCP 位置，确认偏移方向没错。
:::
