# 3.0 版本追踪

:::{admonition} 基于 3.0 EA
:class: warning

本页记录 Isaac Lab 3.0 的各个预发布版本，以及本站内容核对到哪个版本。**本站没有安装、运行 3.0**，表中内容都来自各 tag 内的文件与官方发布页。最后核对日期 2026-10-09；此时最新的 tag 是 v3.0.0-EA，还没有 GA。
:::

本页是参考页，用来回答两个问题：3.0 现在发布到哪一版了；本站哪些页面可能已经过期。

## 版本表

这一节回答：3.0 出过哪些版本，各自改了什么？

| tag | 日期 | Isaac Sim | Python | 主要变化 | 破坏性变更 | 已知问题 |
|---|---|---|---|---|---|---|
| v3.0.0-beta | 2026-03-16 | 6.0.0 | 3.12 | 多物理后端架构；Newton 后端（不需要 Isaac Sim）；可插拔的渲染器与可视化器 | 四元数 WXYZ → XYZW；数据属性返回 Warp 数组；写入方法拆成 index / mask | 只支持 Ubuntu；不是所有任务都有 Newton 预设；部分场景性能下降 |
| v3.0.0-beta2 | 2026-06-16 | 6.0.0 | 3.12 | 多后端稳定化；Newton 扩展（VBD、Kamino、粗糙地形、传感器）；统一的训练与安装命令 | 删除 `fold_preset_tokens`，预设命令行参数的解析方式改变；遥操作回放、Deformable 接口移动 | 仍是 beta，正式版前还可能有破坏性变更；Surface Gripper 只能在 CPU 上用 PhysX；Windows 的 Pink IK 不可用 |
| v3.0.0-beta2.patch1 | 2026-06-30 | 6.0.1 | 3.12 | 支持 Isaac Sim 6.0.1；修依赖与 Docker 镜像 | 无 | 同 beta2 |
| v3.0.0-EA | 2026-09-16 | 6.1.0 | 3.12 | 物理、渲染、可视化各自独立选择；Kit-less 训练；`ProxyArray` 零拷贝数据；统一命令 `isaaclab train / play / benchmark` | 各库自带的 train / play 脚本删除，改用统一命令；执行器限值字段改名 | Surface Gripper 只能在 CPU 上用 PhysX；Pink IK 只支持 Linux；Digit 闭链只支持 PhysX |

*表 1：3.0 各版本。日期为各 tag 的提交日期（`git log -1 <tag>`）；Isaac Sim 与 Python 版本取自各 tag 内 `docs/source/setup/installation/index.rst` 第 6、10 行的版本徽章[^install]；beta、beta2、beta2.patch1 的其余各列取自 EA tag 内的发布说明副本[^rn]；EA 的各列取自 GitHub 上的 EA 发布页[^ea-rel]，执行器字段改名取自迁移文档[^migr]。*

EA 阶段只做 bug 修复、稳定性、兼容性与文档。NVIDIA 在 EA 发布页上写的 GA 目标是 2026 年 10 月底（2026-09-16 发布）[^ea-rel]。本站不作其他预测。

## 要不要升级

这一节回答：现在该不该换到 3.0？

| 场景 | 建议 |
|---|---|
| 研究、尝鲜 | 可以另装一套 3.0 EA（[1.5](../1-env/1.5-install-61-30.md)），与 2.3 的环境并存，用来学新架构 |
| 生产训练 | 继续用 5.1 + 2.3.2。EA 不是正式版，按 [1.2](../1-env/1.2-version-decision.md) 的决策树，等 GA 之后再评估 |
| 与真机联调 | 继续用已经验证过的 2.3.2。迁移会改四元数顺序与数据接口，旧的策略要重训（[8.4](8.4-migration-23-30.md)），不宜在联调期间切换 |

*表 3：升级建议（经验性）。决策树见 1.2，这里不重复。*

## 本页如何维护

这一节回答：这张表谁来更新、什么时候更新？

本站由三个 Claude Code 会话分工维护：设计、实现、校验。Isaac Lab 发布新的 3.0 tag 时：

1. **设计会话**开一张微任务（编号 T-8.6x），写明新 tag 与核对范围；
2. **实现会话**用 `git show <新 tag>:<路径>` 只读新 tag 的文件，在表 1 加一行，并按表 2 逐页核对已写的 3.0 内容。有变化的页面一并修改，"最后核对"改为新日期；
3. **校验会话**按 tag 内的文件逐格复核后合并。

GA 发布时，另外评估主线是否从 2.3.2 切换（[1.2](../1-env/1.2-version-decision.md)）。
