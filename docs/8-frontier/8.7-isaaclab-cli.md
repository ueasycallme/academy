## 一个命令，两类用法

这一节回答：`isaaclab` 命令有哪些功能？

`isaaclab` 是 3.0 装进环境的一个可执行入口，对应 `isaaclab.cli:cli`[^cli-entry]。仓库根目录的 `./isaaclab.sh` 调用的是同一个函数。它有两类用法：

- **子命令**：第一个参数是 `train`、`play`、`benchmark` 等，后面的参数原样交给对应的工作流。
- **选项**：`-i`（安装）、`-n`（从模板新建项目）、`-p`（用当前环境的 Python 运行脚本）、`-f`（格式化）、`-d`（构建文档）、`-u` / `-c`（新建 uv / conda 环境）等，取代 2.3 `isaaclab.sh` 的同名选项。

| 子命令 | 做什么 |
|---|---|
| `train` / `train_multigpu` | 训练；用 `--rl_library` 选 RL 库（rsl_rl、skrl、rl_games、sb3、rlinf，正式版新增 torchrl） |
| `play` | 回放训练好的策略 |
| `zero_agent` / `random_agent` | 全零 / 随机动作跑环境，不需要检查点 |
| `benchmark` / `microbenchmark` | 运行时、启动、训练、回放四类基准，加 `_multigpu` 跨多卡；组件级微基准 |
| `leapp` | 用 LEAPP 导出或部署策略 |
| `teleop` | 遥操作、示教录制与回放（转调仓库里的脚本） |
| `list_envs` | 列出注册的任务；加 `--show_presets` 列出每个任务能用的预设组合，`[default]` 标出默认（正式版新增） |
| `demo` / `example` | 列出或运行打包进来的演示与独立示例（正式版新增） |

*表 1：子命令（`isaaclab --help` 末尾的 commands 一节，本站实测；分发逻辑见源码[^cli-dispatch]）。*

运行子命令之前，CLI 会先导入所有已安装包在 `isaaclab.tasks` 入口点（entry point）组里登记的模块[^cli-entry]；`train`、`play` 的分发函数里还会再导入一次[^dispatch]。下文"注册自己的任务"会用到这一点。

## 安装选择器

这一节回答：`isaaclab -i` 后面能写什么，每一项装了什么？

`-i` 的参数叫安装选择器（install selector），是逗号分隔的若干项。12 个核心子包（`isaaclab`、`isaaclab_physx`、`isaaclab_newton`、`isaaclab_tasks`、`isaaclab_rl` 等）每次都会装[^install-core]，参数只决定**额外**装什么：

| 写法 | 装了什么 | 要不要 Isaac Sim |
|---|---|---|
| `all`（默认，`-i` 不带值） | 核心 + `mimic`、`teleop` 两个可选子包 + `newton`、`rl`、`visualizer` 三个特性集 | 不装 |
| `core`（旧名 `none`） | 只装核心 | 不装 |
| `mimic` / `teleop` | 可选子包：`mimic` 带上 `isaaclab_teleop` 与 `isaaclab_mimic`，`teleop` 只带前者 | 未核对 |
| `rl[rsl-rl\|skrl\|sb3\|rl-games]` | 对应 RL 库；不写选择器时四个都装 | 不需要 |
| `visualizer[kit\|rerun\|viser]` | 可视化器的依赖；`kit` 与 `newton` 不用另装，只有 `rerun`、`viser` 会装东西 | `kit` 要 |
| `newton` | 什么都不装：Newton 引擎与查看器已在核心里 | 不需要 |
| `ov[ovrtx\|ovphysx\|all]` | OV 运行时：OVRTX 渲染器、OvPhysX 物理 | 不需要（两者都不依赖 Kit） |
| `contrib[rlinf]` | contrib 的运行时依赖（目前只有 rlinf） | 不需要 |
| `tetrahedralization` | 四面体剖分的依赖，没有选择器 | 不需要（推断） |
| `isaacsim` | Isaac Sim 本体（`isaacsim[all,extscache]`）。`--help` 里没列出，正式版安装页的选择器表里列了[^install-doc] | 就是它 |

*表 2：`isaaclab -i` 的选择器。来源：`isaaclab --help` 原文（本站实测）与安装代码[^install-core][^install-extra]。`ov`、`contrib`、`tetrahedralization` 不随 `all` 安装，必须显式写[^install-core]。"要不要 Isaac Sim"一列：`kit` 可视化器由 Omniverse 提供；`ov` 两项见 [8.2](8.2-multi-backend.md#渲染器与可视化器)；`mimic` / `teleop` 本站没装过，未核对。*

几种写法：

```bash
./isaaclab.sh -i                              # 等于 all
./isaaclab.sh -i core
./isaaclab.sh -i 'rl[rsl-rl]'                 # 方括号要加引号，否则 shell 会把它当通配符
./isaaclab.sh -i mimic,teleop,'visualizer[rerun]'
```

这几条的写法取自 `--help` 原文。本站在正式版上执行过 `-i`、`-i 'newton,rl[rsl-rl]'`、`-i 'ov[ovphysx]'`、`-i 'ov[ovrtx]'`、`-i 'visualizer[rerun],visualizer[viser]'`（[1.5](../1-env/1.5-install-61-30.md)、[8.8](8.8-kitless.md)）。

## train / play：参数分三层

这一节回答：一条 `isaaclab train` 命令里的参数，分别由谁解析？

`isaaclab train` 后面的参数要经过三道解析：

1. **选 RL 库**：先只解析 `--rl_library`，其余参数原样交给对应的后端模块[^dispatch]。不写 `--rl_library` 时，用任务注册时的 `default_agent`；任务也没写就报错退出（本站实测：Cartpole 不写也能跑，选的是 rsl_rl）。注意 `isaaclab train --help` 的用法行把 `--rl_library` 写成必填，与实际行为不符。
2. **后端的 argparse**：以 rsl_rl 为例，认得的参数有三组：通用训练参数（`--task`、`--num_envs`、`--seed`、`--max_iterations`、`--video` 等）、rsl_rl 专有参数（`--experiment_name`、`--run_name`、`--checkpoint`、`--logger`）、启动器参数（由 `add_launcher_args` 加入：`--device`、`--visualizer` / `--viz`、`--livestream`、`--kit_args` 等[^launcher]）。`isaaclab train --rl_library rsl_rl --help` 能列出全部。
3. **剩下的都给 Hydra**：argparse 不认识的部分（`parse_known_args` 的余项）交给 Hydra[^train-rsl]。其中包括 `env.scene.num_envs=32` 这类路径覆盖，以及三种不带横线的预设记号：`physics=NAME`、`renderer=NAME`、`presets=NAME,…`[^preset-cli]。

```{mermaid}
flowchart TB
    A["isaaclab train …"] --> B["① --rl_library<br/>选后端"]
    B --> C["② 后端 argparse"]
    C -- "余项" --> D{"有回调？"}
    D -- "否" --> E["③ Hydra"]
    D -- "是：取交集" --> E
```

*图 1：`isaaclab train` 的参数流向（v3.0.0，rsl_rl 后端）。箭头表示参数交给下一层。② 认得通用参数、库专有参数与启动器参数；③ 接收路径覆盖与 `physics=` 等预设；菱形是 `--external_callback` 的取交集，见坑一。*

两条规则要记住：

- **CLI 参数比 Hydra 覆盖晚生效**：`--num_envs 64 env.scene.num_envs=32` 最后是 64 个环境。Hydra 先改配置，`apply_env_overrides` 再用 `--num_envs` 覆盖一次[^env-override]（本站实测，日志 `params/env.yaml` 里 `num_envs: 64`）。
- **预设由任务决定**：`physics=` 能选哪些值，要看任务的 `PresetCfg`。`isaaclab train --rl_library rsl_rl --task Isaac-Cartpole-Direct --help` 列出了 `isaacsim_physx`、`newton_kamino`、`newton_mjwarp`、`ovphysx`、`physx` 五个（本站实测）。不写时用任务的默认值，Cartpole（Direct）的默认是 `newton_mjwarp`[^cartpole-presets]，不是 PhysX。预设的设计见 [8.2](8.2-multi-backend.md#预设一个任务几套配置)。

下面 4 条在本站正式版上各跑了 2 次迭代，都正常结束：

```bash
isaaclab train --rl_library rsl_rl --task Isaac-Cartpole-Direct --num_envs 64 --max_iterations 2     # 默认预设：newton_mjwarp
isaaclab train --rl_library rsl_rl --task Isaac-Cartpole-Direct --num_envs 64 --max_iterations 2 physics=isaacsim_physx   # Isaac Sim 的 PhysX
isaaclab train --rl_library rsl_rl --task Isaac-Cartpole-Direct --num_envs 64 --max_iterations 2 --frontend warp physics=newton_mjwarp   # 实验性的 Warp 运行时
isaaclab train --task Isaac-Cartpole-Direct --num_envs 64 --max_iterations 2   # 不写 --rl_library，用任务的 default_agent
```

启动时打印的摘要表里，"Physics"一行就是实际选中的预设。第 3 条的日志里场景管理器是 `InteractiveSceneWarp`。日志目录与 2.3 相同：`logs/rsl_rl/<实验名>/<时间戳>_<run_name>/`。

`play` 的参数结构相同，`--checkpoint` 还接受 `latest`、`best`、`pretrained` 三个选择器（`--help` 原文），本站没有跑 `play`。`benchmark` 的第一个参数是工作流：`runtime`、`startup`、`training`、`play`，加 `_multigpu` 后缀跨多卡（`isaaclab benchmark --help`）。

## 注册自己的任务

这一节回答：自己写的任务，怎么让 `isaaclab train` 找得到？

任务本身仍用 `gym.register` 注册，与 2.3 一样。不同的是：2.3 自己写 `train.py`，在脚本开头 `import` 自己的包就行；3.0 用的是 Isaac Lab 提供的入口，要换一种方式让它导入你的包。有三种：

| 方式 | 写法 | 本站 |
|---|---|---|
| 外部回调（external callback） | `PYTHONPATH=<包所在目录> isaaclab train --task <任务> --external_callback <包>.register_tasks`；回调里 `import` 任务模块，**返回 None** | 实测（8.5 与本页示例） |
| 入口点组 | 把包装进环境，在 `pyproject.toml` 写 `[project.entry-points."isaaclab.tasks"]`；`isaaclab` 运行子命令前自动导入[^cli-entry] | 实测（正式版：把示例 `uv pip install -e` 进 1.5 路线 C 后，不设 `PYTHONPATH`、不给回调，`list_envs` 能列出、`train` 能跑） |
| 自己的脚本 | 脚本里先 `import` 任务包，再调用 `isaaclab_rl.entrypoints.api.train(TrainingRequest(...))`[^api] | 未验证 |

*表 3：把外部任务挂进 `isaaclab` 的三种方式（v3.0.0）。editable 安装会在示例目录里留下 `*.egg-info/`，不用时删掉。*

示例 `examples/isaaclab-3.0/8.7-cli/` 是一个最小的外部包 `academy_cli_demo`：它把 Isaac Lab 自带的 Cartpole（Direct）换个名字注册成 `Academy-Cartpole-Direct`，并带一个返回空列表的反例回调。

```bash
cd examples/isaaclab-3.0/8.7-cli
PYTHONPATH=$PWD isaaclab train --rl_library rsl_rl --task Academy-Cartpole-Direct \
    --num_envs 64 --max_iterations 2 --external_callback academy_cli_demo.register_tasks physics=isaacsim_physx
```

只设 `PYTHONPATH`、不给回调是不够的：`--task academy_cli_demo.tasks:Academy-Cartpole-Direct` 这种 Gymnasium 的"模块:任务名"写法，Isaac Lab 只取冒号后面的任务名[^task-split]，不会导入模块，结果报 `NameNotFound: Environment Academy-Cartpole-Direct doesn't exist`（本站实测）。

**模板生成器**：`isaaclab -n` 会交互式地生成一个新项目[^template]。选 External 时，生成的是一个独立的 uv 项目（`src` 布局），根 `pyproject.toml` 里已经写好 `isaaclab.tasks` 入口点；默认 `uv sync` 只装不依赖 Kit 的 Newton 后端，要用 Isaac Sim 时在命令前加 `uv run --extra isaacsim`。本站没有跑完整的模板流程。

## 与 2.3 的对照

这一节回答：2.3 的 `train.py` 命令，在 3.0 里怎么写？

| 2.3：`python scripts/reinforcement_learning/rsl_rl/train.py …` | 3.0：`isaaclab train --rl_library rsl_rl …` |
|---|---|
| 脚本路径决定 RL 库 | `--rl_library rsl_rl`；不写时用任务的 `default_agent` |
| `--task Isaac-Reach-Franka-v0` | `--task Isaac-Reach-Franka`（任务名去掉了 `-v0`，见 [8.4](8.4-migration-23-30.md)） |
| `--num_envs`、`--seed`、`--max_iterations`、`--video*`、`--agent`、`--distributed` | 同名，含义不变 |
| `--experiment_name`、`--run_name`、`--logger`、`--log_project_name` | 同名 |
| `--resume --load_run <目录> --checkpoint <文件>` | `--checkpoint <路径或选择器>`；3.0 的 rsl_rl 参数里没有 `--resume`、`--load_run`（`--help` 原文） |
| **`--headless`** | **没有这个参数**，写了就报 `unrecognized arguments: --headless`（本站实测）。3.0 默认不开窗口，想看画面用 `--viz kit` 等可视化器；`--viz none` 关掉配置里写的可视化器 |
| `--enable_cameras` | 没有这个参数：场景里有 Kit 相机时自动打开渲染[^launcher] |
| `--device`、`--livestream`、`--kit_args`、`--experience`、`--xr` | 同名；隐藏参数 `--cpu` 已删除，用 `--device cpu`（本站实测） |
| `--viz newton`（3.0 EA） | 改名为 `--viz newton_gl`（另有 `newton_rtx`）；`newton` 仍可用，弃用警告是 `DeprecationWarning`，默认不显示（本站实测）[^viz-alias] |
| 改物理后端：改配置文件或 `env.sim.physx…=` | `physics=physx` / `physics=newton_mjwarp` 等预设，不带横线 |
| 自己的任务：在 `train.py` 里 `import` 自己的包 | `--external_callback`、入口点组，或自己的脚本（表 3） |
| `isaaclab.sh -i rsl_rl` | `isaaclab.sh -i 'rl[rsl-rl]'` |

*表 4：2.3 → 3.0 的命令行对照。2.3 一列依据 v2.3.2 的 `train.py`、`cli_args.py` 与 `AppLauncher`；3.0 一列依据 `isaaclab train --rl_library rsl_rl --help`（本站实测）。*

## 常见坑

:::{admonition} 坑一：外部回调返回空列表，`physics=` 被吞掉
:class: warning

`--external_callback` 的返回值会与剩余参数取交集，再交给 Hydra[^train-rsl]：返回 `None` 表示全部保留，返回列表就只保留列表里有的[^list-intersection]。本站在正式版上用示例的两个回调各跑一次，都带 `physics=physx`：返回 `None` 的那次，摘要里 Physics 是 `physx (ovphysx)`（随后因为没装 OvPhysX 报错，见坑二）；返回 `[]` 的那次是 `newton_mjwarp`，即任务默认值，`physics=physx` 被静默丢掉，而且不报错。EA 时也是这样，正式版没有改。8.5 坑二是同一件事。回调只做注册，返回 None。
:::

:::{admonition} 坑二：`physics=physx` 不一定是 Isaac Sim 的 PhysX
:class: warning

`physx` 是一个"自动"预设：进程里没有别的东西需要 Kit 时，它解析成 OvPhysX（不依赖 Kit 的 PhysX），否则解析成 Isaac Sim 的 PhysX[^physx-auto]。纯 headless 训练没有东西需要 Kit，所以选到 OvPhysX；没装 `ov[ovphysx]` 时启动就报 `ModuleNotFoundError: … requires the optional 'ovphysx' runtime wheel`（本站实测）。要 Isaac Sim 的 PhysX，就明确写 `physics=isaacsim_physx`。
:::

:::{admonition} 坑三：照 2.3 习惯写 `--headless`，直接报错
:class: warning

3.0 的启动器参数里没有 `--headless`[^launcher]。它不会被当作 Hydra 覆盖，argparse 直接报 `isaaclab: error: unrecognized arguments: --headless`，进程以返回码 2 退出（本站实测，EA 与正式版相同）。删掉即可，3.0 默认就不开窗口。正式版的发布页与迁移文档仍写着"`--headless` 不再关掉可视化器"，好像这个参数还在，与 v3.0.0 的代码不一致（[8.4](8.4-migration-23-30.md#迁移清单总表)）。
:::

:::{admonition} 坑四：连 `--help` 都要先接受 EULA
:class: warning

在装了 `isaacsim` 的环境（1.5 路线 A）里，`isaaclab --help` 能直接看，但 `isaaclab train --help` 会先导入任务包，进而初始化 Kit。没设 `OMNI_KIT_ACCEPT_EULA=YES` 时，它停在 EULA 询问，非交互环境里以返回码 1 退出（本站实测）。脚本与 CI 里先 `export OMNI_KIT_ACCEPT_EULA=YES`。不装 `isaacsim` 的 Kit-less 环境（1.5 路线 C）不受影响，`train --help` 直接可用（本站实测，见 [8.8](8.8-kitless.md)）。
:::

:::{admonition} 坑五：选择器拼错不报错，只跳过
:class: warning

`-i` 里写了不认识的项（例如把 `rl[rsl-rl]` 写成 `rsl_rl`），安装程序只打印一行 `Unknown install token … Skipping.`，照样装完其余部分[^install-core]。方括号里的逗号也一样：`visualizer[rerun,viser]` 被当成一个叫 `rerun,viser` 的依赖组，打印 `Unknown root extra 'rerun,viser'` 后跳过，返回码 0，两个可视化器都没装（本站在正式版上实测，EA 时也是这样，见 [8.8 坑一](8.8-kitless.md#常见坑)）；`rl[...]` 的选择器按同样的方式处理[^install-extra]。要装两个就写成 `visualizer[rerun],visualizer[viser]`。方括号不加引号时，shell 可能先把它当通配符展开。装完先用 `pip list` 确认要的包在不在。
:::

## 版本说明
