## ① 处理动作

```python
        # process actions
        self.action_manager.process_action(action.to(self.device))

        self.recorder_manager.record_pre_step()

        # check if we need to do rendering within the physics loop
        # note: checked here once to avoid multiple checks within the loop
        is_rendering = self.sim.has_gui() or self.sim.has_rtx_sensors()
```

*节选 1：L172–L179。*

`process_action` 把整批动作按动作项切开，各自做缩放、偏移，结果缓存起来（[4.10](../4-isaaclab/4.10-observation-action.md)）。这一步只做张量运算，不碰仿真器。是否渲染在这里判断一次：有 GUI 或有 RTX 传感器（相机）才渲染。录制器（recorder）的钩子在不开录制时什么也不做。对应 0.6 表 1 的第 2 步。

## ② decimation 循环

```python
        for _ in range(self.cfg.decimation):
            self._sim_step_counter += 1
            # set actions into buffers
            self.action_manager.apply_action()
            # set actions into simulator
            self.scene.write_data_to_sim()
            # simulate
            self.sim.step(render=False)
            # ...
            if self._sim_step_counter % self.cfg.sim.render_interval == 0 and is_rendering:
                self.sim.render()
            # update buffers at sim dt
            self.scene.update(dt=self.physics_dt)
```

*节选 2：L182–L197（`# ...` 处删去了录制器一行与三行注释）。*

这是一个 step 里唯一推进物理的地方，执行 `decimation` 次。每一轮都重新 `apply_action`：动作在整个 step 里不变，但执行器（如 PD）要按当前的关节状态重算力矩（[4.7](../4-isaaclab/4.7-actuators.md)）。物理步本身不渲染；渲染只在满足间隔、又确实需要时插在中间。`scene.update` 推进各资产与传感器的时间戳（[4.8](../4-isaaclab/4.8-sensors.md)）。对应 0.6 表 1 的第 3–6 步。[7.2](../7-infra/7.2-profiling.md) 的拆分显示，主线 reach 任务约 84% 的时间花在这段循环里。

## ③ 计数、终止、奖励

```python
        self.episode_length_buf += 1  # step in current episode (per env)
        self.common_step_counter += 1  # total step (common for all envs)
        # -- check terminations
        self.reset_buf = self.termination_manager.compute()
        self.reset_terminated = self.termination_manager.terminated
        self.reset_time_outs = self.termination_manager.time_outs
        # -- reward computation
        self.reward_buf = self.reward_manager.compute(dt=self.step_dt)
```

*节选 3：L201–L208。*

回合步数先加一，超时判断才能在这一步生效。终止分成 `terminated`（任务意义上的结束，如掉落）和 `time_outs`（截断），二者都并进 `reset_buf`。奖励紧接着计算，各项乘以权重再乘以 `step_dt`（[4.11](../4-isaaclab/4.11-reward-termination-curriculum.md)）。此时读到的仍是结束那一刻的状态。对应 0.6 表 1 的第 7、8 步。

L210–L213 还有一个分支：开了录制器时，这里会先算一次观测，留给录制用。

## ④ 重置结束的环境

```python
        reset_env_ids = self.reset_buf.nonzero(as_tuple=False).squeeze(-1)
        if len(reset_env_ids) > 0:
            # ...
            self._reset_idx(reset_env_ids)
            # if sensors are added to the scene, make sure we render to reflect changes in reset
            if self.sim.has_rtx_sensors() and self.cfg.num_rerenders_on_reset > 0:
                for _ in range(self.cfg.num_rerenders_on_reset):
                    self.sim.render()
```

*节选 4：L216–L226。*

只重置 `reset_buf` 为真的那些环境，其余环境不受影响。重置在 step 内部当场完成，不会等到下一步。重置后如果有相机，可以按配置多渲染几次，好让图像反映新状态。

`_reset_idx` 内部的顺序（L349–L394）[^reset]：

```python
        self.curriculum_manager.compute(env_ids=env_ids)
        self.scene.reset(env_ids)
        if "reset" in self.event_manager.available_modes:
            # ...
            self.event_manager.apply(mode="reset", env_ids=env_ids, global_env_step_count=env_step_count)
        self.extras["log"] = dict()
        info = self.observation_manager.reset(env_ids)
        # ... 依次：action、reward、curriculum、command、event、termination、recorder
        self.episode_length_buf[env_ids] = 0
```

*节选 5：L356–L394（删减）。*

先更新课程，再清空场景里各资产的内部缓冲，然后执行 reset 事件（写入新的初始状态，[4.12](../4-isaaclab/4.12-event-randomization.md)），最后按固定顺序清零各 Manager。源码注释特意写明这个顺序有讲究。各 Manager 的 `reset` 返回本回合的统计，例如各奖励项的回合平均，汇总进 `extras["log"]`。其中 `command_manager.reset` 会给这些环境重采样目标。

## ⑤ 指令与 interval 事件

```python
        # -- update command
        self.command_manager.compute(dt=self.step_dt)
        # -- step interval events
        if "interval" in self.event_manager.available_modes:
            self.event_manager.apply(mode="interval", dt=self.step_dt)
```

*节选 6：L231–L235。*

`CommandManager.compute`（`command_manager.py` L361）逐项调用 `CommandTerm.compute`（L152–L167）[^cmd]：剩余时间减去 `step_dt`，到期的环境重采样新目标（[4.13](../4-isaaclab/4.13-command-manager.md)）。interval 事件（如周期性推一下机器人）也在这里，按各自的计时器触发。对应 0.6 表 1 的第 10 步。

## ⑥ 观测与返回

```python
        # -- compute observations
        # note: done after reset to get the correct observations for reset envs
        self.obs_buf = self.observation_manager.compute(update_history=True)

        # return observations, rewards, resets and extras
        return self.obs_buf, self.reward_buf, self.reset_terminated, self.reset_time_outs, self.extras
```

*节选 7：L236–L241。*

观测最后算。对刚重置的环境，它读到的是新回合的初始状态与新目标。`update_history=True` 让带历史的观测项在这里前进一格。返回五个值，rsl_rl 的 wrapper 再把 terminated 与 time_outs 合并成 dones（[4.16](../4-isaaclab/4.16-rl-wrappers.md)）。对应 0.6 表 1 的第 11、12 步。

## 三处顺序为什么不能换

| 顺序 | 后果 | 如果反过来 |
|---|---|---|
| 先终止、后奖励 | 结束那一步的奖励可以用终止项（如掉落惩罚）；奖励读到的是结束时的状态 | 奖励函数里用到的 `reset_terminated` 还是上一步的值，终止惩罚会错开一步 |
| 先奖励、再重置、再指令、最后观测 | 重采样那一步，奖励读旧目标，观测读新目标（4.13 的实测：奖励读到 +0.224，观测里是 −0.283） | 若观测在重置前算，策略拿到的是已结束回合的最后一帧，下一步却从新回合开始 |
| interval 事件在观测之前 | 本步被推了一下，观测立刻反映 | 推动的效果要等下一步的观测才看得到，策略晚一步才知道 |

*表 1：三处有后果的顺序（"如果反过来"一列是推断，没有改源码实测）。*

## 父类的 step() 并没有被调用

`ManagerBasedEnv`（不带 RL）也有一个 `step()`（L452–L502）[^base-step]。它有同样的动作处理和 decimation 循环，之后只执行 interval 事件和观测，没有终止、奖励、重置、指令。`ManagerBasedRLEnv.step()` **没有调用** `super().step()`，而是整段重写了一遍。`_reset_idx` 也一样：RL 版（L349）在父类版（L556）[^base-reset]的基础上多了课程、奖励、指令、终止四个 Manager 的 reset，也没有调用父类。读源码时，改父类不会影响 RL 环境，这一点要注意。

## 数据在哪

| 张量 | 形状 | 何时写入 | 生命周期 |
|---|---|---|---|
| `obs_buf` | `dict[组名, (num_envs, dim)]` | ⑥ | 每步覆盖 |
| `reward_buf` | `(num_envs,)` | ③ | 每步覆盖 |
| `reset_buf`、`reset_terminated`、`reset_time_outs` | `(num_envs,)`，布尔 | ③ | 每步覆盖 |
| `episode_length_buf` | `(num_envs,)` | ③ 加一，④ 对重置环境清零 | 跨步累积 |
| `extras["log"]` | `dict[str, 标量]` | ④ 中重建 | 只在有环境重置的那一步重建，其余步保留上一次的内容 |

## 常见误解

:::{admonition} 误解一："step() 调一次，物理走一步"
:class: warning

物理走 `decimation` 步（节选 2）。主线 reach 任务是 4 步，所以每个 RL step 推进 4 × 1/120 s。
:::

:::{admonition} 误解二："重置发生在下一步开头"
:class: warning

重置在本步内、算观测之前就完成了（节选 4、7），返回给策略的已经是新回合的第一帧。下一步开头不再有重置。
:::

:::{admonition} 误解三："观测是物理步之前算的"
:class: warning

观测是整个 step 的最后一件事（节选 7），读的是 decimation 循环结束后的状态。动作作用于上一步返回的观测，这正是 MDP 的"状态 → 动作 → 新状态"（[5.1](../5-rl/5.1-mdp.md)）。
:::
