# `InteractiveScene` 如何克隆环境

:::{admonition} 学习目标
:class: lead-goals

- 沿 v2.3.2 `InteractiveScene.__init__` 读一遍：一份场景配置是怎么变成 N 个环境的
- 说清 `{ENV_REGEX_NS}` 从字符串模板到具体 prim 路径经过了哪几步
- 知道 `replicate_physics` 在这条链上分出的两条路，以及资产对象什么时候才拿到 PhysX 视图

## ① 准备克隆器与 env_0

```python
        # prepare cloner for environment replication
        self.cloner = GridCloner(spacing=self.cfg.env_spacing, stage=self.stage)
        self.cloner.define_base_env(self.env_ns)
        self.env_prim_paths = self.cloner.generate_paths(f"{self.env_ns}/env", self.cfg.num_envs)
        # create source prim
        self.stage.DefinePrim(self.env_prim_paths[0], "Xform")
        # ...
        if not self.cfg.replicate_physics:
            # ...
                env_origins = self.cloner.clone(
                    source_prim_path=self.env_prim_paths[0],
                    prim_paths=self.env_prim_paths,
                    replicate_physics=False,
                    copy_from_source=True,
                    # ...
```

*节选 1：L142–L175。*

`GridCloner` 是 Isaac Sim 的类（[3.7](../3-isaacsim/3.7-cloner.md)）。`define_base_env` 建出 `/World/envs`；`generate_paths` 只是生成字符串 `/World/envs/env_0` … `env_{N-1}`，此时 stage 上只多了一个空的 `env_0`。分支在这里出现：`replicate_physics=False` 时，先把空的 `env_0` 复制 N 份（`copy_from_source=True`，各自独立），让 `env_1` … 在生成实体之前就存在。为什么要这样做，到第 ③ 段才看得出来。`replicate_physics=True` 时什么也不做，环境原点留到第 ④ 段再算。

## ② 从配置生成实体

```python
        for asset_name, asset_cfg in self.cfg.__dict__.items():
            # skip keywords
            # ...
            if asset_name in InteractiveSceneCfg.__dataclass_fields__ or asset_cfg is None:
                continue
            # resolve regex
            if hasattr(asset_cfg, "prim_path"):
                asset_cfg.prim_path = asset_cfg.prim_path.format(ENV_REGEX_NS=self.env_regex_ns)
            # create asset
            if isinstance(asset_cfg, TerrainImporterCfg):
                # ...
            elif isinstance(asset_cfg, ArticulationCfg):
                self._articulations[asset_name] = asset_cfg.class_type(asset_cfg)
```

*节选 2：`_add_entities_from_cfg`，L729–L744。*

场景配置里，除了 `num_envs`、`env_spacing` 这些 `InteractiveSceneCfg` 自带的字段，其余每个字段都是一个实体（[4.5](../4-isaaclab/4.5-interactive-scene.md)）。`{ENV_REGEX_NS}` 的"解析"其实只是 Python 的 `str.format`：把它换成 `/World/envs/env_.*`。得到的仍是一个正则表达式，不是具体路径。然后按配置类型分派，`ArticulationCfg` 走 `class_type(asset_cfg)`，也就是构造 `Articulation` 对象[^add]。传感器还要额外替换几处路径，例如接触传感器的过滤路径、FrameTransformer 的目标帧。

资产对象的构造函数里会生成 prim：

```python
        asset_path = self.cfg.prim_path.split("/")[-1]
        asset_path_is_regex = re.match(r"^[a-zA-Z0-9/_]+$", asset_path) is None
        # spawn the asset
        if self.cfg.spawn is not None and not asset_path_is_regex:
            self.cfg.spawn.func(
                self.cfg.prim_path,
                # ...
            )
        # check that spawn was successful
        matching_prims = sim_utils.find_matching_prims(self.cfg.prim_path)
        # ...
        # register various callback functions
        self._register_callbacks()
```

*节选 3：`AssetBase.__init__`，L80–L96。*

正则只允许出现在路径的父级部分，最后一级必须是普通名字，否则不生成 prim。`_register_callbacks` 只是登记回调：时间线开始播放（PLAY）时再初始化（[4.6](../4-isaaclab/4.6-assets.md)）。所以资产对象构造完时还没有 PhysX 视图。

## ③ `clone` 装饰器：正则变成具体路径

```python
        root_path, asset_path = prim_path.rsplit("/", 1)
        # check if input is a regex expression
        # note: a valid prim path can only contain alphanumeric characters, underscores, and forward slashes
        is_regex_expression = re.match(r"^[a-zA-Z0-9/_]+$", root_path) is None

        # resolve matching prims for source prim path expression
        if is_regex_expression and root_path != "":
            source_prim_paths = find_matching_prim_paths(root_path)
            # ...
        else:
            source_prim_paths = [root_path]

        # resolve prim paths for spawning and cloning
        prim_paths = [f"{source_prim_path}/{asset_path}" for source_prim_path in source_prim_paths]
        # spawn single instance
        prim = func(prim_paths[0], cfg, *args, **kwargs)
        # ...
        if len(prim_paths) > 1:
            cloner = Cloner(stage=stage)
            # ...
```

*节选 4：`sim/utils/prims.py` 的 `clone` 装饰器，L696–L741。*

`spawn_from_usd` 等生成函数都套了这个装饰器[^deco]。它把路径拆成父级 `/World/envs/env_.*` 和名字 `Robot`，用 `find_matching_prim_paths` 在 **当前 stage** 上匹配父级，然后只在第一个匹配上真正生成，其余匹配用 Cloner 复制。正则真正变成具体路径，就在这一步。

第 ① 段的分支在这里起作用：
- `replicate_physics=True` 时，stage 上只有 `env_0`，匹配结果只有一个，实体只生成在 `env_0` 里；
- `replicate_physics=False` 时，空的 `env_i` 已经全部存在，每个实体在这里就逐个复制到所有环境，这就是源码注释说的"per-object level cloning"[^init]。

所以多资产场景（每个环境放不同物体）必须关掉 `replicate_physics`。

## ④ 克隆整个环境，并复制物理

```python
            if self.cfg.replicate_physics:
                self.clone_environments(copy_from_source=False)
            # ...
            if self.cfg.replicate_physics and self.cfg.num_envs > 1:
                # ...
                    self.cloner.replicate_physics(
                        source_prim_path=self.env_prim_paths[0],
                        prim_paths=self.env_prim_paths,
                        base_env_path=self.env_ns,
                        root_path=self.env_regex_ns.replace(".*", ""),
                        enable_env_ids=self.cfg.filter_collisions if self.device != "cpu" else False,
                        # ...
```

*节选 5：L187–L208。*

`clone_environments` 用 `GridCloner.clone` 把 `env_0` 整个复制到 `env_1` … `env_{N-1}`，并按网格算出各环境的原点，存进 `_default_env_origins`（L217–L275）[^clone-env]。这条链上 `GridCloner` 的参数全部来自场景配置：`env_spacing` 决定网格间距，`num_envs` 决定路径数，`replicate_physics`、`filter_collisions`（换成 `enable_env_ids`，CPU 上强制为 False）、`clone_in_fabric` 原样传下去。`copy_from_source` 是例外，场景固定传 False，不读配置。`copy_from_source=False` 时，克隆是"继承"关系，改 `env_0` 会反映到所有环境（3.7 坑一）。

`replicate_physics` 不在 USD 里做任何事：它向 PhysX 登记一个复制器，让 PhysX 解析物理时跳过 `/World/envs` 整棵树，只解析 `env_0`，其余环境直接从它复制[^replicate]。Isaac Sim 的 `clone()` 在 `replicate_physics=True` 且确实有克隆时，已经在内部调用过一次 `replicate_physics`（`cloner.py` L419–L422）[^clone-src]；这里又显式调用一次，参数是场景自己算的 `base_env_path` 与 `root_path`。两次登记的是同一个 stage，推断后一次覆盖前一次，本站未打印验证。省下的是启动时的物理解析时间，3.7 表 2 的实测是：4096 个环境时，reset 从 2.13 s 降到 0.66 s。

## ⑤ 碰撞过滤

```python
            if (not self.cfg.replicate_physics and self.cfg.filter_collisions) or self.device == "cpu":
                self.filter_collisions(self._global_prim_paths)
```

*节选 6：L214–L215。*

环境之间互不碰撞有两种实现：
- GPU 且 `replicate_physics=True` 时，用 PhysX 的环境 ID（env IDs），在节选 5 的 `enable_env_ids` 里一并打开（物理场景上写 `physxScene:envIdInBoundsBitCount`，`cloner.py` L108–L113），不建任何 USD prim；
- 其他情况走 `filter_collisions`：在 `/World/collisions` 下给每个环境建一个碰撞组（collision group），再加一个全局组，全局组里放 `collision_group = -1` 的实体，例如地面（L277–L308）[^filter]。

## 之后：PhysX 视图在 sim.reset() 时才建

`InteractiveScene` 构造完，`ManagerBasedEnv.__init__` 还要做三件事[^env-init]：
1. 先应用 `prestartup` 事件，这是在物理开始前改 USD 的最后机会，例如随机缩放；
2. 再调用 `sim.reset()`，时间线开始播放，每个资产的 PLAY 回调调用 `_initialize_impl`，向 PhysX 要视图（`ArticulationView` 等），此后 `num_instances`、`data.*` 才有效（[9.3](9.3-articulation-data.md)）；
3. 最后调用一次 `scene.update()` 填充数据缓冲。

运行时，场景只负责把调用分发给各实体：
- `write_data_to_sim()` 把各资产缓存的关节目标、外力写进 PhysX；
- `update(dt)` 让各资产与传感器刷新数据；
- `reset(env_ids)` 重置指定环境的资产与传感器状态（L443–L503）[^runtime]。

这三者在 `step()` 里的位置见 [9.1](9.1-rl-env-step.md) 的节选 2 和 4。

## 与 4.5 的对照

4.5"克隆机制"一节的四步，分别对应本页的 ①、② 和 ③（只在 `env_0` 生成，`replicate_physics=True` 时）、④ 和 ⑤。4.5 没有展开的是两处细节：`replicate_physics=False` 的那条支路，以及 GPU 上靠环境 ID 而不是碰撞组来过滤碰撞。

## 常见误解

:::{admonition} 误解一："{ENV_REGEX_NS} 在写配置时就被展开成 N 条路径"
:class: warning

`format` 只把它换成正则 `/World/envs/env_.*`（节选 2）。变成具体路径要等到生成函数的 `clone` 装饰器在 stage 上匹配（节选 4），而匹配到几个，取决于那时 stage 上已经有几个 `env_i`。
:::

:::{admonition} 误解二："构造完 Articulation 就能读关节数据"
:class: warning

构造函数只生成 prim、登记回调（节选 3）。PhysX 视图要等 `sim.reset()` 让时间线开始播放后才建。在那之前读 `num_instances` 或 `data`，拿到的不是有效数据。在 Isaac Lab 环境里不会遇到这个问题，因为 `ManagerBasedEnv` 替你调用了 `sim.reset()`；自己写场景脚本时（[4.5](../4-isaaclab/4.5-interactive-scene.md) 的示例）要记得调用。
:::

:::{admonition} 误解三："filter_collisions 总会在 /World/collisions 下建碰撞组"
:class: warning

GPU 上用默认的 `replicate_physics=True` 时不会：环境间隔离靠 PhysX 的环境 ID（第 ⑤ 段）。只有 `replicate_physics=False` 或用 CPU 时才建碰撞组。所以在 USD 里找不到 `/World/collisions`，不代表碰撞没过滤。
:::

:::{admonition} 误解四："replicate_physics=True 时每个环境都被 PhysX 解析了一遍"
:class: warning

复制器明确把 `/World/envs` 排除在解析之外（`replicationAttachFn` 返回 `[clone_root]`，`cloner.py` L116–L118），PhysX 只解析 `env_0`，再按数量复制。这也是它要求各环境资产一样的原因。
:::
