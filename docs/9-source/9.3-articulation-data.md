[9.2](9.2-scene-cloning.md) 停在 `sim.reset()`：时间线开始播放，每个资产的 PLAY 回调调用 `_initialize_impl`。本页从这里接着读，主线有两条方向：
- 读：PhysX → `ArticulationData` → 你的代码；
- 写：你的代码 → 目标缓冲 → 执行器模型 → PhysX。

## ① 拿到 PhysX 视图

```python
        # -- articulation
        self._root_physx_view = self._physics_sim_view.create_articulation_view(root_prim_path_expr.replace(".*", "*"))
        # ...
        # container for data access
        self._data = ArticulationData(self.root_physx_view, self.device)
        # create buffers
        self._create_buffers()
        # process configuration
        self._process_cfg()
        self._process_actuators_cfg()
        # ...
        # update the robot data
        self.update(0.0)
```

*节选 1：`_initialize_impl`，L1546–L1589。*

`_initialize_impl` 先在第一个环境里找带 `ArticulationRootAPI` 的 prim，再把路径改写成匹配所有环境的表达式（L1506–L1545）。然后用 PhysX 的张量 API（tensor API）建一个 `ArticulationView`，一个视图覆盖全部 N 个环境[^init]。注意路径里的正则 `.*` 被换成了通配符（wildcard）`*`，因为张量 API 用的是通配符。随后创建 `ArticulationData`，它只拿着这个视图的弱引用（weak reference）。`_process_actuators_cfg` 按执行器配置把增益写进 PhysX（第 ④ 段）。最后调用一次 `update(0.0)`。从这一刻起，`num_instances`、`data.*` 才有意义。

## ② 读：时间戳 + 懒读取

```python
    def update(self, dt: float):
        # update the simulation timestamp
        self._sim_timestamp += dt
        # Trigger an update of the joint acceleration buffer at a higher frequency
        # since we do finite differencing.
        self.joint_acc
    # ...
    @property
    def joint_pos(self):
        """Joint positions of all joints. Shape is (num_instances, num_joints)."""
        if self._joint_pos.timestamp < self._sim_timestamp:
            # read data from simulation and set the buffer data and timestamp
            self._joint_pos.data = self._root_physx_view.get_dof_positions()
            self._joint_pos.timestamp = self._sim_timestamp
        return self._joint_pos.data
```

*节选 2：`articulation_data.py` L97–L102 与 L753–L760。*

`ArticulationData` 的大多数状态量都按"懒读取"（lazy read）的模式工作[^data]：
- 每个量配一个 `TimestampedBuffer`，记着上次从 PhysX 读出时的仿真时间；
- `update(dt)` 只把"当前仿真时间"往前推 `dt`，不读任何数据；
- 第一次访问某个属性时，发现缓冲比当前时间旧，才调用一次 `get_dof_positions()` 之类的张量 API；
- 同一时刻再访问，直接返回缓冲。

所以没人读的量不产生 GPU 开销，一个量在一步内被多个 Manager 读多次也只取一次。`root_pos_w` 这类派生量又是在 `root_link_pose_w` 之上切片，读一次根位姿就够用：`root_link_pose_w` 在 L470–L484 懒读取，`root_link_pos_w` 在 L844–L849 取它的前三列，`root_pos_w` 只是后者的别名（L1016–L1018）。

例外是 `joint_acc`：PhysX 不直接给关节加速度，它用两次速度读数做差分。所以 `update` 每次都主动访问一下 `joint_acc`，顺带每个物理步都会读一次关节速度。

**读到的是哪一刻？** 在 Isaac Lab 环境里，`decimation` 循环每走一个物理步，就调用一次 `scene.update(dt)`（[9.1](9.1-rl-env-step.md) 节选 2）。因此 `step()` 结束时，观测读到的是最后一个物理步之后的状态，也就是"这一步"的结果。值是 PhysX 算完后报告的物理量，不是 Isaac Lab 自己推算的。6.1.5 发现，关节静止时速度读数约 0.1 rad/s，而位置差分为 0；直接调用 `get_dof_velocities()` 也是同一个值，所以这个偏差出在 PhysX 的报告值里，不是缓冲没刷新（[6.1.5](../6-galbot/1-asset/6.1.5-joint-drive-tuning.md)"静止时的速度读数"）。

## ③ 写：先写缓冲，不碰仿真

```python
        # set targets
        self._data.joint_pos_target[env_ids, joint_ids] = target
```

*节选 3：`set_joint_position_target`，L1100–L1101。*

`set_joint_position_target`、`set_joint_velocity_target`、`set_joint_effort_target` 都只写 `data` 里的目标缓冲[^target]。docstring 说得明白：要调用 `write_data_to_sim` 才会生效。动作 Manager 的 `JointPositionAction` 每个物理步都调用它（[4.10](../4-isaaclab/4.10-observation-action.md)）。

`write_joint_state_to_sim` 及其拆分出来的 `write_joint_position_to_sim` 等方法不一样：它们是**立即**写进 PhysX 的，用于重置（L580–L616）[^state]。写之前，它们先把新值填进 `data.joint_pos` 缓冲，并把依赖它的连杆位姿等缓冲的时间戳设为 −1，强制下次重读。

## ④ 执行器模型：隐式与显式在这里分开

```python
        for actuator in self.actuators.values():
            # prepare input for actuator model based on cached data
            # TODO : A tensor dict would be nice to do the indexing of all tensors together
            control_action = ArticulationActions(
                joint_positions=self._data.joint_pos_target[:, actuator.joint_indices],
                joint_velocities=self._data.joint_vel_target[:, actuator.joint_indices],
                joint_efforts=self._data.joint_effort_target[:, actuator.joint_indices],
                joint_indices=actuator.joint_indices,
            )
            # compute joint command from the actuator model
            control_action = actuator.compute(
                control_action,
                joint_pos=self._data.joint_pos[:, actuator.joint_indices],
                joint_vel=self._data.joint_vel[:, actuator.joint_indices],
            )
```

*节选 4：`_apply_actuator_model`，L1876–L1890。*

每个执行器组拿到自己那几个关节的目标，再加上**读回的**关节位置和速度（第 ② 段的懒读取），调用 `compute`[^apply]。两类执行器的分叉有两处：

- **初始化时**（`_process_actuators_cfg`，L1759–L1769）：
  - 隐式执行器（`ImplicitActuator`）把刚度、阻尼写进 PhysX 的关节驱动；
  - 显式执行器把 PhysX 里的增益设为 0，让 PhysX 只执行力矩。
- **每一步**（`actuator_pd.py`）[^pd]：
  - 隐式的 `compute` 原样返回目标，PD 由 PhysX 在求解器里完成，它算出的 `computed_effort` 只是估计值，用于奖励和日志；
  - 显式的（如 `IdealPDActuator`）用读回的位置、速度自己算力矩，再把位置、速度目标设为 `None`，只留下力矩。

这就是 6.1.5 那个速度偏差影响不同的原因：显式执行器的阻尼项直接乘上读回的 0.1 rad/s；隐式执行器的阻尼在 PhysX 内部完成，读回值只进入估计力矩（[4.7](../4-isaaclab/4.7-actuators.md)）。

## ⑤ 写进 PhysX

```python
        # apply actuator models
        self._apply_actuator_model()
        # write actions into simulation
        self.root_physx_view.set_dof_actuation_forces(self._joint_effort_target_sim, self._ALL_INDICES)
        # position and velocity targets only for implicit actuators
        if self._has_implicit_actuators:
            self.root_physx_view.set_dof_position_targets(self._joint_pos_target_sim, self._ALL_INDICES)
            self.root_physx_view.set_dof_velocity_targets(self._joint_vel_target_sim, self._ALL_INDICES)
```

*节选 5：`write_data_to_sim`，L257–L264。*

`write_data_to_sim` 在每个物理步之前调用（[9.1](9.1-rl-env-step.md) 节选 2）[^write]：
- 先写外力（节选省略的前半部分）；
- 再跑执行器模型；
- 最后用张量 API 一次性写进所有环境：力矩总会写，位置、速度目标只在有隐式执行器时才写。

"`data.*_target` → `_*_target_sim`"这两套缓冲之间隔着执行器模型。前者是你下的指令，后者是 PhysX 真正收到的。用显式执行器时，两者差别最大。

## 常见误解

:::{admonition} 误解一："set_joint_position_target 之后机器人马上开始动"
:class: warning

它只改缓冲（节选 3）。要等 `write_data_to_sim` 和下一次 `sim.step()`。在 Isaac Lab 环境里，这两步由 `step()` 负责；自己写场景脚本时（[4.5](../4-isaaclab/4.5-interactive-scene.md) 的示例），漏掉 `scene.write_data_to_sim()`，目标永远到不了 PhysX。
:::

:::{admonition} 误解二："data.joint_pos 每次访问都会去问 PhysX"
:class: warning

只有时间戳落后时才问（节选 2）。反过来，时间戳只在 `update(dt)` 时前进。自己写循环时，如果调用了 `sim.step()` 却没有调用 `scene.update(dt)`，再读 `data.joint_pos` 得到的就是旧缓冲。这一点由节选 2 的条件判断推出，本站没有单独实测。
:::

:::{admonition} 误解三："静止时关节速度不为 0，是缓冲没刷新"
:class: warning

缓冲刷新的是 PhysX 报告的值。6.1.5 已对照过：直接从张量 API 读的值与缓冲相同。偏差在物理引擎的报告值里，不在 Isaac Lab 的数据层（第 ② 段）。
:::

:::{admonition} 误解四："隐式执行器的 applied_torque 就是 PhysX 施加的力矩"
:class: warning

隐式执行器的 PD 在 PhysX 里算，Isaac Lab 拿不到实际施加的力矩。`computed_effort` 和 `applied_torque` 是按同样的 PD 公式、用读回的位置和速度估算出来的（第 ④ 段），只适合用于奖励与日志。
:::
