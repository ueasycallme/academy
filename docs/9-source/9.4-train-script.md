## ① 两套命令行参数

```python
cli_args.add_rsl_rl_args(parser)
AppLauncher.add_app_launcher_args(parser)
args_cli, hydra_args = parser.parse_known_args()
# ...
sys.argv = [sys.argv[0]] + hydra_args
app_launcher = AppLauncher(args_cli)
simulation_app = app_launcher.app
```

*节选 1：`train.py` L38–L52[^train]。*

命令行被分成两份。argparse 认识的（`--task`、`--headless`、`--run_name` 等）进 `args_cli`；不认识的，如 `env.scene.num_envs=64`，原样留在 `hydra_args`，再写回 `sys.argv`，等 ② 里的 Hydra 去读。之后立刻启动 Kit：从这里往后才能导入 `isaaclab.envs` 等模块（[3.2](../3-isaacsim/3.2-simulation-app.md)）。本项目导入任务包的那一行也在 Kit 启动之后。

## ② Hydra 覆盖落到配置上

```python
            env_cfg, agent_cfg = register_task_to_hydra(task_name.split(":")[-1], agent_cfg_entry_point)

            @hydra.main(config_path=None, config_name=task_name.split(":")[-1], version_base="1.3")
            def hydra_main(hydra_env_cfg: DictConfig, env_cfg=env_cfg, agent_cfg=agent_cfg):
                # ...
                env_cfg.from_dict(hydra_env_cfg["env"])
                # ...
                    agent_cfg.from_dict(hydra_env_cfg["agent"])
                func(env_cfg, agent_cfg, *args, **kwargs)
```

*节选 2：`isaaclab_tasks/utils/hydra.py` L80–L100[^hydra]。*

`@hydra_task_config` 在 `main()` 被调用时才工作。它先从注册表取出环境配置和 agent 配置（[4.15](../4-isaaclab/4.15-task-registration.md)），转成字典交给 Hydra。Hydra 把 `env.…=`、`agent.…=` 覆盖合并进去，再用 `from_dict` 逐项写回原来的配置对象。配置对象这时早已构造完，所以 `__post_init__` 里算出的派生值不会跟着变（[4.3 常见坑三](../4-isaaclab/4.3-configclass.md#常见坑)）。

`from_dict` 写回时会检查类型：

```python
            elif value is None or isinstance(value, type(obj_mem)):
                pass
            # ...
            else:
                raise ValueError(
                    f"[Config]: Incorrect type under namespace: {key_ns}."
                    f" Expected: {type(obj_mem)}, Received: {type(value)}."
                )
```

*节选 3：`isaaclab/utils/dict.py` `update_class_from_dict` L149–L157[^dict]。*

[5.6](../5-rl/5.6-observation-design.md) 写 `env.observations.policy.history_length=3` 被拒，就是这里：比较的是**当前值**的类型，不是字段注解。组的 `history_length` 默认是 `None`，`isinstance(3, NoneType)` 为假，于是报错。默认值是 `None` 的字段，都不能从命令行赋值。

## ③ `main()`：覆盖顺序与日志目录

```python
    agent_cfg = cli_args.update_rsl_rl_cfg(agent_cfg, args_cli)
    env_cfg.scene.num_envs = args_cli.num_envs if args_cli.num_envs is not None else env_cfg.scene.num_envs
    # ...
    env_cfg.seed = agent_cfg.seed
    # ...
    log_root_path = os.path.join("logs", "rsl_rl", agent_cfg.experiment_name)
    # ...
    log_dir = datetime.now().strftime("%Y-%m-%d_%H-%M-%S")
```

*节选 4：`train.py` L118–L150；L154–L156 再接上 `_<run_name>`[^train]。*

到这里，一个值有三处来源：注册表里的默认值、② 的 Hydra 覆盖、这里的 argparse 参数。后写的覆盖先写的，所以 `--num_envs`、`--max_iterations`、`--seed` 比 Hydra 覆盖后生效。环境种子没有自己的入口：`env_cfg.seed` 直接取 `agent_cfg.seed`。

日志目录 `logs/rsl_rl/<experiment_name>/<日期_时间>[_<run_name>]` 就在这里定下来，是相对**当前目录**的路径。所以要在项目根目录运行训练（[6.5.3](../6-galbot/5-train/6.5.3-experiment-management.md)"命名与目录规范"）。

## ④ 建环境，包适配层

```python
    env = gym.make(args_cli.task, cfg=env_cfg, render_mode="rgb_array" if args_cli.video else None)
    # ...
    env = RslRlVecEnvWrapper(env, clip_actions=agent_cfg.clip_actions)
    # ...
    dump_yaml(os.path.join(log_dir, "params", "env.yaml"), env_cfg)
    dump_yaml(os.path.join(log_dir, "params", "agent.yaml"), agent_cfg)
    runner.learn(num_learning_iterations=agent_cfg.max_iterations, init_at_random_ep_len=True)
```

*节选 5：`train.py` L170–L217，省略了多智能体转换、录像、建 runner（L198–L203）与续训[^train]。*

`params/env.yaml`、`agent.yaml` 在训练开始**之前**写出，内容是 ①–③ 全部覆盖之后的最终值。这就是 6.5.3 说它们"比源码默认值更可信"的原因。中间省略的 `runner.add_git_repo_to_log(__file__)`（L205）把 `train.py` 所在的仓库登记给 rsl_rl，⑤ 里据此写 `git/`。

适配层的 `step` 只做三件事（[4.16](../4-isaaclab/4.16-rl-wrappers.md) 表 2）：

```python
        if self.clip_actions is not None:
            actions = torch.clamp(actions, -self.clip_actions, self.clip_actions)
        obs_dict, rew, terminated, truncated, extras = self.env.step(actions)
        dones = (terminated | truncated).to(dtype=torch.long)
        if not self.unwrapped.cfg.is_finite_horizon:
            extras["time_outs"] = truncated
        return TensorDict(obs_dict, batch_size=[self.num_envs]), rew, dones, extras
```

*节选 6：`isaaclab_rl/rsl_rl/vecenv_wrapper.py` `step` L153–L164[^wrapper]。*

- **裁剪动作**：`clip_actions` 为 `None` 时不裁；
- **合并结束标志**：`terminated` 与 `truncated` 合并成 `dones`，超时另放进 `extras["time_outs"]`，供价值自举（value bootstrapping，见 [4.11](../4-isaaclab/4.11-reward-termination-curriculum.md)）；
- **观测分组**：观测字典按组名包成 `TensorDict`，由 runner 按 `obs_groups` 分给 actor 与 critic（[4.10](../4-isaaclab/4.10-observation-action.md)）。

`extras["log"]`（各奖励项、终止项的回合统计）原样传出。另外，适配层在构造时就调用一次 `env.reset()`（L66），因为 rsl_rl 的 runner 自己不调用 reset。

## ⑤ `OnPolicyRunner.learn`：训练循环

```python
        for it in range(start_iter, tot_iter):
            # ...
            with torch.inference_mode():
                for _ in range(self.num_steps_per_env):
                    actions = self.alg.act(obs)
                    obs, rewards, dones, extras = self.env.step(actions.to(self.env.device))
                    # ...
                    self.alg.process_env_step(obs, rewards, dones, extras)
                    # ...
                self.alg.compute_returns(obs)
            loss_dict = self.alg.update()
            # ...
                self.log(locals())
                if it % self.save_interval == 0:
                    self.save(os.path.join(self.log_dir, f"model_{it}.pt"))
```

*节选 7：rsl_rl 3.1.2 `runners/on_policy_runner.py` L98–L159[^runner]。*

对照 [5.3](../5-rl/5.3-ppo.md)"一次迭代的三段"：

- **采集**：内层循环跑 `num_steps_per_env` 步，在推理模式（`torch.inference_mode`）下不记梯度；
- **算优势**：`compute_returns` 用最后一步的观测做价值自举，也还在 `inference_mode` 里；
- **更新**：`update` 跑若干轮小批量更新。

采集单独计时，算优势与更新合起来计时（L140–L151），就是终端日志 `Computation` 一行括号里的 `collection` 与 `learning`。

之后是记录。采集时每步把 `extras["log"]` 收进 `ep_infos`（L114–L118），`log` 再把其中带 `/` 的键（如 `Episode_Reward/…`）原样写进 TensorBoard，再加上 `Loss/…`（L184–L213）。检查点在 `it % save_interval == 0` 时保存，所以有 `model_0.pt`；循环结束后再存一次最后一轮（L172–L174），1000 次迭代的最后一个就是 `model_999.pt`。`git/` 只在第一轮迭代后写一次（L163–L170）。6.5.1 日志目录里的每一样东西，到这里都找到了出处。

## 常见误解

:::{admonition} 误解一："--experiment_name 能改日志目录"
:class: warning

`cli_args.py` 定义了这个参数（L25–L27），但 `update_rsl_rl_cfg` 从不读它（L60–L91）[^cli]。本站用普通 Python 调用该函数核对过：传入 `--experiment_name my_exp --run_name r1` 后，`run_name` 变成了 `r1`，`experiment_name` 仍是原值。要改目录名，用 Hydra 覆盖 `agent.experiment_name=my_exp`，或者改 agent 配置。
:::

:::{admonition} 误解二："env.seed=123 能单独改环境的种子"
:class: warning

Hydra 确实会把 123 写进 `env_cfg.seed`，但 ③ 里的 `env_cfg.seed = agent_cfg.seed`（L126）随后又覆盖了它。环境种子只能跟着 `--seed` 或 `agent.seed=` 走。这一点由源码顺序推出，本站没有单独实测。
:::

:::{admonition} 误解三："Hydra 覆盖总是最后生效"
:class: warning

`--num_envs`、`--max_iterations` 在 ③ 里比 Hydra 后写。两处同时给时，以 argparse 参数为准。这些参数没给时，它们保持 `None`，不会覆盖 Hydra 的值。
:::

:::{admonition} 误解四："第一次迭代的平均回合长度偏短，说明环境有问题"
:class: warning

`learn(init_at_random_ep_len=True)` 在开始前把每个环境的回合计数随机打散（L67–L70）。目的是让各环境的超时错开，不在同一步一起重置。代价是前几轮会有大量提前到来的超时，回合长度与回报的统计偏低（由源码推出，本站没有单独对比）。
:::
