## 入口与文件布局

这一节回答：一个任务的代码分在哪几个文件里？

```python
gym.register(
    id="Isaac-Lift-Cube-Franka-v0",
    entry_point="isaaclab.envs:ManagerBasedRLEnv",
    kwargs={
        "env_cfg_entry_point": f"{__name__}.joint_pos_env_cfg:FrankaCubeLiftEnvCfg",
        "rsl_rl_cfg_entry_point": f"{agents.__name__}.rsl_rl_ppo_cfg:LiftCubePPORunnerCfg",
        # ...（skrl、rl_games、sb3 三个入口）
    },
    disable_env_checker=True,
)
```

注册在 `config/franka/__init__.py`[^reg]。环境类是通用的 `ManagerBasedRLEnv`，任务的全部内容都在两个配置入口里：环境配置 `FrankaCubeLiftEnvCfg`，PPO 配置 `LiftCubePPORunnerCfg`（机制见 [4.15](../4-isaaclab/4.15-task-registration.md)）。顺着字符串找到的文件是：

| 文件 | 管什么 |
|---|---|
| `lift/lift_env_cfg.py` | 抽象基类 `LiftEnvCfg`：桌子、地面、灯光，以及与机器人无关的 7 个 Manager 配置 |
| `lift/config/franka/joint_pos_env_cfg.py` | Franka 特化：填上机器人、末端坐标系、方块、两个动作项 |
| `lift/config/franka/ik_abs_env_cfg.py`、`ik_rel_env_cfg.py` | 同一任务改用逆运动学动作（绝对 / 相对位姿） |
| `lift/config/franka/agents/` | 四个 RL 库各自的超参数 |
| `lift/mdp/` | 本任务专用的观测、奖励、终止函数，其余从 `isaaclab.envs.mdp` 整体导入[^mdp-init] |

*表 1：lift 任务的文件。路径都在 `isaaclab_tasks/manager_based/manipulation/` 下。*

分成"抽象场景 + 机器人特化"两层，是为了让奖励、终止这些与机器人无关的部分只写一次。换机器人时只写一个子类，补齐几个字段就行（推断，依据是 `lift_env_cfg.py` 中的 `MISSING` 字段与其注释"will be populated by agent env cfg"[^scene]）。

```{mermaid}
flowchart LR
    R["gym.register"] --> F["FrankaCubeLiftEnvCfg<br/>机器人 · 末端 · 方块 · 动作"]
    F --> B["LiftEnvCfg<br/>场景 + 7 个 Manager"]
    B --> M["mdp 函数<br/>lift/mdp + isaaclab.envs.mdp"]
    R --> P["LiftCubePPORunnerCfg"]
```

*图 1：从注册到 mdp 函数的调用链，自左向右。箭头表示"引用"。*

## 场景：先留空，再由子类填

这一节回答：`MISSING` 是什么意思，Franka 子类填了什么？

```python
@configclass
class ObjectTableSceneCfg(InteractiveSceneCfg):
    # ...
    # robots: will be populated by agent env cfg
    robot: ArticulationCfg = MISSING
    # end-effector sensor: will be populated by agent env cfg
    ee_frame: FrameTransformerCfg = MISSING
    # target object: will be populated by agent env cfg
    object: RigidObjectCfg | DeformableObjectCfg = MISSING
    # ...
    # plane
    plane = AssetBaseCfg(
        prim_path="/World/GroundPlane",
        init_state=AssetBaseCfg.InitialStateCfg(pos=[0, 0, -1.05]),
        spawn=GroundPlaneCfg(),
    )
```

`MISSING` 是 dataclasses 的哨兵值，意思是"这一项必须由别人填"[^scene]（[4.3](../4-isaaclab/4.3-configclass.md)）。Franka 子类在 `__post_init__` 里依次填上：

- **机器人**：`FRANKA_PANDA_CFG`；
- **方块**：Nucleus 上的 `DexCube`，缩放 0.8，位置迭代 16、速度迭代 1；
- **末端坐标系**：`FrameTransformer`，源是 `panda_link0`，目标是 `panda_hand` 沿 z 偏移 0.1034 m[^franka]。

FrameTransformer 的偏移把末端从手腕法兰挪到两指之间，奖励里的"手到方块的距离"量的就是这个点。同一目录的 IK 版本用的偏移是 0.107 m[^ik]，两个数不一样，源码里没有说明原因。

**读源码要连资产一起量**。桌子放在 (0.5, 0, 0) 并绕 z 轴转 90°，地面放在 z = −1.05，说明桌子的上表面大约在 z = 0，但具体数值要看资产文件[^scene]。本站用 usd-core 量了 Isaac Sim 5.1 的两份资产（从 Nucleus 的公开地址下载）：

- SeattleLabTable 碰撞体的上表面在 z = −0.003；
- DexCube 边长 0.06 m，缩放后 4.8 cm，静止在桌上时中心约在 z = 0.021。

这两个数决定了下文"举起"判据的实际含义。

## 逐个 Manager 读

这一节回答：每一块配置在表达什么意图？

**Commands：目标放在哪**

```python
    object_pose = mdp.UniformPoseCommandCfg(
        asset_name="robot",
        body_name=MISSING,  # will be set by agent env cfg
        resampling_time_range=(5.0, 5.0),
        debug_vis=True,
        ranges=mdp.UniformPoseCommandCfg.Ranges(
            pos_x=(0.4, 0.6), pos_y=(-0.25, 0.25), pos_z=(0.25, 0.5), roll=(0.0, 0.0), pitch=(0.0, 0.0), yaw=(0.0, 0.0)
        ),
    )
```

目标是相对机器人根的位置，在一个长方体里均匀采样[^cmd]（[4.13](../4-isaaclab/4.13-command-manager.md)）。重采样间隔 5 s，正好等于回合长度，所以一个回合只有一个目标。姿态全为 0，奖励里也只看位置。

**Actions：臂连续，夹爪二值**

```python
        self.actions.arm_action = mdp.JointPositionActionCfg(
            asset_name="robot", joint_names=["panda_joint.*"], scale=0.5, use_default_offset=True
        )
        self.actions.gripper_action = mdp.BinaryJointPositionActionCfg(
            asset_name="robot",
            joint_names=["panda_finger.*"],
            open_command_expr={"panda_finger_.*": 0.04},
            close_command_expr={"panda_finger_.*": 0.0},
        )
```

臂是 7 维连续动作（[4.10](../4-isaaclab/4.10-observation-action.md)）。夹爪只占 1 维：动作值小于 0 时闭合到 0，否则张开到 0.04[^binary]。策略只能决定"开"还是"合"，不能把夹爪停在中间。

**Observations：五项，都在机器人根坐标系**

关节位置、关节速度（全部 9 个关节）、方块相对机器人根的位置、目标位置、上一步动作[^obs]（[4.10](../4-isaaclab/4.10-observation-action.md)）。方块位置用 `subtract_frame_transforms` 换到根坐标系[^obs-fn]，与目标同一坐标系，策略看到的是"方块在哪、要去哪"，与环境在世界里的位置无关。

**Events：每次重置做两件事**

`reset_scene_to_default` 把机器人和方块都放回默认状态，然后 `reset_root_state_uniform` 在 x ±0.1 m、y ±0.25 m 内随机挪动方块[^events]（[4.12](../4-isaaclab/4.12-event-randomization.md)）。

**Rewards：四个阶段 + 两个正则项**

```python
    reaching_object = RewTerm(func=mdp.object_ee_distance, params={"std": 0.1}, weight=1.0)

    lifting_object = RewTerm(func=mdp.object_is_lifted, params={"minimal_height": 0.04}, weight=15.0)

    object_goal_tracking = RewTerm(
        func=mdp.object_goal_distance,
        params={"std": 0.3, "minimal_height": 0.04, "command_name": "object_pose"},
        weight=16.0,
    )

    object_goal_tracking_fine_grained = RewTerm(
        func=mdp.object_goal_distance,
        params={"std": 0.05, "minimal_height": 0.04, "command_name": "object_pose"},
        weight=5.0,
    )
```

这四项按任务的先后排列[^rew]（[4.11](../4-isaaclab/4.11-reward-termination-curriculum.md)）：

- **接近**：1 − tanh(距离 / 0.1)，手离方块越近越大；
- **举起**：方块高于 `minimal_height` 时为 1；
- **跟踪目标**：只有举起后才计，粗、细两档（std 0.3 与 0.05），前者在远处也有梯度，后者奖励最后几厘米[^rew-fn]。

权重 1 : 15 : 16 : 5 让后面的阶段明显更值钱，策略有动力往下一阶段走（[5.5](../5-rl/5.5-reward-design.md)）。动作变化率与关节速度两项正则只有 −1e-4。

`object_is_lifted` 比较的是世界坐标的绝对高度：`root_pos_w[:, 2] > minimal_height`[^rew-fn]。按上一节量到的数字，0.04 意味着方块中心比静止时高约 1.9 cm，而不是"离开桌面 4 cm"。换一张高度不同的桌子，这个数就失去了意义。Galbot 版的桌面在 0.95 m，只能改成相对桌面的高度，见 [6.4.3](../6-galbot/4-task/6.4.3-lift.md)。

**Terminations：超时或掉落**

`object_dropping` 用通用的 `root_height_below_minimum(minimum_height=-0.05)`，同样是世界坐标，即方块掉到桌面以下约 5 cm[^term]（[4.11](../4-isaaclab/4.11-reward-termination-curriculum.md)）。`lift/mdp/terminations.py` 里还有一个 `object_reached_goal`，但配置里没有用它[^reached]。

**Curriculum：惩罚在 10000 步后加大**

```python
    action_rate = CurrTerm(
        func=mdp.modify_reward_weight, params={"term_name": "action_rate", "weight": -1e-1, "num_steps": 10000}
    )
```

另一项 `joint_vel` 写法相同，也在 10000 步时升到 −0.1。`modify_reward_weight` 在 `env.common_step_counter > num_steps` 时把权重改成新值[^curr]。这个计数器每次 `env.step()` 加 1，不乘环境数[^counter]。rsl_rl 每次迭代每个环境采 24 步，所以 10000 步约在第 417 次迭代。课程不是"自动调难度"，而是到点改一次权重（[4.11](../4-isaaclab/4.11-reward-termination-curriculum.md)）。

最后，`LiftEnvCfg.__post_init__` 把时间设为物理步 0.01 s、每 2 个物理步控制一次（50 Hz），回合 5 s[^post]。

## PPO 配置与样本预算

这一节回答：训练要多少样本？

| 参数 | Franka lift[^ppo] | reach（[6.5.1](../6-galbot/5-train/6.5.1-train-reach-rsl-rl.md)） |
|---|---|---|
| `num_steps_per_env` | 24 | 24 |
| `max_iterations` | 1500 | 1000 |
| 网络 | [256, 128, 64] | [64, 64] |
| `learning_rate` | 1e-4 | 1e-3 |
| `entropy_coef` | 0.006 | 0.001 |
| `gamma` | 0.98 | 0.99 |
| `num_learning_epochs` | 5 | 8 |

*表 2：lift 与 reach 的 PPO 配置。*

样本预算可以直接算出来：默认 4096 个环境 × 每次迭代 24 步 × 1500 次迭代 = 147 456 000 个控制步。如果环境数缩到 1024、迭代缩到 1000，样本只剩 2458 万，是原来的六分之一。照搬超参数时，要连同这个预算一起照搬。

## 怎么改它

这一节回答：想改这个任务，从哪里下手？

- **换机器人**：仿照 `joint_pos_env_cfg.py` 写一个 `LiftEnvCfg` 的子类，填上机器人、末端 FrameTransformer、两个动作项和 `commands.object_pose.body_name`，然后自己注册一个任务名。Galbot 版还改了几处与桌子高度相关的判据，见 [6.4.3](../6-galbot/4-task/6.4.3-lift.md)。
- **换物体**：改 `scene.object` 的 `spawn`。可以换成另一个 `UsdFileCfg`，像 IK 版的泰迪熊那样；也可以换成 `CuboidCfg` 这类原始形状，不依赖 Nucleus。物体尺寸一变，`minimal_height` 与初始高度要一起重算。
- **改奖励**：在子类的 `__post_init__` 里改 `self.rewards.<项>.weight`，或者给 `rewards` 加一项。改之前先想清楚各阶段的权重比例（[5.5](../5-rl/5.5-reward-design.md)）。

## 常见误解

:::{admonition} 误解一："`lift_env_cfg.py` 能直接跑"
:class: warning

不能。`LiftEnvCfg` 的机器人、末端、物体、动作和指令的 `body_name` 都是 `MISSING`，只有机器人子类填齐之后才是一个完整的环境；能注册、能跑的是 `FrankaCubeLiftEnvCfg`[^scene][^reg]。
:::

:::{admonition} 误解二："夹爪动作是连续的"
:class: warning

`BinaryJointPositionActionCfg` 只看动作的正负号，输出两个目标中的一个[^binary]。网络输出的夹爪那一维是连续数，但只有它的符号起作用。
:::

:::{admonition} 误解三："观测开了 `enable_corruption` 就有噪声"
:class: warning

PolicyCfg 里设了 `enable_corruption = True`，但五个观测项都没有设 `noise`，所以实际不加任何噪声[^obs]。噪声要逐项配置，开关只决定"配置了的噪声生不生效"（[4.10](../4-isaaclab/4.10-observation-action.md)）。
:::

:::{admonition} 误解四："`minimal_height = 0.04` 就是举起 4 cm"
:class: warning

它是世界坐标的绝对高度。对官方的桌子和方块来说，折合约 1.9 cm；对别的桌子可能毫无意义。见上文"场景"一节的量法。
:::
