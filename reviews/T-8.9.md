**坑二、坑三**（`warp_pitfalls.py`，不启动仿真；`scratch/examine/t89/pitfalls.log`）：
- float64 的 torch 张量与 `(N, 3)` 的 float32 数组都报 `RuntimeError: Error launching kernel … expects an array with dtype=… but passed array has dtype=…`，与页面原文一致；
- CPU 上的指令数组传给 `cuda:0` 的内核不报错，输出 1.004988，与 GPU 对照相同。

**坑三的机理**（本 session 另写的 `scratch/examine/t89/scripts/strict_check.py`）：
- Warp 1.16.0 的 `warp/config.py` L89–L115 定义了 `LaunchArrayAccessMode`，默认 `launch_array_access_mode = RELAXED`。
- `warp/_src/context.py` `pack_arg` 里的注释写明"By default, array pointers are passed through and the hardware access rules determine whether the launch is valid"（L9718–L9721）。
- 同一内核、同一个 CPU 数组，在三种模式下：
  - `RELAXED`：不报错；
  - `CHECKED`：不报错（硬件判定可访问）；
  - `STRICT`：报 `RuntimeError: … trying to launch on device='cuda:0', but input array for argument 'command' is on device=cpu (memory_kind=HOST), whose memory is not accessible or cannot be verified …`。
- 所以"不报错"有源码依据：Warp 默认不检查设备，指针原样交给硬件。"GPU 能直接读主机内存"仍是推断。见问题 1。

**内核与 torch 版对照**：
- torch 版 `tcp_position_error` 为 `‖_tcp(...).pos − _command_w(...).target‖`；
- Warp 内核为 `target = root_pos + quat_rotate(root_quat, cmd_pos)`、`tcp = body_pos + quat_rotate(body_quat, offset_pos)`；
- 两者语义相同。位置误差只用到 `offset_pos`，`offset_rot` 不参与。四元数按 XYZW，与 `wp.quatf` 一致。
