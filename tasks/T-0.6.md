## 目标

本页给出全站反复引用的"锚点图"：从策略输出动作到 PhysX 步进再到观测返回策略，这一圈里每一步在哪一层、由哪个对象负责。读者以后读仿真循环（3.1）、各 Manager（4.9–4.13）、源码导读（9.1）时都回到这张图。

## 必须覆盖

1. **时序图**（一屏内）：参与者为 策略/RL 库 → RL wrapper → `ManagerBasedRLEnv.step` → ActionManager → 资产（Articulation）写入 → `SimulationContext.step`（PhysX）→ 资产数据更新 → Observation/Reward/Termination/Event/Command Manager → 返回。标出 **decimation 循环**的位置（一个 RL step 内多次物理步）。
2. **逐步说明表**：每一步一行：发生什么、在哪一层（对应 0.2 的层）、负责的类与方法、v2.3.2 源码 permalink。
3. **三个时间尺度**：物理 `dt`、控制周期（`dt × decimation`）、渲染间隔（`render_interval`），用主线组合的默认值举例，说明改哪一个影响什么。来源为 `SimulationCfg` 与 `ManagerBasedRLEnvCfg` 源码。
4. **数据在哪里**：说明观测/动作/奖励都是 `(num_envs, …)` 形状的 GPU 张量，环境不是循环而是批量；一句话链接 5.4。
5. **Direct 环境的差异**一段：DirectRLEnv 把 Manager 换成用户自己写的方法，图上标出替换点，链接 4.14（占位）。
6. **常见误解**（至少 3 条）：如"一个 step 就是一次物理步"、"reset 会重新加载场景"、"渲染每步都发生"。

## 不在本页范围

各 Manager 的配置细节（第 4 部分）、PhysX 求解细节（3.3）。
