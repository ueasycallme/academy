# T-0.7c Mermaid 边的颜色不生效（站点级）

状态: 已合并
优先级: P1
类型: 微任务（D-014，源自 reviews/T-0.7b.md；改前就存在）
产出: 修改 `docs/_static/css/academy.css`（首选），必要时 `docs/0-map/0.7-learning-paths.md`

## 背景

0.7 学习路线图的 29 条边渲染后全部是灰色 rgb(102,102,102)，`linkStyle` 里写的颜色没有生效；线型（实线、长虚线、点线、点划线）仍能区分。正文写的是"绿色实线是黄金路径，橙色长虚线……"，与实际显示不符。校验方推测是站点 CSS 对 Mermaid 边的覆盖（T-SITE-05 加的那组规则）压住了 `linkStyle` 的内联样式，未定位到具体规则。

## 原因已定位（设计 session）

`docs/_static/css/academy.css` 约 249–252 行：`.bd-content pre.mermaid svg .flowchart-link, … { stroke: var(--pst-color-text-muted) !important; stroke-width: 1px !important; }`。`!important` 压过了 `linkStyle` 写在元素上的内联 `stroke`，所以所有边都是同一种灰色。箭头头部（约 255 行）同理。

## 必须完成

1. 定位原因：在 `academy.css` 的 Mermaid 覆盖规则里找出作用于边（`.flowchart-link`、`.edgePath path` 等）的 `stroke` 规则，确认是否带 `!important` 或优先级高于内联样式。
2. **首选站点级修法**：让图里显式写的 `linkStyle` 颜色生效，同时未写 `linkStyle` 的边仍用站点默认的深灰细线（例如默认规则不加 `!important`，或用 `:not([style*="stroke"])` 排除带内联样式的边）。深色模式下这些颜色也要可读，必要时约定一组深浅色都可用的路线色并写进附记，设计 session 会并入 CONVENTIONS。
3. 退路：若站点级修法代价过大，改 0.7 正文只按线型描述四条路线，并在附记说明为什么不能用颜色。
4. 回归：用探针或截图确认其他已上线页面的图（至少 0.2、0.6、3.1、4.9）边的样式没有变化。

## 验收标准

0.7 的四条路线颜色与正文描述一致（或正文改为按线型描述）；深浅色截图各一张；其他图无回归；`sphinx-build -W` 零警告。

### 实现附记（isaac-academy-accomplish，2026-09-30）

- **原因**：
  - `academy.css` 的边规则 `.flowchart-link { stroke: … !important; stroke-width: 1px !important }` 压过了 Mermaid 写在 path 上的内联 `style="stroke:#…"`（linkStyle）。
  - 箭头规则 `marker path { fill/stroke: … !important }` 同样压过了 Mermaid 按颜色生成的 marker。Mermaid 11.17.2 会为每种 linkStyle 颜色生成一个 id 形如 `…flowchart-v2-pointEnd__76b900` 的 marker。
- **站点级修法**（只改 `docs/_static/css/academy.css` 两个选择器，加注释）：
  - 边：`.flowchart-link:not([style*="stroke:"])`。未写 linkStyle 的边 style 为 `";"`，仍走默认深灰细线。
  - 箭头：`marker:not([id*="__"]) path`。默认 marker 的 id 不含 `__`，仍为灰色。
- **实测**（1440 宽，computed style）：
  - 0.7：边为 #a855f7、#3b82f6、#f57c00、#76b900，都是 2px；箭头同色。
  - 回归：0.1、0.2（两图）、0.6、1.2、3.1、4.9、4.10 的边都仍是 rgb(102,102,102) / 1px，箭头灰色，与修改前一致（修改前 0.2 同样测得 rgb(102,102,102)）。
- **深色可读性**：四色（绿 #76b900、橙 #f57c00、蓝 #3b82f6、紫 #a855f7）在深色背景上都清楚。建议作为站内"路线色"约定，由设计 session 决定是否并入 CONVENTIONS。
- **截图**：`scratch/shots/t07c-fig-{light,dark}.png`。
- 用 `sphinx-build -E -a` 全量重建确认静态文件已更新；`tools/check_head_build.sh --worktree` 通过（-W）。
- **顺带发现**（未改，正文不在本卡范围）：0.7 正文把合成数据写成"紫色长点划线"，实际线型是 `stroke-dasharray:10 4`，即长虚线，不是点划线；橙色为 `6 3`，是短一些的虚线。是否改措辞请设计 session 决定。
