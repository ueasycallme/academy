## 必须覆盖

1. **前置检查**：驱动版本（`nvidia-smi`）、Python 版本要求、磁盘空间；链接 1.3。
2. **步骤**（与 Isaac Lab v2.3.2 官方安装页 pip 路线一致，但每步加一句原因）：
   - 创建独立环境（conda 或 uv/venv，Python 3.11），说明为什么不用系统 Python
   - `pip install "isaacsim[all,extscache]==5.1.0.0" --extra-index-url ...`（命令以官方页为准），解释 `[all]`、`[extscache]` 是什么、装了多少东西、缓存目录在哪

   - 克隆 Isaac Lab，`git checkout v2.3.2`，`./isaaclab.sh --install`（或 `-i rsl_rl` 等选项），解释 `isaaclab.sh` 做了什么、editable 安装意味着什么（**引用 reviews/ENV.md 记录的坑：仓库移动后 editable 路径失效**）
3. **验证**：运行 `scripts/tutorials/00_sim/create_empty.py --headless`，再跑一个最小训练命令（如 Cartpole 训练 100 iterations）；给出预期输出的关键行、首次启动耗时（着色器编译）说明。
4. **环境变量与路径速查**：Isaac Sim 安装位置、缓存/日志目录、`ISAACSIM_PATH` 等（有来源才写）。
5. **常见坑**（≥ 5，每条来源或本站实测）：PYTHONPATH 被 ROS 污染（reviews/ENV.md）、EULA 交互卡住、editable 路径失效、驱动过旧、首次启动超时误判为卡死。
6. 与二进制安装/容器的关系：一句话链接 1.6、1.7。

**过程中发现并处理的两个问题**（都已写进页面）
1. **自写脚本退出时 `simulation_app.close()` 卡住**：第一版 `verify_install.py` 打印 8/8 后卡在 close() 达 46 分钟，CPU 占满。排查过程：
    - 只启动再关闭：4 秒退出；
    - 创建 `SimulationContext` 并步进后再关闭：卡住（与变量在模块顶层还是在 `main()` 内无关）；
    - 先调用 `sim.clear_all_callbacks()` 与 `sim.clear_instance()` 再关闭：5 秒退出。
    这与 Isaac Lab `ManagerBasedEnv.close()`（v2.3.2 L535–L544）的做法一致。脚本已修正，页面新增"坑七"。
2. **`timeout 600` 杀不掉 `create_empty.py`**：该脚本按设计会一直运行；`timeout` 默认发送的 SIGTERM 被 Kit 忽略（本站实测，进程在 600 秒后仍在运行），同时输出被缓冲，看不到 "Setup complete"。改用 `PYTHONUNBUFFERED=1` 与 `timeout -s KILL` 后正常。页面第五步已补充说明。
