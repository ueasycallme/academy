# T-2.8 Nucleus 与资产服务

状态: 待实现
优先级: P3（第四批第 8 张；不占 GPU；需要联网与磁盘）
类型: 概念页
依赖: T-1.3 / T-1.4（安装）、T-2.6（Kit）、T-A.3（官方资源）
产出: `docs/2-usd-kit/2.8-nucleus.md`（替换占位页）
公共要求: 来源 Isaac Sim 5.1.0 文档（资产、Nucleus / Launcher 弃用说明、`asset_root` 设置）、Isaac Lab v2.3.2 `isaaclab/utils/assets.py`；篇幅 ≤ 3000

## 目标

读者知道官方资产（Franka、仓库场景、材质等）现在从哪里来、Nucleus 在 5.x 还是不是必需品、怎么把资产放到本地或内网让团队不每次都从云上拉；并能解释 Isaac Lab 代码里 `ISAAC_NUCLEUS_DIR` 一类路径到底指向哪。

## 裁断前提

Nucleus 与 Omniverse Launcher 的弃用状态**以 5.1.0 文档与 release notes 原文为准**，页面引用原句（≤ 1 句）并注明日期；不写"已死 / 仍可用"类判断。本机不装 Nucleus（系统设置不动）。

## 必须覆盖

1. **现状一张表**：云端资产（S3 URL 形式）、本地资产包（Isaac Sim Assets 下载包：体积、版本对应）、Nucleus（自建 / 企业版）三种来源——怎么配置、适合谁、5.1 文档怎么说。
2. **路径从哪来**：`/persistent/isaac/asset_root/default` 等设置项、`get_assets_root_path()`（5.1 API）、Isaac Lab `isaaclab/utils/assets.py` 的 `ISAAC_NUCLEUS_DIR` / `ISAACLAB_NUCLEUS_DIR` / `check_file_path`（v2.3.2 permalink）：一张"变量 → 默认值 → 怎么改"表；本站第 4 部分示例实际拉的是哪条 URL（实测日志一行）。
3. **本地化**：下载资产包 → 改设置 → 验证（`check_file_path` 或拉一个资产）三步；实测拉取一个小资产（如 Franka USD）云端 vs 本地的时间各一行；**磁盘**：先 `df -h`，资产包总体积超过可用空间的一半就只下子集并写明。
4. **离线 / 内网**：没有外网时会发生什么（实测一次断网或指向不存在路径的报错原文）；代理不改系统设置，只在命令行环境变量里给（标注）。
5. **常见坑 ≥ 3**（实测优先；候选：首次运行"卡住"其实在下载；资产包版本与 Isaac Sim 版本不配；设置改了但 Kit 缓存了旧路径；`check_server` 超时）。

## 验收标准

设置项 / API 名与 5.1.0 文档一致；Isaac Lab 路径以 v2.3.2 源码为准；实测可复跑（校验方复跑第 3 项的一个资产）；1.3、1.4、2.6、A.3、6.1.7 链接可达；版本说明写 3.0 的资产获取变化或"未核对"。
