# T-3.2 SimulationApp 与 Python 启动方式

状态: 待实现
优先级: P1
类型: 实操页
依赖: T-1.4、T-3.1
产出: `docs/3-isaacsim/3.2-simulation-app.md`；示例 `examples/isaaclab-2.3/3.2-simulation-app/`

## 目标

读者能写出一个最小的 standalone 脚本，并理解为什么 import 顺序有讲究、headless 与 GUI 怎么切、脚本怎么正常退出。

## 必须覆盖

1. **standalone 脚本骨架**（Isaac Sim 原生）：`from isaacsim import SimulationApp` → 实例化 → 再 import 其他 `isaacsim.*`/`omni.*`/`pxr` → 主循环 → `close()`。解释"必须先启动 Kit 再 import 扩展模块"的原因（D-009 补充口径的正面说明）。
2. **Isaac Lab 的等价物**：`AppLauncher`，它多做了什么（命令行参数、headless/livestream/enable_cameras、加载的 `.kit` 体验文件）。给 v2.3.2 源码 permalink。
3. **两个最小示例**：纯 Isaac Sim 版与 Isaac Lab 版，各约 30 行，都用 `main()` 写法（T-1.4 踩到的模块顶层 SimulationContext 导致退出卡住的坑写进常见坑）。
4. **启动参数**：headless、分辨率、`--device`、常用 Kit 参数的传法。
5. **退出**：正常退出的写法；`close()` 前必须 `sys.stdout.flush()`，否则重定向到文件或管道时输出几乎全部丢失（本站实测，reviews/T-2.4.md：管道下只剩 2 行）；SIGTERM 被 Kit 忽略、需要 SIGKILL 超时的现象（本站实测，见 T-1.4 附记）；输出缓冲问题（`python -u`）。
6. **GUI 里的 Script Editor vs standalone**：何时用哪个，一段即可，链接 0.5。
7. 常见坑 ≥ 4（均有来源或本站实测）。

## 验收标准

两个示例在主线环境 headless 运行并正常退出（校验方复跑，记录耗时）；篇幅 1200–2000 字。
