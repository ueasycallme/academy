## 目标

读者理解"一个环境 → 几千个环境"在 USD / PhysX 层面发生了什么：Cloner 复制 prim、`replicate_physics` 让 PhysX 只解析一次、Fabric 绕过 USD 写回——以及每一项对启动时间、每步耗时、显存各起什么作用。

## 必须覆盖

1. **Cloner 是什么**：`isaacsim.core.cloner` 的 `Cloner` / `GridCloner`（`define_base_env`、`generate_paths`、`clone` 的参数：`replicate_physics`、`copy_from_source`、`position_offsets`），源码 permalink；克隆产物在 Stage 上长什么样（`/World/envs/env_0` → `env_N`，与 4.5 的 `{ENV_REGEX_NS}` 对应）。
2. **replicate_physics 的含义**：PhysX 侧"复制一份解析结果"而非逐个解析；代价是各环境的物理参数必须一致（与 4.12 / 6.4.2 的 startup 随机化限制呼应，回链）；Isaac Lab `InteractiveScene.clone_environments` 怎么调用它（v2.3.2 L105 附近 permalink）与 `filter_collisions`（环境间碰撞过滤，回链 6.2.1 的 env_spacing 一节）。
3. **Fabric 与 Stage in Memory**：`SimulationCfg.use_fabric`（v2.3.2 `simulation_cfg.py` L392）绕过 USD 写回的意义；"看不到 USD 属性在变"是 Fabric 的后果（回链 4.4 的 `physics.updateToUsd`）；Stage in Memory 一段（Isaac Sim 5.x 文档，是什么、Isaac Lab 2.3.2 是否用到，以来源为准，查不到写未核对）。
4. **实测**：一个最小脚本：Galbot（或 Cartpole）场景 `num_envs` = 16 / 256 / 1024 / 4096，分别记录：克隆用时、首次 `reset` 用时、每步耗时、按进程显存、主机 RSS；再对 1024 做两组对照：`replicate_physics` True/False、`use_fabric` True/False。结论按证据门槛写（单因素对照可写"观察到"）。4096 组跑前看主机内存（WORKFLOW）。
5. **一张图**：Stage 层（prim 复制）→ PhysX 层（解析/复制）→ Fabric（张量视图）的分层图（D-017 竖排）。
6. 常见坑 ≥ 3（候选：克隆后改了 env_0 以为全体都变；replicate_physics 下 startup 随机化不生效；use_fabric 时用 USD API 读位姿读到旧值）。

## 验收标准

API 与 v2.3.2 / 5.1.0 源码一致（permalink）；实测表可复跑（计时 ±20%、显存 ±5%）；4.4、4.5、4.12、6.2.1 链接可达。
