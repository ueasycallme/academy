## 目标

读者理解"没有 Isaac Lab 时用 Isaac Sim 写一个 RL 环境要自己做哪些事"，从而知道 Isaac Lab 的每个抽象是为了省掉什么。本页是第 4 部分的入口。

## 必须覆盖

1. **四件重复劳动**：并行环境的克隆与路径管理、GPU 张量数据的读写、任务定义（观测/动作/奖励/终止/重置）的组织、与 RL 库的对接。每件配一句"Isaac Lab 用什么解决"，链接到 4.5 / 4.6 / 4.9 / 4.16。
2. **对照**：同一件小事（让 N 个 Cartpole 并行、读取关节位置）用纯 Isaac Sim API 与用 Isaac Lab 各写出关键片段（各 ≤ 15 行），不要求完整可运行，但 API 必须真实存在并给来源。
3. **Isaac Lab 的模块地图**（一张依赖图，竖排）：`sim`、`scene`、`assets`、`sensors`、`actuators`、`managers`、`envs`、`terrains`、`controllers`、`devices`、`utils`，各一句话，链接本部分对应页。
4. **两种环境写法的预告**：Manager-based 与 Direct，各一句话，链接 4.9、4.14。
5. **Isaac Lab 不做什么**：不是仿真器、不是 RL 算法库、不含真机部署；各指向相应部分。
6. 常见误解 ≥ 3。

## 验收标准

对照片段中的 API 在 5.1.0 / v2.3.2 中存在；模块地图与源码目录一致。
