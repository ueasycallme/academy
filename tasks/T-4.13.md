公共要求: 见 `tasks/T-4-common.md`

## 目标

读者理解"目标指令"为什么是独立的 Manager 而不是观测的一部分：它有自己的生命周期（按时间重采样、按 episode 重置）、自己的度量，并能被观测、奖励、终止同时引用。读完能为自己的任务写一个 `CommandTerm`。

## 必须覆盖

1. **职责与位置**：Command Manager 在 0.6 图 / 4.9 `step()` 中的位置（`load_managers` 里最先创建、`step()` 末尾 `compute(dt)`；给 permalink）；与观测项的分工——指令由 Command Manager 生成，观测项 `generated_commands` 只是读出来。
2. **`CommandTerm` 的生命周期**：`resampling_time_range` 与 `time_left` 计数、`_resample` → `_resample_command` / `_update_command` 的分工、`reset` 时发生什么、`metrics` 的用途（写进 `extras["log"]`）；以 `command_manager.py` v2.3.2 为准，逐个方法一句话。
3. **内置指令项**：`NullCommand`、`UniformPoseCommand`（含 `make_quat_unique`、`debug_vis` 的目标/当前位姿双 marker）、`UniformVelocityCommand`（含 `heading_command` 与 `rel_standing_envs`）、`UniformPose2dCommand` / `TerrainBasedPose2dCommand`；一张对照表：输出维度、坐标系、重采样时机、适用任务。
4. **主线案例**：官方 `Isaac-Reach-Franka-v0` 的 `ee_pose`（`UniformPoseCommandCfg`，`body_name`、`ranges`、`resampling_time_range`）怎么被观测 `pose_command`、奖励 `position_command_error` 同时引用；与 6.4.1 中 Galbot reach 的指令范围对照，一句话指出工作空间范围来自 6.4.1 的 `workspace.py`（链接，不重复内容）。
5. **自定义指令项**：写一个最小 `CommandTerm` 子类（例如"桌面随机目标点，每 N 秒重采样"或 Cartpole 的"目标小车位置"），展示必须实现的方法与 `CommandTermCfg` 的 `class_type` 绑定；给 debug_vis 的最小实现（可选）。
6. **示例**：`examples/isaaclab-2.3/4.13-command-manager/`：用 Cartpole（第 4 部分贯穿示例）加一个目标位置指令项，打印若干环境在重采样前后的指令值与 `time_left`，验证重采样时间范围生效；再打印 `env.command_manager` 的 `__str__` 表。`num_envs` 小、headless、几秒内跑完。
7. 常见误解 ≥ 3（候选：把目标直接写进观测项就行；指令在每步都重新采样；`command` 的坐标系是世界系）。
