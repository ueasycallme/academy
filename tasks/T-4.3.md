## 目标

读者理解 Isaac Lab 为什么几乎一切都用 `@configclass` 描述，能读懂官方任务里多层继承的配置，并会用覆盖的方式改出自己的变体。

## 必须覆盖

1. **它是什么**：对 `dataclass` 的封装，解决了哪些原生 dataclass 的不便（可变默认值、嵌套、`MISSING`、`to_dict`/`from_dict`、`replace`、`copy`、`validate`）。每项给源码位置。
2. **"配置 + 类"的成对约定**：`XxxCfg` 里的 `class_type` 指向实现类；`func` 指向函数（spawner、mdp term）。举 `ArticulationCfg` 与 `RewardTermCfg` 两例。
3. **三种改配置的方式**：继承后在 `__post_init__` 里改、`.replace(...)`、实例化后直接赋值；各自适用场景与官方任务里的实例。
4. **`MISSING`**：必须由使用者填的字段，没填时何时报错。
5. **与 Hydra / 命令行的关系**：`train.py` 中 `hydra_task_config` 如何把命令行覆盖映射到 env cfg 与 agent cfg，给出 2–3 个实际可用的覆盖示例并实测。
6. **读懂一个真实配置**：以 Cartpole 的 env cfg 为例，画出它的配置嵌套树（场景、观测、动作、奖励、终止、事件各一层）。
7. 常见坑 ≥ 3：可变默认值被多个实例共享的历史问题、在类体里写逻辑、`__post_init__` 覆盖顺序。

## 验收标准

Hydra 覆盖示例校验方复跑成功；示例脚本可选（纯配置演示可不启动仿真，若如此在页面注明）。
