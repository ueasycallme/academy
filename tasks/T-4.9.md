## 目标

读者看懂一个 Manager-based 任务的全貌：配置类里每一块是什么、各 Manager 在一次 step 里的执行顺序，并能跑起一个官方任务、改动一处配置看到效果。本页是 4.10–4.13 的总纲。

## 必须覆盖

1. **两层类**：`ManagerBasedEnv`（无 RL 概念）与 `ManagerBasedRLEnv`（加上奖励、终止、课程、指令）；各自的 Cfg 字段表（`scene`、`observations`、`actions`、`events`、`rewards`、`terminations`、`curriculum`、`commands`、`recorders`、`decimation`、`episode_length_s`、`sim`、`viewer` 等，以源码为准）。
2. **Manager 一览**：每个 Manager 一行——管什么、Term 的配置类、Term 的签名（函数还是类）、输出形状。链接 4.10–4.13。
3. **Term 的概念**：一个 Manager 由若干 Term 组成；Term = 函数/类 + 参数 + （权重/噪声/…）；`mdp` 模块是 Term 函数库；如何在自己的任务里加一个自定义 Term（最小例）。
4. **执行顺序**：`step()` 内各 Manager 的调用顺序与 reset 分支，与 0.6 锚点图逐项对应（不重复画整张图，用一张"Manager 视角"的精简时序图，上→下）。`load_managers()` 的构建顺序。
5. **读懂 Cartpole**：把官方 manager-based Cartpole 的 env cfg 拆成表：每个 Term 是什么、用的哪个 mdp 函数、参数。
6. **动手**：用 `scripts/environments/random_agent.py` 或 `zero_agent.py` 跑 Cartpole；用 Hydra 覆盖改一个奖励权重或 `num_envs`；再写一个继承官方 cfg、只改一处的子类并运行。
7. **调试入口**：Manager 的打印表（启动时各 Manager 输出的 Term 表）怎么读；`env.unwrapped`；观测/奖励各项的查看方法。
8. 常见坑 ≥ 4。

## 验收标准

执行顺序与 v2.3.2 `manager_based_rl_env.py` / `manager_based_env.py` 一致（校验方逐步对照）；动手部分的命令全部复跑。


## 补充（设计 session，源自 T-4.3 的发现）

Hydra / 命令行覆盖是在 `__post_init__` 之后通过 `from_dict` 应用的，所以 `__post_init__` 里由其他字段推导出来的值不会跟着变。例：Cartpole 覆盖 `decimation` 后 `render_interval` 不变，`ManagerBasedEnv` 会打印警告。本页凡涉及命令行覆盖的地方都要提一句并链接 4.3 的常见坑第三条；校验方复核时实测一次。
