# T-5.4 为什么需要几千个并行环境

## 目标

读者理解并行环境数对训练的三重影响（吞吐、每次更新的数据量、显存），知道 `num_envs` 怎么选，并明白这正是 Isaac Lab 存在的理由。

## 必须覆盖

1. **样本需求的量级**：on-policy 方法需要的样本量；单环境实时仿真要多久，并行后要多久（用 Cartpole 的实测数字算一笔账）。
2. **GPU 仿真为什么快**：物理、观测、奖励全在 GPU 上以张量批量计算，没有 CPU↔GPU 往返（回链 0.6、3.1、4.6）。
3. **实测**：Cartpole 训练在 `num_envs` = 64 / 256 / 1024 / 4096 下的每秒步数、每次迭代耗时、达到同一回报所需的墙上时间、按进程显存（RTX 5070 12 GB，headless）。与 1.3 的纯仿真吞吐数据对照说明差异。标注"本站实测"，给脚本与命令。
4. **`num_envs` 与 `num_steps_per_env` 的配合**：批量大小、每次更新覆盖的时间跨度；环境多了是否可以少走几步。
5. **收益递减与上限**：吞吐不随环境数线性增长的原因；显存上限（回链 1.3）；带相机的任务为什么远小于 4096。
6. **并行的副作用**：所有环境同时重置导致的同步（`init_at_random_ep_len` 的作用，回链 4.11）；统计量的噪声随环境数减小。
7. **怎么选**：给一张"任务类型 → 起步 num_envs"的建议表，标明经验性；主线机器上的建议值。
8. 常见误解 ≥ 3：如"环境越多学得越好"、"num_envs 只影响速度"、"4096 是必须的"。

## 验收标准

实测表由校验方同机复跑（误差 ≤ 15%，显存按进程口径）；结论与数据一致，差异在波动范围内的不写成确定性结论（T-4.14b 的教训）。
