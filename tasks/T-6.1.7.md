公共要求: 见 `tasks/T-6-common.md`；篇幅 ≤ 3500

## 目标

本项目的资产策略已经在用：描述仓库固定 commit、生成的 USD 不提交、修改全部写在转换脚本里。本页把它讲成一套可以复用的规则，并补上缺的一环——怎么知道手里的 USD 是哪个版本、由哪些参数生成的。

## 必须覆盖

1. **三种做法对照**：大文件进 Git LFS、用 DVC 之类工具管外部存储、只提交"来源 + 转换脚本"按需重新生成（本项目）；各自适合什么（团队规模、资产是否手工编辑过、CI 是否要跑）。一张表。Nucleus 只提一句链接 2.8 占位页。
2. **清单文件**：`asset_manifest.py` 记录来源仓库与 commit、转换器版本（Isaac Sim 版本）、转换参数（含 mimic 增益 1000 / 1.0、`--floating_base`、自碰撞过滤对等本项目已有的改动）、输出文件的 sha256 与大小、生成日期；校验模式比对当前文件并给出差异。页面解释为什么 sha256 要配合参数一起看。
3. **手工修改放哪一层**：回链 2.3——手工编辑与脚本生成分层，重新生成不丢改动；本项目 `assets/physics.py` 写进资产的做法与"单独 sublayer"做法的取舍（各一段，实测本项目现状即可）。
4. **变更记录**：本项目到今天为止资产改过的每一项（来自 T-6-common"已核实的事实"第 1、8、11、12 条等），一张"日期 / 改了什么 / 为什么 / 哪张卡"的表，作为变更记录的示范。
5. **常见坑 ≥ 3**（候选：usdc 二进制 diff 看不出改动、转换器升级后输出变化但 commit 没变、LFS 配额与 clone 速度、绝对路径写进 USD）。

## 验收标准

`asset_manifest.py` 在本机生成一次并能校验通过、改一个参数后能报出差异（校验方复跑）；2.3、6.1.1、6.1.2、6.1.4、6.1.5 链接可达；LFS / DVC 的断言有官方文档来源。
