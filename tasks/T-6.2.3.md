## 目标

读者知道 Galbot 场景在这台 12 GB 显存 / 16 GB 主机内存的机器上能开到多少环境、瓶颈在哪一层（USD 克隆 / PhysX / 渲染 / 主机内存 / Python），以及每个常用优化各能换回多少——用数字说话。

## 必须覆盖

1. **基线表**：reach 场景 `num_envs` = 256 / 1024 / 2048 / 4096（/ 8192 若主机内存允许，否则引 6.5.2 的实测）：克隆用时、首次 reset、每步仿真耗时、每秒环境步（吞吐）、按进程显存、主机 RSS、MemAvailable 最低值。
2. **瓶颈在哪一层**：用 3.7 的分层说明 + 简单计时拆分（物理步 vs `scene.update` vs Python 侧），指出 Galbot 这个场景在 1024 与 4096 时各卡在哪（结论按证据门槛，拆分计时要可复跑）；预告 7.2（profiler）不展开。
3. **逐项优化对照**（每项单因素，与基线同 num_envs）：碰撞体简化（6.1.4 的 convex hull vs 网格，若已是最简则说明）、`env_spacing` 与 `filter_collisions`、`replicate_physics`、去掉桌子（6.2.1"要不要桌子"）、关掉 debug_vis、`decimation` / `dt` 不动（那是任务参数，回链 4.4）。每项给耗时与显存变化。
4. **主机内存**：为什么 8192 在 16 GB 上挂（6.5.2 实测）；RSS 构成粗估（Kit + 扩展 + PhysX 解析 + Python），标推断；给出"每 1024 环境大约多少 RSS"的经验数（本站实测）。
5. **推荐配置**：本站主线训练用 1024（默认）/ 2048（训练时 --num_envs），理由用上面的数字；给读者一张"按显存 / 主机内存选 num_envs"的速查表（回链 1.3 / 5.4）。
6. 常见坑 ≥ 3（候选：显存够但主机内存不够；env_spacing 太小环境互撞；克隆后忘了 filter_collisions）。

## 验收标准

所有数字本站实测、可复跑（计时 ±20%、显存 ±5%）；单因素对照只写观察到；3.7、6.2.1、6.5.2、1.3、5.4、7.2 链接可达。
