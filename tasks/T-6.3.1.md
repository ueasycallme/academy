## 目标

4.4 讲了参数是什么，本页讲改了会怎样：物理步长 dt、求解器迭代次数、接触偏移 / 静止偏移、GPU 缓冲上限，对一个具体场景（Galbot 抓方块）的稳定性与速度各有什么影响。读者学会用一个固定的"稳定性探针"去调参数，而不是凭感觉。

## 必须覆盖

1. **稳定性探针**：用 6.4.6 的脚本化示教跑固定的 20 次抓取（固定种子），指标：抓取成功数、搬运中方块相对 TCP 的滑移（6.4.6 trace 的口径）、是否出现穿透 / 弹飞 / NaN；每步墙上时间。写成 `sweep_physics.py` 的一个模式。
2. **四个单因素扫描**（每次只改一项，其余主线默认）：dt（1/60、1/120、1/240，decimation 同步调整使控制频率不变，并说明为什么必须同步）；位置迭代 1 / 4 / 8、速度迭代 0 / 1 / 4；接触偏移 / 静止偏移三组；`gpu_max_rigid_contact_count` 等缓冲在 1 / 64 / 1024 环境下的溢出警告与处理。每个扫描一张小表（稳定性 + 代价）。
3. **结论与主线取舍**：本项目最后用哪组参数、为什么（按证据门槛写）；哪些参数改了就要重训（dt 改变了策略看到的动力学）。
4. **常见坑 ≥ 3**（实测优先；候选：改 dt 不改 decimation、接触偏移大于碰撞体尺度、GPU 缓冲溢出只在多环境时出现、"更多迭代更稳"不总成立）。
5. 一张图：dt / 迭代次数与滑移、每步时间的关系（D-017 / D-025）。

## 验收标准

扫描本站实测可复跑（校验方复跑 dt 一组 + 迭代一组）；每组 ≥ 20 次抓取；4.4、6.1.4、6.1.5、6.4.6 链接可达；没有"更接近真机"类断言。
