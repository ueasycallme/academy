## 目标

读者训练几十次以后还能回答"这个检查点是哪份配置、哪个种子、哪个代码版本训出来的"，并能把一次训练在另一台机器上复现到可比的结果。本页把 6.5.1 / 6.5.2 里零散的做法（run_name、seed、eval_reach、TBD 表）收拢成一套最小规范。

## 必须覆盖

1. **一次训练留下什么**：rsl_rl 在 `logs/rsl_rl/<experiment_name>/<时间戳>[_<run_name>]/` 下写了什么（`params/env.yaml`、`params/agent.yaml`、`params/env.pkl`、TensorBoard 事件、`model_*.pt`，以 v2.3.2 `train.py` 与 rsl_rl 3.1.2 源码为准，permalink）；每样东西能回答哪个问题。
2. **三件决定可复现的事**：代码版本（Isaac Lab commit、本项目 commit、Isaac Sim 版本——哪些 rsl_rl 自动记了、哪些没记）、配置（yaml 快照 vs Hydra 命令行覆盖，覆盖项记在哪里）、随机种子（`--seed`、`torch.manual_seed` 的覆盖范围、`torch_deterministic` 的作用与代价，以源码为准）。本站实测口径：同种子两次训练逐位相同（引 reviews/T-6.5.1.md），换机器/换驱动时能期待什么（标经验性）。
3. **命名与目录规范**（本站约定，一张表）：`--run_name` 的写法（例如 `<改动>_s<seed>`）、何时新开 `experiment_name`、`generated/` 与 `logs/` 的分工、检查点保留策略（保留哪几个 `model_*.pt`，回链 6.5.1"比较检查点"）。
4. **实验记录表**：把 6.5.2 的消融记录（它的"记录实验"一节）升级为本页的模板：列出改动、种子、run 目录、关键指标（中位数 / <5 cm 比例，来自 `eval_reach.py`）、结论一句话；给一个脚本 `scripts/collect_runs.py`（可选）把各 run 的 `params/agent.yaml` 差异与 eval 结果汇成一张表。
5. **TensorBoard 之外**：`logger` 字段支持 `tensorboard` / `wandb` / `neptune`（`RslRlOnPolicyRunnerCfg`，permalink），各自需要什么环境变量；本站只实测 TensorBoard，W&B / Neptune 写"未验证"并链接官方文档；多 run 对比用 `plot_training.py`（6.5.1）。
6. 常见坑 ≥ 3（候选：只存最后一个检查点；命令行覆盖没记进 yaml；换 Isaac Lab commit 后旧检查点加载失败或行为变化；`logs/` 进了 git）。

## 验收标准

第 1、2、5 项逐条有 v2.3.2 / rsl_rl 3.1.2 permalink；目录结构与本机 `logs/rsl_rl/galbot_reach/` 的实际内容一致（列 `tree` 输出一次）；若有脚本，可在已有 logs 上离线运行（不需要 GPU）；链接 6.5.1、6.5.2、7.x 占位可达。
