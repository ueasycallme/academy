## 裁断前提（用户 2026-10-11）

本机只有一张 GPU。本页写成"来源 + 单卡能验证的部分"：多卡 / 多节点的断言全部引官方文档与 v2.3.2 源码并标"未验证（本机单卡）"；单卡能跑的 `torchrun --nproc_per_node=1 ... --distributed` 路径实测，证明命令与代码路径正确。不得在单卡上起两个 rank 冒充多卡（设备按 `local_rank` 分配，会失败；把失败现象记为一条坑即可）。

## 必须覆盖

1. **机制**：Isaac Lab 的 `--distributed` 做了什么（v2.3.2 `app_launcher.py` 的 `local_rank` / `device` 处理、`train.py` 的种子偏移与只在 rank 0 记日志，permalink，9.4 已讲的部分回链不重复）；rsl_rl 3.x 的多 GPU 配置（`multi_gpu_cfg` / 梯度 all-reduce 在哪，permalink）；每张卡跑自己的环境副本、同步什么、不同步什么，一张图（D-017）。
2. **命令**：单机多卡 `torchrun --nproc_per_node=N`，多节点 `--nnodes / --node_rank / --master_addr`（官方文档原样引用参数名）；本站实测 `nproc_per_node=1 --distributed` 跑通 reach 若干迭代，记耗时与显存，并与不加 `--distributed` 的同配置一行对照。
3. **预期收益与代价**：官方文档 / 公开数据给的扩展比例（引用、标来源），为什么不是线性（渲染、同步、每进程 Kit 内存：本站单进程 RSS 3.6 GB × N 的估算）；`num_envs` 是每卡还是总数（源码定）。
4. **常见坑 ≥ 3**（来源为主，单卡能复现的实测：候选：单卡起两个 rank 的报错原文；种子不偏移导致各卡环境相同；日志目录各 rank 各写一份；NCCL 环境变量与 headless 必需）。
5. **容器里跑**：与 1.6 的衔接一句（`--gpus all`），标未验证。

## 验收标准

引用的参数名 / 函数名与官方文档、v2.3.2 源码一致；单卡实测可复跑（校验方复跑一次）；每条多卡断言都标"未验证（本机单卡）"；6.5.1、9.4、7.1、1.6 链接可达。
