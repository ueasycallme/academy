## 目标

读者能在一台没有显示器、只能 SSH 的 GPU 机器上完成训练、回放和录视频，并能在需要时从本地浏览器看到仿真画面。

## 必须覆盖

1. **headless 到底关掉了什么**：窗口、渲染（与 `--enable_cameras` 的关系）、哪些功能 headless 下仍可用（录视频、相机观测、Replicator）；回链 3.2 表 1 与 2.6。本站实测：同一训练 headless 与 GUI 的每迭代耗时、显存、主机 RSS 对比（1024 环境，100 次迭代即可）。
2. **SSH 场景的三件事**：① 环境变量与 `DISPLAY`（没有 X 时 GUI 模式会怎样失败，错误长什么样）；② 长任务不随断线死掉（`nohup` / `tmux` / `setsid`，给一种本站约定并说明理由；日志重定向要配合 CONVENTIONS 退出三步里的 flush）；③ 结果取回（TensorBoard 远程端口转发 `ssh -L`、把 `logs/` 同步回本地）。
3. **livestream 看画面**：Isaac Sim 5.1.0 的 WebRTC livestream（`LIVESTREAM=1/2` 或 AppLauncher `--livestream`，v2.3.2 源码 L115 附近的三种取值与含义），客户端是什么（Isaac Sim WebRTC Streaming Client，官方下载页）、端口、与 headless 的关系；本站实测：本机 headless + livestream，从同一台机器的客户端连上，记一次延迟体感与额外显存/内存。远程机器上连不到时先查什么（防火墙 / 端口 / 公网与内网两种模式）。
4. **一个推荐的远程训练流程**（一张左→右流程图，D-017）：SSH → tmux → headless 训练 → 端口转发看 TensorBoard → 需要看画面时临时开 livestream → 回放录视频（6.6.1）→ 同步结果。
5. **容器与集群**：一段，指向 1.6 占位与官方 Docker / 集群文档，不展开。
6. 常见坑 ≥ 3（候选：忘了 `--headless` 在无显示器机器上启动失败；断线后训练被杀；livestream 开着不关占显存；录视频需要渲染，主机内存比训练高——引 6.6.1 实测 8.4 GB）。

## 验收标准

第 1、3 项有本站实测数字；livestream 的取值与 v2.3.2 源码一致；客户端与端口信息来自 5.1.0 官方文档；3.2、2.6、6.5.1、6.6.1、1.6 链接可达。

**实测**（单进程串行，均先问过 examine，并开着内存守护）：

| 组 | 方式 | 每次迭代 | 显存 / 主机 RSS 峰值 | 体验文件 |
|---|---|---|---|---|
| M1 | `--headless`，1024 个环境，100 次 | 1.491 s | 3041 / 5940 MiB | headless.kit |
| G1 | 带界面（DISPLAY=:0），同上 | 2.669 s | 5744 / 9632 MiB | isaaclab.python.kit |
| M4 | `--headless --livestream 2`，同上，没有客户端 | 2.665 s | 5840 / 9546 MiB | isaaclab.python.kit |

- M3：`env -u DISPLAY`、不加 `--headless`。训练照常进行；SimulationApp 自动加 `--no-window` 并打印警告（simulation_app.py v5.1.0 L447–457）；体验文件是 GUI 版。**与卡片候选坑"忘了 --headless 启动失败"不符**，按实测改写为坑一（设计已同意）。
- M4：TCP 49100 在约 10 s 后开始监听；UDP 47998 没有观察到，标推断。AppLauncher 开 livestream 时选 GUI 体验文件（app_launcher.py L721–741 中的 "headless and not livestream"），所以 M4 与 G1 的开销几乎相同。
- 断线：
  - 先用 `script` 伪终端模拟断线（H1 普通启动、H2 setsid nohup），两者都活了下来，说明这种模拟没有把 SIGHUP 送到训练进程，**不采用**；
  - 改为直接 `kill -HUP`：H3 普通启动的 SigIgn 中 SIGHUP 位为 0，进程立即退出（rc 129）；H4 nohup 启动的 SigIgn 中 SIGHUP 位为 1，5 s 后仍在运行。页面按这一组写。
- SSH：`ssh -o BatchMode=yes localhost` 被拒（Permission denied (publickey,password)）：本机 authorized_keys 里没有自己的公钥，密码登录要人输入。改 authorized_keys 是安全配置，我没有改。所以真实 SSH 断线、`ssh -L`、rsync 都标**未验证**。为测试而临时接受的 localhost 主机密钥写在 scratchpad 的 known_hosts_local 里，没有动 ~/.ssh。
- WebRTC 客户端没有下载，连接与延迟体感标未验证（设计已同意）。
- tmux 本机没装，没有安装，标未验证。
