## 目标

读者给自己的 Isaac Lab 项目加上"改了代码还能不能跑"的保险：哪些检查不需要 GPU、能放进 CI；哪些必须起 Kit、怎么写才不会每个用例都起一次 Kit；训练回归怎么定阈值才不会被随机性误报。全部以主线 Galbot 项目为例。

## 必须覆盖

1. **三层测试**（一张表：层 / 测什么 / 需要什么 / 耗时）：① 无 GPU 单元测试（配置类能构造、`conversion.py` 参数、`asset_manifest.py verify`、`policy_spec.py` 的匹配 / 不匹配、`eval_report.py` 对固定 CSV 的表格、`sim2real_report.py` 的限位计数）；② 有 GPU 冒烟（创建环境 → reset → step 若干步：观测有限、形状对、奖励非 NaN；`check_env` 回链 7.3）；③ 训练回归（固定种子短训若干迭代，指标落在区间内）。
2. **在 Kit 里写 pytest**：一个进程只能起一次 `AppLauncher`——模块级 / session 级 fixture 的写法，参照 Isaac Lab v2.3.2 自身测试的做法（`source/isaaclab/test/` 中的 `AppLauncher(headless=True)` 模式与 `isaaclab.sh --test` 入口，permalink）；为什么用例之间要清场（`env.close()`、场景残留），实测"每用例起 Kit"与"共用 Kit"的耗时对比一行。
3. **回归阈值怎么定**：用 6.6.2 的区间口径：同种子重跑应逐位相同（6.4.4 的证据）→ 可以用"逐位相同"做确定性回归；换种子 / 换机器用区间。两种各给一个用例，写明各自在什么改动下会误报。
4. **CI**：GitHub Actions 只跑无 GPU 层（本仓库实装 workflow，触发条件限定 `examples/isaaclab-2.3/6-galbot-project/**`；Python 3.10；不装 isaacsim）；自托管 GPU runner 的做法只讲要点并引官方文档，标"未验证（本站无 runner）"。workflow 在合并前只能本地做 YAML 与路径检查，**首次在 GitHub 上的实跑由校验方在合并后确认并写入附记**；若红，设计开修补卡。
5. **常见坑 ≥ 3**（实测优先；候选：Kit 失败时返回码仍为 0（T-6-common 事实 6）→ 用例必须断言输出而不是返回码；pytest 收集阶段 `import isaacsim` 触发 Kit 启动；用例之间场景 / 全局状态泄漏；CI 的 pip 缓存与 numpy 版本漂移）。

## 验收标准

本机 `pytest tests/` 全绿并给出两层各自耗时与按进程显存；校验方复跑；workflow 通过 YAML 解析与路径核对；7.3、6.6.2、6.1.7、6.7.1、6.4.4 链接可达；无 GPU 层在系统 python3 下也能跑（不依赖 Isaac 环境）。

## 设计补充（2026-10-11，实现方交付后）

1. **两个 Kit 进程并存**：附记写 `slow` 一次跑 tests/gpu 与 tests/regression 时两个 Isaac 进程同时在、RSS 8.7 GB。本机 16 GB 主机内存的规则是任一时刻只一个 Kit 长进程（WORKFLOW）。要求：页面与 README 把回归层写成**单独一次 pytest 调用**（不与 gpu 冒烟同一进程 / 同时），或让回归用例在 session 级 Kit 关闭后再起子进程；二选一并在页面坑里写明"两个 Kit 并存的内存代价"。校验方按此核。
2. 工作流审查（设计）：`permissions: contents: read`、依赖钉版本、paths 限定项目目录——可以进仓库。合并后首次实跑由校验方确认。
