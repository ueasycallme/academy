# T-7.5 数据管理

状态: 待实现
优先级: P3（第四批第 6 张；不占 GPU：只量现有产物）
类型: 概念页
依赖: T-6.1.7（资产清单）、T-6.4.6 / T-6.4.7（示教 HDF5）、T-3.9（合成数据输出）、T-6.5.3（实验管理 / 检查点）、T-1.6（容器里的卷）
产出: `docs/7-infra/7.5-data-management.md`（替换占位页）；项目 `docs/DATA.md`（数据目录约定一页）或 README 加节
公共要求: 见 `tasks/T-7-common.md`；篇幅 ≤ 3500

## 目标

读者知道一个 Isaac Lab 项目会产生哪几类数据、各自多大、放哪、怎么命名、怎么和代码版本对上，用本站主线项目的真实数字说话。

## 必须覆盖

1. **四类数据一张表**：资产（生成的 USD）、示教数据（HDF5）、合成数据（3.9 输出）、训练产物（检查点 / 日志 / 评估 CSV）——格式、本项目实际体积（实测 `du`）、生成成本（时间）、是否可再生、谁依赖它。
2. **示教 HDF5 的结构**：Isaac Lab v2.3.2 `HDF5DatasetFileHandler`（permalink）写出的组 / 数据集布局，用本项目 `galbot_pick_place.hdf5` `h5ls` 实测一段（≤ 15 行）；压缩与追加的注意点。
3. **放哪、怎么版本化**：三种做法（随仓库 LFS / 外部存储 + 清单 / 可再生就不存）与 6.1.7 一致；本项目的目录约定（`datasets/`、`logs/`、`generated/`，gitignore 规则）写成 `DATA.md`；容器里用命名卷（1.6）一句。云存储 / NAS 只讲要点，标"未验证"。
4. **可追溯链**：来源 commit → 资产 sha（6.1.7）→ 示教文件 → 检查点 → 评估 CSV，一张图（D-017）；每一环在本项目里记录在哪个文件。
5. **常见坑 ≥ 3**（实测优先；候选：把图像观测录进 HDF5 体积爆炸（估算一行）；日志目录按时间戳命名找不到对应 commit；数据集里的绝对路径；检查点与配置不配套）。

## 验收标准

表中数字本站实测（校验方复核 `du` / `h5ls`）；6.1.7、6.4.6、6.4.7、6.5.3、3.9、1.6 链接可达（3.9 未合并时链占位页并在合并后由校验方核对）。
