# T-8.2 多后端架构解读

状态: 实现中
优先级: P2（3.0 线第二张；8.5 训练期间的填充，源码为主 + 几分钟实测）
类型: 概念页（3.0 前沿）
依赖: T-8.1、T-1.5、T-8.5（本页引用 8.5 的实测作例子）
产出: `docs/8-frontier/8.2-multi-backend.md`（替换占位页）；可选 `examples/isaaclab-3.0/8.2-backends/`（列出预设、切换后端跑 Cartpole 各一次的脚本）
公共要求: 见 `tasks/T-8-common.md`

## 目标

读者理解 3.0 把"物理引擎"从 Isaac Lab 核心里抽成可替换的 backend 是怎么做到的：抽象边界在哪、`physics=` 预设怎么把一套配置换成另一套、五种可视化后端各是什么；并能判断自己的任务该选哪个组合。

## 必须覆盖

1. **抽象边界**：EA `backend_architecture.rst` + 源码：后端工厂 / 注册机制（`sim/` 下的 backend 模块，permalink）、`SimulationCfg` 里与后端相关的字段、`schemas/_backend_hooks.py` 的作用（schema 配置如何按后端分发）；一张分层图（D-017 竖排：任务 cfg → Isaac Lab 核心 → backend 接口 → PhysX / Newton / OvPhysX）。
2. **三种物理后端**：PhysX（经 Isaac Sim）、Newton（Kit-less，宿主多种求解器：MJWarp 主路径、Kamino beta 等）、OvPhysX（Experimental）：各自的运行条件（要不要 Isaac Sim）、数据路径、成熟度，以 EA `physics_backends.rst` 为准做表。
3. **预设（presets）**：`physics=newton_mjwarp` 这类命令行预设的机制（`backends_and_presets.rst` + 源码）、内置预设清单、预设覆盖了配置的哪些字段；"任务不变、预设换引擎"的含义与边界（哪些任务不能换）。
4. **可视化后端**：EA 文档列的五种（renderers.rst / `_renderer_gallery.rst`）各一句：是什么、依赖什么、适合什么；与 Kit-less 的关系。
5. **实测**：Cartpole 在 PhysX / Newton-MJWarp（/ 其他可用预设）各跑一次短训练（≤ 3 分钟），记录启动时间、每迭代耗时、显存、RSS；标明是 EA。
6. **对读者代码的影响**：写任务时哪些写法是后端无关的、哪些会绑死某个后端（以 8.5 的迁移实录为例）。
7. 常见误解 ≥ 3（候选：Newton = MJWarp；换预设就能无损换引擎；Kit-less 就没有渲染）。
