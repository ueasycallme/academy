## 目标

读者拿着一个 2.3.2 的任务（以本站 Galbot reach 为样本），能逐项对照出要改哪些地方，并知道哪些改动是机械替换、哪些要重新思考。本页是清单，不讲动机（动机在 8.1）。

## 必须覆盖

1. **迁移清单总表**：按类别列（数据类型、四元数约定、API 改名/移动、配置字段、脚本入口、依赖与安装），每行：2.3.2 写法 → 3.0 写法 → 改动性质（机械替换 / 需重测 / 行为变化）→ 来源（EA 迁移文档 `migrating_to_isaaclab_3-0.rst` 的对应小节或源码 permalink）。以官方迁移文档为骨架，不要自造条目；官方文档没提但源码对比能看出的，单独一节"文档未列、源码可见"并标推断。
2. **四元数 WXYZ → XYZW**：影响面（哪些 `data.*` 字段、哪些 `math` 函数），给 2.3.2 与 EA 两侧 permalink；一条"怎么自查"（grep 什么）。
3. **`torch.Tensor` → `wp.array`**：读者代码里最常碰到的三种情形（索引、与 torch 互转、`.to(device)`）在 EA 里怎么写，以 EA 文档/源码为据；性能说法不引没有来源的数字。
4. **主线样本对照**：拿 6.4.1 的 `reach_env_cfg.py` 与 mdp 函数，列出按清单要动的每一处（只列，不写 3.0 版代码——那是 8.5 的事），标注"未验证"。
5. **迁移步骤**：建议顺序（先装环境 1.5 → 跑官方同类任务 → 再改自己的）一段，回链 1.5 占位、8.5 占位。
6. 常见坑 ≥ 3（来自迁移文档与 Releases 里的 known issues，注明来源）。

## 验收标准

总表每行有来源；与官方迁移文档逐条对得上（校验方按文档逐条核，多出的条目必须有源码依据）；页面明示"本站未运行 3.0"；6.4.1、1.5、8.1、8.5 链接可达。
