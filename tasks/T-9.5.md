## 目标

读者能独立读懂一个官方 Manager-based 任务：从 `gym.register` 的入口找到 cfg 类，再按 Manager 逐块读懂每一项的意图；读完知道"改一个官方任务"从哪动手。

## 必须覆盖

1. **入口与文件布局**：`isaaclab_tasks/manager_based/manipulation/lift/` 的文件各管什么（`lift_env_cfg.py` 抽象基类、`config/franka/joint_pos_env_cfg.py` 与 `ik_*` 变体、`agents/`、`mdp/`），`__init__.py` 里的注册与 entry point（回链 4.15）；"抽象场景 + 机器人特化"的两层设计为什么这样做。
2. **场景**：`ObjectTableSceneCfg` 里 `MISSING` 字段的含义、在 Franka 子类里怎么填（机器人、末端 FrameTransformer、物体）；`FrameTransformer` 的 offset 怎么来的。
3. **逐 Manager 读**：Commands（`object_pose`）、Actions（臂 + 夹爪二值动作）、Observations（五项，坐标系）、Events（reset_all、reset_object_position 的范围）、Rewards（四项 + 两项正则，权重与 std 的含义，`object_is_lifted` 的 `minimal_height`）、Terminations（time_out、object_dropping 用 `root_height_below_minimum`）、Curriculum（两项惩罚在 10000 步升到 −0.1）。每块：节选 + 意图 + 回链 4.x。
4. **PPO 配置**：`rsl_rl_ppo_cfg.py` 的 `num_steps_per_env=24`、`max_iterations=1500`、`entropy_coef=0.006`、`learning_rate=1e-4` 等与 reach（6.5.1）的差异，样本预算 = 4096 × 24 × 1500 这一算式写明（6.4.3 的教训之一）。
5. **怎么改它**：三个常见改法各一段——换机器人（子类化，Galbot 版链接 6.4.3）、换物体（UsdFileCfg / 原始形状）、改奖励（加项/改权重，回链 5.5）。
6. 一张"文件 → Manager → mdp 函数"的调用链图（D-017）。
7. 常见误解 ≥ 3（候选：`lift_env_cfg.py` 能直接跑；夹爪动作是连续的；课程学习是自动的）。
