2. **生成方式**：`tools/gen_changelog.py` 从 `git log`（提交信息 `T-<编号>: <标题>` 的约定 + 每次提交涉及的 `docs/**.md`）生成表格主体；人工摘要只在"里程碑"小节（例如 2026-09-30 站点上线、2026-10-09 黄金路径闭环），由设计 session 维护。生成脚本放 `tools/`，接入 `tools/check_head_build.sh` 的 `--check`（与占位页一样：HEAD 的页面须与生成结果一致）——这一步由设计 session 做，实现方只提供脚本和 `--check` 模式。
3. **粒度**：按提交合并同一页面同一天的多次改动；占位页的重新生成不计入（过滤 `gen_placeholders` 的提交或 `orphan: true` 页面）。
4. **读者视角**：每条写页面标题而非任务编号；任务编号可放次要列。
5. 维护规则：合并时自动再生成，人工只改"里程碑"。

**生成规则**（脚本开头的 docstring 写了同样的内容）：
- **范围**：2026-09-30 起改动过 `docs/**.md` 的提交（`docs/_*` 除外）。不收 A.5 本身，也不收 `docs/conf.py` 中 `exclude_patterns` 里的 .md（目前只有 MIGRATION-NOTES，它不进站点，链接会让 -W 失败）。
- **占位页过滤**：看文件内容，不看提交。以下三种都算占位页：gen_placeholders 写入的标记；早期手写的"待写，见 OUTLINE"；一级标题以"（待写）"结尾。这一版还是占位页的跳过。占位页都是 gen_placeholders 生成的，它们的识别标记就是那行 placeholder 标记，所以卡上说的 `orphan: true` 过滤由这一条覆盖。
- **变化类型**：上一版不存在或还是占位页，记"新增"。任务编号属于 T-8.6 的后续微任务（`T-8.6[a-z]`），记"版本核对"。其余记"修订"。
- **合并**：同一页面同一天的多次提交合并为一行，类型按 新增 > 修订 > 版本核对 取。一句话用分号拼接；同一天如果既有正文改动又有统一的版本核对，只写正文改动的说明。
- **页面列**：标题取当天最新一次提交时的 frontmatter `title`，没有就取一级标题，所以以后改名不会改动历史行。现在已不存在的页面（如 `0-map/index.md`）只写标题并注明"页面已移除"，不加链接。
- **一句话**：取提交标题，去掉开头的任务编号（每个以"；"分开的部分都去）。任务编号放在最后一列，次要位置。
- **排序**：按日期倒序；同一天内按提交从新到旧，排序是稳定的。

**--check 语义**：只比较、不写，不一致时退出码 1。页面是在提交前生成的，所以表里不含"重新生成它的那次提交"。为此，如果最新一次改动 docs 的提交同时改了 A.5，并且那一版 A.5 已经带有表格标记，就用这次提交之前的提交来比较；否则用全部提交比较。接入 `check_head_build.sh` 由设计负责；接法与占位页的检查相同。合并带 A.5 的提交时请先运行 `python3 tools/gen_changelog.py`，提交后 HEAD 上 `--check` 应返回 0。
