## 目标

## 必须完成

1. 定位：Sphinx 前端 `searchtools.js` 的 `splitQuery` 不分中文；后端索引已用 jieba 分词。
2. 方案二选一并说明理由：(a) 覆盖 `splitQuery`，前端用与后端一致的规则切分（把连续汉字按 2-gram 或按索引里已有词表切分）；(b) 后端在 `html_search_options` 或自定义 `SearchLanguage` 里把索引改为 2-gram，前端同样 2-gram。以能命中 reviews/T-SITE-03.md 列出的失败用例为准。
3. 测试用例 ≥ 8（含单词、双词短语、中英混合如"Isaac Lab 边界"、英文），结果写附记。
4. 不引入外部搜索服务。

### 实现附记（isaac-academy-accomplish，2026-09-30）

**方案选 (a)：前端覆盖 `splitQuery`，按索引词表正向最长匹配。** 理由：
- 索引端不用改。`sphinx/search/zh.py` 已用 `jieba.cut_for_search`，长词和其中的短词都进了索引；它的 `word_filter` 只收录长度 > 1 的词。
- 前端直接用已加载的 `Search._index.terms` / `titleterms` 作词表，切出来的词一定是索引里有的词，与后端规则一致。
- (b) 改成 2-gram 索引会让索引变大，也会丢掉 jieba 的词边界（例如"本站"与"站实"都会成词），查准率下降。

**实现**：
- 新增 `docs/_static/js/cjk-search.js`，在 `conf.py` 的 `html_js_files` 中注册。它在 `searchtools.js` 之前加载，已核对 `search.html` 中的脚本顺序；`searchtools.js` L172 只在 `splitQuery` 未定义时才用默认实现。
- 切分规则：
  1. 先按 Sphinx 默认规则切分，再把每段中的连续汉字与非汉字分开，例如 `Lab边界` 切成 `Lab` 与 `边界`。
  2. 整段汉字在索引中就原样保留；否则在索引词表中做正向最长匹配，最长 8 个字。
  3. 匹配不上的单字丢弃，与索引端不收录单字一致，例如"旧导入路径"切成"导入""路径"。
  4. 匹配不上的连续多字原样保留，因此查询索引中没有的词仍返回 0 条（对照组"量子纠缠"为 0）。
- README 部署一节补了一句搜索的实现方式。
- `tools/check_head_build.sh --worktree` 通过（-W）。

**测试**：

**已知限制**：
- 短语被切成多个词后按"同时包含"匹配，不要求相邻。所以"版本绑定"从 1 页变成 4 页（原来的 1 页仍在其中），排序也不会优先显示含完整短语的页面。截图中"导入路径"的第一条结果是 0.2，含完整短语的 1.4 排在第三。
- 如需"含完整短语的页面优先"，可以再加一步：在排序阶段对标题或正文含原始短语的结果加分。这需要改动 Sphinx 的 `Scorer`，本次没有做，等设计 session 决定是否需要。
- 设计 session 裁断（2026-09-30）：不改 `Scorer`，精确短语优先排序作为已知限制，README 已写明，页面增多后再评估。
