# T-SITE-12 占位页对读者友好

状态: 已合并
优先级: P1（用户反馈；不占 GPU，穿插做）
类型: 基础设施
产出: 全部占位页（当前 61 个）、`docs/index.md`、生成/检查脚本放 `tools/`

## 背景

用户打开 2.3 看到"待写，见 OUTLINE 2.3"。OUTLINE.md 不在站上，读者不知道这是什么、什么时候有。

## 必须完成

1. **统一占位页模板**（由脚本从 OUTLINE.md 生成，保证 61 页一致，今后新占位页也用它）：
   - 顶部一个 `note` 提示框："本页尚未编写。"
   - "计划内容"：OUTLINE 中该页的一句话说明。
   - "优先级与顺序"：P1 / P2 / P3 的含义一句话（P1 = 黄金路径与核心概念，先写；P2 = 第二阶段；P3 = 长期补充），本页属于哪一级。
   - "现在可以读什么"：链接 0.7 学习路线图与同部分已完成的页面（脚本按 OUTLINE 与现有正式页自动生成）。
   - "进度"：链接 A.5 更新日志（若 A.5 仍是占位，先在首页放一个简表，见第 2 项）。
   - 保留 `orphan: true` 与现有 slug，不改 toctree。
2. **首页进度表**：`docs/index.md` 加一节"建设进度"：各部分 P1 已完成 / 总数、P2、P3 的页数（脚本从 OUTLINE 与占位页标记统计生成，提交时写死数字并注明生成日期；每次合并不必更新，设计 session 定期刷新）。
3. **左侧目录**：评估能否给未完成页面的目录项加一个轻量标记（如灰色或"草稿"后缀，用 CSS 类）；pydata 不支持就说明并跳过，不做复杂定制。
4. 脚本 `tools/gen_placeholders.py`：输入 OUTLINE.md 与 docs/，为每个"待写"页重写模板内容；带 `--check` 模式供 check_head_build 调用，确保占位页都符合模板。

## 验收标准

61 个占位页内容一致、说明可读；首页进度表数字与实际一致；`sphinx-build -W` 零警告；截图一个占位页（浅色）放附记。

**做法**
1. 模板：H1 后缀"（待写）"、生成标记注释、note 提示框"本页尚未编写"、计划内容（OUTLINE 的说明；"← 4.8"这样的依赖箭头改写为"（建议先读 4.8）"）、优先级（P1 / P2 / P3 的含义各一句）、现在可以读什么（0.7 加上同一部分已完成的页面；第 6 部分按小节 6.x 分，其余按部分分）、进度（链接首页的建设进度）。frontmatter 原样保留；占位页本来都没有 orphan，slug 与 toctree 都没动。OUTLINE 的表格列数不统一（有的有"类型"列、附录没有说明列），脚本按 P1/P2/P3 定位优先级列。
2. 首页进度表：按部分统计 P1 / P2 / P3 的"已完成 / 总数"，以及合计。**注意**：统计按工作区计算，当前包括尚未合并的 6.5.1 草稿（第 6 部分 P1 显示 10 / 12）。合并时请按提交内容重跑一次 `python3 tools/gen_placeholders.py` 刷新数字；生成日期写在表注里。
3. 左侧目录标记：没有用 CSS。占位页的 H1 加"（待写）"后，pydata 的目录直接显示这个后缀；上一页 / 下一页的链接与面包屑也一并显示，这是原生行为，不需要定制。
4. `--check`：重新生成后与现有文件逐字比较，不一致时返回 1（当前 61 个，不一致 0）。某页从占位转为正式页后，同部分占位页的"现在可以读什么"列表会过时，--check 会报告，重跑脚本即可。是否接入 `tools/check_head_build.sh` 由设计 session 决定（那是设计的文件）。

**验证**：`tools/check_head_build.sh --worktree` 通过；`--check` 返回 0。截图（浅色，1440 宽，6.2.2 占位页，左侧目录可见"（待写）"）：scratchpad `ph_light.png`。
