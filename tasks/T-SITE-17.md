# T-SITE-17 页面去掉本站内部叫法："校验方 / 实现方"、reviews/ 路径、任务卡号

状态: 待实现
优先级: P2（排在 T-GA-05 之后；纯文字，约 1.5 h，不跑 GPU）
类型: 全站文字清理 + 巡检规则
依赖: 无（T-GA-05 合并后开工，避免同时改同一批页面）
产出: `docs/` 下命中的页面；`reviews/` 侧由校验方在 `audit-all.sh` 加一项检查

## 背景

设计方 2026-10-24 统计：28 个已发布页面共 45 处写了"校验方 / 实现方"（41 / 4），4 处引用 `reviews/…`，若干处在正文引用任务卡号（如"T-6.1.5b"）。这些是三个 session 协作的内部叫法，读者看不懂，`reviews/` 和 `tasks/` 也不在站点上。T-GA-01 合并时已在 1.5 改过一处，说明这类写法会随"照实写"不断带进来。

## 要做什么

1. **"校验方 / 实现方"**：改成读者能懂的说法，按语境选："本站在第二个环境里复现"、"本站两次独立测量"、"本站复测"等。表格里两列分别是两方测量的（如 4.14 表"实现方 3 次 / 校验方 3 次"），改为"第一组 / 第二组（独立环境）"之类，并在表注说明两组的差别（环境、时间）。数字与结论不改。
2. **`reviews/…` 引用**：页面上指向 `reviews/` 的说法改为在页内写清实测要点（一两句），或改为"本站实测"并保留日期；不要链接到站点上不存在的文件。
3. **任务卡号**：正文里的卡号（`T-…`）删掉或改为页面链接；**例外**：6.1.7"资产版本管理"里作为提交信息示例出现的卡号，若是在演示 commit message 的写法，可以保留，但要让读者明白那是示例。`docs/MIGRATION-NOTES.md`、`docs/0-map/_template-check.md` 若不是站点页面（不在任何 toctree 里），不改，在附记说明。
4. A.5 更新日志的"任务"列本来就是卡号，不改。
5. 改完 `grep -rn "校验方\|实现方" docs --include=*.md` 应无命中（A.5 除外）；剩余的 `reviews/` 与 `T-` 命中逐条在附记说明保留理由。

## 校验（examine）

- 抽查 10 处改写，数字与结论未变、语义未变。
- 在 `audit-all.sh` 加第 12 项检查：`docs/` 页面（排除 A.5 与 `_build`）出现"校验方 / 实现方 / reviews/"即报一般问题；把这条写进 `validator-audit-scripts` 记忆。
- -W 构建。

## 验收标准

页面不再出现内部角色名与 `reviews/` 路径；卡号只剩有理由的示例；巡检脚本能拦住今后的回归。
